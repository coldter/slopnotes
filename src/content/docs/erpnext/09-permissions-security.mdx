## Role-Based Access Control (RBAC)

Roles define what actions a user can perform on a DocType — enforced at the ORM and API layers, not in hand-written guards. For ScoopJoy: a franchise manager sees only their outlet's data; HQ sees everything.

Create roles in an `after_install` hook, or declaratively via fixtures (preferred — they ship with the app and migrate between sites):

```python title="franchise_management/setup/roles.py"
import frappe

def create_franchise_roles():
    roles = [
        {"role_name": "Franchise Manager", "desk_access": 1, "is_custom": 1},
        {"role_name": "Franchise Staff", "desk_access": 1, "is_custom": 1},
        {"role_name": "Franchise Auditor", "desk_access": 1, "is_custom": 1},
        {"role_name": "Franchise Portal User", "desk_access": 0, "is_custom": 1},
    ]
    for role in roles:
        if not frappe.db.exists("Role", role["role_name"]):
            frappe.get_doc({"doctype": "Role", **role}).insert(ignore_permissions=True)
```

```json title="franchise_management/fixtures/role.json"
    {"doctype": "Role", "role_name": "Franchise Manager", "desk_access": 1, "is_custom": 1},
    {"doctype": "Role", "role_name": "Franchise Staff", "desk_access": 1, "is_custom": 1},
    {"doctype": "Role", "role_name": "Franchise Auditor", "desk_access": 1, "is_custom": 1}
]
```

## DocType permission matrix

Each DocType's JSON (or the **Role Permission Manager** UI) defines what each role can do:

| Permission | Description |
|------------|-------------|
| `read` / `write` / `create` / `delete` | CRUD |
| `submit` / `cancel` / `amend` | Submittable lifecycle |
| `print` / `email` / `report` | Output actions |
| `import` / `export` / `share` | Data movement and sharing |

```json title="franchise_management/doctype/franchise_outlet/franchise_outlet.json"
{
    "permissions": [
        {
            "role": "System Manager",
            "read": 1, "write": 1, "create": 1, "delete": 1,
            "submit": 0, "cancel": 0, "amend": 0,
            "print": 1, "email": 1, "report": 1,
            "import": 1, "export": 1, "share": 1,
            "permlevel": 0
        },
        {
            "role": "Franchise Manager",
            "read": 1, "write": 1, "create": 0, "delete": 0,
            "print": 1, "email": 1, "report": 1,
            "export": 1,
            "permlevel": 0
        },
        {
            "role": "Franchise Staff",
            "read": 1, "write": 0, "create": 0, "delete": 0,
            "print": 1,
            "permlevel": 0

        {
            "role": "Franchise Auditor",
            "read": 1, "write": 0, "create": 0, "delete": 0,
            "report": 1, "export": 1,

}
```

## Permission levels: field-level security

Permlevels (0–9) hide sensitive fields from lower roles. Level 0 is default; higher levels are progressively restricted. Set `permlevel` on the field, then give each role one permission row per level:

```json
{ "fieldname": "custom_cost_price", "fieldtype": "Currency", "label": "Cost Price", "permlevel": 1 }
{ "fieldname": "custom_profit_margin", "fieldtype": "Percent", "label": "Profit Margin", "permlevel": 1 }
{ "fieldname": "custom_royalty_amount", "fieldtype": "Currency", "label": "Royalty Amount", "permlevel": 2 }
```

```python
# Level 0 = all roles with read · Level 1 = cost data · Level 2 = royalty data
{
    "permissions": [
        # System Manager: full access to all levels
        {"role": "System Manager", "permlevel": 0, "read": 1, "write": 1},
        {"role": "System Manager", "permlevel": 1, "read": 1, "write": 1},
        {"role": "System Manager", "permlevel": 2, "read": 1, "write": 1},

        # Franchise Manager: sees costs read-only, no royalty internals
        {"role": "Franchise Manager", "permlevel": 0, "read": 1, "write": 1},
        {"role": "Franchise Manager", "permlevel": 1, "read": 1, "write": 0},

        # Franchise Staff: only level 0 fields
        {"role": "Franchise Staff", "permlevel": 0, "read": 1, "write": 0},

        # Franchise Auditor: read-only on all levels
        {"role": "Franchise Auditor", "permlevel": 0, "read": 1, "write": 0},
        {"role": "Franchise Auditor", "permlevel": 1, "read": 1, "write": 0},
        {"role": "Franchise Auditor", "permlevel": 2, "read": 1, "write": 0},
    ]
}
```

Result: Staff never sees cost/royalty fields; Managers see costs read-only; Auditors see everything read-only.

## User Permissions: row-level filtering

User Permissions restrict which documents a user can see, based on Link field values — an automatic `WHERE outlet = ?` on every query. If `User A` has `User Permission: Franchise Outlet = OUTLET-001`, they see only that outlet and any DocType linked to it.

```python title="franchise_management/setup/user_permissions.py"
import frappe

def assign_outlet_to_manager(outlet_name, user_email):
    """Restrict a user to only their assigned outlet."""
    frappe.db.delete("User Permission", {
        "user": user_email,
        "allow": "Franchise Outlet",
    })
    frappe.get_doc({
        "doctype": "User Permission",
        "user": user_email,
        "allow": "Franchise Outlet",
        "for_value": outlet_name,
        "apply_to_all_doctypes": 1,  # apply across all DocTypes
    }).insert(ignore_permissions=True)

    territory = frappe.db.get_value("Franchise Outlet", outlet_name, "territory")
    if territory:
        frappe.get_doc({
            "doctype": "User Permission",
            "user": user_email,
            "allow": "Territory",
            "for_value": territory,
        }).insert(ignore_permissions=True)


def assign_multi_outlet_manager(user_email, outlet_names):
    """Assign a regional manager to multiple outlets."""
    frappe.db.delete("User Permission", {
        "user": user_email,
        "allow": "Franchise Outlet",
    })
    for outlet_name in outlet_names:
        frappe.get_doc({
            "doctype": "User Permission",
            "user": user_email,
            "allow": "Franchise Outlet",
            "for_value": outlet_name,
            "apply_to_all_doctypes": 1,
        }).insert(ignore_permissions=True)
```

:::caution[User Permissions restrict — they don't grant]
No User Permission for a DocType means the user sees ALL records. The moment you add one, access narrows to only matching records. Adding a permission restricts; it never expands.
:::

## `has_permission()`: custom permission logic

The escape hatch for rules that depend on document data or runtime state. Checks both the DocType matrix and this hook.

:::caution[v16 breaking change: return True explicitly]
In v16, `has_permission` methods must `return True` to grant access. Returning `None`, `1`, or any other truthy value no longer works.
:::

```python title="franchise_management/doctype/franchise_outlet/franchise_outlet.py"
import frappe
from frappe.model.document import Document

class FranchiseOutlet(Document):
    def has_permission(self, permtype="read", user=None):
        user = user or frappe.session.user

        if user == "Administrator" or "System Manager" in frappe.get_roles(user):
            return True

        if permtype == "read" and "Franchise Auditor" in frappe.get_roles(user):
            return True

        if "Franchise Manager" in frappe.get_roles(user):
            if self.custom_manager_user == user:
                return True
            is_regional = frappe.db.exists("User Permission", {
                "user": user,
                "allow": "Territory",
                "for_value": self.territory,
            })
            if is_regional:
                return True

        if "Franchise Staff" in frappe.get_roles(user):
            staff_outlet = frappe.db.get_value(
                "User Permission",
                {"user": user, "allow": "Franchise Outlet"},
                "for_value",
            )
            if staff_outlet == self.name:
                return True

        return False
```

Call it directly in whitelisted methods:

```python title="franchise_management/api.py"
@frappe.whitelist()
def get_outlet_financials(outlet: str):
    """Check permissions before returning sensitive financial data."""
    if not frappe.has_permission("Franchise Outlet", doc=outlet, ptype="read"):
        frappe.throw("You do not have permission to view this outlet", frappe.PermissionError)

    if "Franchise Auditor" not in frappe.get_roles():
        frappe.throw("Only Franchise Auditors can view financial data", frappe.PermissionError)

    return get_financial_data(outlet)
```

## Document sharing

Sharing grants access to one specific document — a controlled exception to the rules above. (A share-escalation vulnerability was patched in v15.98.0/v14.100.0 — keep your install current.)

```python title="franchise_management/setup/sharing.py"
import frappe

def share_report_with_franchise_owner(report_name, owner_email):
    frappe.share.add(
        doctype="Franchise Report",
        name=report_name,
        user=owner_email,
        read=1, write=0, submit=0, share=0,
        notify=1,  # email notification
    )

# Remove a share
frappe.share.remove(doctype="Franchise Report", name=report_name, user=owner_email)

# Check existing shares
shares = frappe.share.get_shared(doctype="Franchise Report", name=report_name)
```

## Guest access and website permissions

Public endpoints return only safe fields — never internal data to guests:

```python title="franchise_management/api.py"
@frappe.whitelist(allow_guest=True, methods=["GET"])
def get_public_outlet_info(outlet: str):
    """Public franchise-portal API — no login required."""
    outlet_doc = frappe.get_doc("Franchise Outlet", outlet)
    return {
        "outlet_name": outlet_doc.outlet_name,
        "city": outlet_doc.city,
        "state": outlet_doc.state,
        "opening_hours": outlet_doc.custom_opening_hours,
        "contact_phone": outlet_doc.custom_public_phone,
    }
```

## System Manager vs Administrator

| | System Manager (Role) | Administrator (User) |
|---|---|---|
| **What** | A role assigned to users | A single user account |
| **Scope** | Full desk access, manages users/roles | Bypasses ALL permission checks |
| **User Permissions** | Applied (can be restricted) | Never applied |
| **`has_permission`** | Checked (usually returns True) | Skipped entirely |
| **Use case** | Day-to-day admin | Emergency access, initial setup |

Never use Administrator for daily work — create named users with the System Manager role so audit trails trace to real people.

## Complete franchise permission setup

One `after_install` entry point that creates roles, sets DocType permissions, and seeds user permissions:

```python title="franchise_management/setup/permissions.py"
import frappe

def setup_franchise_permissions():
    """Complete permission setup. Call from after_install hook."""

    # 1. Create roles
    roles = {
        "Franchise Manager": {"desk_access": 1},
        "Franchise Staff": {"desk_access": 1},
        "Franchise Auditor": {"desk_access": 1},
    }
    for role_name, props in roles.items():
        if not frappe.db.exists("Role", role_name):
            frappe.get_doc({"doctype": "Role", "role_name": role_name, **props}).insert(
                ignore_permissions=True
            )

    # 2. DocType permissions for Franchise Outlet
    set_doctype_permissions("Franchise Outlet", [
        {"role": "Franchise Manager", "read": 1, "write": 1, "create": 0,
         "delete": 0, "print": 1, "email": 1, "report": 1, "export": 1},
        {"role": "Franchise Staff", "read": 1, "write": 0, "create": 0,
         "delete": 0, "print": 1},
        {"role": "Franchise Auditor", "read": 1, "write": 0, "create": 0,
         "delete": 0, "report": 1, "export": 1},
    ])

    # 3. DocType permissions for Franchise Royalty — Staff cannot see it at all
    set_doctype_permissions("Franchise Royalty", [
        {"role": "Franchise Manager", "read": 1, "write": 0, "report": 1},
        {"role": "Franchise Auditor", "read": 1, "write": 0, "report": 1, "export": 1},
    ])

    # 4. Sample user permission
    sample_setup_user_permission(
        user="john@lakeside.com",
        outlet="OUTLET-001",
        territory="Midwest",
    )


def set_doctype_permissions(doctype, permission_list):
    """Set permissions on a DocType via Custom DocPerm rows."""
    frappe.get_meta(doctype)
    for perm in permission_list:
        existing = frappe.db.exists("Custom DocPerm", {
            "parent": doctype,
            "role": perm["role"],
            "permlevel": perm.get("permlevel", 0),
        })
        if existing:
            frappe.delete_doc("Custom DocPerm", existing, ignore_permissions=True)

        frappe.get_doc({
            "doctype": "Custom DocPerm",
            "parent": doctype,
            "parenttype": "DocType",
            "parentfield": "permissions",
            "role": perm["role"],
            "permlevel": perm.get("permlevel", 0),
            **{k: v for k, v in perm.items() if k not in ("role", "permlevel")},
        }).insert(ignore_permissions=True)


def sample_setup_user_permission(user, outlet, territory):
    for allow, value in [("Franchise Outlet", outlet), ("Territory", territory)]:
        if not frappe.db.exists("User Permission", {
            "user": user, "allow": allow, "for_value": value,
        }):
            frappe.get_doc({
                "doctype": "User Permission",
                "user": user,
                "allow": allow,
                "for_value": value,
                "apply_to_all_doctypes": 1,
            }).insert(ignore_permissions=True)
```

## Security best practices

### CSRF protection

Built in. Every non-GET request needs the token — automatic in Desk, required for external callers. (A CSRF bypass in v15 allowed password changes via GET — keep Frappe patched.)

```javascript
fetch("/api/method/some_method", {
    method: "POST",
    headers: {
        "Content-Type": "application/json",
        "X-Frappe-CSRF-Token": frappe.csrf_token,
    },
    body: JSON.stringify({ key: "value" }),
});
```

### SQL injection prevention

The ORM (`frappe.get_all`, `frappe.get_list`, `frappe.db.get_value`) is safe by default. Raw SQL is the danger zone:

```python
# DANGEROUS — SQL injection via string concatenation
def get_outlet_sales_UNSAFE(outlet_name):
    return frappe.db.sql(
        f"SELECT * FROM `tabSales Invoice` WHERE custom_franchise_outlet = '{outlet_name}'"
    )

# SAFE — parameterized queries
def get_outlet_sales(outlet_name):
    return frappe.db.sql(
        "SELECT * FROM `tabSales Invoice` WHERE custom_franchise_outlet = %s",
        (outlet_name,),
        as_dict=True,
    )

# SAFEST — the ORM
def get_outlet_sales_orm(outlet_name):
    return frappe.get_all(
        "Sales Invoice",
        filters={"custom_franchise_outlet": outlet_name},
        fields=["name", "grand_total", "posting_date"],
    )
```

:::danger[Never concatenate user input into SQL]
CVE-2025-30212 and CVE-2025-56380 exposed SQL injection where user input was concatenated into queries. Always use `%s` placeholders or the ORM. Never build SQL with f-strings or `.format()`.
:::

### XSS prevention

Jinja auto-escapes `{{ variable }}`. Only `| safe` bypasses it — never use that with user input:

```python
# DANGEROUS — user input as raw HTML
frappe.msgprint(f"Welcome, {user_input}")

# SAFE — explicit escaping
frappe.msgprint(f"Welcome, {frappe.bold(frappe.utils.escape_html(user_input))}")
```

### Whitelisted method security

A whitelisted method is a public endpoint — validate types, check permissions, restrict roles, never trust the client's field list:

```python title="franchise_management/api.py"
@frappe.whitelist()
def update_outlet_settings(outlet: str, settings: dict):
    """Secure whitelisted method with proper checks."""
    # 1. Type annotations enforce parameter types (v16+)

    # 2. Always check permissions
    frappe.has_permission("Franchise Outlet", doc=outlet, ptype="write", throw=True)

    # 3. Restrict to specific roles
    frappe.only_for(["Franchise Manager", "System Manager"])

    # 4. Validate input — don't trust the client
    allowed_fields = {"opening_hours", "contact_phone", "seating_capacity"}
    for key in settings:
        if key not in allowed_fields:
            frappe.throw(f"Cannot update field: {key}")

    # 5. Controlled updates via set_value, not doc.update with an arbitrary dict
    for field, value in settings.items():
        frappe.db.set_value("Franchise Outlet", outlet, field, value)
```

### Security layers summary

| Layer | Mechanism | Scope |
|-------|-----------|-------|
| **Authentication** | Login + session/token/OAuth | Who is accessing |
| **Role Permissions** | DocType permission matrix | What they can do (CRUD) |
| **Permission Levels** | Field-level `permlevel` (0–9) | Which fields they see |
| **User Permissions** | Link-field row filtering | Which records they see |
| **`has_permission()`** | Custom Python logic | Complex business rules |
| **Sharing** | Document-level grants | Exceptions to the above |
| **CSRF Tokens** | `X-Frappe-CSRF-Token` header | Cross-site attack prevention |
| **Input Validation** | Type annotations, parameterized SQL | Injection prevention |
