## Prerequisites

| Dependency  | Required Version | Why |
|-------------|------------------|-----|
| Python      | 3.14+            | Frappe v16 server-side runtime |
| Node.js     | 24 LTS           | Asset building (esbuild) + Socket.IO |
| MariaDB     | 10.6+            | Primary database (or Postgres 14+) |
| Redis       | 8+               | Caching, queues, real-time messaging |
| Git         | 2.x              | App management, version control |
| pip         | Latest           | Python package installer |
| wkhtmltopdf | 0.12.6+          | PDF generation (legacy; v16 adds Chrome) |
| Yarn        | 1.x              | Node.js dependency management |

## Choosing an install method

**Native bench** installs on the host OS — best for production servers and full control. **Docker** uses the official `frappe_docker` DevContainer — sidesteps "works on my machine". Pick one.

  <TabItem label="Native bench">

Ubuntu 24.04 bare-metal: install Python, Node, MariaDB, Redis, bench, then init a bench and site.

<Steps>

1. **Install system dependencies.**

   ```bash
   sudo apt update && sudo apt upgrade -y
   sudo apt install -y \
     git python3-dev python3-pip python3-venv python3-setuptools \
     build-essential libffi-dev libssl-dev libjpeg-dev libpng-dev \
     zlib1g-dev libmysqlclient-dev curl wget software-properties-common
   ```

2. **Install Python 3.14.** Ubuntu 24.04 ships 3.12 — Frappe v16 needs 3.14.

   ```bash
   sudo add-apt-repository ppa:deadsnakes/ppa -y
   sudo apt update
   sudo apt install -y python3.14 python3.14-dev python3.14-venv
   python3.14 --version  # Python 3.14.x
   ```

   If deadsnakes lacks 3.14 for your platform, use [pyenv](https://github.com/pyenv/pyenv): `curl https://pyenv.run | bash && pyenv install 3.14 && pyenv local 3.14`.

3. **Install Node.js 24.**

   ```bash
   curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
   sudo apt install -y nodejs
   node --version   # v24.x.x
   npm --version    # 10.x.x
   sudo npm install -g yarn
   ```

4. **Install and configure MariaDB.** `utf8mb4` is mandatory.

   ```bash
   sudo apt install -y mariadb-server mariadb-client
   sudo mysql_secure_installation
   # unix_socket auth: N · root password: Y · anonymous: Y · remote root: Y · test db: Y · reload: Y
   ```

   ```ini title="/etc/mysql/mariadb.conf.d/99-frappe.cnf"
   [mysqld]
   character-set-client-handshake = FALSE
   character-set-server = utf8mb4
   collation-server = utf8mb4_unicode_ci

   [mysql]
   default-character-set = utf8mb4
   ```

   ```bash
   sudo systemctl restart mariadb
   mariadb --version  # mariadb Ver 15.x Distrib 10.x.x-MariaDB
   ```

   :::caution[Don't skip the character set]
   Without `utf8mb4` you get errors on emoji, multilingual data, and various Frappe operations. It is not optional.
   :::

5. **Install Redis.**

   ```bash
   sudo apt install -y redis-server
   redis-server --version  # Redis server v=8.x.x ...
   sudo systemctl enable redis-server
   sudo systemctl start redis-server
   ```

6. **Install wkhtmltopdf.**

   ```bash
   wget https://github.com/wkhtmltopdf/packaging/releases/download/0.12.6.1-3/wkhtmltox_0.12.6.1-3.jammy_amd64.deb
   sudo dpkg -i wkhtmltox_0.12.6.1-3.jammy_amd64.deb
   sudo apt install -f -y
   wkhtmltopdf --version  # wkhtmltopdf 0.12.6.1 (with patched qt)
   ```

   v16 also ships Chrome-based PDF rendering with modern CSS (flexbox, grid) — set it in **Print Settings > PDF Engine**. wkhtmltopdf remains the legacy fallback.

7. **Install bench.**

   ```bash
   pip install frappe-bench
   bench --version  # 5.x.x
   ```

8. **Initialize a bench** with Frappe v16.

   ```bash
   bench init frappe-bench --frappe-branch version-16 --python python3.14
   cd frappe-bench
   ```

9. **Create a site.**

   ```bash
   bench new-site icecream.localhost --mariadb-root-password <your-mariadb-root-password>
   bench use icecream.localhost
   ```

10. **Install ERPNext.**

    ```bash
    bench get-app erpnext --branch version-16
    bench --site icecream.localhost install-app erpnext
    ```

11. **Start the development server.**

    ```bash
    bench start
    # web.1       Running on http://0.0.0.0:8000
    # socketio.1  listening on port 9000
    # watch.1     watching for file changes...
    # worker.1    Worker rq:worker started
    # schedule.1  Scheduler started
    ```

</Steps>

Open `http://icecream.localhost:8000` and log in as **Administrator** with the password from `bench new-site` (`admin` if unset). If the hostname doesn't resolve: `echo "127.0.0.1 icecream.localhost" | sudo tee -a /etc/hosts`.

  </TabItem>
  <TabItem label="Docker">

The official `frappe_docker` repo provides a VS Code DevContainer that provisions MariaDB, Redis, and the bench.

<Steps>

1. **Install Docker, Compose, and VS Code** with the Dev Containers extension (`ms-vscode-remote.remote-containers`).

   ```bash
   curl -fsSL https://get.docker.com | bash
   sudo usermod -aG docker $USER  # log out and back in
   docker --version        # Docker version 27.x.x
   docker compose version  # Docker Compose version v2.x.x
   ```

2. **Clone and configure** the repo.

   ```bash
   git clone https://github.com/frappe/frappe_docker.git
   cd frappe_docker
   cp -R devcontainer-example .devcontainer
   cp -R development/vscode-example development/.vscode
   ```

3. **Open in the DevContainer.** Run `code .`, click **"Reopen in Container"** (or `Ctrl+Shift+P` → "Dev Containers: Reopen in Container"). The first build provisions MariaDB, Redis, and the bench.

4. **Initialize bench inside the container** (working dir `/workspace/development`).

   ```bash
   bench init --skip-redis-config-generation frappe-bench
   cd frappe-bench
   bench set-config -g db_host mariadb
   bench set-config -g redis_cache redis://redis-cache:6379
   bench set-config -g redis_queue redis://redis-queue:6379
   bench set-config -g redis_socketio redis://redis-cache:6379
   bench new-site icecream.localhost --mariadb-root-password 123 --admin-password admin
   bench get-app erpnext --branch version-16
   bench --site icecream.localhost install-app erpnext
   bench start
   ```

</Steps>

:::caution[Weak default password]
The Docker setup's default MariaDB root password is `123` — fine locally, never in production.
:::

The dev Compose file starts:

| Service     | Port | Purpose |
|-------------|------|---------|
| frappe      | 8000 | Bench development server |
| mariadb     | 3306 | Database |
| redis-cache | 6379 | Cache and Socket.IO pub/sub |
| redis-queue | 6380 | Background job queues |

## Cloud environments (Gitpod / Codespaces)

Zero-local-setup option for workshops and demos. **Gitpod**: open `https://gitpod.io/#https://github.com/frappe/frappe_docker` (swap in your fork). **Codespaces**: fork `frappe/frappe_docker`, click **Code → Codespaces → Create codespace on main**, then run the same `bench init` steps as the Docker tab. For daily work with large datasets, local is more responsive.

## VS Code: extensions and debugging

Recommended extensions:

```json title="~/frappe-bench/.vscode/extensions.json"
{
  "recommendations": [
    "ms-python.python",
    "ms-python.debugpy",
    "dbaeumer.vscode-eslint",
    "esbenp.prettier-vscode",
    "ms-vscode-remote.remote-containers",
    "samuelcolvin.jinjahtml"
  ]
}
```

Debug config — launches the web server and a worker under `debugpy`. Note `--noreload`: the auto-reloader and debugger don't coexist.

```json title="~/frappe-bench/.vscode/launch.json"
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Frappe Web",
      "type": "debugpy",
      "request": "launch",
      "program": "${workspaceFolder}/apps/frappe/frappe/utils/bench_helper.py",
      "args": ["frappe", "serve", "--port", "8000", "--noreload"],
      "env": {
        "DEV_SERVER": "1"
      },
      "cwd": "${workspaceFolder}/sites",
      "python": "${workspaceFolder}/env/bin/python"
    },
    {
      "name": "Frappe Worker (short)",
      "type": "debugpy",
      "request": "launch",
      "program": "${workspaceFolder}/apps/frappe/frappe/utils/bench_helper.py",
      "args": ["frappe", "worker", "--queue", "short"],
      "cwd": "${workspaceFolder}/sites",
      "python": "${workspaceFolder}/env/bin/python"
    }
  ]
}
```

<Steps>
1. Stop `bench start` if running (it holds port 8000).
2. Set breakpoints in your Python code.
3. Press `F5` to start the **Frappe Web** configuration.
4. Trigger the code path from the browser.
5. VS Code hits your breakpoint with full stack inspection.
</Steps>

Point the Python tooling at the bench virtualenv and app source:

```json title="~/frappe-bench/.vscode/settings.json"
{
  "python.defaultInterpreterPath": "./env/bin/python",
  "python.analysis.extraPaths": [
    "./apps/frappe",
    "./apps/erpnext",
    "./apps/scoopjoy"
  ],
  "[python]": {
    "editor.defaultFormatter": "ms-python.python"
  }
}
```

## Common setup issues

### `bench new-site` fails: "Access denied for user 'root'@'localhost'"

```bash
sudo mariadb -u root
```

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY 'your_new_password';
FLUSH PRIVILEGES;
EXIT;
```

Retry: `bench new-site icecream.localhost --mariadb-root-password your_new_password`

### "Node.js version not supported"

```bash
node --version
sudo apt remove -y nodejs
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt install -y nodejs
```

### `bench start` shows Redis connection errors

```bash
sudo systemctl status redis-server
sudo systemctl start redis-server
sudo systemctl enable redis-server
redis-cli ping  # PONG
```

### Site does not load (DNS resolution)

```bash
echo "127.0.0.1 icecream.localhost" | sudo tee -a /etc/hosts
# Or hit 127.0.0.1:8000 directly after: bench use icecream.localhost
```

### Python version mismatch during `bench init`

```bash
bench init frappe-bench --frappe-branch version-16 --python python3.14
# If python3.14 is not in PATH:
bench init frappe-bench --frappe-branch version-16 --python /usr/bin/python3.14
```

### `pip install frappe-bench` permission error

```bash
pip install --user frappe-bench
# Or a dedicated venv:
python3.14 -m venv ~/bench-env
source ~/bench-env/bin/activate
pip install frappe-bench
```
