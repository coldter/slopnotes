## What Frappe is

Frappe is a metadata-driven full-stack framework in Python + JavaScript. From Node.js: it's roughly NestJS + Prisma + AdminJS, but driven by declarative **DocType** definitions instead of decorators.

It gives you an ORM with automatic schema management, auto-generated REST/RPC APIs, the **Desk** admin SPA, a Jinja2 website builder, Redis Queue background jobs, role-based permissions, and Socket.IO realtime.

## ERPNext sits on top

ERPNext is a Frappe **app** — DocTypes, controllers, reports, and print formats implementing accounting, inventory, manufacturing, HR, and CRM. Frappe runs without ERPNext; ERPNext cannot run without Frappe. Your custom apps extend or override both.

## The site-bench-app model

Three-level hierarchy:

- **Bench** — deployment directory: framework, apps, sites, shared virtualenv. One bench = one set of app versions.
- **App** — a Python/JS package following Frappe conventions. Frappe is an app; ERPNext is an app; your code is an app.
- **Site** — a tenant with its own database, files, and config. One bench can host dozens of sites, each with its own MariaDB database but sharing the same app code.

  - apps/

## Request lifecycle

<Mermaid title="Request flow: Nginx → WSGI → handler → DB" height={460} code={`
flowchart TB
  Browser["Browser request"] -->|"HTTP/HTTPS :80/:443"| Nginx["Nginx<br/>reverse proxy · static files"]
  Nginx -->|"proxy_pass :8000"| App["Gunicorn (prod)<br/>or Werkzeug (dev)"]
  App --> WSGI["Frappe WSGI app<br/>1 resolve site · 2 init context<br/>3 connect DB · 4 auth · 5 route"]
  WSGI --> Handler["Request handler"]
  Handler -->|"/api/method/*"| M["whitelisted Python fn"]
  Handler -->|"/api/resource/*"| R["DocType REST API"]
  Handler -->|"/app/*"| Desk["Desk SPA"]
  Handler -->|"/*"| Web["Website (Jinja)"]
  M --> Ctrl["App controller<br/>validation · triggers · logic"]
  R --> Ctrl
  Ctrl --> DB["MariaDB via frappe.db / frappe.qb"]
`} />

URL dispatch: `/api/method/*` → whitelisted Python function, `/api/resource/*` → DocType REST API, `/app/*` → Desk SPA, everything else → Jinja website page. Realtime events publish to Redis; the Node Socket.IO server pushes them to browsers.

### Saving a Sales Order

<Steps>
1. Browser sends `POST /api/resource/Sales Order`.
2. Frappe authenticates and resolves the site from the `Host` header.
3. Loads the Sales Order DocType definition (cached in Redis).
4. `before_validate()` runs (your custom hook).
5. Mandatory fields, links, and formulas are validated.
6. `validate()` runs (business logic).
7. `before_save()` runs.
8. Rows write to `tabSales Order` and `tabSales Order Item`.
9. `after_save()` / `on_update()` run.
10. Transaction commits.
11. Realtime event publishes via Redis → Socket.IO.
12. JSON response returns to the browser.
</Steps>

## Background workers (Redis Queue)

Long tasks never run in the request cycle. Frappe uses Python RQ with three default queues, each with a dedicated worker:

| Queue | Use for |
|-------|---------|
| `default` | Standard jobs: emails, reports |
| `short` | Quick tasks, seconds |
| `long` | Heavy: data import, bulk ops, report generation |

<Mermaid title="Enqueue on web request, execute in worker" height={300} code={`
flowchart LR
  W["Web request<br/>(enqueue job)"] --> Q["Redis Queue<br/>default · short · long"]
  Q --> R["RQ Worker<br/>background Python process"]
`} />

```python
# Enqueue a background job from your app controller
import frappe

frappe.enqueue(
    "scoopjoy.tasks.sync_franchise_inventory",
    queue="long",
    timeout=600,
    franchise_id="FRAN-001",
)
```

The scheduler (`bench enable-scheduler`) runs periodic tasks from `hooks.py`:

```python title="scoopjoy/hooks.py"
scheduler_events = {
    "daily": [
        "scoopjoy.tasks.generate_daily_sales_report",
    ],
    "hourly": [
        "scoopjoy.tasks.sync_ingredient_stock",
    ],
    "cron": {
        "0 9 * * *": [
            "scoopjoy.tasks.send_franchise_morning_briefing",
        ],
    },
}
```

## "Everything is a DocType"

Every entity — Customer, Sales Invoice, User, Email Account, Print Format, Workflow, even DocType itself — is a DocType. The system is self-referential and metadata-driven.

<Mermaid title="One DocType generates table + API + form + list + permissions + search + tracking" height={420} code={`
flowchart LR
  D["DocType<br/>(meta-definition)"] --> T["Database table (tabDocType Name)"]
  D --> A["REST API (/api/resource/...)"]
  D --> F["Form view (layout + validation)"]
  D --> L["List view (filters, sorting)"]
  D --> P["Permission model (per role)"]
  D --> S["Search indexing"]
  D --> V["Activity log / version tracking"]
`} />

- Creating a DocType automatically creates the table, REST API, form, list view, permissions, search, and change tracking.
- **No migration files.** Frappe alters the table from the JSON definition on `bench migrate`.
- Custom Fields, Property Setters, and Client Scripts are themselves DocTypes — customization without code.

### DocType types

| Type | Description | Example |
|------|-------------|---------|
| Regular | Standard CRUD document with list + form views | Customer, Sales Order |
| Child Table | Rows inside a parent document (1:N) | Sales Order Item |
| Single | Singleton — one record (settings) | Selling Settings |
| Submittable | Draft → Submitted → Cancelled lifecycle | Sales Invoice, Journal Entry |
| Tree | Hierarchical parent-child | Account, Territory |
| Virtual | No table; data from an external source | API-backed DocType |

### Example: Ice Cream Flavor DocType

One JSON file gives you a table, REST API, admin form, list view, permissions, and search.

```json title="scoopjoy/scoopjoy/doctype/ice_cream_flavor/ice_cream_flavor.json"
{
  "name": "Ice Cream Flavor",
  "module": "ScoopJoy",
  "doctype": "DocType",
  "is_tree": 0,
  "is_submittable": 0,
  "fields": [
    { "fieldname": "flavor_name", "fieldtype": "Data", "label": "Flavor Name", "reqd": 1, "unique": 1 },
    { "fieldname": "base_type", "fieldtype": "Select", "label": "Base Type", "options": "\nDairy\nSorbet\nVegan", "default": "Dairy" },
    { "fieldname": "cost_per_scoop", "fieldtype": "Currency", "label": "Cost Per Scoop", "reqd": 1 },
    { "fieldname": "is_seasonal", "fieldtype": "Check", "label": "Is Seasonal" },
    { "fieldname": "available_from", "fieldtype": "Date", "label": "Available From", "depends_on": "eval:doc.is_seasonal" },
    { "fieldname": "available_until", "fieldtype": "Date", "label": "Available Until", "depends_on": "eval:doc.is_seasonal" }
  ],
  "permissions": [
    { "role": "System Manager", "read": 1, "write": 1, "create": 1, "delete": 1 }
  ],
  "naming_rule": "By fieldname",
  "autoname": "field:flavor_name",
  "sort_field": "creation",
  "sort_order": "DESC"
}
```

:::caution[v16 changed the default sort]
Frappe v16 sorts by `creation` instead of `modified` for all DocTypes and queries (`frappe.get_all`, `frappe.get_list`). Pass `order_by="modified desc"` explicitly if you need modification order.
:::

## ERPNext v16 vs older versions

| Area | v15 and earlier | v16 |
|------|-----------------|-----|
| **Performance** | Standard caching | "Frappe Caffeine" — ~2× faster page loads, ~30% less CPU/RAM, framework-level so existing apps benefit without code changes |
| **UI/UX** | Fixed-width layout | Redesigned workspace, persistent sidebar, full-width adaptive layout |
| **List views** | Fixed columns | Scrollable, unlimited columns, horizontal scroll |
| **Child tables** | Fixed columns | Scrollable with sticky columns |
| **PDF generation** | wkhtmltopdf only | Chrome-based rendering (modern CSS incl. flexbox) |
| **Security** | Basic field-level permissions | Role-based field masking (sensitive fields show `xxxx`) |
| **Python** | 3.10+ | 3.14+ (required) |
| **Node.js** | 18+ | 24 LTS (required) |
| **Database** | MariaDB/Postgres only | Adds native SQLite for lightweight deployments |
| **Developer tools** | Manual linting | Automated linter, typed APIs, app dependency management |
| **Accounting** | Basic statements | Customizable statement templates, separate COGS/service accounting |
| **Manufacturing** | Standard MRP | Stock reservation, landed cost on stock entries, better traceability |
