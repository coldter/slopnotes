## Creating DocTypes: UI vs code

**Desk UI** (recommended in dev): search bar → "New DocType" → fill fields/properties → Save. In developer mode, Frappe writes the JSON + Python controller to disk for Git.

**Code**: create the JSON + controller in the right directory, then `bench migrate` syncs it to the DB. Teammates pulling your code get the DocType via migrate.

Matching controller — generates the franchise code in `before_save`, validates in `validate`:

```python title="apps/scoopjoy/scoopjoy/franchise_management/doctype/franchise_outlet/franchise_outlet.py"
import frappe
from frappe.model.document import Document


class FranchiseOutlet(Document):
    def before_save(self):
        if not self.franchise_code:
            self.franchise_code = self.generate_franchise_code()

    def validate(self):
        self.validate_operating_hours()
        self.validate_royalty_percentage()

    def validate_operating_hours(self):
        if self.is_24_hours:
            self.opening_time = None
            self.closing_time = None
            return

        if self.opening_time and self.closing_time:
            if self.opening_time >= self.closing_time:
                frappe.throw("Closing time must be after opening time")

    def validate_royalty_percentage(self):
        if self.royalty_percentage and self.royalty_percentage > 50:
            frappe.throw("Royalty percentage cannot exceed 50%")

    def generate_franchise_code(self):
        """Generate a unique franchise code like FC-MUM-001"""
        city_code = (self.city or "XXX")[:3].upper()
        count = frappe.db.count(
            "Franchise Outlet",
            filters={"city": self.city}
        )
        return f"FC-{city_code}-{str(count + 1).zfill(3)}"
```

## Form layout: tabs → sections → columns

v16 forms are tab-based: `Tab Break → Section Break → Column Break → Fields`.

- **Tab Break** — new tab at the top of the form (the first defines the first tab).
- **Section Break** — horizontal section within a tab; can be labeled and collapsible.
- **Column Break** — splits a section into columns (typically 2).

The Franchise Outlet form uses four tabs: **Details** (basic info, contact, location), **Operations** (hours, warehouse, menu), **Financials** (rent, royalties, bank), **Notes**. Tabs keep long forms scannable — group related fields, don't show everything at once.

## Naming conventions

| Naming rule | `autoname` value | Example output |
|---|---|---|
| Expression (Custom) | `FO-.{city}.-.###` | FO-Mumbai-001 |
| By fieldname | `field:outlet_name` | Mumbai Central Outlet |
| By "Naming Series" field | `naming_series:` | FO-2025-001 |
| Random / Hash | `hash` | a1b2c3d4e5 |
| UUID | `UUID` | 01945abc-def0-7... |
| Prompt | `prompt` | (user enters manually) |

`###` auto-increments; `{city}` pulls from the document's field. v16 UUID naming uses **UUID7** — time-sortable, better for indexing than random UUIDs.

## fetch_from: auto-populating fields

When a Link field changes, `fetch_from` copies a field from the linked document (`read_only` blocks manual edits):

```json
{
  "fieldname": "owner_email",
  "fieldtype": "Data",
  "label": "Owner Email",
  "fetch_from": "owner_name.email_id",
  "read_only": 1
}
```

## Link field filters

Static filter on a Link field's options:

```json
{
  "fieldname": "warehouse",
  "fieldtype": "Link",
  "label": "Default Warehouse",
  "options": "Warehouse",
  "link_filters": "[[\"Warehouse\",\"company\",\"=\",\"ScoopJoy Foods\"]]"
}
```

Dynamic filters (depending on other fields) go in the client script — see [Chapter 19](/erpnext/19-client-scripts-pages/).

## Conditional field properties

Formula-based properties toggle fields dynamically. The `eval:` prefix evaluates JavaScript; `doc` is the current document:

```json
{
  "fieldname": "opening_time",
  "fieldtype": "Time",
  "label": "Opening Time",
  "mandatory_depends_on": "eval:!doc.is_24_hours",
  "read_only_depends_on": "eval:doc.is_24_hours",
  "hidden_depends_on": ""
}
```

| Property | Effect when expression is true |
|---|---|
| `mandatory_depends_on` | Field becomes required |
| `read_only_depends_on` | Field becomes read-only |
| `hidden_depends_on` | Field is hidden |

The agreement controller validates dates/terms and syncs the outlet's status on submit/cancel:

```python title="apps/scoopjoy/scoopjoy/franchise_management/doctype/franchise_agreement/franchise_agreement.py"
import frappe
from frappe.model.document import Document
from frappe.utils import getdate, add_years


class FranchiseAgreement(Document):
    def validate(self):
        self.validate_dates()
        self.validate_terms()

    def validate_dates(self):
        if getdate(self.expiry_date) <= getdate(self.agreement_date):
            frappe.throw("Expiry Date must be after Agreement Date")

    def validate_terms(self):
        if not self.agreement_terms:
            frappe.throw("At least one Agreement Term is required")

        mandatory_count = sum(
            1 for term in self.agreement_terms if term.is_mandatory
        )
        if mandatory_count == 0:
            frappe.throw("At least one term must be marked as Mandatory")

    def on_submit(self):
        self.update_outlet_status()

    def on_cancel(self):
        self.revert_outlet_status()

    def update_outlet_status(self):
        outlet = frappe.get_doc("Franchise Outlet", self.franchise_outlet)
        outlet.db_set("status", "Active")

    def revert_outlet_status(self):
        # Revert only if no other active agreements remain
        active_agreements = frappe.db.count(
            "Franchise Agreement",
            filters={
                "franchise_outlet": self.franchise_outlet,
                "docstatus": 1,
                "name": ["!=", self.name],
            },
        )
        if active_agreements == 0:
            outlet = frappe.get_doc("Franchise Outlet", self.franchise_outlet)
            outlet.db_set("status", "Inactive")
```

## Custom fields: extending existing DocTypes

Three approaches to add fields to ERPNext DocTypes without touching source:

| Approach | Where it lives | Transfers to other sites? |
|---|---|---|
| 1. Desk UI (Customize Form) | Database only | No — unless exported as fixtures |
| 2. Fixtures in `hooks.py` (recommended) | Version-controlled JSON | Yes — auto-imported on migrate/install |
| 3. Custom Field API (programmatic) | Code, run at install/patch time | Yes |

### Approach 2: fixtures (recommended)

Add fields via **Customize Form**, then filter fixtures by module in `hooks.py` so `export-fixtures` only grabs yours (unfiltered exports pull in every app's fields — the most common fixture mistake):

```python title="apps/scoopjoy/scoopjoy/hooks.py"
fixtures = [
    {
        "dt": "Custom Field",
        "filters": [
            ["module", "=", "Franchise Management"]
        ]
    },
    {
        "dt": "Property Setter",
        "filters": [
            ["module", "=", "Franchise Management"]
        ]
    },
]
```

```bash
bench --site icecream.localhost export-fixtures --app scoopjoy
```

### Approach 3: Custom Field API

For fields created at install/patch time:

## Property setters: modifying existing field properties

Change a property of an existing field without replacing it:

```python
from frappe.custom.doctype.property_setter.property_setter import make_property_setter

# Make territory mandatory on Sales Invoice
make_property_setter(
    "Sales Invoice",    # doctype
    "territory",        # fieldname
    "reqd",             # property
    1,                  # value
    "Check",            # property type
)

# Change default naming series
make_property_setter(
    "Sales Invoice",
    "naming_series",
    "default",
    "FC-INV-.YYYY.-",
    "Data",
)
```

## Fixture export workflow

<Steps>

1. Make customizations via **Customize Form** in Desk.
2. Define fixture filters in `hooks.py` (above).
3. Export: `bench --site icecream.localhost export-fixtures --app scoopjoy`
4. Verify: `ls apps/scoopjoy/scoopjoy/fixtures/` → `custom_field.json`, `property_setter.json`
5. Commit: `cd ~/frappe-bench/apps/scoopjoy && git add scoopjoy/fixtures/ && git commit -m "Add custom fields for Sales Invoice franchise tracking"`
6. On any other site, after pulling: `bench --site othersite.localhost migrate` — fixtures import automatically.

</Steps>

Run `bench export-fixtures` before every commit that touches customizations — stale fixture files cause "works on my machine" bugs. Consider a pre-commit hook.
