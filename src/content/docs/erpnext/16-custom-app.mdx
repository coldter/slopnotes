## Why custom apps?

Forking ERPNext means merging your changes with every upstream release. A **custom app** avoids that: your code lives in its own directory, installs on any bench with one command, and upgrades independently of ERPNext.

| Benefit | What it means |
|---|---|
| Isolation | Your code is separate from ERPNext source |
| Upgradability | ERPNext updates never touch your app |
| Portability | `bench get-app` + `install-app` on any site |
| Collaboration | Multiple devs work without affecting core |
| Marketplace | Publish or sell the app |

Hooks, events, and APIs integrate your app deeply while keeping it decoupled. Node.js equivalent: `npm init` for a domain package that plugs into a host that hands you an ORM, admin UI, and API layer for free.

## Scaffold: `bench new-app`

```bash
cd ~/frappe-bench
bench new-app scoopjoy
```

```text
App Title (default: Scoopjoy): ScoopJoy
App Description: Franchise outlet management, royalty tracking, and compliance for ScoopJoy's multi-location ice-cream business
App Publisher: ScoopJoy
App Email: dev@scoopjoy.example
Create GitHub Workflow (y/n, default n): y          # say y — generates a CI pipeline with Frappe Linter
Branch name for GitHub Workflow (default: version-16): version-16
```

The app lands in `~/frappe-bench/apps/scoopjoy/`.

## App directory structure

<FileTree>
- scoopjoy/
  - scoopjoy/
    - __init__.py
    - **hooks.py** app configuration and hooks
    - patches.txt migration patches registry
    - modules.txt registered modules
    - templates/
      - __init__.py
      - pages/
        - __init__.py
    - scoopjoy/ default module (same name as app)
      - __init__.py
      - doctype/ DocTypes go here
        - __init__.py
    - config/
      - __init__.py
      - desktop.py legacy — v16 uses Workspace JSON files instead
    - public/
      - js/
      - css/
  - .github/
    - workflows/
      - ci.yml auto-generated CI workflow
  - setup.py
  - pyproject.toml
  - setup.cfg
  - requirements.txt
  - license.txt
  - MANIFEST.in
  - README.md
</FileTree>

:::caution[setup.py is legacy in v16]
In v16, `pyproject.toml` is the only required build config. `setup.py`/`setup.cfg` are legacy artifacts — pip 25.1+ enforces `pyproject.toml`, and Frappe Cloud requires a valid one. Safe to ignore or delete from new apps.
:::

### hooks.py: the app's configuration hub

```python title="scoopjoy/scoopjoy/hooks.py"
app_name = "scoopjoy"
app_title = "ScoopJoy"
app_publisher = "ScoopJoy"
app_description = "Franchise outlet management, royalty tracking, and compliance for ScoopJoy's multi-location ice-cream business"
app_email = "dev@scoopjoy.example"
app_license = "MIT"

required_apps = ["frappe/erpnext"]  # Frappe refuses to install this app if ERPNext isn't installed

# Document Events — hook on document methods and events
# doc_events = {
#     "*": {
#         "on_update": "method",
#     }
# }

# Scheduled Tasks
# scheduler_events = {
#     "daily": [],
#     "hourly": [],
#     "cron": {"0 */6 * * *": []},
# }
```

### modules.txt

Registers the app's modules (functional groupings). One line per module; each maps to a subdirectory under the inner package:

```text title="scoopjoy/scoopjoy/modules.txt"
ScoopJoy
ScoopJoy Compliance
ScoopJoy Analytics
```

Each new module needs its directory. One module is usually enough — split only for genuinely distinct functional areas:

```bash
mkdir -p scoopjoy/scoopjoy/scoopjoy_compliance/doctype
touch scoopjoy/scoopjoy/scoopjoy_compliance/__init__.py
touch scoopjoy/scoopjoy/scoopjoy_compliance/doctype/__init__.py
```

### pyproject.toml

```toml title="scoopjoy/pyproject.toml"
[project]
name = "scoopjoy"
dynamic = ["version"]
requires-python = ">=3.14,<3.15"
dependencies = []

[build-system]
requires = ["flit_core >=3.4,<4"]
build-backend = "flit_core.buildapi"

[tool.bench.frappe-dependencies]
frappe = ">=16.0.0"
erpnext = ">=16.0.0"
```

:::caution[Python 3.14 required]
Frappe v16 requires Python 3.14+. Older Python gives cryptic import errors — check with `python3 --version` first.
:::

## Install the app

```bash
bench --site icecream.localhost install-app scoopjoy
# Installing scoopjoy... / Updating Dashboard for scoopjoy

bench --site icecream.localhost list-apps
# frappe / erpnext / scoopjoy
```

Or confirm in Desk at **Setup > Installed Applications**.

## Development workflow

Cycle: **Code → `bench migrate` → `bench build` → Test → Repeat**.

<Steps>

1. **Code** — edit Python files, create DocTypes via the Desk UI (developer mode), write client scripts.

2. **`bench migrate`** — applies schema changes. Run after creating/modifying DocTypes, adding patches, or changing fixtures:

   ```bash
   bench --site icecream.localhost migrate
   ```

3. **`bench build`** — compiles JS/CSS from `public/`. Run after editing assets; use `bench watch` in dev to auto-rebuild:

   ```bash
   bench build --app scoopjoy
   bench watch
   ```

4. **Test:**

   ```bash
   bench --site icecream.localhost run-tests --app scoopjoy
   ```

5. **`bench clear-cache`** if the UI shows stale data:

   ```bash
   bench --site icecream.localhost clear-cache
   ```

</Steps>

Keep two terminals open during active development: one running `bench start`, one for bench commands. The dev server auto-reloads Python, but JS/CSS still needs `bench build` or `bench watch`.

## Developer mode

Lets you create/modify DocTypes from the Desk UI and auto-writes the JSON + controller files to disk for Git:

```bash
bench --site icecream.localhost set-config developer_mode 1
```

:::caution[Never enable developer mode in production]
It exposes development tools, can corrupt data, and hurts performance. Dev sites only.
:::

## Version control

```bash
cd ~/frappe-bench/apps/scoopjoy
git init
git add .
git commit -m "Initial scaffold: ScoopJoy app for Frappe v16"
```

The scaffolded `.gitignore` already excludes `.eggs/`, `*.egg-info/`, `*.pyc`, `__pycache__/`, `dist/`, `build/`, `node_modules/`, `.env`, etc.

```bash
git remote add origin git@github.com:scoopjoy/scoopjoy.git
git push -u origin version-16
```

## Publishing and sharing

`bench get-app` is the `npm install <git-url>` — it clones into the bench; `install-app` activates it on a site (tenant):

```bash
bench get-app https://github.com/scoopjoy/scoopjoy.git
bench get-app git@github.com:scoopjoy/scoopjoy.git            # private repo via SSH
bench get-app https://github.com/scoopjoy/scoopjoy.git --branch version-16
bench --site icecream.localhost install-app scoopjoy
```

On Frappe Cloud, add the app via the dashboard pointing at your Git repo — it builds and deploys automatically.

## Zero to running app

<Steps>

1. `cd ~/frappe-bench && bench new-app scoopjoy` (answer the prompts above).

2. `bench --site icecream.localhost install-app scoopjoy`

3. `bench --site icecream.localhost list-apps` — verify `scoopjoy` is listed.

4. `bench start`

5. Open `http://icecream.localhost:8000`, log in to Desk, check **Setup > Installed Applications** shows ScoopJoy.

6. `cd apps/scoopjoy && git init && git add . && git commit -m "Initial scaffold: ScoopJoy app"`

</Steps>
