## Identifying bottlenecks

```bash
bench doctor                                        # worker queue depth: high = workers can't keep up
sudo mariadb -e "SELECT * FROM mysql.slow_log ORDER BY start_time DESC LIMIT 20;"
htop                                                # CPU/memory per process
iostat -x 1                                         # disk I/O wait
vmstat 1                                            # overall system health
redis-cli INFO memory | grep used_memory_human
redis-cli INFO clients | grep connected_clients
```

| Symptom | Likely cause | Fix first |
|---------|--------------|-----------|
| Slow page loads | Slow DB queries | Indexing, query optimization |
| Jobs backing up | Too few workers | Increase worker count |
| High memory usage | Oversized buffer pool + app memory | Right-size buffer pool |
| Intermittent timeouts | Gunicorn workers saturated | Add workers |
| Slow reports | Full table scans | Indexes + caching |

### Index management

Frappe creates basic indexes automatically; add yours in a patch or `after_migrate` hook so they're reproducible:

```python title="scoopjoy/scoopjoy/patches/add_custom_indexes.py"
import frappe

def add_custom_indexes():
    """Indexes for frequently queried franchise fields."""
    frappe.db.add_index("Sales Invoice", ["franchise_outlet", "posting_date"])
    frappe.db.add_index("Sales Invoice", ["franchise_outlet", "docstatus", "posting_date"])
    frappe.db.add_index("Stock Ledger Entry", ["warehouse", "posting_date", "item_code"])
    frappe.db.add_index("Sales Invoice", ["franchise_outlet", "docstatus", "grand_total"])
```

### Slow query log analysis

Rank by **frequency × average duration**, not just the single slowest query:

```bash
sudo mariadb -e "SET GLOBAL slow_query_log = 1;"
sudo mariadb -e "SET GLOBAL long_query_time = 1;"
```

```sql
SELECT
  LEFT(sql_text, 200) AS query,
  COUNT(*) AS frequency,
  ROUND(AVG(query_time), 2) AS avg_time,
  ROUND(MAX(query_time), 2) AS max_time
FROM mysql.slow_log
WHERE start_time > DATE_SUB(NOW(), INTERVAL 24 HOUR)
GROUP BY LEFT(sql_text, 200)
ORDER BY frequency * AVG(query_time) DESC
LIMIT 20;
```

```bash
sudo mysqldumpslow -s at -t 20 /var/log/mysql/slow.log
```

### Read replicas for heavy reports

Offload big aggregations to a replica so they don't compete with transactions:

```json title="sites/icecream.localhost/site_config.json"
{
  "read_from_replica": 1,
  "replica_host": "replica-db.example.com"
}
```

```python title="scoopjoy/scoopjoy/report/franchise_royalty/franchise_royalty.py"
import frappe

def execute(filters=None):
    # Runs on the replica automatically when read_from_replica is enabled
    data = frappe.db.sql("""
        SELECT
            si.franchise_outlet,
            SUM(si.grand_total) as total_revenue,
            COUNT(*) as invoice_count
        FROM `tabSales Invoice` si
        WHERE si.docstatus = 1
          AND si.posting_date BETWEEN %(from_date)s AND %(to_date)s
        GROUP BY si.franchise_outlet
        ORDER BY total_revenue DESC
    """, filters, as_dict=True)

    return columns, data
```

## Redis optimization

Frappe uses two Redis connections:

| Instance | Default port | Purpose | Memory | Eviction |
|----------|-------------|---------|--------|----------|
| `redis_cache` | 13000 | Doc cache, sessions | 256MB–1GB | `allkeys-lru` (evict freely) |
| `redis_queue` | 11000 | Job queues, pub/sub | 128MB–512MB | `noeviction` — losing a queued job is data loss |

:::tip[Since v15, redis_socketio merged into redis_queue]
Only two Redis instances are needed: `redis_cache` and `redis_queue`. No separate SocketIO Redis.
:::

```ini title="/etc/redis/redis-cache.conf"
maxmemory 512mb
maxmemory-policy allkeys-lru
save ""
appendonly no
```

```ini title="/etc/redis/redis-queue.conf"
maxmemory 256mb
maxmemory-policy noeviction
save 900 1
appendonly yes
```

### frappe.cache patterns

Cache-aside: check cache, fall back to DB on miss, store with TTL. In v15+/v16 use `frappe.cache` as a **property** (older guides show `frappe.cache()` — v14 syntax):

```python
import frappe

# Basic key-value
def get_franchise_config(outlet):
    cache_key = f"franchise_config:{outlet}"
    config = frappe.cache.get_value(cache_key)
    if config:
        return config

    config = frappe.get_doc("Franchise Outlet", outlet).as_dict()
    frappe.cache.set_value(cache_key, config, expires_in_sec=3600)
    return config

# Hash-based for structured per-outlet stats
def get_outlet_daily_stats(outlet, date):
    hkey = f"outlet_stats:{date}"
    stats = frappe.cache.hget(hkey, outlet)
    if stats:
        return stats

    stats = calculate_daily_stats(outlet, date)
    frappe.cache.hset(hkey, outlet, stats)
    return stats

# Invalidation on new data
def on_sales_invoice_submit(doc, method):
    if doc.franchise_outlet:
        date = str(doc.posting_date)
        frappe.cache.hdel(f"outlet_stats:{date}", doc.franchise_outlet)
        frappe.cache.delete_value(f"franchise_config:{doc.franchise_outlet}")
```

### Centralized cache manager

One class owns every key + TTL for an outlet, so invalidation stays honest:

```python title="scoopjoy/scoopjoy/caching.py"
import frappe

class FranchiseCacheManager:
    """Centralized cache management for franchise operations."""

    MENU_CACHE_TTL = 1800       # 30 min
    CONFIG_CACHE_TTL = 3600     # 1 hour
    STATS_CACHE_TTL = 300       # 5 min

    @staticmethod
    def get_outlet_menu(outlet):
        """Cache the active menu per outlet (changes infrequently)."""
        key = f"franchise_menu:{outlet}"
        menu = frappe.cache.get_value(key)
        if menu is None:
            menu = frappe.get_all(
                "Franchise Menu Item",
                filters={"outlet": outlet, "is_active": 1},
                fields=["item_code", "item_name", "price", "category"],
                order_by="category, item_name"
            )
            frappe.cache.set_value(key, menu, expires_in_sec=FranchiseCacheManager.MENU_CACHE_TTL)
        return menu

    @staticmethod
    def get_dashboard_stats(outlet):
        """Near-real-time stats, short TTL."""
        key = f"franchise_dashboard:{outlet}"
        stats = frappe.cache.get_value(key)
        if stats is None:
            stats = _compute_dashboard_stats(outlet)
            frappe.cache.set_value(key, stats, expires_in_sec=FranchiseCacheManager.STATS_CACHE_TTL)
        return stats

    @staticmethod
    def invalidate_outlet(outlet):
        """Clear all caches for an outlet after config changes."""
        for key in [
            f"franchise_menu:{outlet}",
            f"franchise_dashboard:{outlet}",
            f"franchise_config:{outlet}",
        ]:
            frappe.cache.delete_value(key)
```

## Gunicorn tuning

Workers = `(2 × CPU cores) + 1`:

| Server spec | Workers | Fits |
|-------------|---------|------|
| 2 CPU / 4GB | 5 | 10–20 users |
| 4 CPU / 8GB | 9 | 30–50 users |
| 8 CPU / 16GB | 17 | 50–100 users |
| 16 CPU / 32GB | 33 | 100+ users |

Each worker uses 150–300MB RAM — size accordingly.

## Background job optimization

Pick the queue by expected duration so quick notifications never sit behind a 20-minute import:

| Queue | Timeout | Use for |
|-------|---------|---------|
| `short` | 300s | Notifications, cache updates, email |
| `default` | 300s | Standard ops, PDF generation, report emails |
| `long` | 1500s | Imports, bulk updates, heavy reports, backups |

```python
import frappe

# Heavy aggregation → long queue
frappe.enqueue(
    "scoopjoy.tasks.generate_royalty_report",
    queue="long", timeout=1200, outlet=outlet, period=period
)

# Quick email → short queue
frappe.enqueue(
    "scoopjoy.tasks.send_summary_email",
    queue="short", outlet=outlet
)
```

Worker counts per queue (50-user deployment):

```ini title="config/supervisor.conf"
[program:frappe-bench-frappe-worker-short]
numprocs=2     ; quick tasks, high throughput

[program:frappe-bench-frappe-worker-default]
numprocs=3     ; bulk of the work

[program:frappe-bench-frappe-worker-long]
numprocs=2     ; heavy tasks, fewer but longer-running
```

## ORM patterns that matter

### 1. Always specify fields in `get_all()`

Without `fields`, every column is fetched — including large text fields:

```python
# BAD: fetches all columns
invoices = frappe.get_all("Sales Invoice", filters={"franchise_outlet": outlet})

# GOOD: only what you need
invoices = frappe.get_all("Sales Invoice",
    filters={"franchise_outlet": outlet},
    fields=["name", "posting_date", "grand_total", "status"],
    limit_page_length=100)
```

### 2. Use `get_value()` instead of `get_doc()` for simple lookups

`get_doc()` loads the whole document including child tables:

```python
# BAD: full document load for one field
doc = frappe.get_doc("Franchise Outlet", outlet_name)
owner = doc.franchise_owner

# GOOD: single-column fetch
owner = frappe.db.get_value("Franchise Outlet", outlet_name, "franchise_owner")

# GOOD: multiple columns in one query
owner, region, status = frappe.db.get_value(
    "Franchise Outlet", outlet_name, ["franchise_owner", "region", "status"]
)
```

### 3. Never query in a loop (N+1)

```python
# BAD: N+1
for outlet_name in outlet_names:
    doc = frappe.get_doc("Franchise Outlet", outlet_name)
    results.append(doc.franchise_owner)

# GOOD: one bulk query
results = frappe.get_all("Franchise Outlet",
    filters={"name": ["in", outlet_names]},
    fields=["name", "franchise_owner"])

# BAD: insert in a loop
for item in items:
    frappe.get_doc({"doctype": "Sales Invoice Item", ...}).insert()

# GOOD: bulk insert
frappe.db.bulk_insert("Sales Invoice Item",
    fields=["item_code", "qty", "rate"],
    values=[(i["code"], i["qty"], i["rate"]) for i in items])
```

### 4. Enqueue heavy operations

Don't block the HTTP request on a 30-second computation:

```python
# BAD: blocks the request
@frappe.whitelist()
def generate_franchise_report(outlet, from_date, to_date):
    return compute_report(outlet, from_date, to_date)  # 30+ seconds

# GOOD: return immediately, process in background
@frappe.whitelist()
def generate_franchise_report(outlet, from_date, to_date):
    frappe.enqueue(
        "scoopjoy.reports.compute_and_email_report",
        queue="long", timeout=600,
        outlet=outlet, from_date=from_date, to_date=to_date,
        user=frappe.session.user
    )
    return {"status": "queued", "message": "Report will be emailed when ready."}
```

### 5. Cache expensive computations

```python
import frappe

@frappe.whitelist()
def get_franchise_dashboard(outlet):
    """Dashboard data with 5-minute cache."""
    cache_key = f"franchise_dashboard_v2:{outlet}"

    data = frappe.cache.get_value(cache_key)
    if data:
        return data

    data = {
        "today_revenue": frappe.db.sql("""
            SELECT COALESCE(SUM(grand_total), 0)
            FROM `tabSales Invoice`
            WHERE franchise_outlet = %s
              AND posting_date = CURDATE()
              AND docstatus = 1
        """, outlet)[0][0],

        "pending_orders": frappe.db.count("Sales Order", {
            "franchise_outlet": outlet,
            "docstatus": 1,
            "delivery_status": ["!=", "Fully Delivered"]
        }),

        "low_stock_items": frappe.db.sql("""
            SELECT item_code, actual_qty, reorder_level
            FROM `tabBin`
            WHERE warehouse IN (
                SELECT default_warehouse
                FROM `tabFranchise Outlet`
                WHERE name = %s
            )
            AND actual_qty < reorder_level
        """, outlet, as_dict=True)
    }

    frappe.cache.set_value(cache_key, data, expires_in_sec=300)
    return data
```

## Worked example: slow script report, 45s → 0.3s

The slow version commits two N+1 sins — one query per outlet, then a full doc load per invoice:

<Tabs>
  <TabItem label="Before (45s)">

  ```python title="scoopjoy/scoopjoy/report/franchise_royalty/franchise_royalty.py"
  def execute(filters=None):
      outlets = frappe.get_all("Franchise Outlet", fields=["name"])

      data = []
      for outlet in outlets:
          # N+1: one query per outlet
          invoices = frappe.get_all("Sales Invoice",
              filters={
                  "franchise_outlet": outlet.name,
                  "posting_date": ["between", [filters.from_date, filters.to_date]],
                  "docstatus": 1
              })

          total = 0
          for inv in invoices:
              # N+1 again: full doc load per invoice
              doc = frappe.get_doc("Sales Invoice", inv.name)
              total += doc.grand_total

          data.append({
              "outlet": outlet.name,
              "revenue": total,
              "royalty": total * 0.05
          })

      return columns, data
  ```

  </TabItem>
  <TabItem label="After (0.3s)">

  ```python title="scoopjoy/scoopjoy/report/franchise_royalty/franchise_royalty.py"
  def execute(filters=None):
      # Single aggregation query replaces hundreds of queries
      data = frappe.db.sql("""
          SELECT
              si.franchise_outlet AS outlet,
              fo.franchise_owner AS owner,
              fo.region,
              COUNT(si.name) AS invoice_count,
              SUM(si.grand_total) AS revenue,
              SUM(si.grand_total) * COALESCE(fo.royalty_rate, 0.05) AS royalty
          FROM `tabSales Invoice` si
          INNER JOIN `tabFranchise Outlet` fo ON fo.name = si.franchise_outlet
          WHERE si.docstatus = 1
            AND si.posting_date BETWEEN %(from_date)s AND %(to_date)s
          GROUP BY si.franchise_outlet, fo.franchise_owner, fo.region, fo.royalty_rate
          ORDER BY revenue DESC
      """, filters, as_dict=True)

      return columns, data
  ```

  </TabItem>
</Tabs>

Fixes: single aggregation query instead of N+1, `INNER JOIN` instead of doc loads, `SUM()` in SQL instead of Python loops, plus the composite index `frappe.db.add_index("Sales Invoice", ["franchise_outlet", "docstatus", "posting_date"])`.

## Load testing with Locust

Weight tasks to match real traffic — dashboards far more than invoice creation:

```python title="locustfile.py"
from locust import HttpUser, task, between

class FranchiseUser(HttpUser):
    wait_time = between(1, 5)
    host = "https://franchisehq.com"

    def on_start(self):
        """Login at the start of each simulated user session."""
        response = self.client.post("/api/method/login", json={
            "usr": "test@franchise.com",
            "pwd": "test-password"
        })
        self.csrf_token = response.cookies.get("csrf_token", "")

    @task(5)
    def view_dashboard(self):
        self.client.get("/api/method/frappe.client.get_count",
            params={"doctype": "Sales Invoice"})

    @task(3)
    def list_invoices(self):
        self.client.get("/api/resource/Sales Invoice",
            params={
                "fields": '["name","posting_date","grand_total","status"]',
                "filters": '[]',
                "limit_page_length": 20
            })

    @task(2)
    def view_invoice(self):
        self.client.get("/api/resource/Sales Invoice/ACC-SINV-2026-00001")

    @task(1)
    def create_invoice(self):
        self.client.post("/api/resource/Sales Invoice",
            json={
                "customer": "Test Franchise Customer",
                "items": [{"item_code": "FRANCHISE-ITEM-001", "qty": 1, "rate": 100}]
            },
            headers={"X-Frappe-CSRF-Token": self.csrf_token})

    @task(1)
    def run_report(self):
        self.client.get("/api/method/frappe.desk.query_report.run",
            params={
                "report_name": "Franchise Royalty Report",
                "filters": '{"from_date":"2026-01-01","to_date":"2026-03-20"}'
            })
```

| Metric | Target | Action if exceeded |
|--------|--------|--------------------|
| P50 response time | < 500ms | Check slow queries |
| P95 response time | < 2s | Add Gunicorn workers |

| Throughput | > 50 req/s | Scale horizontally |
