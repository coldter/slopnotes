A DocType is a Mongoose schema + Prisma model + Express route handler in one. A single definition generates a database table, a REST API (`/api/resource/<DocType>`), a CRUD UI in Desk, plus permissions, validation, and workflows. ERPNext is ~800+ DocTypes working together.

## How DocTypes map to the database

Creating a DocType called `Franchise Outlet` makes Frappe:

1. Create table `tabFranchise Outlet` (`tab` prefix).
2. Add standard columns: `name` (primary key), `owner`, `creation`, `modified`, `modified_by`, `docstatus`.
3. Add one column per field, plus indexes on frequently queried fields.

```text
DocType Name          →  SQL Table
─────────────────────────────────────
Item                  →  tabItem
Sales Invoice         →  tabSales Invoice
Franchise Outlet      →  tabFranchise Outlet
Outlet Equipment      →  tabOutlet Equipment  (child table)
```

The `name` column is always a VARCHAR primary key, never an auto-increment integer — every document is identified by its string `name`.

## Field types reference

Frappe ships 30+ field types. The ones you'll use most:

### Text & data

| Field Type | SQL Type | Use Case |
|---|---|---|
| `Data` | VARCHAR(140) | Short text — names, codes, emails |
| `Small Text` | TEXT | Multi-line, a few paragraphs |
| `Text` / `Long Text` | LONGTEXT | Large text blocks |
| `Text Editor` | LONGTEXT | Rich text with HTML toolbar |
| `Code` | LONGTEXT | Syntax-highlighted code |
| `Password` | VARCHAR(140) | Stored encrypted, masked in UI |
| `Read Only` | VARCHAR(140) | Display-only computed values |

### Numeric

| Field Type | SQL Type | Use Case |
|---|---|---|
| `Int` | INT(11) | Whole numbers — quantities, counts |
| `Float` | DECIMAL(18,6) | Decimal numbers |
| `Currency` | DECIMAL(18,6) | Money (respects currency settings) |
| `Percent` | DECIMAL(18,6) | 0–100 percentage |

### Date & time

| Field Type | SQL Type | Use Case |
|---|---|---|
| `Date` | DATE | Calendar date |
| `Datetime` | DATETIME(6) | Date + time with microseconds |
| `Time` | TIME(6) | Time only |
| `Duration` | DECIMAL(18,6) | Duration in seconds |

### Relationships

| Field Type | SQL Type | Use Case |
|---|---|---|
| `Link` | VARCHAR(140) | Foreign key to another DocType |
| `Dynamic Link` | VARCHAR(140) | Polymorphic reference (companion field picks the type) |
| `Table` | — | Child table (1:N) |
| `Table MultiSelect` | — | Many-to-many via link child table |

### Selection, boolean, files, special

| Field Type | SQL Type | Use Case |
|---|---|---|
| `Select` | VARCHAR(140) | Dropdown with predefined options |
| `Check` | INT(1) | Boolean checkbox (0/1) |
| `Attach` / `Attach Image` | TEXT | File / image attachment |
| `Geolocation` | LONGTEXT | Map coordinates (GeoJSON) |
| `JSON` | LONGTEXT | Raw JSON data |
| `Signature` | LONGTEXT | Digital signature capture |
| `Color` | VARCHAR(140) | Color picker |

### Layout fields (no database column)

| Field Type | Purpose |
|---|---|
| `Section Break` | Start a new form section |
| `Column Break` | Split into columns within a section |
| `Tab Break` | Start a new tab in the form |

:::caution[Layout fields are render-only]
`Section Break`, `Column Break`, `Tab Break` create no columns — they only control form rendering. They still need a `fieldname` (Frappe auto-generates one if blank).
:::

## Naming patterns

Every document has a unique `name` (the PK), generated via `naming_rule` + `autoname`. Priority: Document Naming Rule (Desk config) → `autoname` controller method → `autoname` DocType property.

```python
# 1. Format expression — naming_rule: "Expression"
"autoname": "format:FO-{city_code}-{####}"
# FO-MUM-0001, FO-DEL-0002 · {####} = counter, {field} = field value
# Date tokens: {YYYY}, {MM}, {DD}, {YY} · e.g. "format:FSR-{YYYY}-{MM}-{####}"

# 2. Naming series — naming_rule: "By Naming Series"
"autoname": "naming_series:"
# Needs a `naming_series` Select field; user picks prefix "FO-MUM-.####"

# 3. Field-based — naming_rule: "By fieldname"
"autoname": "field:outlet_name"   # name = field value, must be unique

# 4. Hash — naming_rule: "Random"
"autoname": "hash"                # a1b2c3d4e5 (10-char random)

# 5. Prompt — naming_rule: "Set by user"
"autoname": "Prompt"              # user types the name

# 6. Python controller: def autoname(self): ...  (see chapter 5)
```

For Indian business documents, prefer `naming_series` — accountants customize prefixes per financial year (`FO-2526-.####` for FY 2025-26) without code changes.

## Link fields — foreign keys

A `Link` field stores the referenced document's `name` as a VARCHAR:

```json
{
  "fieldname": "manager",
  "fieldtype": "Link",
  "label": "Outlet Manager",
  "options": "Employee"
}
```

The UI gives a searchable dropdown. Multiple Link fields can point to the same DocType (e.g. `primary_supplier` and `backup_supplier` both `options: "Supplier"`).

### fetch_from: auto-pull related data

```json
{
  "fieldname": "manager_name",
  "fieldtype": "Data",
  "label": "Manager Name",
  "fetch_from": "manager.employee_name",
  "read_only": 1
}
```

Selecting a manager copies `employee_name` into `manager_name` — denormalized in the DB for performance, not computed on the fly.

### Parent-child tracking

Every child row gets hidden fields managed by Frappe:

| Field | Description | Example |
|---|---|---|
| `parent` | Parent document's `name` | `FO-MUM-0001` |
| `parenttype` | Parent DocType | `Franchise Outlet` |
| `parentfield` | Table fieldname on the parent | `equipment` |

Plus an `idx` field (1-based) preserving row order.

### Referencing from the parent

```json
{
  "fieldname": "equipment",
  "fieldtype": "Table",
  "label": "Outlet Equipment",
  "options": "Outlet Equipment"
}
```

In Python, access child rows as `self.equipment` — a list of `Document` objects.

## Dynamic Link — polymorphic references

A Dynamic Link references different DocTypes depending on a companion field. Classic case: an `Address` belonging to a Customer, Supplier, or Lead.

```json
{
  "fieldname": "party_type",
  "fieldtype": "Link",
  "label": "Party Type",
  "options": "DocType",
  "reqd": 1
},
{
  "fieldname": "party_name",
  "fieldtype": "Dynamic Link",
  "label": "Party Name",
  "options": "party_type",
  "reqd": 1
}
```

Pick `party_type = "Customer"` and `party_name` shows Customers; switch to `"Supplier"` and it shows Suppliers. Use a `Select` companion instead of `Link` to `DocType` to restrict the available types (a DocType link shows every DocType in the system). Example — a complaint against an Outlet or Supplier:

```json
{
  "fieldname": "complaint_against_type",
  "fieldtype": "Select",
  "label": "Complaint Against",
  "options": "\nFranchise Outlet\nSupplier",
  "reqd": 1
},
{
  "fieldname": "complaint_against",
  "fieldtype": "Dynamic Link",
  "label": "Complaint Against Name",
  "options": "complaint_against_type",
  "reqd": 1
}
```

## DocType properties

| Property | Default | Effect |
|---|---|---|
| `is_submittable` | 0 | Draft → Submitted → Cancelled workflow. Adds `docstatus` (0/1/2). Invoices, orders, journal entries. |
| `is_tree` | 0 | Nested Set Model for hierarchy. Adds `parent_<doctype>`, `lft`, `rgt`. Chart of Accounts, Item Groups, Territories. |
| `is_single` | 0 | One document only, stored in `tabSingles`. Settings pages. |
| `istable` | 0 | Child table — cannot exist independently. |
| `track_changes` | 0 | Version history (who changed what, when) in the `Version` DocType. |
| `is_virtual` | 0 | No database table; implement data access in the controller. |
| `naming_rule` | — | "Expression", "By Naming Series", "By fieldname", "Random", "Set by user" |
| `title_field` | — | Field shown as the document title instead of `name` |
| `search_fields` | — | Comma-separated fields searchable in Link dropdowns |
| `sort_field` | `creation` (v16) | Default list sort. v15 default was `modified`. |
| `sort_order` | `DESC` | Default sort order |

### Submittable lifecycle

<Mermaid title="docstatus state machine: Draft → Submitted → Cancelled → Amended" height={360} code={`
stateDiagram-v2
  [*] --> Draft
  Draft --> Submitted : submit (docstatus 0 to 1)
  Submitted --> Cancelled : cancel (docstatus 1 to 2)
  Cancelled --> Amended : amend (new doc, docstatus 0)
  Amended --> Submitted : submit
`} />

- Draft (`docstatus=0`): freely editable.
- Submitted (`docstatus=1`): locked; only `allow_on_submit` fields change.
- Cancelled (`docstatus=2`): not editable; "Amend" creates a new draft copy.

## Virtual DocTypes

Virtual DocTypes (v15+, improved in v16) have no database table — the controller provides the data source (external API, computed data, etc.). They look like normal DocTypes in Desk.

```json title="ice_cream_biz/franchise_management/doctype/franchise_dashboard/franchise_dashboard.json"
{
  "doctype": "DocType",
  "name": "Franchise Dashboard",
  "module": "Franchise Management",
  "is_virtual": 1,
  "fields": [
    { "fieldname": "outlet", "fieldtype": "Link", "label": "Outlet", "options": "Franchise Outlet", "in_list_view": 1 },
    { "fieldname": "total_sales_today", "fieldtype": "Currency", "label": "Total Sales Today", "in_list_view": 1 },
    { "fieldname": "active_pos_sessions", "fieldtype": "Int", "label": "Active POS Sessions", "in_list_view": 1 }
  ]
}
```

The controller implements static data-access methods plus `load_from_db`, and blocks writes:

```python title="ice_cream_biz/franchise_management/doctype/franchise_dashboard/franchise_dashboard.py"
import frappe
from frappe.model.document import Document


class FranchiseDashboard(Document):
    """Virtual DocType — data is computed, not stored in a table."""

    @staticmethod
    def get_list(args):
        """Return list of records for the list view."""
        outlets = frappe.get_all(
            "Franchise Outlet",
            filters={"status": "Active"},
            fields=["name", "outlet_name"],
        )
        result = []
        for outlet in outlets:
            today_sales = frappe.db.sql(
                """
                SELECT IFNULL(SUM(grand_total), 0) as total
                FROM `tabSales Invoice`
                WHERE franchise_outlet = %s
                  AND posting_date = CURDATE()
                  AND docstatus = 1
                """,
                outlet.name,
                as_dict=True,
            )[0].total

            result.append(frappe._dict({
                "name": outlet.name,
                "outlet": outlet.name,
                "total_sales_today": today_sales,
                "active_pos_sessions": get_active_sessions(outlet.name),
            }))
        return result

    @staticmethod
    def get_count(args):
        """Return total count for the list view."""
        return frappe.db.count("Franchise Outlet", {"status": "Active"})

    @staticmethod
    def get_stats(args):
        """Return sidebar stats."""
        return {}

    def db_insert(self, *args, **kwargs):
        """Virtual DocType — inserts not supported."""
        frappe.throw("Franchise Dashboard is read-only")

    def load_from_db(self):
        """Load a single record by self.name."""
        outlet = frappe.get_doc("Franchise Outlet", self.name)
        self.outlet = outlet.name
        self.total_sales_today = frappe.db.sql(
            """
            SELECT IFNULL(SUM(grand_total), 0)
            FROM `tabSales Invoice`
            WHERE franchise_outlet = %s
              AND posting_date = CURDATE()
              AND docstatus = 1
            """,
            self.name,
        )[0][0]
        self.active_pos_sessions = get_active_sessions(self.name)

    def db_update(self):
        """Virtual DocType — updates not supported."""
        frappe.throw("Franchise Dashboard is read-only")

    def delete(self):
        """Virtual DocType — deletion not supported."""
        frappe.throw("Franchise Dashboard is read-only")


def get_active_sessions(outlet_name):
    return frappe.db.count("POS Opening Entry", {
        "franchise_outlet": outlet_name,
        "status": "Open",
    })
```

:::caution[Static methods only]
`get_list`, `get_count`, `get_stats` must be `@staticmethod` — not instance methods, not `@classmethod`. Frappe raises "Incomplete Virtual Doctype Implementation" otherwise. v16 also adds virtual child tables: read-only child rows computed when the form opens.
:::

### Reading documents

```python
outlet = frappe.get_doc("Franchise Outlet", "FO-MUM-0001")

    "Franchise Outlet", "FO-MUM-0001",

    as_dict=True

```

### Listing documents

```python
# frappe.get_all() — list of dicts, IGNORES permissions (server-side logic, background jobs)
outlets = frappe.get_all(
    "Franchise Outlet",
    filters={"status": "Active", "city": "Mumbai"},
    fields=["name", "outlet_name", "manager_name", "monthly_rent"],
    order_by="creation desc",
    limit_page_length=20,
)

# frappe.get_list() — same but RESPECTS user permissions (whitelisted API methods)
outlets = frappe.get_list(
    "Franchise Outlet",
    filters={"status": "Active"},
    fields=["name", "outlet_name", "city"],
    limit_page_length=50,
)

# Filter operators
outlets = frappe.get_all(
    "Franchise Outlet",
    filters={
        "monthly_rent": [">", 50000],
        "opening_date": [">=", "2026-01-01"],
        "status": ["in", ["Active", "Under Renovation"]],
        "city": ["like", "%Mum%"],
    },
    fields=["name", "outlet_name", "monthly_rent"],
)
```

### Updating documents

```python
# Load, modify, save — triggers all hooks
outlet = frappe.get_doc("Franchise Outlet", "FO-MUM-0001")
outlet.status = "Under Renovation"
outlet.save()

# Direct DB write — bypasses controller hooks
frappe.db.set_value("Franchise Outlet", "FO-MUM-0001", "status", "Under Renovation")
frappe.db.set_value("Franchise Outlet", "FO-MUM-0001", {
    "status": "Under Renovation",
    "notes": "Renovation started March 2026",
})
```

:::caution[set_value bypasses hooks]
`frappe.db.set_value()` writes directly to the DB, skipping `validate`, `before_save`, and all controller hooks. It still sends a `doc_update` realtime event. Use only for lightweight status updates where hooks aren't needed.
:::

### Raw SQL

```python
results = frappe.db.sql("""
    SELECT fo.city, COUNT(*) as outlet_count, SUM(fo.monthly_rent) as total_rent
    FROM `tabFranchise Outlet` fo
    WHERE fo.status = 'Active'
    GROUP BY fo.city
    ORDER BY outlet_count DESC
""", as_dict=True)

# ALWAYS parameterize with %s
results = frappe.db.sql("""
    SELECT name, outlet_name, monthly_rent
    FROM `tabFranchise Outlet`
    WHERE city = %s AND status = %s
""", ("Mumbai", "Active"), as_dict=True)
```

:::caution[Never interpolate into SQL]
No f-strings or concatenation in SQL — always use `%s` placeholders. Frappe parameterizes under the hood to prevent SQL injection.
:::

## Creating DocTypes: UI vs code

### Via the Desk UI

<Steps>
1. Search bar → `DocType` → **New DocType**.
2. Fill in name, module, naming rule.
3. Add fields in the field editor (drag to reorder).
4. Set permissions in the Permissions table.
5. Click **Save** — Frappe writes the JSON to your app directory and runs `ALTER TABLE`.
</Steps>

Fastest way to prototype; the JSON is committed to Git.

### Manually

There is no `bench new-doctype` command. Create the directory + JSON + controller + test files yourself, then migrate:

```bash
mkdir -p apps/ice_cream_biz/ice_cream_biz/franchise_management/doctype/franchise_outlet
# write franchise_outlet.json, franchise_outlet.py, test_franchise_outlet.py
bench --site icecream.localhost migrate
```
