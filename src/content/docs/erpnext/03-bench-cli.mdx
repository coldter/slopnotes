## What is bench?

Bench orchestrates the whole Frappe ecosystem: sites, apps, database operations, workers, deployments. Think `docker compose` + `npm` + `django-admin` in one. You never touch Gunicorn, Redis, or MariaDB directly in day-to-day work.

```bash
bench --help
# Usage: bench [OPTIONS] COMMAND [ARGS]...
# Commands:
#   backup  build  clear-cache  console  disable-scheduler  doctor  drop-site
#   enable-scheduler  execute  export-csv  get-app  init  install-app  migrate
#   new-app  new-site  pip  remove-app  restart  restore  run-tests  set-config
#   setup  start  switch-to-branch  update  use  version  watch
```

## Site management

A site is a tenant with its own database and files.

### Creating sites

```bash
bench new-site icecream.localhost --mariadb-root-password mypassword
bench new-site icecream.localhost \
  --mariadb-root-password mypassword --admin-password SecurePass123
bench new-site icecream.localhost \
  --mariadb-root-password mypassword --db-name icecream_db
# Postgres instead of MariaDB:
bench new-site icecream.localhost --db-type postgres --db-host localhost --db-port 5432
```

### Switching and configuring sites

```bash
bench use icecream.localhost                      # set default site
ls sites/*/site_config.json                       # list all sites
bench --site icecream.localhost set-config key value   # site config
bench set-config -g key value                     # common config (all sites)
cat sites/icecream.localhost/site_config.json     # view site config
```

### Removing sites

```bash
bench drop-site test-site.localhost --mariadb-root-password mypassword
bench drop-site test-site.localhost --force --mariadb-root-password mypassword
```

:::danger
`bench drop-site` is irreversible — it deletes the database and all site files. Run `bench backup` first.
:::

### Migrations

`bench migrate` pushes schema changes to the database: reads DocType JSON, alters tables, runs patches, rebuilds the search index. There are no hand-written migration files.

```bash
bench --site icecream.localhost migrate   # one site
bench --site all migrate                  # all sites
# Migrating icecream.localhost
# Updating DocTypes for frappe: [========================================] 100%
# Updating DocTypes for erpnext: [========================================] 100%
# Running patches... / Updating Dashboard...
```

## App management

### Getting apps

```bash
bench get-app erpnext --branch version-16
bench get-app https://github.com/your-org/ice_cream_shop.git --branch main
bench get-app /path/to/local/ice_cream_shop
```

### Creating a new app

```bash
bench new-app ice_cream_shop
# Prompts: App Title, Description, Publisher, Email, License (default MIT)
# App ice_cream_shop created at apps/ice_cream_shop
```

<FileTree>
- apps/ice_cream_shop/
  - ice_cream_shop/
    - __init__.py
    - hooks.py app configuration and event hooks
    - patches.txt database migration patches
    - modules.txt list of modules in this app
    - templates/
      - __init__.py
    - ice_cream_shop/ default module (same name as app)
      - __init__.py
    - public/ static assets (JS, CSS, images)
    - www/ website pages
  - setup.py
  - pyproject.toml
  - requirements.txt
  - license.txt
  - README.md
</FileTree>

### Installing and removing apps

```bash
bench --site icecream.localhost install-app ice_cream_shop
bench --site icecream.localhost remove-app ice_cream_shop
bench remove-app ice_cream_shop   # from the whole bench (uninstalls from all sites first)
```

## Development commands

### Start the dev server

```bash
bench start
# Reads the Procfile and starts:
# web:       bench serve --port 8000
# socketio:  node apps/frappe/socketio.js
# watch:     bench watch
# schedule:  bench schedule
# worker:    bench worker --queue short,default,long
# Ctrl+C stops all processes.
```

### Build assets

```bash
bench build                    # all apps
bench build --app ice_cream_shop
bench watch                    # rebuild on change (already in bench start)
```

### Clear caches

```bash
bench --site icecream.localhost clear-cache
bench --site icecream.localhost clear-website-cache
```

Clear after modifying `hooks.py`, editing DocType JSON manually, switching branches, or when the UI shows stale data. Nuclear option when nothing else works: `bench --site icecream.localhost clear-cache && bench build && bench --site icecream.localhost migrate`.

## Console and debugging

### Interactive Python console

`bench --site icecream.localhost console` opens an IPython REPL with the full Frappe context — database connection, session, caching — already wired up.

```bash
bench --site icecream.localhost console
# In [1]: frappe.get_doc("User", "Administrator")
# In [2]: frappe.db.sql("SELECT name, email FROM tabUser LIMIT 5")
# In [3]: frappe.db.count("Sales Invoice")          # 42
# In [4]: doc = frappe.get_doc({"doctype": "Ice Cream Flavor",
#         "flavor_name": "Mango Alphonso", "base_type": "Sorbet", "cost_per_scoop": 45.00})
# In [5]: doc.insert()
# In [6]: frappe.db.commit()
```

### Execute functions directly

```bash
bench --site icecream.localhost execute frappe.client.get_count --args '["Sales Invoice"]'
bench --site icecream.localhost execute \
  ice_cream_shop.tasks.sync_franchise_inventory \
  --kwargs '{"franchise_id": "FRAN-001"}'
```

### Run tests

```bash
bench --site icecream.localhost run-tests --app ice_cream_shop
bench --site icecream.localhost run-tests --doctype "Ice Cream Flavor"
bench --site icecream.localhost run-tests \
  --module ice_cream_shop.ice_cream_shop.doctype.ice_cream_flavor.test_ice_cream_flavor
bench --site icecream.localhost run-tests --app ice_cream_shop -v
# Ran 5 tests in 3.456s — OK
```

### Direct database access

```bash
bench --site icecream.localhost mariadb
# MariaDB [icecream_db]> SHOW TABLES LIKE '%flavor%';
# -> tabIce Cream Flavor
# MariaDB [icecream_db]> SELECT name, base_type, cost_per_scoop FROM `tabIce Cream Flavor` LIMIT 5;
```

## Backup and restore

```bash
bench --site icecream.localhost backup                          # database only
bench --site icecream.localhost backup --with-files             # + private + public files
bench --site icecream.localhost backup --with-files --compress --backup-path /tmp/backups/
bench --site all backup --with-files
# -> sites/icecream.localhost/private/backups/20260320_143000-icecream_localhost-database.sql.gz
# -> ...-private-files.tar  ...-files.tar
```

```bash
bench --site icecream.localhost restore /path/to/...-database.sql.gz
bench --site icecream.localhost restore /path/to/...-database.sql.gz \
  --with-private-files /path/to/...-private-files.tar \
  --with-public-files /path/to/...-files.tar
bench --site icecream.localhost migrate   # always migrate after restore
```

:::caution
Restoring a backup from a different site/server resets the Administrator password to `admin` unless `admin_password` is set in `site_config.json`. Copy the source site's `encryption_key` to preserve encrypted field data.
:::

## Production setup

```bash
sudo bench setup production <your-linux-username>
# Generates /etc/nginx/conf.d/frappe-bench.conf and /etc/supervisor/conf.d/frappe-bench.conf,
# enables Supervisor + Nginx, enables the scheduler.
sudo bench setup nginx        # regenerate nginx config
sudo bench setup supervisor   # regenerate supervisor config
sudo bench restart            # restart production services
```

### Nginx and SSL

```bash
sudo bench setup lets-encrypt icecream.example.com
sudo bench setup wildcard-ssl example.com   # multi-tenant wildcard
```

## Scheduler management

The scheduler fires the periodic jobs in your app's `hooks.py` — required in production.

```bash
bench --site icecream.localhost enable-scheduler
bench --site icecream.localhost disable-scheduler   # during maintenance
bench doctor
# icecream.localhost: Active / Workers online: 3 / No active or queued jobs
```

## Multi-tenancy

One bench serves multiple sites via different domains — one codebase, every ScoopJoy franchise.

```bash
bench config dns_multitenant on
bench new-site franchise-north.example.com --mariadb-root-password mypassword
bench --site franchise-north.example.com install-app erpnext
bench --site franchise-north.example.com install-app ice_cream_shop
bench setup add-domain franchise-north.example.com --site franchise-north.example.com
bench setup nginx && sudo service nginx reload
```

## Version management

```bash
bench update                  # pull + install requirements + build + migrate + restart
bench update --no-restart     # skip restart
bench update --pull           # pull code only
bench update --apps erpnext   # one app only
```

:::caution
`bench update --reset` runs `git reset --hard` on all apps, discarding uncommitted changes. Commit or stash first.
:::

### Switching branches

```bash
bench switch-to-branch version-16 frappe erpnext
bench switch-to-branch develop erpnext
bench --site icecream.localhost migrate   # always migrate after switching
```

## Zero to running custom app

<Steps>
1. `bench init ice-cream-bench --frappe-branch version-16 --python python3.14 && cd ice-cream-bench`
2. `bench new-site icecream.localhost --mariadb-root-password mypassword --admin-password admin123 && bench use icecream.localhost`
3. `bench get-app erpnext --branch version-16 && bench --site icecream.localhost install-app erpnext`
4. `bench new-app ice_cream_shop && bench --site icecream.localhost install-app ice_cream_shop`
5. `bench start` — open `http://icecream.localhost:8000`
6. After code changes: `bench build --app ice_cream_shop && bench --site icecream.localhost run-tests --app ice_cream_shop`
7. After DocType changes: `bench --site icecream.localhost migrate`
8. `bench --site icecream.localhost backup --with-files`
9. If anything looks stale: `bench --site icecream.localhost clear-cache`
10. `bench doctor`
</Steps>

### Quick reference

| Command | Purpose |
|---------|---------|
| `bench start` | Start dev server |
| `bench new-site <name>` | Create a new site |
| `bench use <name>` | Set default site |
| `bench get-app <url/name>` | Download an app |
| `bench --site <name> install-app <app>` | Install app on site |
| `bench new-app <name>` | Scaffold a new app |
| `bench --site <name> migrate` | Run migrations and patches |
| `bench --site <name> clear-cache` | Clear all caches |
| `bench build` | Build JS/CSS assets |
| `bench --site <name> console` | Python REPL with Frappe context |
| `bench --site <name> backup --with-files` | Full backup |
| `bench --site <name> restore <file>` | Restore from backup |
| `bench --site <name> mariadb` | Open database shell |
| `bench --site <name> run-tests --app <app>` | Run tests |
| `bench doctor` | Check scheduler and worker health |
| `bench update` | Pull, build, migrate, restart |
| `bench --site <name> set-config <k> <v>` | Set site config value |
| `bench execute <dotted.path>` | Run a Python function |
