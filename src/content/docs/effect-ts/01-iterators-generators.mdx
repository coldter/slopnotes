`Effect.gen`, `Effect.fn`, and every `yield*` consume the JS generator protocol directly. Master these mechanics and the rest follows.

## The two protocols

```ts
// Iterator protocol — a one-shot cursor over values
interface Iterator<T, TReturn = any, TNext = undefined> {
  next(...args: [] | [TNext]): IteratorResult<T, TReturn>
}

type IteratorResult<T, TReturn = any> =
  | { done: false; value: T }
  | { done: true; value: TReturn }

// Iterable protocol — "hand out a fresh iterator"
interface Iterable<T> {
  [Symbol.iterator](): Iterator<T>
}

// IterableIterator — both at once (what generators produce)
interface IterableIterator<T> extends Iterator<T>, Iterable<T> {}
```

An **iterator** is a one-shot cursor. An **iterable** is a factory — each `[Symbol.iterator]()` returns a fresh cursor, so arrays iterate many times. Generators return objects that are both.

:::caution[One-shot vs restartable]
A generator *function* is restartable; a generator *object* is not. After it completes, every `.next()` returns `{ done: true, value: undefined }` forever. `Effect.gen` re-invokes the generator function **once per effect execution** — that's what makes effects re-runnable.
:::

## `next()` drives both directions

1. **Values flow both ways.** `next(arg)` makes `arg` the value of the suspended `yield` expression — the only JS construct where the callee injects into the caller's expression. Effect uses this to feed success values into `const x = yield* ...`.
2. **`throw(err)` and `return(v)` complete the generator from outside.** `throw` makes the suspended `yield` raise `err` (your `try/catch` sees it); `return(v)` forces `done: true` with `v`, running `finally` blocks. The runtime uses both to inject failures and unwind interrupted fibers.

```ts
function* demo() {
  try {
    const received = yield 1
    console.log("got:", received)
    yield 2
  } finally {
    console.log("cleanup ran") // runs on return()/throw()/completion
  }
}

const it = demo()
it.next()            // { value: 1, done: false }
it.next("hello")     // logs "got: hello" → { value: 2, done: false }
it.return("bye")     // logs "cleanup ran" → { value: "bye", done: true }
```

## Typed generators: three parameters

```ts
interface Generator<Y = unknown, R = unknown, N = unknown>
  extends Iterator<Y, R, N> {
  next(...args: [] | [N]): IteratorResult<Y, R>
}
```

- `Y` — type of values **yielded** out
- `R` — **return** type when done
- `N` — type the caller passes **into** `next()`

```ts
function* counter(): Generator<number, string, void> {
  let i = 0
  while (i < 3) {
    const _ignored = yield i++
  }
  return "done"
}
```

`yield x` types the expression as `N`. `yield* expr` uses the delegate's own `N` — that's how `yield* someEffect` gets its `A` into your variable.

## `yield*` delegates fully

- Drives the inner iterator to completion, forwarding `next()` args in and yielded values out.
- Expression value = the inner iterator's **return value** (`const a = yield* gen()` types `a` as the return type).
- Inner exceptions propagate out.
- If the outer gets `return()` while suspended in a `yield*`, the inner gets `return()` too — unwinding cascades through delegation, running inner `finally` blocks. This is how cancellation reaches nested generators.

```ts
function* inner(): Generator<number, number, void> {
  yield 1
  yield 2
  return 42
}

function* outer(): Generator<number, number, void> {
  const result = yield* inner() // result === 42
  return result + 1
}
```

Delegation is synchronous control-flow plumbing: whoever drives the outer iterator drives the inner one too.

## Build async/await by hand

A generator is a resumable function; whoever holds the iterator decides what yielded values mean. `async/await` is this pattern baked into engines. Here's a coroutine runner for thunks:

```ts
type Thunk<A> = () => Promise<A>

function run<A>(genFn: () => Generator<Thunk<any>, A, any>): Promise<A> {
  return new Promise((resolve, reject) => {
    const it = genFn()
    function step(next: IteratorResult<Thunk<any>, A>): void {
      if (next.done) return resolve(next.value)
      next.value().then(
        (value) => step(it.next(value)),
        (error) => step(it.throw!(error))
      )
    }
    step(it.next())
  })
}

const program = function* () {
  const user = yield () => fetchUser(1)      // "await"
  const posts = yield () => fetchPosts(user.id)
  return [user, posts] as const
}

run(program).then(console.log)
```

Twenty lines give you: imperative-looking async, errors through normal `try/catch`, and a program that is a value separate from its execution. Swap the interpreter and the same body means something else.

| toy runner | Effect runtime |
|---|---|
| `Thunk<A>` yielded | `Effect<A, E, R>` descriptions yielded |
| resolved value fed back via `next(value)` | success `A` via `next(a)` |
| reject → `it.throw(error)` | fail → resumes generator so `yield*` raises the typed error |
| no cancellation | interrupt → unwinds iterator, runs finalizers |
| no context | threads `Context` through, satisfying `R` |
| no scheduling | cooperative scheduler, fiber budget, keep-alive |

Effect's interpreter is a production-grade fiber runtime. Because yielded values are inert descriptions, the same body runs eagerly, or is inspected, retried, timed, traced, or run under a virtual clock.

## Performance notes

- Each `yield` is a real suspension — a result-wrapper allocation plus a state-machine transition. V8 optimizes generators well, but it's not free.
- `Effect.gen` drives `iterator.next(value)` directly in a loop — no `for await`, no helper libraries. Overhead stays at the protocol minimum.
- `yield*` on an Effect is **not** a nested run — no recursion, no stack growth. Delegation flattens at the iterator level; the runtime sees one linear instruction sequence. Deeply nested `gen` bodies don't risk stack overflow.

## Remember

1. `next(value)` injects; `throw(err)` raises; `return(v)` unwinds — the driver controls the generator.
2. `yield*` delegates values, args, exceptions, and early completion; its value is the delegate's return.
3. The body is a blueprint; the iterator is the single execution. Re-runnable programs re-invoke the body.
4. Interpreters give yielded values meaning. Effect's meaning: "suspend this fiber until this described computation produces a result."
