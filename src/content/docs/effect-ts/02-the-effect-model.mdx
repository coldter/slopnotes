## An Effect is a description

```ts
const program = Effect.gen(function*() {
  yield* Effect.log("hello")
  return 42
})
```

Nothing has executed. `program` is an immutable AST of instructions — code as a value, except Effects are *declarations*, not closures. Everything follows:

- **Lazy**: constructing does nothing. Running executes. Run the same value twice, it runs twice.
- **Immutable & re-runnable**: descriptions compose without side effects at composition time.
- **Transform or run**: you don't peek inside.

`Promise` is an outcome placeholder — created hot, memoized, uncancellable.

| Property | `Promise<A>` | `Effect<A, E, R>` |
|---|---|---|
| When created | starts immediately | inert |
| Failure type | `any` | `E`, tracked in the type |
| Requirements | none expressible | `R` — services from context |
| Cancellation | impossible | first-class fiber interruption with cleanup |
| Re-runnable | no — memoized | yes — re-execute the description |
| Sync support | no | `Effect.runSync` |
| Composition | methods + `await` | combinators + generator syntax |

## Decoding `Effect<A, E, R>`

```ts
export interface Effect<out A, out E = never, out R = never>
  extends Pipeable, Inspectable {
  readonly [TypeId]: Variance<A, E, R>
  [Symbol.iterator](): EffectIterator<Effect<A, E, R>>
}
```

1. **Phantom variance markers** (`Variance<A, E, R>`): all three channels are covariant (`out`), so `Effect<User>` is usable where `Effect<unknown>` is expected. This makes dual signatures like `Effect.map` infer correctly.
2. **`[Symbol.iterator]`**: makes every Effect yieldable with `yield*`. Anything with this method can appear after `yield*` in an `Effect.gen` body.
3. **Defaults `E = never`, `R = never`**: an effect that can't fail and needs nothing is just `Effect<number>`.

### Reading triples

```ts
declare const fetchUser: (id: string) => Effect.Effect<User, UserNotFound, Database>
// "a computation producing a User, that may fail with UserNotFound,
//  and requires a Database service in context"
```

`R` is dependency injection: effects *require* services instead of taking them as parameters. Until provided, `R` propagates up as a pending debt — the compiler won't let you run a program that still owes services.

## Creating effects

```ts
import { Effect } from "effect"

const one: Effect.Effect<number> = Effect.succeed(1)              // succeed
const boom: Effect.Effect<never, string> = Effect.fail("boom")    // typed fail
const crash: Effect.Effect<never> = Effect.die(new Error("bug"))   // defect
const now: Effect.Effect<number, unknown> = Effect.try(() => Date.now()) // throwing sync

type FetchError = { readonly _tag: "FetchError"; cause: unknown }
const data = Effect.tryPromise({                                   // promise
  try: () => fetch("https://example.com").then((r) => r.json()),
  catch: (cause) => ({ _tag: "FetchError", cause })
})

let counter = 0
const next = Effect.sync(() => ++counter)                          // deferred sync
```

:::note[Fail vs Die]
`fail` puts a value in `E` — an expected, handled failure ("user not found"). `die` produces a **defect** — a bug ("this should never happen"). Defects skip `E`, crash the fiber, land in `Cause.Die`. See [05 Errors](/effect-ts/05-errors/) and [06 Cause & Exit](/effect-ts/06-cause-exit/).
:::

## Executing: the `run*` family

```ts
import { Effect } from "effect"

const program = Effect.succeed(42)

await Effect.runPromise(program)       // 42 — rejects with Cause-wrapped failure on error/die/interrupt
await Effect.runPromiseExit(program)   // Exit.Success(42) — never rejects
const n = Effect.runSync(program)      // fully synchronous — throws on async ops
const fiber = Effect.runFork(program)  // fork a fiber, keep going
```

- **Library code** never runs anything — return descriptions.
- **Application entry**: `runPromise` for scripts, or `NodeRuntime.runMain(Layer.launch(appLayer))` for services ([29 Runtime Integration](/effect-ts/29-runtime-integration/)).
- `runSync` only works if nothing suspends asynchronously.
- `runPromise` rejects with a `Cause.Failure` wrapper holding the full multi-reason cause — not the raw `E`.

:::caution[v4 keep-alive]
v3 needed `runMain` so a suspended fiber kept the process alive. v4 holds a reference-counted keep-alive timer, so `runPromise` stays alive while fibers have pending work. `runMain` is still recommended for signals and exit codes.
:::

## Composing lazily

```ts
import { Effect } from "effect"

const parse = (input: string) =>
  Effect.try({
    try: () => JSON.parse(input) as { n: number },
    catch: (cause) => new Error("bad json", { cause })
  })

const doubled = Effect.map(parse("[1,2]"), (v) => v.n * 2)
const chained = Effect.flatMap(doubled, (n) => Effect.succeed(n + 1))
```

Composition builds AST nodes; only `run*` walks them. That's why you can build candidate strategies and try them later, run tests under a fake clock, and provide dependencies after the fact — `Effect.provide(program, layer)` wraps one description in another.

## Where the runtime lives

Each `run*` becomes a **fiber** — a lightweight virtual thread with its own continuation stack, interruption state, and context. Fibers cooperate through a scheduler that yields every N operations so tight loops can't starve the event loop. Details in [13 Fibers](/effect-ts/13-fibers/):

- one root fiber per `run*` call
- forks create child fibers tied to their parent's scope
- interruption is cooperative but guaranteed: cleanup always runs
