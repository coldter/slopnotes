`Option<A>` models *maybe absent*; `Result<A, E>` models *already settled, either way*. Both are plain values you transform synchronously — and both are **yieldable** inside `Effect.gen`, where they meet the error channel. Note the v3 breaking change: `Result` is **success-first**.

## Option\<A\>

```ts
type Option<A> = Some<A> | None<A>

interface Some<A> { readonly _tag: "Some"; readonly value: A }
interface None<A>  { readonly _tag: "None" }
```

```ts title="src/option-basics.ts"
import { Option } from "effect"

const found = Option.some(42)
const missed = Option.none<number>()

if (Option.isSome(found)) {
  found.value // number
}

const label = Option.match(found, {
  onNone: () => "nothing",
  onSome: (n) => `got ${n}`
})

Option.getOrElse(missed, () => 0) // 0
Option.getOrNull(missed)          // null — for JS-facing boundaries
Option.getOrUndefined(missed)     // undefined

const doubled = Option.map(found, (n) => n * 2) // Option.some(84)

// filterMap: keep-and-transform in one pass
const evens = Option.filterMap(Option.some(7), (n) => (n % 2 === 0 ? Option.some(n) : Option.none()))
```

```ts
import { Option } from "effect"

declare const input: string | null
const maybe: Option.Option<string> = Option.fromNullishOr(input)
```

Also: `Option.gen` — generator syntax for synchronous Option pipelines (short-circuits on first `None`); `Option.liftPredicate(pred, orFailWith)` — value → `Some`/`None` by predicate.

### Option is yieldable — absence fails

Yielding an `Option` in `Effect.gen` unwraps a `Some`; a `None` **fails the effect with `NoSuchElementError`**:

```ts title="src/option-gen.ts"
import { Cause, Effect } from "effect"

declare const lookupUser: (id: string) => Effect.Effect<Option.Option<{ name: string }>>

const program = Effect.gen(function* () {
  const user = yield* lookupUser("u_1") // user: { name: string }
  return user.name
})

await Effect.runPromiseExit(program)
// Exit.fail(Cause.NoSuchElementError) if the lookup returned None
```

To get absence back as a value instead:

```ts
const tolerant = lookupUser("u_1").pipe(Effect.catchNoSuchElement)
// Effect<Option<{ name: string }>> — NoSuchElementError → None, others untouched
```

:::tip[Decide per call site]
Yield raw when absence is genuinely exceptional ("the invariant says this row exists"). Wrap with `catchNoSuchElement` when absence is normal ("cache miss"). The type system makes each decision visible.
:::

Related: `Effect.fromOption(option, onError?)` lifts an Option into the error channel; `Effect.transposeOption` turns `Option<Effect>` into `Effect<Option>`.

## Result\<A, E\> — success first!

The change that breaks every v3 instinct:

```ts
// v3: Either<E, A>   ← error FIRST (Scala/Rust heritage)
// v4: Result<A, E>   ← SUCCESS FIRST (matches Effect<A, E>)
```

First type parameter = success, second = failure.

```ts title="src/result-basics.ts"
import { Result } from "effect"

type Parsed = Result.Result<number, string>

const ok: Parsed = Result.succeed(42)
const bad: Parsed = Result.fail("not a number")

if (Result.isSuccess(ok)) {
  ok.success // number
}
if (Result.isFailure(bad)) {
  bad.failure // string
}

Result.match(ok, {
  onSuccess: (n) => `value ${n}`,
  onFailure: (e) => `why: ${e}`
})

Result.map(ok, (n) => n + 1)                // Success(43)
Result.mapError(bad, (e) => new Error(e))   // Failure(Error)
Result.mapBoth(bad, {
  onFailure: (e) => new Error(e),
  onSuccess: (n) => n * 2
})
Result.flatMap(Result.succeed(2), (n) =>
  n > 0 ? Result.succeed(n * 10) : Result.fail("non-positive")
) // Success(20)

Result.getOrElse(bad, () => -1)             // -1
Result.orElse(bad, () => Result.succeed(0)) // Success(0)

Result.flip(ok)                             // Failure(42)
```

`Result` has a generator DSL too — evaluated eagerly and synchronously, unlike `Effect.gen`:

```ts
import { Result } from "effect"

const total = Result.gen(function* () {
  const a = yield* Result.succeed(1)
  const b = yield* parseIntSafe("2")
  return a + b
})
// short-circuits with the first Failure
```

`Result.all` collects tuples/records, short-circuiting on first failure — pure structure reshaping, no concurrency dimension:

```ts
import { Result } from "effect"

declare const a: Result.Result<number, string>
declare const b: Result.Result<number, string>
declare const bad: Result.Result<number, string>

Result.all([a, b])                    // Result<[number, number], string>
Result.all({ width: a, height: bad }) // Result<{ width: number; height: number }, string>
```

### Result is yieldable too

Yielding a `Result` feeds the success value through; a failure fails the effect **with its `E`**:

```ts title="src/result-gen.ts"
import { Effect, Result, Schema } from "effect"

class InvalidInput extends Schema.TaggedError<InvalidInput>()("InvalidInput", {
  detail: Schema.String
}) {}

const parseQty = (raw: string): Result.Result<number, InvalidInput> =>
  /^\d+$/.test(raw) ? Result.succeed(Number(raw)) : Result.fail(new InvalidInput({ detail: raw }))

const order = Effect.gen(function* () {
  const qty = yield* parseQty("12") // qty: number; InvalidInput joins E
  return qty * 2
})
// Effect<number, InvalidInput>
```

This is the bridge between pure validation layers (plain functions returning `Result` — trivially unit-testable, no runtime) and effectful orchestration. Keep business rules `Result`-returning; lift them into effects at the edge.

### Interop helpers

| Effect world → data | Code |
|---|---|
| Settled effect → `Result` | `yield* Effect.result(eff)` / `eff.pipe(Effect.result)` |
| Settled effect → `Option` | `Effect.option(eff)` |
| `Result` back into channel | `Effect.fromResult(result)` |
| Full envelope incl. defects | `Effect.exit(eff)` (chapter 06) |

`Effect.result` never fails: typed errors become `Failure(e)`; defects stay defects — that's why `result` exists separately from `exit`.

## Typed absence vs the error channel

| Situation | Reach for |
|---|---|
| Lookup may legitimately miss; caller decides what missing means | `Option<A>` |
| Operation may fail; failure carries *why*; caller must handle | `Effect<A, E>` |
| Pure computation may fail; testability matters; no I/O yet | `Result<A, E>` |
| Absence would be a broken invariant | yield raw / `NoSuchElementError` |
| You're about to reach for `E = Option<X>` or boolean returns | don't |

Avoid encoding absence *in* the error channel (`Effect<A, NotFound | null>`-style unions) or presence *in* the success channel (`Effect<A | null>`) — each forces defensive checks the types were meant to eliminate.

## Structural equality is the default now

v3 compared plain objects by reference unless wrapped in `Data`. v4 inverts the default: **`Equal.equals` compares plain objects, arrays, Maps, Sets, Dates, and RegExps structurally** — and everything built on it (Cause, Exit, Option, Result, Data instances, `Filter.equals`, HashMap keys...) follows.

```ts title="src/equality.ts"
import { Equal } from "effect"

Equal.equals({ a: 1 }, { a: 1 })                 // true — was false in v3!
Equal.equals([1, [2, 3]], [1, [2, 3]])           // true
Equal.equals(NaN, NaN)                           // true — NaN === NaN here
Equal.equals(new Date("2026-01-01"), new Date("2026-01-01")) // true (by timestamp)
Equal.equals(
  new Map([["a", 1], ["b", 2]]),
  new Map([["b", 2], ["a", 1]])
)                                                // true — order-independent
Equal.equals(/abc/g, /abc/g)                     // true (by source+flags)
```

### Consequences you'll hit

**1. Effect collections hash structurally.**

```ts
import { Equal, HashSet } from "effect"

HashSet.make({ id: 1 }).has({ id: 1 }) // true — needed Data in v3
```

Native `new Map()`/`new Set()` still compare by reference — structural equality applies to Effect's own structures and `Equal.equals`, not V8 internals. For plain-object keys across a boundary, prefer `HashMap`/`HashSet`.

**2. Tests assert by value.**

```ts
import { Equal, Exit } from "effect"
import { expect } from "vitest"

declare const runProgram: () => Exit.Exit<number, string>

expect(Equal.equals(runProgram(), Exit.succeed(42))).toBe(true)
```

Exits with equal causes (defects included) compare equal — failure-shape regression tests are one `Equal.equals` away.

**3. Don't mutate after comparing.** Comparison results are cached per object pair; mutating after the first comparison yields stale results. Treat compared objects as immutable.

### Opting out

```ts
import { Equal } from "effect"

const a = { x: 1 }
const b = { x: 1 }

// proxy wrapper: original untouched
const ref1 = Equal.byReference(a)
Equal.equals(ref1, b)     // false
ref1.x                    // 1

// marks the object itself (irreversible, zero allocation)
const obj = { y: 2 }
const ref2 = Equal.byReferenceUnsafe(obj)
ref2 === obj              // true
Equal.equals(obj, { y: 2 }) // false forever
```

Use these for identity-meaningful objects: cache entries keyed by handle, mutable builders. Note `byReference(x) !== byReference(x)` — each call wraps anew.

## The Data module

With free structural equality, most of v3's reasons for `Data` evaporated. What remains is real but narrower:

```ts title="src/data.ts"
import { Data } from "effect"

// 1. Pipeable value classes with methods
class Money extends Data.Class<{ readonly cents: number }> {
  add(that: Money): Money {
    return new Money({ cents: this.cents + that.cents })
  }
  toString(): string {
    return `$${(this.cents / 100).toFixed(2)}`
  }
}
Equal.equals(new Money({ cents: 500 }), new Money({ cents: 500 })) // true

// 2. Tagged single variants
class Started extends Data.TaggedClass("Started")<{ readonly at: number }> {}
new Started({ at: 1 })._tag // "Started"

// 3. Yieldable errors without Schema (Schema.TaggedError in chapter 05)
class Denied extends Data.TaggedError("Denied")<{ who: string }> {}

// 4. Tagged enums: union + constructors + matchers in one declaration
type Conn =
  | Data.TaggedEnum<{ Open: { readonly host: string }; Closed: {} }>
const Conn = Data.taggedEnum<Conn>()

const c = Conn.Open({ host: "db.local" })
c._tag // "Open"
Conn.$is("Closed")(c) // false

const label = Conn.$match(c, {
  Open: ({ host }) => `connected to ${host}`,
  Closed: () => "disconnected"
})
```

What `Data.Class` still buys over a bare literal: a real class (methods, `extends`, nominal identity in stack traces), `Pipeable` (`.pipe(...)` chains), consistent `Equal`/`Hash`, and `Data.TaggedError`. When plain literals suffice — JSON payloads, ad-hoc tuples, most returns — skip `Data`. Sweet spots: domain objects carrying behaviour, discriminated unions constructed in many places.

## Opaque ids: Brand & Newtype

Structural equality cuts both ways: `{ id: "u_1" }` equals any object shaped like it. For domain identifiers you want *nominal* typing — two id types that both wrap strings shouldn't mix.

```ts title="src/ids.ts"
import { Brand } from "effect"

export type UserId = string & Brand.Brand<"UserId">
export type OrderId = string & Brand.Brand<"OrderId">

declare function fetchUser(id: UserId): void

const raw = "u_1"
fetchUser(raw)             // ✗ compile error: string is not UserId
fetchUser(raw as UserId)   // ✓ explicit cast at the trust boundary
```

`Brand.Brand<"Key">` is a phantom property in a unique symbol — erased at runtime, so branded strings remain plain strings with zero overhead. Structural equality still works within a brand.

`Brand.nominal<T>()` produces a callable wrapper with no runtime validation (`.option`/`.result`/`.is` variants included); validated construction is `Brand.check`/`Brand.make` territory:

```ts
import { Brand } from "effect"

const mkUserId = Brand.nominal<UserId>()
const u1 = mkUserId("u_1" as UserId) // no runtime check, just the cast formalised
```

In practice, most codebases brand via **Schema** — `Schema.brand` adds the phantom during decoding, so ids are minted validated at the boundary and flow nominally typed through the app. Rule: *brand at decode time, consume everywhere*. (The older `Newtype` module still exists but brands compose better with Schema.)

## Cheat sheet

| Task | Code |
|---|---|
| Maybe-absent value | `Option.some(v)` / `Option.none()` |
| Unwrap Option in gen | `const v = yield* opt` (None → `NoSuchElementError`) |
| Absence back to value | `Effect.catchNoSuchElement` |
| Settled outcome | `Result.succeed(a)` / `Result.fail(e)` |
| Remember the order | `Result<A, E>` — **success first** |
| Unwrap Result in gen | `const v = yield* res` (failure → `E` in channel) |
| Effect → data | `Effect.result` / `Effect.option` / `Effect.exit` |
| Compare structurally | `Equal.equals(a, b)` |
| Reference semantics | `Equal.byReference(obj)` |
| Value class | `Data.Class<{...}>` + methods |
| Tagged union + ctors | `Data.TaggedEnum` + `Data.taggedEnum` |
| Opaque id | `string & Brand.Brand<"UserId">` |
