You already live in vim mode (Zed, VS Code). `h j k l`, `dd`, `:w` are muscle memory. What still feels slow: copying a word by dragging a selection first, then yanking. That's the select-then-act reflex from your old editor — the one Vim exists to delete.

This guide fixes the mental model: state a **verb**, then a **noun**. Once that clicks, keystrokes become derivable instead of memorized.

:::note[Who this is for]
You know normal vs. insert mode, `w`/`b` motions, and run vim mode in a GUI editor. This is not a from-zero "what is normal mode" guide.
:::

## The core idea: verb, then noun

Vim is a tiny grammar. State an **operator** (the verb: `y` yank, `d` delete, `c` change), then a **motion or text object** (the noun: a word, inside the quotes, to the next comma). `yiw` = "yank inner word." `ci(` = "change inside parentheses."

Every verb composes with every noun — you never memorize `yiw` and `ci(` as separate facts.
