Two front-ends guard two different **perimeters**: operators administer *all* tenants behind Cloudflare Access; tenant users see only *their own* org behind Better Auth. One bundle talking to both API surfaces and both auth models is a blast radius no one wants — so the front end is two SPAs that share visual primitives via `packages/ui` but diverge on routing, auth, API client, and state.

## App matrix

| App | Stack | Served at | Auth | API target | Owner |
| --- | --- | --- | --- | --- | --- |
| `apps/admin-ui` | React SPA | `admin.example.com` | Cloudflare Access (no login form) | `apps/admin` | operators |
| `apps/app` | React SPA | `*.app.example.com` + custom domains | Better Auth cookies + SSO + password | `apps/server` | tenant users |
| `packages/ui` (new) | React component library | n/a | n/a | n/a | shared |
| `apps/admin` | Hono Worker (API + serves admin-ui) | `admin.example.com` | CF Access JWT | self / service bindings | infra |
| `apps/app` (worker) | Static-assets Worker | non-public; via service binding | none (public assets) | n/a | infra |

Both web apps share a base stack: TanStack Router (file-based, `(protected)` route group), TanStack Query, Zustand, Tailwind, `@hookform/resolvers` + Zod, `@hey-api/openapi-ts` for typed clients.

:::note[Workers Static Assets]
The `apps/app` *worker* isn't a server in the usual sense — it hands back pre-built SPA files from an attached bucket. Its `fetch` handler is one line. That's why it can stay non-public and be reached only through a service binding.
:::

## apps/admin-ui

The `apps/admin-ui` SPA is the renamed `apps/web`. Routes map onto operator equivalents:

- `/` — operator dashboard (queue depths, recent audit, active tenant count)
- `/enrollment` — one-time landing for the first-login `x-admin-enrollment-token` claim
- `/tenants`, `/tenants/:id`, `/tenants/:id/hostnames`, `/tenants/:id/sso`
- `/users` — cross-tenant user search (rate-limited; row-capped)
- `/audit-logs` — cross-tenant audit filter
- `/global-admins` — `super_admin` only
- `/system/queues`, `/system/workflows`
- `/profile` — the operator's own profile

There is deliberately **no** `/login` route: Cloudflare Access intercepts before the SPA loads.

### What gets removed from the old `apps/web`

- The multi-step login form (`apps/web/src/modules/auth/`) is deleted entirely.
- 2FA setup flows targeting tenant users are deleted — operators get MFA from the IdP behind Cloudflare Access.
- Existing `dashboard`, `audit-logs`, `users` routes are repurposed into cross-tenant operator equivalents.

### The enrollment flow

A brand-new operator has a CF Access identity but no `global_admins` row yet:

<Steps>

1. `globalAdminMiddleware` returns `403 { code: "ENROLLMENT_REQUIRED" }`.
2. The SPA's global error handler navigates to `/enrollment`, which shows a single input for the one-time token.
3. On submit, the next API call carries `x-admin-enrollment-token: <value>`, and the middleware atomically binds the operator's `sub` to the pending row.
4. A successful claim navigates back to `/`.

</Steps>

### API client

The admin SPA generates a typed client from the admin worker's OpenAPI spec:

```ts title="apps/admin-ui/openapi-ts.config.ts"
{
  input: "../admin/openapi.cache.json",     // generated by apps/admin's generate-openapi script
  output: "./src/api.gen/",
  plugins: ["@hey-api/client-fetch", "@hey-api/sdk", "@tanstack/react-query", "zod"],
}
```

Base URL is always `https://admin.example.com` (or `import.meta.env.VITE_ADMIN_URL` in local dev). No tenant context to thread — operators work across all tenants. The build runs in two steps:

<Steps>

1. `apps/admin#generate-openapi` runs the in-process Hono app and writes `apps/admin/openapi.cache.json`.
2. `apps/admin-ui#generate-client` reads that file and emits the typed client into `src/api.gen/`.

</Steps>

This reuses the existing `generate-openapi` task name from `turbo.json` so the pipeline stays uniform across both web apps.

## apps/app

The tenant-facing SPA. Runs on `*.app.example.com` and tenant custom domains, calls `apps/server`. Unlike the admin panel, it has a real login surface.

### Routes

Public routes live outside the `(protected)` group:

- `/login` — SSO-aware: fetches `/api/tenancy/current` and branches on `enforceSSO`
- `/accept-invite/:invitationId` — public; orchestrates user creation plus sign-in (see [Admin Panel](/multi-tenant/admin-panel/#operator-led-onboarding))
- `/forgot-password`, `/reset-password` — Better Auth's OTP flow

Protected routes live inside `(protected)` and redirect to `/login` without a session:

- `/`, `/dashboard`
- `/settings/profile`, `/settings/security` (2FA management)
- `/org/members` — invite or remove members
- `/org/settings` — org name and per-tenant branding
- `/org/settings/sso` — register, edit, delete SSO providers; toggle `enforce_sso`
- `/org/settings/domains` — add, verify, remove custom hostnames
- `/org/audit-logs` — tenant-scoped audit (including operator-attribution rows)

:::note
There is no client-side `/sso/callback` route. Better Auth's SSO callback hits `/api/auth/sso/callback/{providerId}` on `apps/server`; after setting the cookie it 302s to the passed `callbackURL` (typically `/`).
:::

### Tenant context, resolved at runtime

A single-tenant app bakes the tenant and API URL into the build. With thousands of tenants and custom domains, that means a rebuild per tenant — impossible. Instead the SPA ships one identical artifact and, on boot, reads `window.location.host` and asks the server "which tenant is this host?" The bundle is tenant-agnostic; **the URL the user typed is the tenant identifier.**

```tsx title="apps/app/src/lib/tenant.ts"
export type TenantInfo = {
  organizationId: string;
  slug: string;
  enforceSSO: boolean;
  providers: Array<{ providerId: string; label: string }>;
  branding: { logoUrl?: string; primaryColor?: string; appName: string };
};

export async function resolveTenant(): Promise<TenantInfo | null> {
  const headers: Record<string, string> = {};
  if (import.meta.env.DEV && import.meta.env.VITE_DEV_TENANT_SLUG) {
    headers["x-dev-tenant-slug"] = import.meta.env.VITE_DEV_TENANT_SLUG;
  }
  const r = await fetch(`${window.location.origin}/api/tenancy/current`, { credentials: "include", headers });
  if (!r.ok) return null;
  return r.json() as Promise<TenantInfo>;
}
```

The bootstrap resolves session and tenant in parallel, bails with a not-found screen when the host maps to no tenant, and applies branding before the router renders:

```tsx title="apps/app/src/main.tsx"
const [session, tenant] = await Promise.all([
  queryClient.ensureQueryData(sessionQueryOptions).catch(() => null),
  resolveTenant(),
]);
if (!tenant) { renderTenantNotFound(); return; }
applyBranding(tenant.branding);
renderRouter({ session, tenant });
```

### Better Auth client

The auth client's `baseURL` is `window.location.origin`, so the cookie and API call always match the host the user is on:

```tsx title="apps/app/src/lib/auth-client.ts" {3}
export const authClient = createAuthClient({
  baseURL: window.location.origin,    // NOT a build-time env var
  basePath: "/api/auth",
  plugins: [organizationClient(), twoFactorClient(), ssoClient()],
});
```

A build-time `VITE_SERVER_URL` would force a rebuild per tenant. `window.location.host` is the tenant identifier.

### The `apps/app` worker

```ts title="apps/app/src/index.ts"
export default {
  fetch: (request: Request, env: { ASSETS: Fetcher }) => env.ASSETS.fetch(request),
};
```

```jsonc title="apps/app/wrangler.jsonc"
{
  "name": "app",
  "main": "src/index.ts",
  "compatibility_date": "2026-04-01",
  "workers_dev": false,
  "preview_urls": false,
  "assets": {
    "directory": "./dist",
    "binding": "ASSETS",
    "not_found_handling": "single-page-application"
  }
  // No public routes — reachable only via apps/server's STATIC_ASSETS binding.
}
```

`not_found_handling: "single-page-application"` lets a hard reload of a client-side route like `/dashboard` resolve to `index.html`. `Cache-Control` and `ETag` pass through the service binding unchanged.

### `apps/server` proxies non-API paths

The tenant SPA is never reached directly. Anything under `/api/` falls through to API handlers; everything else is fetched from the static-assets worker:

```ts title="apps/server/src/server.ts"
app.get("*", async (c, next) => {
  const path = new URL(c.req.url).pathname;
  if (path.startsWith("/api/")) return next();   // API handlers downstream
  return c.env.STATIC_ASSETS.fetch(c.req.raw);   // SPA assets
});
```

That's what makes custom hostnames "just work" for the SPA: `app.acme.com` lands on `apps/server` through the Cloudflare for SaaS fallback origin, and its non-API paths proxy to `apps/app` — no per-tenant build, no per-tenant route.

## packages/ui

The shared package holds UI primitives and the Tailwind preset both apps consume — one place for look-and-feel without coupling data layers.

**In scope:** all Radix/shadcn wrappers (`Button`, `Dialog`, `DataTable`, `DropdownMenu`, `Sheet`, `Tabs`, `Toast`, …); stateless utilities (`cn`, `useDialogState`, `useMobile`, `useTableUrlState`); composition patterns (`ConfirmDialog`, `EmptyState`, `LoadingState`, `ErrorBoundary`, `FullPageError`); the **Tailwind preset** (`packages/ui/tailwind.preset.ts`); **Storybook** (lives in `packages/ui` only — not duplicated per app).

**Not in scope:** anything that knows a specific worker's API or auth model stays in the consuming app — query hooks, Zustand stores, the Better Auth client, route infrastructure, generated API types. Rule: stateless + visual = shared; anything importing `react-query`, `better-auth/client`, or `api.gen/` stays in the app.

## Per-tenant branding

Each org carries three branding columns: `organization.branding_logo_url` (text, URL into R2), `branding_primary_color` (text, CSS color validated by a Zod regex), `branding_app_name` (text, defaults to `organization.name`). `/api/tenancy/current` returns them under `branding: { logoUrl?, primaryColor?, appName }`.

### Logo hosting

Logos live in R2 (Cloudflare's S3-style object store), not the database — the row stores only a URL:

- A Cloudflare R2 bucket, `BRANDING_ASSETS`, is bound to `apps/server`.
- A tenant admin uploads via `POST /api/org/branding/logo` — a plain multipart upload *through* `apps/server` (validates and writes to R2), not a presigned direct-to-bucket URL. Limits: max 256KB, PNG/SVG/WebP only.
- Objects stored at `R2:{orgId}/logo-{cuid}.{ext}`.
- Served through a Cloudflare custom domain on the bucket (`branding.example.com`); CSP `img-src` allows that host.

:::caution[Sniff the content-type from bytes]
The upload endpoint determines content-type by inspecting the file's bytes, not the multipart header — a client-supplied header is forgeable.
:::

### Primary-color validation

```ts title="apps/server — branding validation"
const primaryColor = z.string().regex(/^(#[0-9a-f]{3,8}|rgb\(.+\)|hsl\(.+\))$/i);
```

### Applying the branding

Set CSS custom properties and the document title — never inject markup:

```tsx title="apps/app/src/lib/branding.ts"
function applyBranding(b: TenantInfo["branding"]) {
  if (b.primaryColor) document.documentElement.style.setProperty("--brand-primary", b.primaryColor);
  document.title = b.appName;
}
```

The logo renders via a React component — `<TenantLogo src={tenant.branding.logoUrl} alt={tenant.branding.appName} />` — on the login page, sidebar, and anywhere the brand appears.

:::note[Why `setProperty`, not a `<style>` tag]
`element.style.setProperty(...)` is CSP-safe: it sets a property on an existing element rather than parsing new CSS. A `<style>` tag would need a per-render nonce or `unsafe-inline`, weakening a strict CSP.
:::

## Local development

Each SPA runs against its target worker locally, double-gated so dev shortcuts never reach production:

- **`apps/app`** — `bun dev` runs `vite --port=3000`; `.env.development` sets `VITE_DEV_TENANT_SLUG=acme`; Vite proxies `/api/*` to `http://localhost:8787` (local `apps/server`). The tenant resolves via an `X-Dev-Tenant-Slug: acme` header honored only when `NODE_ENV=development` **and** `ALLOW_DEV_TENANT_HEADER=true` (a Cloudflare Secret).
- **`apps/admin-ui`** — `bun dev` runs `vite --port=3001`; Vite proxies `/api/*` to `http://localhost:8788` (local `apps/admin`). Operator auth uses `LOCAL_DEV_ADMIN_EMAIL`, gated by `NODE_ENV=development` **and** `ALLOW_DEV_ADMIN_AUTH=true`.
- **Seeding** — `bun run seed:dev` creates one org with slug `acme` and one `global_admin` matching `LOCAL_DEV_ADMIN_EMAIL` with role `super_admin` (idempotent UPSERTs). A CI guard rejects any deploy whose merged config has `NODE_ENV !== "production"`.

## Deployment

Turborepo wires each web app to its target worker so the typed client regenerates before the SPA builds:

<Mermaid title="Turborepo build pipeline" height={360} code={`

  subgraph Tenant["Tenant app"]
    SO["apps/server#generate-openapi"] --> AC["apps/app#generate-client"]
    AC --> AB["apps/app#build"]
    AB --> AD["wrangler deploy"]
  end
  subgraph Admin["Admin app"]
    AdO["apps/admin#generate-openapi"] --> AdC["apps/admin-ui#generate-client"]
    AdC --> AdB["apps/admin-ui#build"]

  end

`turbo.json` declares `generate-client` with `dependsOn: ["^generate-openapi"]` (caret = upstream package dependencies — resolves because each web app's `package.json` depends on its target worker's package).

Topology: the `apps/admin` deploy ships both the worker **and** `apps/admin-ui/dist/` (assets-binding directory `../admin-ui/dist`). `apps/app` deploys as a separate static-assets worker, reachable only via `apps/server`'s `STATIC_ASSETS` binding. `apps/server` and `apps/auth` deploy independently with no asset payloads.

## The apex page

The wildcard's apex, `app.example.com`, maps to no tenant. v1 ships a static "Find your team" landing from `apps/app/dist/apex/`: an email input looks up org memberships and redirects to `{slug}.app.example.com/login`; a forgot-password link routes to the tenant subdomain. Served whenever `parseHostname` returns `kind: "apex"`. The membership lookup is a v2 nice-to-have; v1 can ship a purely static page.

## Gotchas worth keeping in mind

- **`workers_dev: false`** on every worker, including `apps/app` — otherwise the static-assets worker is reachable at `app.<account>.workers.dev`.
- **`not_found_handling: "single-page-application"`** on `apps/app` is non-negotiable for TanStack Router client-side routes.
- **Don't share generated API types across apps** — each `api.gen/` is pinned to its target worker's deploy cycle.
- **Auth client `baseURL` is `window.location.origin`**, never a build-time env var.
- **Apply CSS via `setProperty`, not `<style>` injection** — strict-CSP compatibility.
- **Logo upload sniffs content-type from bytes**, not the multipart header.
- **`/sso/callback` is not an `apps/app` route** — Better Auth handles it at `/api/auth/sso/callback/{providerId}` on `apps/server`.
- **Storybook lives in `packages/ui` only.**
- **Local dev relies on two env signals** — `NODE_ENV=development` **and** an `ALLOW_*` secret. Single-signal gates are forgeable.
