## Starter `mise.toml`

The 30-second per-project baseline: tools, env, one task.

```toml title="mise.toml"
[tools]
node = "22"
python = "3.13"

[env]
_.file = ".env"            # load dotenv if present
DATABASE_URL = { default = "postgres://localhost/dev_db" }

[tasks.dev]
run = "npm run dev"
description = "Start the dev server"
```

Replaces an `.nvmrc`, an `.envrc`, and a `make dev`. Commit it, gitignore `mise.local.toml`. See [Tools](/mise/02-tools-backends/) and [Environments](/mise/03-environments-secrets/).

## Ad-hoc tool, zero config

```bash
mise x node@22 -- node --version
mise exec python@3.12 go@1.23 -- ./build.sh   # multiple tools at once
```

Run any tool at any version without touching `mise.toml` — mise installs it on the fly. See [Install & Activate](/mise/01-install-activate/).

## `mise exec` in cron, systemd & scripts

Non-interactive contexts never run your shell rc, so `mise activate` was never wired up:

```bash title="crontab / systemd ExecStart"
# crontab: full path to mise, exec the tool from the project dir
*/5 * * * * cd /srv/app && /home/deploy/.local/bin/mise exec -- node cron-job.js
```

```ini title="myapp.service"
[Service]
WorkingDirectory=/srv/app
ExecStart=/home/deploy/.local/bin/mise exec -- node server.js
```

`mise exec` reads the project's `mise.toml` and sets up `PATH`/env for that one command — no activation, no login shell. Alternative: put `~/.local/share/mise/shims` on `PATH`. See [CI, Docker & IDEs](/mise/07-ci-docker-ide/).

## Python auto-venv

```toml title="mise.toml"
[tools]
python = "3.13"

[env]
_.python.venv = { path = ".venv", create = true }
```

`cd` in and the venv is active — no `python -m venv` + `source` dance. See [Environments & Secrets](/mise/03-environments-secrets/).

## `corepack enable` for pnpm / yarn

```toml title="mise.toml"
[tools]
node = { version = "22", postinstall = "corepack enable" }
```

`mise install` leaves `pnpm`/`yarn` ready (driven by your `packageManager` field) — no global `npm i -g pnpm`. The postinstall hook gets `MISE_TOOL_VERSION`. See [Watch, Hooks & Automation](/mise/05-watch-hooks/).

## Auto-install on enter

```toml title="mise.toml"
[hooks]
enter = "mise install"
```

The first `cd` into a freshly cloned repo installs the exact pinned toolchain. Needs an active `mise activate` session. See [Watch, Hooks & Automation](/mise/05-watch-hooks/).

## Multi-platform lockfile

```bash
mise lock --platform linux-x64,macos-arm64
```

```toml title="mise.toml"
[settings]
lockfile = true
```

One `mise.lock` that resolves on every machine. Commit it; there is no `--frozen` flag. See [Tools & Backends](/mise/02-tools-backends/).

## Secrets with sops + age

```bash
mise use -g sops age
age-keygen -o ~/.config/mise/age.txt          # note the public key it prints
sops encrypt -i --age <age-public-key> .env.json
```

```toml title="mise.toml"
[settings]
experimental = true                            # secrets are experimental

[env]
_.file = { path = ".env.json", redact = true } # auto-decrypts on load
```

Secrets encrypted at rest, redacted in `mise env` output; mise finds the key via `MISE_SOPS_AGE_KEY` → `~/.config/mise/age.txt`. For teams, look at `fnox`. See [Environments & Secrets](/mise/03-environments-secrets/).

## Monorepo task fan-out

```toml title="mise.toml (repo root)"
monorepo_root = true

[monorepo]
config_roots = ["packages/*", "services/*"]
```

```bash
mise run "//...:test"            # run `test` in every config_root, at any depth
mise run "//services/api:deploy" # one specific project
```

`//...:task` fans out across the monorepo; `:task` targets the current root. Declare `config_roots` — auto filesystem-walk discovery is deprecated. See [Designing Your Workflow](/mise/06-workflow-design/).

## `MISE_ENV` dev / ci / prod profiles

```toml title="mise.production.toml"
[env]
LOG_LEVEL = "warn"
DATABASE_URL = { default = "postgres://prod-host/app" }
```

```bash
MISE_ENV=production mise run migrate
```

`MISE_ENV=production` loads `mise.production.toml` over `mise.toml` (and `mise.production.local.toml` over that). Comma-list allowed, last wins. See [Environments & Secrets](/mise/03-environments-secrets/).

## `confirm` on a destructive task

```toml title="mise.toml"
[tasks.db-reset]
run = "dropdb app_dev && createdb app_dev && mise run migrate"
confirm = "This wipes the dev database. Continue?"
```

One key turns a footgun into a prompt; skip it in automation with `MISE_YES=1 mise run db-reset`. See [The Task Runner](/mise/04-tasks/).

## Task args with the `usage` spec

```toml title="mise.toml"
[tasks.greet]
usage = '''
arg "<name>" help="Who to greet"
flag "-l --loud" help="Shout it"
'''
run = '''
msg="hello, $usage_name"
[ "$usage_loud" = "true" ] && msg=$(echo "$msg" | tr a-z A-Z)
echo "$msg"
'''
```

```bash
mise run greet world --loud   # HELLO, WORLD
```

Parsed args surface as `$usage_<name>` env vars and feed shell completions. Don't use the old Tera `arg()`/`flag()` functions — removed in 2027.5.0. See [The Task Runner](/mise/04-tasks/).

## Generate a git pre-commit hook

```bash
mise generate git-pre-commit --write --task pre-commit
```

```toml title="mise.toml"
[tasks.pre-commit]
run = "mise run lint ::: mise run test"   # staged files available in $STAGED
```

The generated hook just runs `mise run pre-commit`, so the logic lives in your committed config. For richer hooks see `hk`. See [Watch, Hooks & Automation](/mise/05-watch-hooks/).

## Shell aliases from config

```toml title="mise.toml"
[shell_alias]
mr = "mise run"
mx = "mise exec --"
```

Project-scoped aliases that activate with the directory — no editing `.zshrc` per repo. Needs an active `mise activate` session. See [Install & Activate](/mise/01-install-activate/).

## Debugging: doctor, which, where

```bash
mise doctor          # config, activation, untrusted paths, version warnings
mise which node      # the real binary path mise resolves (not the shim)
mise where node@22   # the install directory for a specific version
```

`which node` may show a shim; `mise which node` shows the actual resolved binary. `mise doctor` is the first stop for activation and trust problems — and confirms you're on mise ≥ 2026.6.4. See [Install & Activate](/mise/01-install-activate/).
