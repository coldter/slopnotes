mise does the `direnv` job from the same `mise.toml` that pins your tools — no second config file, no `.envrc`.

:::caution[mise replaces direnv — don't run both]
direnv interop is deprecated. Use `[env]` for everything below; don't layer mise on top of an `.envrc`. Migration steps in [Migrating off the old tools](/mise/08-migration/).
:::

## The `[env]` block

```toml title="mise.toml"
[env]
NODE_ENV = "development"
PORT = "3000"
DATABASE_URL = "postgres://localhost/app_dev"
```

`cd` in and these are exported; `cd` out and they're gone.

Three modifiers handle the edge cases:

```toml title="mise.toml"
[env]
LOG_LEVEL = { default = "info" }   # use this UNLESS already set in the shell
API_TOKEN = { required = true }    # error if unset — fail fast, not at runtime
CI = false                         # actively UNSET an inherited variable
```

- `default` — a fallback that an existing shell value overrides.
- `required` — mise errors when you enter the dir if the var isn't set elsewhere.
- `false` — removes the variable (scrub an inherited `CI`/`DEBUG`).

### `_.path` — extend `PATH` per project

```toml title="mise.toml"
[env]
_.path = "./bin"                       # relative → resolved from config_root
# _.path = ["./bin", "./node_modules/.bin"]
```

Prepends project-local binaries to `PATH`. Relative paths anchor at the config file's directory, not your cwd.

### `_.file` — load dotenv / JSON / YAML / TOML

```toml title="mise.toml"
[env]
_.file = ".env"                        # dotenv by default
```

Format is inferred from the extension — `.env`, `.json`, `.yaml`, `.toml` all work. Table form for options:

```toml title="mise.toml"
[env]
_.file = { path = ".env.secret", redact = true }   # hide values in `mise env`
_.file = { path = ".env.tools", tools = true }      # load AFTER tools install
```

- `redact = true` — values masked in `mise env` / logs.
- `tools = true` — defers loading until tools are installed, so the file can reference tool-provided binaries.

:::tip[Keep secrets out of git]
Commit a `.env.example`; gitignore the real `.env*`. For encrypted-at-rest secrets you *can* commit, see [Secrets](#secrets) below.
:::

### `_.source` — run a shell script and import its exports

```toml title="mise.toml"
[env]
_.source = "./scripts/env.sh"          # bash; its `export`s become mise env
```

This executes code, so it's [trust-gated](/mise/06-workflow-design/) — mise won't run it until you `mise trust`.

### Ordering and `[[env]]`

`[env]` entries within a block are unordered; when one value must reference another, use the array-of-tables form so blocks apply in sequence:

```toml title="mise.toml"
[[env]]
_.file = ".env"
[[env]]
DATABASE_URL = "{{env.DB_HOST}}/app"   # DB_HOST from the .env loaded above
```

## Templating with Tera

mise renders config through [Tera](https://keats.github.io/tera/). Reference another variable as `{{env.X}}` — **not** `$X`:

```toml title="mise.toml"
[env]
PROJECT = "{{config_root | basename}}"           # the project dir name
CACHE_DIR = "{{config_root}}/.cache"             # absolute path to this config
GIT_SHA = "{{ exec(command='git rev-parse --short HEAD') }}"
EDITOR = "{{ get_env(name='EDITOR', default='vim') }}"
```

Building blocks: vars `env`, `cwd`, `config_root`, `mise_bin`, `mise_env`; functions `exec(command=…)`, `get_env(name=…, default=…)`, `arch()`, `os()`, `num_cpus()`; filters like `basename`, `dirname`, `kebabcase`.

:::caution[`$VAR` shell expansion is off by default]
`FOO = "$HOME/x"` does **not** expand — you get the literal string. Shell expansion needs `env_shell_expand = true`. Prefer `"{{env.HOME}}/x"`; it's portable.
:::

## Config environments (profiles)

One project, several environments. Set `MISE_ENV` (or `-E/--env`) and mise loads the matching files on top of the base:

```bash
MISE_ENV=production mise run deploy   # also loads mise.production.toml
mise -E ci run test
```

```toml title="mise.production.toml"
[env]
NODE_ENV = "production"
LOG_LEVEL = "warn"
DATABASE_URL = { required = true }    # no localhost default in prod
```

`MISE_ENV` accepts a comma list (`MISE_ENV=ci,prod`) — later wins. For a given environment, files merge highest-to-lowest, key by key:

| Precedence | File | Commit? | Purpose |
|---|---|---|---|
| highest | `mise.<env>.local.toml` | gitignore | your machine, this env |
| | `mise.local.toml` | gitignore | your machine, all envs |
| | `mise.<env>.toml` | commit | shared, this env |
| lowest | `mise.toml` | commit | shared base |

:::tip[Commit shared, gitignore personal]
Commit `mise.toml` and `mise.<env>.toml`; add `*.local.toml` to `.gitignore`.
:::

## Python virtualenv auto-activation

mise creates and activates a project venv on directory entry — no `source .venv/bin/activate`:

```toml title="mise.toml"
[tools]
python = "3.13"

[env]
_.python.venv = { path = ".venv", create = true }   # create if missing, then activate
```

`cd` in and the venv is active; `pip`/`python` resolve inside it. Combined with the `[tools]` pin, a new dev gets the right Python *and* an isolated venv from a single `mise install`.

## Secrets

mise loads encrypted secrets so ciphertext is safe to commit and plaintext only exists in memory. Both built-in methods are experimental:

```toml title="mise.toml"
[settings]
experimental = true
```

The decryption key — your **age private key** — stays out of the repo (default `~/.config/mise/age.txt`). Commit only ciphertext.

### sops + age (encrypted file)

<Steps>

1. Install the tools and generate a key:

   ```bash
   mise use -g sops age
   age-keygen -o ~/.config/mise/age.txt   # prints the public key
   ```

2. Encrypt a secrets file in place with your public key:

   ```bash
   sops encrypt -i --age age1xxxxxxxx... .env.json
   ```

3. Load it — mise auto-decrypts via the age key on entry:

   ```toml title="mise.toml"
   [env]
   _.file = { path = ".env.json", redact = true }
   ```

</Steps>

Key lookup order: `MISE_SOPS_AGE_KEY` → `*_FILE` → `SOPS_AGE_KEY*` → `~/.config/mise/age.txt`.

:::note[TOML secrets need the built-in backend]
The external `sops` CLI can't encrypt TOML. Use JSON or YAML, or enable mise's built-in rops with `sops.rops = true` for TOML files.
:::

### Inline age (single value)

```bash
mise set --age-encrypt --prompt DB_PASSWORD
```

```toml title="mise.toml"
[env]
DB_PASSWORD = { age = { value = "-----BEGIN AGE…", format = "raw" } }
```

View the decrypted environment with `mise env` (or `mise env --redacted --values` to confirm masking).

### Redaction

```toml title="mise.toml"
[settings]
redactions = ["*_TOKEN", "*_SECRET", "DB_PASSWORD"]
```

### Teams: `fnox`

Per-developer age keys work for small teams. For shared/remote secret backends (1Password, AWS Secrets Manager, KMS), jdx's separate **[`fnox`](https://github.com/jdx/fnox)** manager integrates with mise without putting any private key on disk.
