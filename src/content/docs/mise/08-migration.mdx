## The big before/after table

| You ran… | …now you run / write | Notes |
|---|---|---|
| `nvm use 22` / `nvm install 22` | `mise use node@22` | writes nearest `mise.toml` + installs |
| `pyenv install 3.13` / `pyenv local 3.13` | `mise use python@3.13` | array form: `python = ["3.13", "3.12"]` |
| `rbenv install 3.3` / `rbenv local 3.3` | `mise use ruby@3.3` | |
| `volta install node@22` | `mise use -g node@22` | `-g` = global (`~/.config/mise/config.toml`) |
| `sdk install java 21-tem` | `mise use java@temurin-21` | `mise registry java` to see backends |
| `asdf plugin add X && asdf install X v` | `mise use X@v` | no `plugin add` step |
| `asdf global X v` / `asdf local X v` | `mise use -g X@v` / `mise use X@v` | global vs nearest config |
| `nvm ls` / `pyenv versions` / `asdf list` | `mise ls` | `mise ls -c` for what's active here |
| `nvm ls-remote` / `asdf list-all X` | `mise ls-remote X` | |
| `.nvmrc` / `.node-version` / `.python-version` / `.tool-versions` | `[tools]` in `mise.toml` | idiomatic files are **opt-in** (gotcha #1) |
| `direnv` + `.envrc` (`export FOO=bar`) | `[env]` in `mise.toml` | see [Environments & Secrets](/mise/03-environments-secrets/) |
| `.envrc` → `dotenv .env` | `[env]` → `_.file = ".env"` | |
| `.envrc` → `layout python` (venv) | `[env]` → `_.python.venv = { path = ".venv", create = true }` | |
| `Makefile` / `npm run` / `just` | `[tasks]` + `mise run` | see [The Task Runner](/mise/04-tasks/) |

That table *is* the migration for most repos. Delete the old config, add a `mise.toml`, commit it.

## The three gotchas

### 1. Idiomatic version files are NOT read by default

mise reads `mise.toml` and `.tool-versions`, but **ignores** `.nvmrc`, `.node-version`, `.python-version`, `.ruby-version`, and `.sdkmanrc` until you opt in — per tool:

```bash
mise settings add idiomatic_version_file_enable_tools node
mise settings add idiomatic_version_file_enable_tools python
```

```toml title="…or in mise.toml"
[settings]
idiomatic_version_file_enable_tools = ["node", "python"]
```

:::note[Prefer migrating over enabling]
Enabling idiomatic files is a bridge for repos you don't control yet. The real fix is to move the version into `[tools]` and delete the dotfile.
:::

### 2. "default packages" files are deprecated

asdf/nvm let you list always-install global packages in `~/.default-npm-packages`, `~/.default-gems`, etc. mise still reads these, but they're **deprecated**: they warn from `2026.11.0` and are removed in `2027.11.0`. Use a tool `postinstall` instead:

```toml title="mise.toml"
[tools]
# before: ~/.default-npm-packages held `prettier`, `corepack`…
node = { version = "22", postinstall = "corepack enable && npm i -g prettier" }
```

### 3. asdf install dirs are not reused — reinstall

mise does **not** adopt tools already in `~/.asdf/installs` — the layout and download sources differ (mise uses verified aqua/github downloads, not asdf plugin scripts). Just reinstall:

```bash
mise install            # installs everything in the resolved config
mise ls                 # confirm versions are active
```

Once happy, remove asdf entirely (`~/.asdf`, the shim line in your rc file, the Homebrew formula).

## asdf → aqua: why the backend changed

mise's default backend in 2026 is [**aqua**](/mise/02-tools-backends/). The difference is supply-chain trust:

| | asdf plugin | aqua (mise default) |
|---|---|---|
| What runs at install | arbitrary **bash** from a 3rd-party plugin repo | declarative download from a curated registry |
| Download integrity | whatever the script does | **verified** downloads (checksums) |
| Windows | mostly unsupported | supported |
| Maintenance | often stale / unmaintained | central registry |

```toml title="mise.toml — same tool, better backend"
[tools]
ripgrep = "latest"                          # bare name resolves via registry to aqua
"aqua:BurntSushi/ripgrep" = "latest"        # or address a backend explicitly
```

Run `mise registry` to see which backend a short name resolves to. If a tool only exists as an asdf plugin, `asdf:owner/repo` still works — treat it as a last resort.

## direnv: don't combine them — port to `[env]`

The official 2026 stance: **not** mise + direnv together. Port your `.envrc` into `[env]` and delete it.

The mise direnv *interop* shim is deprecated. Everything direnv did (vars, dotenv, `PATH_add`, venv layouts) is native in [Environments & Secrets](/mise/03-environments-secrets/), plus secrets and profiles direnv never had.

## Homebrew stays — it's complementary

mise replaces version *managers*, not your system package manager.

| Keep in Homebrew | Move to mise |
|---|---|
| system libs (`openssl`, `libpq`), GUI casks | project runtimes (node, python, go, ruby) |
| long-lived services you `brew services start` | per-project CLI tools (ripgrep, terraform, kubectl) |
| `mise` itself (`brew install mise`) | everything you used to `brew install <runtime>` for |

A common cleanup: `brew uninstall node python@3.x` once mise pins them per project.

## When NOT to reach for mise

mise is **version-based, not hermetic** — it puts the right tool versions on `PATH`; it does not sandbox your build from the host OS, and it doesn't run services.

| Need | Reach for | Why not mise |
|---|---|---|
| Fully **hermetic**, hash-locked builds | [Nix](https://nixos.org/) / [devbox](https://www.jetify.com/devbox) | mise pins versions, not the whole dependency graph |
| **OS-level** isolation / clean Linux userland | [devcontainers](https://containers.dev/) / Docker | mise shares your host OS and libs |
| **Running** databases, queues, daemons | Docker Compose | mise installs the binary, it does **not** supervise it |

:::note[They compose well]
A common 2026 setup: a **devcontainer** for OS isolation, **mise** inside it for tool versions + env + tasks, **Docker Compose** for the database. See [Designing Your Workflow](/mise/06-workflow-design/) and [CI, Docker & IDEs](/mise/07-ci-docker-ide/).
:::

## A clean cut-over

<Steps>

1. Pin tools: `mise use node@22 python@3.13` (or hand-write `[tools]`).
2. Port `.envrc` → `[env]`; port `Makefile`/`npm run` → `[tasks]`.
3. Lock it: `[settings] lockfile = true`, `mise lock`, commit `mise.lock`.
4. Delete `.nvmrc` / `.python-version` / `.tool-versions` / `.envrc`.
5. Remove the old tools: `asdf`, `nvm`, `direnv` (and their rc-file shims).
6. Teammates pull and run `mise install` — identical setup, one config.

</Steps>
