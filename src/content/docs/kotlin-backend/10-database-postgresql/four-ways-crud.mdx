## Goal

Implement the same `User` CRUD four ways — raw JDBC, Spring Data JPA, Exposed, jOOQ — against one PostgreSQL table. Same table, same DTO, same REST endpoints; four very different code shapes. The JVM version of: hand-written SQL (`database/sql`, `pg`) vs. ORM (`gorm`, Prisma) vs. type-safe query builder (`sqlc`, Knex).

## What you'll build

A single Spring Boot app wiring the same table behind four repositories, each under its own path prefix:

| Approach | What it is | Closest TS/Go analogue | Base URL |
|---|---|---|---|
| JDBC | Raw SQL + manual row mapping | `database/sql` (Go), `pg` (Node) | `/api/jdbc/users` |
| JPA | Full ORM, dirty checking | `gorm`, Prisma, TypeORM | `/api/jpa/users` |
| Exposed | Kotlin DSL query builder | Knex / Kysely (TS) | `/api/exposed/users` |
| jOOQ | Type-safe SQL from generated code | `sqlc` (Go) | `/api/jooq/users` |

### Shared pieces

One migration creates the table; Flyway runs it on startup:

```sql title="src/main/resources/db/migration/V1__create_users_table.sql"
CREATE TABLE IF NOT EXISTS mod10_database.users (
    id          BIGSERIAL PRIMARY KEY,
    name        VARCHAR(255) NOT NULL,
    email       VARCHAR(255) NOT NULL UNIQUE,
    active      BOOLEAN NOT NULL DEFAULT true,
    created_at  TIMESTAMP NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_users_email ON mod10_database.users (email);
CREATE INDEX IF NOT EXISTS idx_users_active ON mod10_database.users (active);
```

One shared DTO is the common currency — every repository returns `UserDTO`:

### The same five operations, four ways

`create`, `findById`, `findAll`, `update`, `delete` — written once per library. Code goes **up** as you give up magic and take back control of the SQL.

<Tabs syncKey="dbaccess">
  <TabItem label="JDBC">

Raw SQL strings + hand-written `RowMapper`. No magic — you write the `INSERT`, pull each column from the `ResultSet` by name, read the affected-row count yourself. Note the `GeneratedKeyHolder` dance to get the new `id` back.

```kotlin title="src/main/kotlin/com/example/jdbc/UserJdbcRepository.kt"
package com.example.jdbc

import com.example.model.UserDTO
import org.springframework.jdbc.core.JdbcTemplate
import org.springframework.jdbc.core.RowMapper
import org.springframework.jdbc.support.GeneratedKeyHolder
import org.springframework.stereotype.Repository
import java.sql.Statement

@Repository
class UserJdbcRepository(private val jdbcTemplate: JdbcTemplate) {

    private val rowMapper = RowMapper<UserDTO> { rs, _ ->
        UserDTO(
            id = rs.getLong("id"),
            name = rs.getString("name"),
            email = rs.getString("email"),
            active = rs.getBoolean("active"),
            createdAt = rs.getTimestamp("created_at").toInstant()
        )
    }

    fun create(name: String, email: String): UserDTO {
        val keyHolder = GeneratedKeyHolder()
        jdbcTemplate.update({ conn ->
            val stmt = conn.prepareStatement(
                "INSERT INTO mod10_database.users (name, email) VALUES (?, ?)",
                Statement.RETURN_GENERATED_KEYS
            )
            stmt.setString(1, name)
            stmt.setString(2, email)
            stmt
        }, keyHolder)

        val id = keyHolder.keys?.get("id") as Long
        return findById(id)!!
    }

    fun findById(id: Long): UserDTO? {
        val results = jdbcTemplate.query(
            "SELECT * FROM mod10_database.users WHERE id = ?",
            rowMapper,
            id
        )
        return results.firstOrNull()
    }

    fun findAll(): List<UserDTO> =
        jdbcTemplate.query("SELECT * FROM mod10_database.users ORDER BY id", rowMapper)

    fun update(id: Long, name: String, email: String, active: Boolean): Boolean {
        val rows = jdbcTemplate.update(
            "UPDATE mod10_database.users SET name = ?, email = ?, active = ? WHERE id = ?",
            name, email, active, id
        )
        return rows > 0
    }

    fun delete(id: Long): Boolean =
        jdbcTemplate.update("DELETE FROM mod10_database.users WHERE id = ?", id) > 0
}
```

  <TabItem label="JPA">

The ORM end. Declare an `@Entity`, then barely write any query code — `JpaRepository` gives you `save`, `findById`, `findAll`, `deleteById` for free, and derived queries like `findByEmail` are generated from the method name. The cost is hidden behavior: persistence context, dirty checking, lazy loading. Note the entity is a mutable `class` (not `data class`) with custom `equals`/`hashCode` keyed on the database `id`.

```kotlin title="src/main/kotlin/com/example/jpa/UserJpaEntity.kt"
package com.example.jpa

import jakarta.persistence.*
import java.time.Instant

@Entity
@Table(name = "users", schema = "mod10_database")
class UserJpaEntity(
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    val id: Long = 0,

    @Column(nullable = false)
    var name: String = "",

    @Column(nullable = false, unique = true)
    var email: String = "",

    @Column(nullable = false)
    var active: Boolean = true,

    @Column(name = "created_at", nullable = false, updatable = false)
    val createdAt: Instant = Instant.now()
) {
    override fun equals(other: Any?): Boolean {
        if (this === other) return true
        if (other !is UserJpaEntity) return false
        return id != 0L && id == other.id
    }

    override fun hashCode(): Int = id.hashCode()

    override fun toString(): String = "UserJpaEntity(id=$id, name=$name, email=$email)"
}
```

```kotlin title="src/main/kotlin/com/example/jpa/UserJpaRepository.kt"
package com.example.jpa

import org.springframework.data.jpa.repository.JpaRepository

interface UserJpaRepository : JpaRepository<UserJpaEntity, Long> {
    fun findByEmail(email: String): UserJpaEntity?
    fun findByActiveTrue(): List<UserJpaEntity>
}
```

  <TabItem label="Exposed">

JetBrains' Kotlin-native query builder. Describe the table once as a Kotlin `object`, then build queries with a typed DSL — `insert`, `selectAll`, `update`, `deleteWhere` — real Kotlin code the compiler checks. The Knex/Kysely sweet spot: no string SQL, no full ORM.

```kotlin title="src/main/kotlin/com/example/exposed/UserExposedRepository.kt"
package com.example.exposed

import com.example.model.UserDTO
import org.jetbrains.exposed.sql.*
import org.jetbrains.exposed.sql.SqlExpressionBuilder.eq
import org.jetbrains.exposed.sql.javatime.timestamp
import org.springframework.stereotype.Repository
import org.springframework.transaction.annotation.Transactional

object UsersTable : Table("mod10_database.users") {
    val id = long("id").autoIncrement()
    val name = varchar("name", 255)
    val email = varchar("email", 255)
    val active = bool("active").default(true)
    val createdAt = timestamp("created_at").defaultExpression(CurrentTimestamp)

    override val primaryKey = PrimaryKey(id)
}

@Repository
@Transactional
class UserExposedRepository {

    fun create(name: String, email: String): UserDTO {
        val id = UsersTable.insert {
            it[UsersTable.name] = name
            it[UsersTable.email] = email
        } get UsersTable.id

        return findById(id)!!
    }

    @Transactional(readOnly = true)
    fun findById(id: Long): UserDTO? {
        return UsersTable
            .selectAll()
            .where { UsersTable.id eq id }
            .map { it.toUserDTO() }
            .singleOrNull()
    }

    @Transactional(readOnly = true)
    fun findAll(): List<UserDTO> {
        return UsersTable
            .selectAll()
            .orderBy(UsersTable.id)
            .map { it.toUserDTO() }
    }

    fun update(id: Long, name: String, email: String, active: Boolean): Boolean {
        val updated = UsersTable.update({ UsersTable.id eq id }) {
            it[UsersTable.name] = name
            it[UsersTable.email] = email
            it[UsersTable.active] = active
        }
        return updated > 0
    }

    fun delete(id: Long): Boolean =
        UsersTable.deleteWhere { UsersTable.id eq id } > 0

    private fun ResultRow.toUserDTO() = UserDTO(
        id = this[UsersTable.id],
        name = this[UsersTable.name],
        email = this[UsersTable.email],
        active = this[UsersTable.active],
        createdAt = this[UsersTable.createdAt]
    )
}
```

  <TabItem label="jOOQ">

Closest JVM equivalent to Go's `sqlc`: point a code generator at your real schema, it emits typed classes — here `USERS` with `USERS.ID`, `USERS.NAME`, etc. Write SQL through a fluent, fully type-safe `DSLContext`. Rename a column and regenerate — queries that reference it stop compiling. Spring Boot auto-configures the `DSLContext` bean via `spring-boot-starter-jooq`.

```kotlin title="src/main/kotlin/com/example/jooq/UserJooqRepository.kt"
package com.example.jooq

import com.example.generated.tables.references.USERS
import com.example.model.UserDTO
import org.jooq.DSLContext
import org.jooq.Record
import org.springframework.stereotype.Repository

@Repository
class UserJooqRepository(private val dsl: DSLContext) {

    fun create(name: String, email: String): UserDTO {
        val id = dsl.insertInto(USERS)
            .set(USERS.NAME, name)
            .set(USERS.EMAIL, email)
            .returning(USERS.ID)
            .fetchOne()!!
            .id

        return findById(id)!!
    }

    fun findById(id: Long): UserDTO? {
        return dsl.selectFrom(USERS)
            .where(USERS.ID.eq(id))
            .fetchOne()
            ?.toUserDTO()
    }

    fun findAll(): List<UserDTO> {
        return dsl.selectFrom(USERS)
            .orderBy(USERS.ID)
            .fetch()
            .map { it.toUserDTO() }
    }

    fun update(id: Long, name: String, email: String, active: Boolean): Boolean {
        val rows = dsl.update(USERS)
            .set(USERS.NAME, name)
            .set(USERS.EMAIL, email)
            .set(USERS.ACTIVE, active)
            .where(USERS.ID.eq(id))
            .execute()
        return rows > 0
    }

    fun delete(id: Long): Boolean {
        return dsl.deleteFrom(USERS)
            .where(USERS.ID.eq(id))
            .execute() > 0
    }

    private fun Record.toUserDTO() = UserDTO(
        id = this[USERS.ID]!!,
        name = this[USERS.NAME]!!,
        email = this[USERS.EMAIL]!!,
        active = this[USERS.ACTIVE]!!,
        createdAt = this[USERS.CREATED_AT]?.toInstant(java.time.ZoneOffset.UTC)
    )
}
```

:::note[jOOQ needs code generation first]
Unlike the other three, jOOQ won't compile until you run its generator against a live schema to produce the `USERS` reference. Add the `org.jooq.jooq-codegen-gradle` plugin, point it at your Postgres URL, run `./gradlew jooqCodegen`. That generation step is the price of compile-time safety — and exactly what makes it feel like `sqlc`.
:::

### One controller, four backends

The controller is deliberately dumb — delegates the same five operations to each repository under a different prefix, mapping everything to the shared `UserDTO`:

```kotlin title="src/main/kotlin/com/example/Application.kt" {32-38,40-68}
@RestController
@RequestMapping("/api")
class UserController(
    private val jdbcRepo: UserJdbcRepository,
    private val jpaRepo: UserJpaRepository,
    private val exposedRepo: UserExposedRepository
) {

    // ==================== JDBC ====================

    @PostMapping("/jdbc/users")
    fun jdbcCreate(@RequestBody req: CreateUserRequest): ResponseEntity<UserDTO> {
        val user = jdbcRepo.create(req.name, req.email)
        return ResponseEntity.status(HttpStatus.CREATED).body(user)
    }

    @GetMapping("/jdbc/users")
    fun jdbcList(): List<UserDTO> = jdbcRepo.findAll()

    @GetMapping("/jdbc/users/{id}")
    fun jdbcGet(@PathVariable id: Long): ResponseEntity<UserDTO> {
        val user = jdbcRepo.findById(id) ?: return ResponseEntity.notFound().build()
        return ResponseEntity.ok(user)
    }

    // ... jpaCreate / jpaList / jpaGet ... mirror these under /jpa/users
    // ... exposedCreate / exposedList / ... mirror these under /exposed/users
}
```

```kotlin title="src/main/kotlin/com/example/Application.kt"
// JPA entity → DTO mapping
private fun UserJpaEntity.toDTO() = UserDTO(
    id = id,
    name = name,
    email = email,
    active = active,
    createdAt = createdAt
)
```

### What changed

- **JDBC** — most lines, all explicit. You own every SQL string and column read. Zero magic, but a typo in a column name is a runtime error.
- **JPA** — fewest lines: the repository is an empty interface. Price is the most hidden behavior — persistence context, dirty checking, lazy loading.
- **Exposed** — Kotlin-native middle ground. Typed queries, no string SQL, no full ORM. The table `object` is the single source of truth.
- **jOOQ** — type safety rooted in your *actual* schema. Rename a column and the build breaks instead of production. Cost is the generation step.

No universal winner: JPA for boring CRUD, JDBC/jOOQ when you need to own the SQL, Exposed for idiomatic Kotlin without a full ORM. A real Spring Boot app can mix them — JPA for entities, jOOQ for the gnarly reporting query — over the same `DataSource`.

## Configuration

```yaml title="src/main/resources/application.yml"
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/kotlin_course
    username: dev
    password: dev
    hikari:
      maximum-pool-size: 10
      minimum-idle: 5

  jpa:
    hibernate:
      ddl-auto: validate          # Flyway owns the schema; Hibernate only checks
    show-sql: true                # watch the SQL each approach emits
    properties:
      hibernate:
        format_sql: true
        default_schema: mod10_database

  flyway:
    enabled: true
    locations: classpath:db/migration
    schemas: mod10_database
    baseline-on-migrate: true

server:
  port: 8080
```

## Run and test

<Steps>

1. Start PostgreSQL from the shared infra:

   ```bash
   cd shared-infra
   docker compose up -d postgres
   ```

2. Run the app — Flyway applies the migration on startup:

   ```bash
   ./gradlew bootRun
   ```

3. Create the same user through each prefix and watch the SQL log differ:

   ```bash
   curl -X POST http://localhost:8080/api/jdbc/users \
     -H "Content-Type: application/json" \
     -d '{"name": "Alice", "email": "alice@example.com"}'
   ```

4. List, get, update, delete — the API is identical across prefixes:

   ```bash
   curl http://localhost:8080/api/jpa/users
   curl http://localhost:8080/api/exposed/users/1

   curl -X PUT http://localhost:8080/api/jdbc/users/1 \
     -H "Content-Type: application/json" \
     -d '{"name": "Alice Updated", "email": "alice@example.com", "active": true}'

   curl -X DELETE http://localhost:8080/api/jpa/users/1
   ```

</Steps>

:::tip[Watch the SQL]
With `spring.jpa.show-sql: true`, every JPA call prints the SQL Hibernate generated. Run the same create/update through JDBC, Exposed, and JPA and compare the console output — the fastest way to build intuition for what each layer does on your behalf.
:::
