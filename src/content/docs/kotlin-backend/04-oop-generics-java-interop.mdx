Kotlin adds generics variance, sealed hierarchies, class delegation, and seamless Java interop on top of what TS/Go offer.

## Classes & constructors

### Primary constructors

The constructor is in the class header — properties declared directly:

```kotlin
class User(
    val id: String,          // read-only (like TS readonly)
    var name: String,        // mutable
    var email: String,
    private var age: Int     // private
)

val user = User("u1", "Alice", "alice@corp.com", 30)
// No `new` keyword — Kotlin drops it.
```

### init blocks

```kotlin
class User(
    val id: String,
    var name: String,
    var email: String,
    private var age: Int
) {
    init {
        require(id.isNotBlank()) { "ID must not be blank" }
        require(age in 0..150) { "Age must be 0-150" }
        name = name.trim()
        email = email.lowercase()
    }
}
```

### Secondary constructors

Must delegate to primary with `this(...)`. Prefer default parameters instead:

```kotlin
class User(val id: String, var name: String = "Unknown") {
    constructor(id: String, name: String) : this(id, name)
}
```

### Properties, getters, setters

```kotlin
class Account(
    val id: String,
    initialBalance: Double       // no val/var = constructor param only, NOT a property
) {
    val isActive: Boolean
        get() = balance > 0.0    // computed, no backing field

    var balance: Double = initialBalance
        set(value) {
            require(value >= 0) { "Balance cannot be negative" }
            field = value        // `field` = the backing field
        }

    var transactionCount: Int = 0
        private set          // read-only outside, mutable inside
}
```

### Visibility modifiers

| Modifier | Kotlin | TypeScript | Go |
|---|---|---|---|
| `public` | default | `public` (default) | Capitalized name |
| `private` | same file/class | `private` | lowercase name |
| `protected` | class + subclasses | `protected` | N/A |
| `internal` | same Gradle module | N/A | package-level |

## Interfaces & abstract classes

Interfaces can have default methods and abstract properties:

```kotlin
interface Logger {
    val prefix: String
    fun log(message: String)
    fun error(message: String) { log("ERROR: $message") }   // default impl
    fun warn(message: String) { log("$prefix WARN: $message") }
}

class ConsoleLogger : Logger {
    override val prefix = "[CONSOLE]"
    override fun log(message: String) { println("$prefix $message") }
    // error() and warn() inherited
}
```

Abstract classes can have state (interfaces can't):

```kotlin
abstract class Repository<T>(protected val tableName: String) {
    abstract fun findById(id: String): T?
    abstract fun save(entity: T): T
    fun exists(id: String): Boolean = findById(id) != null   // concrete
}
```

| Use an **interface** when | Use an **abstract class** when |
|---|---|
| You define a capability | You share state across subclasses |
| Multiple inheritance needed | You need a constructor with params |
| No shared state | You have a base implementation |

### Multiple interface implementation

```kotlin
interface Cacheable { val cacheKey: String; fun ttlSeconds(): Int = 300 }
interface Serializable { fun toJson(): String }
interface Auditable { val createdAt: Long; val updatedAt: Long }

data class Product(
    val id: String,
    override val createdAt: Long = System.currentTimeMillis(),
    override val updatedAt: Long = System.currentTimeMillis()
) : Cacheable, Serializable, Auditable {
    override val cacheKey get() = "product:$id"
    override fun toJson() = """{"id":"$id"}"""
}
```

When two interfaces provide the same default method, override and pick with `super<A>.greet()` / `super<B>.greet()`.

## Inheritance: open/override

Classes and methods are **final by default**. Mark `open` to allow inheritance.

```kotlin
open class Animal(protected val name: String) {
    open fun speak(): String = "$name makes a sound"
    fun species(): String = "Animal"    // final — cannot override
}

class Dog(name: String) : Animal(name) {
    override fun speak(): String = "$name barks"   // `override` is mandatory
}
```

- Kotlin: final by default, prevents fragile base class. `override` keyword required.
- TypeScript: everything open by default.
- Go: no inheritance — embedding is composition, not polymorphism.

## Sealed classes and interfaces

Restricts which classes can extend. Compiler enforces exhaustive `when`.

```kotlin
sealed class Result<out T> {
    data class Success<T>(val value: T) : Result<T>()
    data class Failure(val error: String) : Result<Nothing>()
    data object Loading : Result<Nothing>()
}

fun handle(result: Result<String>): String = when (result) {
    is Result.Success -> result.value
    is Result.Failure -> "Error: ${result.error}"
    is Result.Loading -> "Loading..."
    // no else — compiler knows all subtypes
}
```

### Real-world: API responses

```kotlin
sealed interface ApiResponse<out T> {
    data class Ok<T>(val data: T, val statusCode: Int = 200) : ApiResponse<T>
    data class Error(val message: String, val statusCode: Int) : ApiResponse<Nothing>
    data class Redirect(val url: String, val statusCode: Int = 302) : ApiResponse<Nothing>
}

sealed interface ValidationResult {
    data object Valid : ValidationResult
    data class Invalid(val errors: List<String>) : ValidationResult
}
```

### Composition: delegation with `by`

```kotlin
interface Logger { fun log(message: String); fun error(message: String) }

// `by logger` auto-generates all forwarding methods
class UserService(logger: Logger) : Logger by logger {
    fun createUser(name: String) {
        log("Creating: $name")   // calls logger.log()
    }
    override fun error(message: String) {
        System.err.println("!!! $message")
    }
}

// Multi-interface delegation
class CachedUserService(cache: Cache, metrics: Metrics)
    : Cache by cache, Metrics by metrics
```

`by` generates forwarding at compile time. Go embedding promotes methods but isn't true delegation. TS requires manual forwarding.

## Generics deep dive

### Basic generics

```kotlin
class Box<T>(private val value: T) {
    fun get(): T = value
    fun <U> map(transform: (T) -> U): Box<U> = Box(transform(value))
}

val stringBox = Box("hello")
val lengthBox = stringBox.map { it.length }   // Box<Int>
```

Go generics can't have type parameters on methods — you must use top-level functions.

### Variance: `out` and `in`

Should `List<Dog>` be assignable to `List<Animal>`? Read-only: yes. Mutable: no.

```kotlin
interface Producer<out T> {           // covariant — T only in out position
    fun produce(): T
}

interface Consumer<in T> {            // contravariant — T only in in position
    fun consume(item: T)
}

// invariant (default): MutableBox<T> with both get() and set()

val dogProducer: Producer<Dog> = ...
val animalProducer: Producer<Animal> = dogProducer   // OK — out T

val animalConsumer: Consumer<Animal> = ...
val dogConsumer: Consumer<Dog> = animalConsumer      // OK — in T
```

Built-in collections use variance: `List<out E>` is covariant (read-only), `MutableList<E>` is invariant.

```kotlin
val dogs: List<Dog> = listOf(Dog("Rex"))
val animals: List<Animal> = dogs        // OK — List is covariant

val mutableDogs: MutableList<Dog> = mutableListOf()
// val x: MutableList<Animal> = mutableDogs  // COMPILE ERROR — invariant
```

Kotlin uses declaration-site variance (declared once on the type). TS arrays are unsoundly covariant. Go has no variance at all.

### Use-site variance (type projections)

```kotlin
fun copy(from: Array<out Animal>, to: Array<Animal>) {   // read-only from
    for (i in from.indices) to[i] = from[i]
}

fun addAll(to: Array<in Dog>, dogs: List<Dog>) {         // write-only to
    for (dog in dogs) to[dogs.indexOf(dog)] = dog
}
```

### Type bounds

```kotlin
fun <T : Comparable<T>> max(a: T, b: T): T = if (a >= b) a else b

fun <T> sort(list: List<T>): List<T>
    where T : Comparable<T>,
          T : Serializable {          // multiple bounds with `where`
    return list.sorted()
}
```

### Star projection `<*>`

"I don't know the type argument" — like TS `unknown`, Java `<?>`.

```kotlin
fun printBox(box: Box<*>) {
    val value: Any? = box.get()    // safe but loses type info
}
// Producer<out T> -> Producer<*> = Producer<out Any?>  (can read Any?)
// Consumer<in T>  -> Consumer<*> = Consumer<in Nothing> (cannot write)
```

### Reified type parameters

JVM erases generics at runtime — unless you use `reified` with `inline`:

```kotlin
inline fun <reified T> isType(value: Any): Boolean = value is T

inline fun <reified T> List<Any>.filterByType(): List<T> = filterIsInstance<T>()

println(isType<String>("hello"))   // true
```

Practical use — type-safe service locator, no `Class<T>` tokens:

```kotlin
class ServiceLocator {
    private val services = mutableMapOf<String, Any>()

    inline fun <reified T : Any> register(service: T) {
        services[T::class.qualifiedName!!] = service
    }

    inline fun <reified T : Any> get(): T {
        val key = T::class.qualifiedName!!
        return services[key] as? T
            ?: throw IllegalStateException("Service not found: $key")
    }
}

val locator = ServiceLocator()
locator.register<UserRepository>(InMemoryUserRepository())
val repo = locator.get<UserRepository>()   // no Class<T>, no string keys
```

`reified` only works with `inline` functions — the compiler substitutes the actual type at each call site.

### Type erasure

At runtime, `List<String>` and `List<Int>` are both just `List`. You cannot do `if (strings is List<String>)`. Escape hatches: `reified`, pass `KClass<T>`, or check elements not containers.

## Java interop

### Platform types (`T!`)

Java code has no nullability annotations, so Kotlin sees return types as platform types (`String!`). Treat them as nullable unless annotated.

```kotlin
// Java: public String findUserName(String id) { return users.get(id); }  // can return null
val name: String? = service.findUserName("u1")   // SAFE — treat as nullable
val names: List<String?> = service.getAllNames()
names.filterNotNull()
```

:::caution[Always treat Java returns as nullable]
Assigning a real null into a non-null `String` throws at runtime. Default to `String?` unless the Java is annotated `@NotNull`.
:::

### `@Jvm` annotations for Java callers

| Annotation | Purpose | Without it (from Java) |
|---|---|---|
| `@JvmStatic` | Companion member as real static | `Foo.Companion.method()` |
| `@JvmField` | Property as public field | `Foo.Companion.getPROP()` |
| `@JvmOverloads` | Overloads for default params | Must pass all params |
| `@JvmName` | Change generated name | Uses Kotlin-generated name |
| `@file:JvmName` | Change filename class name | `FileNameKt.function()` |
| `@Throws` | Declare checked exceptions | Java can't catch them |

```kotlin
class UserService(val defaultRole: String = "viewer") {
    companion object {
        @JvmStatic fun create(name: String): UserService = UserService()
        @JvmField val MAX_USERS = 1000
    }
    @JvmOverloads
    fun greet(name: String, greeting: String = "Hello", punctuation: String = "!") =
        "$greeting, $name$punctuation"
}

@Throws(java.io.IOException::class)
fun readFile(path: String): String = java.io.File(path).readText()
```

### Key Java classes

**`BigDecimal`** — never use `Double` for money. Build from String, not Double.

```kotlin
val price = BigDecimal("19.99")
val total = price * BigDecimal("3") + price * BigDecimal("0.08")  // operator overloading
// Note: BigDecimal("1.0") == BigDecimal("1.00") is FALSE (scale differs)
// Use a.compareTo(b) == 0 for numeric equality
```

**`java.time`** — the modern date/time API (JSR-310).

```kotlin
val now = Instant.now()
val today = LocalDate.now()
val date = LocalDate.parse("2024-03-15")
val nextWeek = today.plusWeeks(1)
val daysBetween = ChronoUnit.DAYS.between(date, today)
val formatted = date.format(DateTimeFormatter.ofPattern("MMMM d, yyyy"))
```

**`Optional`** — convert to Kotlin nullable at the boundary:

```kotlin
val name: String? = javaStyleFind("u1").orElse(null)   // collapse Optional immediately
```

### SAM conversions

Java functional interfaces (single abstract method) accept Kotlin lambdas:

```kotlin
val runnable = Runnable { println("Running") }
executor.submit(Callable { "result" })
names.sortWith { a, b -> a.length - b.length }   // Comparator SAM

// Kotlin's own fun interface (Kotlin 1.4+)
fun interface Predicate<T> { fun test(value: T): Boolean }
```

### Working with Java libraries

Jackson, Guava, Apache Commons all work seamlessly:

```kotlin
// Jackson (Spring Boot's default)
val mapper = jacksonObjectMapper()
val json = mapper.writeValueAsString(user)
val parsed: ApiUser = mapper.readValue(json)   // reified, no TypeReference

// Guava
val parts = Splitter.on(",").trimResults().omitEmptyStrings().splitToList("a, b, c")

// Dependencies:
// implementation("com.fasterxml.jackson.module:jackson-module-kotlin:2.17.0")
// implementation("com.google.guava:guava:33.1.0-jre")
// implementation("org.apache.commons:commons-lang3:3.14.0")
```

:::caution[Immutability is compile-time only]
Kotlin's `List<T>` is a compile-time restriction. At runtime, a Java reference to the same object could mutate it. For true immutability use `kotlinx.collections.immutable` or defensive copying.
:::

## Design patterns in Kotlin

| Pattern | Kotlin idiom |
|---|---|
| Singleton | `object Database { }` — thread-safe, lazy, zero boilerplate |
| Factory | `companion object { fun createLocal() = ... }` |
| Builder | `HttpRequest().apply { url = "..." }` — no builder class needed |
| Strategy | `typealias PricingStrategy = (Double, Int) -> Double` — just a function type |
| Observer | `var name by Delegates.observable("") { _, old, new -> ... }` |
| Decorator | `class LoggingClient(client: HttpClient) : HttpClient by client { override fun get(...) }` |

Decorator with `by` — stack them:

```kotlin
class LoggingHttpClient(private val client: HttpClient) : HttpClient by client {
    override fun get(url: String): String {
        println("[LOG] GET $url")
        return client.get(url)
    }
    // delete() auto-forwarded — no boilerplate
}

val client: HttpClient = LoggingHttpClient(RetryHttpClient(BasicHttpClient()))
```
