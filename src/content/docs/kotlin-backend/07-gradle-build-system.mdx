Gradle fills the gap npm/go-mod leave for JVM projects: compilation, complex classpaths, multi-module monorepos, build variants. Build files are executable Kotlin scripts, not just config.

## Mental model: npm / go mod / Gradle

| Concept | npm (TS) | go mod (Go) | Gradle (Kotlin) |
|---|---|---|---|
| Project manifest | `package.json` | `go.mod` | `build.gradle.kts` |
| Lock file | `package-lock.json` | `go.sum` | `gradle.lockfile` (opt-in) |
| Install deps | `npm install` | `go mod download` | `./gradlew build` (auto) |
| Run scripts | `npm run dev` | `go run .` | `./gradlew run` |
| Test | `npm test` | `go test ./...` | `./gradlew test` |
| Workspaces/modules | npm workspaces | Go workspace | Multi-module project |
| Registry | npmjs.com | proxy.golang.org | Maven Central / Google |
| Dev dependencies | `devDependencies` | N/A | `testImplementation` |
| Build output | `dist/` | binary in `$GOPATH` | `build/` |

:::note[Key insight]
`package.json` is declarative data. `build.gradle.kts` is an **executable Kotlin script** — you can use `if/else`, loops, functions.
:::

## Project structure

<FileTree>
- my-app/
  - **build.gradle.kts** build configuration
  - settings.gradle.kts project name + module declarations
  - gradle.properties build properties
  - gradle/
    - wrapper/ gradle-wrapper.jar + .properties
    - libs.versions.toml version catalog
  - gradlew / gradlew.bat wrapper scripts
  - src/
    - main/kotlin/com/example/App.kt
    - main/resources/application.yml
    - test/kotlin/com/example/AppTest.kt
</FileTree>

Dependencies live in `~/.gradle/caches/` (global cache) — never copied into your project, no `node_modules` to accidentally commit.

## build.gradle.kts in depth

```kotlin title="build.gradle.kts"
plugins {
    kotlin("jvm") version "2.1.0"       // Kotlin compiler plugin
    application                           // enables `./gradlew run`
}

group = "com.example"
version = "1.0.0"

repositories {
    mavenCentral()                        // like npmjs.com
}

dependencies {
    implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.9.0")
    testImplementation(kotlin("test"))
}

kotlin {
    jvmToolchain(21)                      // target JDK 21
}

application {
    mainClass.set("com.example.AppKt")
}

tasks.test {
    useJUnitPlatform()
}
```

### Dependencies

| Gradle | npm | Go | When |
|---|---|---|---|
| `implementation` | `dependencies` | `require` | Code calls directly |
| `api` | `peerDependencies` | N/A | Type exposed in public API (library modules) |
| `testImplementation` | `devDependencies` | test imports | Test only |
| `runtimeOnly` | — | — | Runtime only (drivers) |
| `compileOnly` | `@types/*` | — | Compile only |

Coordinate format: `group:artifact:version` — like `org.jetbrains.kotlinx:kotlinx-coroutines-core:1.9.0` (group like npm scope, artifact like package name). Find them on [search.maven.org](https://search.maven.org).

```kotlin
// Exclusions (like npm overrides)
implementation("some.library:core:1.0") {
    exclude(group = "commons-logging", module = "commons-logging")
}

// Force a version (like npm overrides)
configurations.all {
    resolutionStrategy {
        force("com.google.guava:guava:33.4.0-jre")
        failOnVersionConflict()
    }
}

// BOM — locks a set of related deps (like a framework's curated package.json)
implementation(platform("org.springframework.boot:spring-boot-dependencies:3.4.1"))
implementation("org.springframework.boot:spring-boot-starter-web")  // version from BOM
```

```bash
./gradlew dependencies                                    # like npm ls
./gradlew dependencies --configuration runtimeClasspath
./gradlew dependencyInsight --dependency kotlin-stdlib   # like npm why
```

## Version catalogs

`gradle/libs.versions.toml` centralizes every version — one source of truth, type-safe accessors.

```toml title="gradle/libs.versions.toml"
[versions]
kotlin = "2.1.0"
coroutines = "1.9.0"
ktor = "3.0.3"
spring-boot = "3.4.1"

[libraries]
kotlinx-coroutines-core = { group = "org.jetbrains.kotlinx", name = "kotlinx-coroutines-core", version.ref = "coroutines" }
ktor-server-core = { group = "io.ktor", name = "ktor-server-core", version.ref = "ktor" }
spring-boot-starter-web = { group = "org.springframework.boot", name = "spring-boot-starter-web", version.ref = "spring-boot" }

[bundles]
ktor-server = ["ktor-server-core", "ktor-server-netty", "ktor-server-content-negotiation"]

[plugins]
kotlin-jvm = { id = "org.jetbrains.kotlin.jvm", version.ref = "kotlin" }
ktor = { id = "io.ktor.plugin", version.ref = "ktor" }
```

```kotlin title="build.gradle.kts"
plugins {
    alias(libs.plugins.kotlin.jvm)
    alias(libs.plugins.ktor)
}

dependencies {
    implementation(libs.kotlinx.coroutines.core)
    implementation(libs.bundles.ktor.server)
}
```

:::note[Accessor names]
TOML key `ktor-server-core` → Kotlin accessor `libs.ktor.server.core`: dashes/underscores become dots.
:::

## Multi-module projects

Use when you have shared library code, separate API/impl modules, or need to enforce architectural boundaries.

<FileTree>
- my-platform/
  - settings.gradle.kts declares all modules
  - build.gradle.kts root: shared config for all modules
  - gradle/libs.versions.toml shared catalog
  - common/ shared library
  - api-models/ shared DTOs
  - service-users/ microservice 1
  - service-orders/ microservice 2
</FileTree>

```kotlin title="settings.gradle.kts"
rootProject.name = "my-platform"

include("common")
include("api-models")
include("service-users")
include("service-orders")
```

Root build shares config via `subprojects { }` — `apply false` declares the plugin version without applying to root:

```kotlin title="build.gradle.kts (root)"
plugins {
    kotlin("jvm") version "2.1.0" apply false
}

subprojects {
    apply(plugin = "org.jetbrains.kotlin.jvm")

    group = "com.example.platform"
    version = "1.0.0"

    repositories { mavenCentral() }

    configure<org.jetbrains.kotlin.gradle.dsl.KotlinJvmProjectExtension> {
        jvmToolchain(21)
    }

    tasks.withType<Test> { useJUnitPlatform() }
}
```

```kotlin title="service-users/build.gradle.kts"
plugins {
    kotlin("jvm")           // no version — pinned at root
    application
}

dependencies {
    implementation(project(":common"))         // sibling module — like a workspace package
    implementation(project(":api-models"))
    implementation("io.ktor:ktor-server-netty:3.0.3")
    testImplementation(kotlin("test"))
}

application {
    mainClass.set("com.example.users.AppKt")
}
```

`allprojects { }` = root + all modules. `subprojects { }` = modules only, not root.

For large projects, use `buildSrc` with convention plugins to avoid duplicating build logic:

```kotlin title="buildSrc/src/main/kotlin/kotlin-conventions.gradle.kts"
plugins { kotlin("jvm") }

group = "com.example.platform"
version = "1.0.0"
repositories { mavenCentral() }
kotlin { jvmToolchain(21) }
tasks.test { useJUnitPlatform() }
```

```kotlin title="service-users/build.gradle.kts"
plugins {
    id("kotlin-conventions")
    application
}
```

## Custom tasks

Tasks are Gradle's unit of work — the npm equivalent is `package.json` scripts, the Go equivalent is Makefile targets.

```bash
./gradlew tasks          # list tasks
./gradlew tasks --all
```

```kotlin title="build.gradle.kts"
// Simple task
tasks.register("hello") {
    group = "custom"
    description = "Prints a greeting"
    doLast {                            // doLast = execution phase
        println("Hello from Gradle!")
    }
}

// doFirst vs doLast: code directly in the block runs during CONFIGURATION.
// Always defer real work into doFirst/doLast.
tasks.register("lifecycle") {
    println("This runs during configuration!")   // every time, even for ./gradlew help
    doFirst { println("First action") }
    doLast { println("Last action") }
}

// Task dependencies
tasks.register("publishDocs") {
    dependsOn("generateDocs")
    doLast { println("Publishing...") }
}

// Typed tasks
tasks.register<Copy>("copyConfigs") {
    from("src/main/resources")
    into("build/configs")
    include("*.yml", "*.properties")
}

tasks.register<Delete>("cleanLogs") { delete("logs/") }

tasks.register<Exec>("dockerBuild") {
    commandLine("docker", "build", "-t", "my-app:latest", ".")
}

tasks.register<Zip>("packageApp") {
    from("build/libs")
    archiveFileName.set("my-app-${project.version}.zip")
}

// Hook into existing tasks
tasks.test {
    doFirst { println("Setting up test env...") }
    doLast { println("Cleaning up...") }
}

tasks.build {
    dependsOn("generateDocs")
}

// Practical: database migration task
tasks.register<Exec>("dbMigrate") {
    group = "database"
    commandLine(
        "docker", "exec", "kotlin-course-postgres",
        "psql", "-U", "dev", "-d", "kotlin_course",
        "-f", "/migrations/migrate.sql"
    )
}
```

## Build lifecycle

<Mermaid title="Gradle build lifecycle" height={360} code={`
flowchart LR
  I["1. INIT<br/>Which projects?<br/>Read settings.gradle.kts"] --> C["2. CONFIGURATION<br/>Configure all tasks<br/>(even ones you won't run)"]
  C --> E["3. EXECUTION<br/>Run requested tasks only"]
`} />

<Steps>

1. **Initialization** — reads `settings.gradle.kts`, determines projects, creates `Project` instances.

2. **Configuration** — executes ALL `build.gradle.kts` files, creates and configures ALL tasks, builds the task graph. Most build-script code runs here.

3. **Execution** — runs only requested tasks and their dependencies. `doFirst {}`/`doLast {}` execute here.

</Steps>

:::caution[Common mistake: work during configuration]
Code directly in a task block runs during configuration — every time, even for `./gradlew help`. Defer real work into `doLast { }`.

```kotlin
// BAD: runs during configuration
tasks.register("deploy") {
    val version = Runtime.getRuntime().exec("git describe --tags")...  // WRONG
}

// GOOD: defer to execution
tasks.register("deploy") {
    doLast {
        val version = providers.exec { commandLine("git", "describe", "--tags") }
            .standardOutput.asText.get().trim()
    }
}
```
:::

## The Gradle wrapper

`gradlew` downloads and runs the exact Gradle version the project needs — always use `./gradlew`, never global `gradle`. Commit these to git:

<FileTree>
- gradle/wrapper/gradle-wrapper.jar (~60KB bootstrap)
- gradle/wrapper/gradle-wrapper.properties (version config)
- gradlew
- gradlew.bat
</FileTree>

```properties title="gradle/wrapper/gradle-wrapper.properties"
distributionUrl=https\://services.gradle.org/distributions/gradle-8.12-bin.zip
networkTimeout=10000
validateDistributionUrl=true
```

```bash
./gradlew wrapper --gradle-version 8.12
./gradlew wrapper --gradle-version latest
```

## Common commands

```bash
# Everyday
./gradlew build                    # compile + test + package
./gradlew run                      # run the app
./gradlew test                     # tests
./gradlew clean                    # remove build outputs
./gradlew test --tests "com.example.UserServiceTest"
./gradlew build --continuous       # watch mode (like nodemon)
./gradlew -t build                 # shorthand

# Dependencies
./gradlew dependencies
./gradlew dependencies --configuration runtimeClasspath
./gradlew dependencyInsight --dependency kotlin-stdlib

# Project info
./gradlew tasks --all
./gradlew properties
./gradlew projects

# Multi-module
./gradlew :service-users:build
./gradlew :service-users:run
./gradlew :common:test

# Performance
./gradlew build --scan             # build scan
./gradlew build --parallel
./gradlew build -Dorg.gradle.jvmargs="-Xmx4g"
./gradlew build --build-cache
```

| Task | Gradle | npm | Go |
|---|---|---|---|
| Build | `./gradlew build` | `npm run build` | `go build ./...` |
| Run | `./gradlew run` | `npm start` | `go run .` |
| Test | `./gradlew test` | `npm test` | `go test ./...` |
| Clean | `./gradlew clean` | `rm -rf dist/` | `go clean` |
| Dep tree | `./gradlew dependencies` | `npm ls` | `go mod graph` |
| Watch | `./gradlew -t build` | `nodemon` | N/A |
| Format | `./gradlew ktlintFormat` | `prettier --write .` | `go fmt ./...` |
| Lint | `./gradlew ktlintCheck` | `eslint .` | `go vet ./...` |

## Plugins

```kotlin
plugins {
    application                         // core plugin
    `java-library`
    kotlin("jvm") version "2.1.0"       // community plugin with version
    alias(libs.plugins.kotlin.jvm)      // from version catalog
    id("io.ktor.plugin") version "3.0.3"
}
```

| Plugin | Purpose | npm equivalent |
|---|---|---|
| `kotlin("jvm")` | Compile Kotlin | `typescript` |
| `application` | Run as app, create dist | start script |
| `kotlin("plugin.serialization")` | kotlinx.serialization | built into JSON.parse |
| `kotlin("plugin.spring")` | Open classes for Spring | classes open by default in TS |
| `id("org.springframework.boot")` | Spring Boot packaging | N/A |
| `id("io.ktor.plugin")` | Ktor fat JAR, Docker | N/A |
| `id("com.google.devtools.ksp")` | Kotlin Symbol Processing | Babel plugins |
| `id("com.gradleup.shadow")` | Fat JAR (`./gradlew shadowJar`) | `pkg` / `webpack` |
| `id("org.jlleitschuh.gradle.ktlint")` | Lint + format | `eslint` / `prettier` |

## gradle.properties

```properties title="gradle.properties"
org.gradle.jvmargs=-Xmx2g -XX:+UseParallelGC
org.gradle.parallel=true
org.gradle.caching=true
org.gradle.configuration-cache=true
kotlin.code.style=official
myapp.version=1.0.0
```

```kotlin
// Read project properties
val myVersion: String by project
val dbUrl = findProperty("db.url")?.toString() ?: "jdbc:postgresql://localhost:5432/dev"
val env = findProperty("env")?.toString() ?: "development"
```

```bash
./gradlew build -PmyProp=value       # project property (-P) → project.findProperty()
./gradlew build -Dmy.system.prop=value  # system property (-D) → System.getProperty()
./gradlew run -Pdb.url=jdbc:postgresql://prod-host:5432/mydb
```

## Troubleshooting

| Problem | Fix |
|---|---|
| "Could not resolve dependency" | Declare the right repository: `mavenCentral()`, `google()`, `maven("https://jitpack.io")` |
| "Unresolved reference" after adding dep | IDE hasn't synced — click Gradle elephant icon or run `./gradlew build` |
| Build cache issues | `./gradlew clean`, `rm -rf ~/.gradle/caches/`, `rm -rf .gradle/`, or `./gradlew clean build --no-build-cache` |
| Daemon OOM | `org.gradle.jvmargs=-Xmx4g -XX:+HeapDumpOnOutOfMemoryError` |
| Version conflicts | `./gradlew dependencies --configuration runtimeClasspath \| grep -i "FAILED\|CONFLICT"` then `./gradlew dependencyInsight --dependency <lib>` |
| Slow builds | Enable `org.gradle.parallel=true`, `org.gradle.caching=true`, `org.gradle.configuration-cache=true`; run `./gradlew build --scan` |
