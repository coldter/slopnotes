Run Keycloak as the identity provider and wire Spring Boot as an OAuth2 **resource server** — validate the JWTs Keycloak issues. The API never sees a password or signing key; it fetches the issuer's public keys (JWKS) to verify signatures.

## What you'll build

<Steps>

1. A Keycloak instance (Docker) with a realm, client, roles, and a test user.
2. A Spring Boot resource server pointed at Keycloak's `issuer-uri` — Spring auto-discovers the JWKS endpoint.
3. A converter mapping Keycloak's `realm_access.roles` claim to `ROLE_*` authorities.
4. Three endpoints: public health, authenticated profile, admin-only via `@PreAuthorize`.

</Steps>

## How the flow works

### application.yml — one line of JWT config

Spring takes the `issuer-uri`, hits `{issuer}/.well-known/openid-configuration`, discovers the JWKS endpoint, and caches the public keys. It also enforces that every token's `iss` claim matches.

```yaml title="src/main/resources/application.yml" {7}
spring:
  application:
    name: oauth2-keycloak-demo
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: http://localhost:8180/realms/task-app

server:
  port: 8080
```

### KeycloakRoleConverter.kt

Keycloak puts realm roles in a nested `realm_access.roles` claim. Spring's default converter looks at `scope`/`scp` instead, so write a custom one:

```kotlin title="src/main/kotlin/com/example/oauth2/config/KeycloakRoleConverter.kt" {10-18}
package com.example.oauth2.config

import org.springframework.core.convert.converter.Converter
import org.springframework.security.core.GrantedAuthority
import org.springframework.security.core.authority.SimpleGrantedAuthority
import org.springframework.security.oauth2.jwt.Jwt

class KeycloakRoleConverter : Converter<Jwt, Collection<GrantedAuthority>> {

    override fun convert(jwt: Jwt): Collection<GrantedAuthority> {
        val realmAccess = jwt.getClaimAsMap("realm_access") ?: return emptyList()
        @Suppress("UNCHECKED_CAST")
        val roles = realmAccess["roles"] as? List<String> ?: return emptyList()
        return roles.map { SimpleGrantedAuthority("ROLE_${it.uppercase()}") }
    }
}
```

Kotlin idioms here: `?:` (Elvis) does null-guard-and-early-return in one line; `as?` is a safe cast that yields `null` instead of throwing; `"ROLE_${it.uppercase()}"` is a string template — `ROLE_` is the prefix `hasRole("ADMIN")` expects.

### SecurityConfig.kt

```kotlin title="src/main/kotlin/com/example/oauth2/config/SecurityConfig.kt" {12-14,22-26,28-32}
package com.example.oauth2.config

import org.springframework.context.annotation.Bean
import org.springframework.context.annotation.Configuration
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity
import org.springframework.security.config.annotation.web.builders.HttpSecurity
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity
import org.springframework.security.config.annotation.web.invoke
import org.springframework.security.oauth2.server.resource.authentication.JwtAuthenticationConverter
import org.springframework.security.web.SecurityFilterChain

@Configuration
@EnableWebSecurity
@EnableMethodSecurity
class SecurityConfig {

    @Bean
    fun securityFilterChain(http: HttpSecurity): SecurityFilterChain {
        http {
            csrf { disable() }

            authorizeHttpRequests {
                authorize("/api/public/**", permitAll)
                authorize("/api/admin/**", hasRole("ADMIN"))
                authorize("/api/**", authenticated)
            }

            oauth2ResourceServer {
                jwt { jwtAuthenticationConverter = jwtAuthenticationConverter() }
            }
        }
        return http.build()
    }

    private fun jwtAuthenticationConverter(): JwtAuthenticationConverter {
        return JwtAuthenticationConverter().apply {
            setJwtGrantedAuthoritiesConverter(KeycloakRoleConverter())
        }
    }
}
```

:::note[Rule ordering matters]
`authorizeHttpRequests` rules match top-down, first-match-wins. `/api/admin/**` (needs `ADMIN`) must come *before* the catch-all `/api/**`.
:::

### ProfileController.kt

`@AuthenticationPrincipal jwt: Jwt` injects the validated token. The admin route is double-guarded — URL rule + `@PreAuthorize`.

```kotlin title="src/main/kotlin/com/example/oauth2/controller/ProfileController.kt" {14-24,26-30,32-35}
package com.example.oauth2.controller

import org.springframework.security.access.prepost.PreAuthorize
import org.springframework.security.core.annotation.AuthenticationPrincipal
import org.springframework.security.oauth2.jwt.Jwt
import org.springframework.web.bind.annotation.GetMapping
import org.springframework.web.bind.annotation.RequestMapping
import org.springframework.web.bind.annotation.RestController

@RestController
@RequestMapping("/api")
class ProfileController {

    @GetMapping("/profile")
    fun getProfile(@AuthenticationPrincipal jwt: Jwt): Map<String, Any?> = mapOf(
        "sub" to jwt.subject,
        "email" to jwt.getClaimAsString("email"),
        "name" to jwt.getClaimAsString("preferred_username"),
        "roles" to extractRoles(jwt),
        "issued_at" to jwt.issuedAt,
        "expires_at" to jwt.expiresAt,
    )

    @GetMapping("/admin/users")
    @PreAuthorize("hasRole('ADMIN')")
    fun adminOnly(): Map<String, String> = mapOf("message" to "You have admin access")

    @GetMapping("/public/health")
    fun healthCheck(): Map<String, String> = mapOf("status" to "ok")

    private fun extractRoles(jwt: Jwt): List<String> {
        val realmAccess = jwt.getClaimAsMap("realm_access") ?: return emptyList()
        @Suppress("UNCHECKED_CAST")
        return realmAccess["roles"] as? List<String> ?: emptyList()
    }
}
```

### The test — auth without a live Keycloak

`@WithMockUser` fakes authorities so tests verify authorization rules without Keycloak. `401` = not authenticated (no/invalid token); `403` = authenticated but not allowed.

```kotlin title="src/test/kotlin/com/example/oauth2/OAuth2SecurityTest.kt" {17-24,32-40,42-47}
package com.example.oauth2

import org.springframework.beans.factory.annotation.Autowired
import org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc
import org.springframework.boot.test.context.SpringBootTest
import org.springframework.security.test.context.support.WithMockUser
import org.springframework.test.web.servlet.MockMvc
import org.springframework.test.web.servlet.get
import kotlin.test.Test

@SpringBootTest
@AutoConfigureMockMvc
class OAuth2SecurityTest {

    @Autowired lateinit var mockMvc: MockMvc

    @Test
    fun `public endpoint is accessible without auth`() {
        mockMvc.get("/api/public/health").andExpect {
            status { isOk() }
            jsonPath("$.status") { value("ok") }
        }
    }

    @Test
    fun `protected endpoint returns 401 without auth`() {
        mockMvc.get("/api/profile").andExpect { status { isUnauthorized() } }
    }

    @Test
    @WithMockUser(username = "admin", roles = ["ADMIN"])
    fun `admin endpoint accessible with ADMIN role`() {
        mockMvc.get("/api/admin/users").andExpect {
            status { isOk() }
            jsonPath("$.message") { value("You have admin access") }
        }
    }

    @Test
    @WithMockUser(username = "user", roles = ["USER"])
    fun `admin endpoint returns 403 for non-admin`() {
        mockMvc.get("/api/admin/users").andExpect { status { isForbidden() } }
    }
}
```

## Set up Keycloak

<Steps>

1. Start Keycloak (admin console at `http://localhost:8180`, login `admin`/`admin`):

   ```bash
   docker compose up -d
   ```

2. **Create the realm**: "Create Realm" → Name: `task-app`.

3. **Create the client**: Clients → Create.
   - Client ID: `task-api`
   - Client authentication: **ON** (confidential client — you'll need its secret for the token request)

4. **Create realm roles**: Realm roles → Create — add `USER` and `ADMIN`.

5. **Create a user**: Users → Add user.
   - Username: `testuser`, Email: `test@example.com`
   - Credentials tab → set password `password123` (Temporary: **OFF**)
   - Role Mapping tab → assign `USER`

</Steps>

:::note
The realm name `task-app` must match the path in `application.yml`'s `issuer-uri` (`/realms/task-app`). Change one and you must change the other, or token validation fails with an issuer mismatch.
:::

## Run and test

<Steps>

1. Start the resource server (Keycloak must already be up):

   ```bash
   ./gradlew bootRun
   ```

2. Grab a token (Resource Owner Password grant — local testing only). Get the client secret from the Keycloak client's Credentials tab:

   ```bash
   TOKEN=$(curl -s -X POST http://localhost:8180/realms/task-app/protocol/openid-connect/token \
     -H "Content-Type: application/x-www-form-urlencoded" \
     -d "grant_type=password" \
     -d "client_id=task-api" \
     -d "client_secret=<your-client-secret>" \
     -d "username=testuser" \
     -d "password=password123" | jq -r '.access_token')
   ```

3. Hit the endpoints — public works with no token; profile needs the bearer; admin returns `403` for `testuser` (only `USER`):

   ```bash
   curl http://localhost:8080/api/public/health
   curl http://localhost:8080/api/profile -H "Authorization: Bearer $TOKEN"
   curl http://localhost:8080/api/admin/users -H "Authorization: Bearer $TOKEN"
   ```

4. Run the (Keycloak-free) authorization tests:

   ```bash
   ./gradlew test
   ```

5. Tear it down:

   ```bash
   docker compose down -v
   ```

</Steps>

## What to take away

- Spring validates JWTs from an external IdP off a single `issuer-uri` — it discovers the JWKS endpoint and caches the public keys.
- Keycloak realm roles arrive in a nested `realm_access.roles` claim; a small `Converter` maps them to `ROLE_*` authorities.
- `@PreAuthorize` and URL-based rules both read those authorities — use either or both.
- Self-issued JWTs are verified with a shared secret you hold; IdP-issued JWTs are verified with the issuer's public keys, and your app never handles a credential or signing key.

:::tip[Stretch goals]
- Add an `ADMIN` user (or assign `ADMIN` to `testuser`) and confirm the admin endpoint returns `200`.
- Import the realm from JSON (`--import-realm`) so the whole setup is reproducible.
- Map Keycloak *client* roles (`resource_access.<client>.roles`) in addition to realm roles.
- Switch to the authorization-code flow with a real browser login instead of the password grant.
