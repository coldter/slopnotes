## Kafka core concepts

<Mermaid title="Producer → topic (partitions) → consumer group — partitions divide among consumers" code={`

| Concept | Description |
|---|---|
| **Topic** | Named stream of messages |
| **Partition** | Ordered, immutable sequence within a topic — ordering is per-partition |
| **Offset** | Position within a partition (monotonically increasing) |
| **Consumer Group** | Set of consumers; each partition goes to exactly one consumer |
| **Key** | Messages with the same key go to the same partition (ordering guarantee) |
| **Broker** | Kafka server node |

### When to use what

| Use Case | Tool | Why |
|---|---|---|
| Fire-and-forget notifications | Redis Pub/Sub | Simplest, lowest latency |
| Task queue (process once) | RabbitMQ / Redis Streams | Built-in ack, simpler ops |
| Event sourcing, audit log | **Kafka** | Persistent, replayable, ordered |
| Data pipeline between services | **Kafka** | Decouples producers from consumers |
| Real-time analytics | **Kafka** | High throughput, consumer groups |
| Request/reply RPC | HTTP or gRPC | Kafka is not for request/reply |

```kotlin title="src/main/kotlin/com/example/config/KafkaTopicConfig.kt"
    @Bean
    fun orderEventsTopic(): NewTopic = TopicBuilder
        .name("order-events")
        .partitions(6)
        .replicas(1)

    fun deadLetterTopic(): NewTopic = TopicBuilder
```

```kotlin
import org.springframework.kafka.core.KafkaTemplate
import org.springframework.stereotype.Service

data class OrderEvent(
    val orderId: String,
    val userId: Long,
    val amount: Double,
    val status: String,
    val timestamp: Instant = Instant.now()
)

@Service
class OrderProducer(private val kafkaTemplate: KafkaTemplate<String, Any>) {

    // Fire and forget (internal retries)
    fun sendOrder(event: OrderEvent) {
        kafkaTemplate.send("orders", event.orderId, event)
    }

    // Async with callback
    fun sendOrderAsync(event: OrderEvent) {
        val future = kafkaTemplate.send("orders", event.orderId, event)
        future.whenComplete { result, ex ->
            if (ex != null) println("Failed to send: ${ex.message}")
            else {
                val md = result.recordMetadata
                println("Sent to ${md.topic()}-${md.partition()} @ offset ${md.offset()}")
            }
        }
    }

    // Blocking
    fun sendOrderSync(event: OrderEvent) {
        val result = kafkaTemplate.send("orders", event.orderId, event).get()
        val md = result.recordMetadata
        println("Sent to ${md.topic()}-${md.partition()} @ offset ${md.offset()}")
    }

    // Specific partition
    fun sendToPartition(event: OrderEvent, partition: Int) {
        kafkaTemplate.send("orders", partition, event.orderId, event)
    }

    // With headers
    fun sendWithHeaders(event: OrderEvent) {
        val record = org.apache.kafka.clients.producer.ProducerRecord<String, Any>(
            "orders", null, event.orderId, event
        )
        record.headers().add("event-type", "ORDER_CREATED".toByteArray())
        record.headers().add("source", "order-service".toByteArray())
        kafkaTemplate.send(record)
    }
}
```

### Key strategy

The key determines the partition — same key = same partition = ordered.

| Key Strategy | Ordering Guarantee | Use Case |
|---|---|---|
| Entity ID (e.g. `orderId`) | All events for same entity ordered | Order lifecycle, user actions |
| No key (null) | Round-robin, no ordering | Metrics, logs, independent events |
| Composite key (`userId:action`) | Grouped ordering | User-action streams |

```kotlin
@Service
class EventProducer(private val kafkaTemplate: KafkaTemplate<String, Any>) {

    fun sendOrderEvent(orderId: String, event: Any) {
        kafkaTemplate.send("order-events", orderId, event)  // same orderId → same partition
    }

    fun sendUserEvent(userId: String, event: Any) {
        kafkaTemplate.send("user-events", userId, event)
    }

    fun sendMetricEvent(event: Any) {
        kafkaTemplate.send("metrics", event)  // no key → round-robin
    }
}
```

### Concurrency

```kotlin
@Component
class ConcurrentConsumer {

    // 3 consumer threads — each gets a subset of partitions
    @KafkaListener(topics = ["orders"], groupId = "concurrent-processor", concurrency = "3")
    fun process(event: OrderEvent) {
        println("[${Thread.currentThread().name}] Processing: ${event.orderId}")
    }
}
```

Rules: `concurrency = N` creates N threads. Each gets `total partitions / N` partitions max. Excess threads idle. 6 partitions + concurrency 3 = 2 partitions per thread.

### Multi-type topics: sealed class + `when`

```kotlin
sealed class OrderDomainEvent {
    abstract val orderId: String
    abstract val timestamp: Instant
}

data class OrderCreated(
    override val orderId: String,
    val userId: Long,
    val amount: Double,
    override val timestamp: Instant = Instant.now()

data class OrderPaid(
    override val orderId: String,
    val paymentId: String,
    override val timestamp: Instant = Instant.now()
) : OrderDomainEvent()

data class OrderShipped(
    override val orderId: String,
    val trackingNumber: String,
    override val timestamp: Instant = Instant.now()
) : OrderDomainEvent()

@Service
class OrderEventProducer(private val kafkaTemplate: KafkaTemplate<String, Any>) {
    fun orderCreated(orderId: String, userId: Long, amount: Double) {
        kafkaTemplate.send("order-events", orderId, OrderCreated(orderId, userId, amount))
    }
    fun orderPaid(orderId: String, paymentId: String) {
        kafkaTemplate.send("order-events", orderId, OrderPaid(orderId, paymentId))
    }
    fun orderShipped(orderId: String, trackingNumber: String) {
        kafkaTemplate.send("order-events", orderId, OrderShipped(orderId, trackingNumber))
    }
}

@Component
class OrderEventConsumer {

    @KafkaListener(topics = ["order-events"], groupId = "order-event-handler")
    fun handle(event: OrderDomainEvent) {
        when (event) {  // exhaustive
            is OrderCreated -> println("Order ${event.orderId} created by ${event.userId}")
            is OrderPaid -> println("Order ${event.orderId} paid: ${event.paymentId}")
            is OrderShipped -> println("Order ${event.orderId} shipped: ${event.trackingNumber}")
        }
    }
}
```

### Retry with backoff

```kotlin
import org.springframework.context.annotation.Bean
import org.springframework.context.annotation.Configuration
import org.springframework.kafka.listener.DefaultErrorHandler
import org.springframework.util.backoff.FixedBackOff

@Configuration
class KafkaErrorConfig {

    @Bean
    fun kafkaErrorHandler(): DefaultErrorHandler {
        // Retry 3 times with 1 second between retries
        val backoff = FixedBackOff(1000L, 3L)  // interval, maxAttempts
        val handler = DefaultErrorHandler(backoff)

        // Don't retry these — they'll always fail
        handler.addNotRetryableExceptions(
            com.fasterxml.jackson.core.JsonParseException::class.java,
            IllegalArgumentException::class.java
        )
        return handler
    }
}
```

```kotlin
import org.springframework.kafka.listener.DeadLetterPublishingRecoverer
import org.springframework.kafka.listener.DefaultErrorHandler
import org.springframework.util.backoff.ExponentialBackOff

@Configuration
class KafkaDLTConfig {

    @Bean
    fun kafkaErrorHandler(kafkaTemplate: KafkaTemplate<String, Any>): DefaultErrorHandler {
        val recoverer = DeadLetterPublishingRecoverer(kafkaTemplate) { record, ex ->
            TopicPartition("${record.topic()}.DLT", -1)  // -1 = any partition
        }

        // Exponential backoff: 1s, 2s, 4s, 8s, then give up
        val backoff = ExponentialBackOff(1000L, 2.0).apply {
            maxElapsedTime = 15000L  // Give up after 15 seconds total
        }

        return DefaultErrorHandler(recoverer, backoff).apply {
            addNotRetryableExceptions(com.fasterxml.jackson.core.JsonParseException::class.java)
        }
    }
}
```

## Exactly-once semantics

| Guarantee | Meaning | How |
|---|---|---|
| **At-most-once** | May be lost, never duplicated | Commit offsets before processing |
| **At-least-once** | Never lost, may be duplicated | Commit after processing (default) |
| **Exactly-once** | Processed exactly once | Idempotent producer + transactional consumer |

### Idempotent producer

```yaml
spring:
  kafka:
    producer:
      properties:
        enable.idempotence: true
        acks: all
        max.in.flight.requests.per.connection: 5
```

The producer assigns a sequence number per message; the broker dedupes on `(producerId, sequence)`. No code changes.

### Transactional producer

```yaml
spring:
  kafka:
    producer:
      transaction-id-prefix: order-tx-  # Enables transactions
```

```kotlin
@Service
class TransactionalProducer(private val kafkaTemplate: KafkaTemplate<String, Any>) {

    fun processOrderTransaction(order: OrderEvent) {
        kafkaTemplate.executeInTransaction { template ->
            // All committed or all rolled back
            template.send("orders", order.orderId, order)
            template.send("order-events", order.orderId, OrderCreated(order.orderId, order.userId, order.amount))
            template.send("analytics", "order-created", mapOf("orderId" to order.orderId, "amount" to order.amount))
        }
    }
}
```

### Consume-transform-produce (the key EOS pattern)

<Mermaid title="Consume → transform → produce in one transaction, offset committed atomically" code={`

  C->>P: send(enriched)

```kotlin
@Configuration
class ExactlyOnceConfig {

    @Bean
    fun producerFactory(): ProducerFactory<String, Any> {
        val config = mapOf(
            ProducerConfig.BOOTSTRAP_SERVERS_CONFIG to "localhost:29092",
            ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG to StringSerializer::class.java,
            ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG to JsonSerializer::class.java,
            ProducerConfig.ENABLE_IDEMPOTENCE_CONFIG to true,
            ProducerConfig.TRANSACTIONAL_ID_CONFIG to "order-processor-tx"
        )
        return DefaultKafkaProducerFactory(config)
    }

    @Bean
    fun kafkaTemplate(producerFactory: ProducerFactory<String, Any>): KafkaTemplate<String, Any> =
        KafkaTemplate(producerFactory)

    @Bean
    fun kafkaTransactionManager(producerFactory: ProducerFactory<String, Any>): KafkaTransactionManager<String, Any> =
        KafkaTransactionManager(producerFactory)

    @Bean
    fun listenerContainerFactory(
        consumerFactory: ConsumerFactory<String, Any>,
        kafkaTransactionManager: KafkaTransactionManager<String, Any>
    ): ConcurrentKafkaListenerContainerFactory<String, Any> {
        val factory = ConcurrentKafkaListenerContainerFactory<String, Any>()
        factory.consumerFactory = consumerFactory
        factory.containerProperties.transactionManager = kafkaTransactionManager
        factory.containerProperties.kafkaConsumerProperties[ConsumerConfig.ISOLATION_LEVEL_CONFIG] = "read_committed"
        return factory
    }
}

@Component
class ExactlyOnceProcessor(private val kafkaTemplate: KafkaTemplate<String, Any>) {

    @KafkaListener(topics = ["raw-orders"], groupId = "order-enricher")
    fun processAndForward(order: OrderEvent) {
        val enriched = order.copy(status = "ENRICHED")
        kafkaTemplate.send("enriched-orders", order.orderId, enriched)
        // Offset committed as part of the producer transaction
    }
}
```

### When to use exactly-once

| Scenario | Guarantee Needed | Why |
|---|---|---|
| Logging, metrics | At-most-once | Losing a log line is OK |
| Order processing | At-least-once + idempotent consumer | Duplicate check simpler than EOS |
| Financial transactions | Exactly-once | Cannot tolerate duplicates or loss |
| Consume-transform-produce | Exactly-once | Atomic pipeline processing |

:::tip[Pragmatic advice]
At-least-once + idempotent consumers handles most cases. EOS adds complexity and throughput cost.
:::

### Idempotent consumer pattern

Build a unique event ID from `topic + partition + offset` and skip duplicates:

```kotlin
@Component
class IdempotentOrderConsumer(
    private val orderRepository: OrderRepository,
    private val processedEventRepository: ProcessedEventRepository
) {
    @KafkaListener(topics = ["orders"], groupId = "idempotent-processor")
    @Transactional
    fun process(
        event: OrderEvent,
        @Header(KafkaHeaders.RECEIVED_TOPIC) topic: String,
        @Header(KafkaHeaders.RECEIVED_PARTITION) partition: Int,
        @Header(KafkaHeaders.OFFSET) offset: Long
    ) {
        val eventId = "$topic-$partition-$offset"
        if (processedEventRepository.existsById(eventId)) return  // duplicate

        orderRepository.save(Order(orderId = event.orderId, userId = event.userId,
            amount = event.amount, status = "PROCESSING"))
        processedEventRepository.save(ProcessedEvent(eventId, Instant.now()))  // same DB tx
    }
}
```

## Offset management

### Auto vs manual commit

```yaml
# Auto commit (default) — timer-based, not message-based
spring:
  kafka:
    consumer:
      enable-auto-commit: true
      auto-commit-interval: 5000
```

:::caution[Auto-commit trap]
Offsets commit on a timer, not after processing. A crash after commit but before processing loses the message.
:::

```yaml
# Manual commit (recommended)
spring:
  kafka:
    consumer:
      enable-auto-commit: false
    listener:
      ack-mode: MANUAL  # or MANUAL_IMMEDIATE, RECORD, BATCH
```

### Acknowledgment modes

```kotlin
// MANUAL — you control exactly when offset commits
@KafkaListener(topics = ["orders"], groupId = "manual-ack")
fun processWithManualAck(event: OrderEvent, acknowledgment: Acknowledgment) {
    try {
        processOrder(event)
        acknowledgment.acknowledge()  // Commit only after success
    } catch (e: Exception) {
        throw e  // Don't acknowledge — message redelivered
    }
}
```

| Ack Mode | Behavior | Guarantee | Performance |
|---|---|---|---|
| `RECORD` | Commit after each record | At-least-once (per record) | Slower (many commits) |
| `BATCH` | Commit after all records in poll | At-least-once (per batch) | Better |
| `MANUAL` | You call `ack.acknowledge()` | At-least-once (you decide) | Flexible |
| `MANUAL_IMMEDIATE` | Commit immediately on ack | At-least-once (immediate) | Flexible |
| Auto-commit | Timer-based | At-most-once possible | Best throughput |

Use `RECORD` or `BATCH` for most cases. `MANUAL` when you need precise control (e.g. after a DB write).

### Seeking to specific offsets

```kotlin
@Component
class OffsetSeekConsumer : ConsumerSeekAware {

    private lateinit var seekCallback: ConsumerSeekAware.ConsumerSeekCallback

    override fun registerSeekCallback(callback: ConsumerSeekAware.ConsumerSeekCallback) {
        this.seekCallback = callback
    }

    fun seekToBeginning(topic: String, partition: Int) = seekCallback.seekToBeginning(topic, partition)
    fun seekToOffset(topic: String, partition: Int, offset: Long) = seekCallback.seek(topic, partition, offset)
    fun seekToTimestamp(topic: String, partition: Int, timestamp: Long) = seekCallback.seekToTimestamp(topic, partition, timestamp)

    @KafkaListener(topics = ["orders"], groupId = "seek-consumer")
    fun process(event: OrderEvent) { println("Processing: ${event.orderId}") }
}
```

## Schema evolution

### Backward-compatible changes (safe with JSON)

```kotlin
// V1
data class OrderEvent(val orderId: String, val amount: Double, val timestamp: Instant)

// V2 — added field with default (safe)
data class OrderEvent(
    val orderId: String, val amount: Double, val timestamp: Instant,
    val currency: String = "USD"
)

// V3 — another optional field
data class OrderEvent(
    val orderId: String, val amount: Double, val timestamp: Instant,
    val currency: String = "USD",
    val metadata: Map<String, String> = emptyMap()
)
```

Rules: add fields with defaults; never remove required fields, rename fields, or change types.

### Jackson forward compatibility

```kotlin
import com.fasterxml.jackson.annotation.JsonIgnoreProperties
```

```kotlin
import org.springframework.boot.test.context.SpringBootTest

@SpringBootTest
@EmbeddedKafka(
    partitions = 1,

class OrderProcessingIntegrationTest {
```
