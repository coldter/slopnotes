## The landscape

| Your background | Closest Kotlin/JVM equivalent | Style |
|---|---|---|
| `database/sql` (Go) | **JDBC** | Raw SQL, manual mapping |
| `sqlc` (Go) | **jOOQ** | Type-safe generated code from SQL |
| Prisma (TS) | **Exposed DAO** | ORM-like, schema-first |
| Drizzle / Knex (TS) | **Exposed DSL** | Type-safe query builder |
| TypeORM / GORM | **Spring Data JPA** | Full ORM |

## JDBC: the foundation

Every JVM database library builds on JDBC — the equivalent of Go's `database/sql`.

```kotlin
import java.sql.DriverManager

fun main() {
    val url = "jdbc:postgresql://localhost:5432/kotlin_course"
    val connection = DriverManager.getConnection(url, "dev", "dev")

    connection.use { conn ->
        val stmt = conn.prepareStatement(
            "SELECT id, name, email FROM users WHERE active = ?"
        )
        stmt.setBoolean(1, true)

        val rs = stmt.executeQuery()
        while (rs.next()) {
            val id = rs.getLong("id")
            val name = rs.getString("name")
            val email = rs.getString("email")
            println("$id: $name ($email)")
        }
    }
}
```

- `?` placeholders (not `$1` like native PostgreSQL).
- `connection.use { }` auto-closes — like Go's `defer conn.Close()`.
- `ResultSet` is cursor-based: `next()` then get columns by name/index.
- No automatic row-to-object mapping.

### CRUD with JDBC

```kotlin
data class User(
    val id: Long = 0,
    val name: String,
    val email: String,
    val active: Boolean = true
)

class UserJdbcRepository(private val conn: Connection) {

    fun create(user: User): User {
        val sql = "INSERT INTO users (name, email, active) VALUES (?, ?, ?) RETURNING id"
        val stmt = conn.prepareStatement(sql)
        stmt.setString(1, user.name)
        stmt.setString(2, user.email)
        stmt.setBoolean(3, user.active)
        val rs = stmt.executeQuery()
        rs.next()
        return user.copy(id = rs.getLong("id"))
    }

    fun findById(id: Long): User? {
        val stmt = conn.prepareStatement("SELECT id, name, email, active FROM users WHERE id = ?")
        stmt.setLong(1, id)
        val rs = stmt.executeQuery()
        return if (rs.next()) rs.toUser() else null
    }

    fun findAll(): List<User> {
        val rs = conn.prepareStatement("SELECT id, name, email, active FROM users").executeQuery()
        val users = mutableListOf<User>()
        while (rs.next()) users.add(rs.toUser())
        return users
    }

    fun update(user: User): Boolean {
        val stmt = conn.prepareStatement("UPDATE users SET name = ?, email = ?, active = ? WHERE id = ?")
        stmt.setString(1, user.name)
        stmt.setString(2, user.email)
        stmt.setBoolean(3, user.active)
        stmt.setLong(4, user.id)
        return stmt.executeUpdate() > 0
    }

    fun delete(id: Long): Boolean {
        val stmt = conn.prepareStatement("DELETE FROM users WHERE id = ?")
        stmt.setLong(1, id)
        return stmt.executeUpdate() > 0
    }

    fun createBatch(users: List<User>): List<User> {
        val stmt = conn.prepareStatement(
            "INSERT INTO users (name, email, active) VALUES (?, ?, ?)",
            Statement.RETURN_GENERATED_KEYS
        )
        for (user in users) {
            stmt.setString(1, user.name)
            stmt.setString(2, user.email)
            stmt.setBoolean(3, user.active)
            stmt.addBatch()
        }
        stmt.executeBatch()
        val keys = stmt.generatedKeys
        return users.mapIndexed { _, user ->
            keys.next()
            user.copy(id = keys.getLong(1))
        }
    }
}

private fun java.sql.ResultSet.toUser() = User(
    id = getLong("id"),
    name = getString("name"),
    email = getString("email"),
    active = getBoolean("active")
)
```

JDBC is verbose: SQL string, manual parameter binding by index, manual ResultSet mapping, manual cleanup. That's why you moved to GORM/Prisma — higher-level libraries reduce this boilerplate.

## Connection pooling: HikariCP

Go's `database/sql` and Node's `pg.Pool` have built-in pools. On the JVM, use **HikariCP** — the fastest pool available.

```kotlin
import com.zaxxer.hikari.HikariConfig
import com.zaxxer.hikari.HikariDataSource

fun createDataSource(): HikariDataSource {
    val config = HikariConfig().apply {
        jdbcUrl = "jdbc:postgresql://localhost:5432/kotlin_course"
        username = "dev"
        password = "dev"
        driverClassName = "org.postgresql.Driver"

        maximumPoolSize = 10          // max connections
        minimumIdle = 5               // min idle kept alive
        idleTimeout = 300_000         // 5 min before idle conn removed
        connectionTimeout = 30_000    // 30s to wait for a connection
        maxLifetime = 1_800_000       // 30 min max lifetime per connection

        addDataSourceProperty("cachePrepStmts", "true")
        addDataSourceProperty("prepStmtCacheSize", "250")
        addDataSourceProperty("prepStmtCacheSqlLimit", "2048")
    }
    return HikariDataSource(config)
}

fun main() {
    val dataSource = createDataSource()
    dataSource.connection.use { conn ->
        val rs = conn.prepareStatement("SELECT count(*) FROM users").executeQuery()
        rs.next()
        println("User count: ${rs.getLong(1)}")
    }
    // connection returned to pool when `use` block ends
    dataSource.close()
}
```

Spring Boot auto-configures HikariCP:

```yaml title="application.yml"
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/kotlin_course
    username: dev
    password: dev
    hikari:
      maximum-pool-size: 10
      minimum-idle: 5
      idle-timeout: 300000
      connection-timeout: 30000
      max-lifetime: 1800000
```

| Guideline | Value | Reason |
|---|---|---|
| Max pool size | `CPU cores * 2 + disk spindles` | Classic formula, typically 10-20 |
| Min idle | same as max (steady load) | avoids connection creation latency |
| Connection timeout | 30s | fail fast if pool exhausted |
| Max lifetime | 30 min | prevent stale connections |

## Spring Data JPA / Hibernate

Closest equivalent to TypeORM or GORM.

```kotlin title="build.gradle.kts"
plugins {
    kotlin("jvm") version "2.1.0"
    kotlin("plugin.spring") version "2.1.0"
    kotlin("plugin.jpa") version "2.1.0"       // CRITICAL for Kotlin entities
    kotlin("plugin.allopen") version "2.1.0"   // opens JPA classes for proxying
    id("org.springframework.boot") version "3.4.1"
    id("io.spring.dependency-management") version "1.1.7"
}

dependencies {
    implementation("org.springframework.boot:spring-boot-starter-data-jpa")
    runtimeOnly("org.postgresql:postgresql")
}
```

:::caution[Plugins are essential]
Without `kotlin-jpa` and `kotlin-allopen`, JPA entities fail at runtime — Hibernate needs no-arg constructors and non-final classes. See [Kotlin JPA Gotchas](#kotlin-jpa-gotchas).
:::

### Entities

```kotlin
import jakarta.persistence.*
import java.time.Instant

@Entity
@Table(name = "users", schema = "mod10_database")
class User(
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    val id: Long = 0,

    @Column(nullable = false)
    var name: String,

    @Column(nullable = false, unique = true)
    var email: String,

    @Column(nullable = false)
    var active: Boolean = true,

    @Column(name = "created_at", nullable = false, updatable = false)
    val createdAt: Instant = Instant.now()
)
```

- JPA entities are **classes, not data classes** (see gotchas below).
- Mutable fields use `var`, immutable use `val`.
- `GenerationType.IDENTITY` = auto-increment (like `SERIAL`).
- Use `jakarta.persistence.*` (Jakarta EE 9+, not old `javax.*`).

### Relationships

```kotlin
@Entity
@Table(name = "posts", schema = "mod10_database")
class Post(
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    val id: Long = 0,

    @Column(nullable = false)
    var title: String,

    @Column(columnDefinition = "TEXT")
    var content: String,

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "author_id", nullable = false)
    var author: User,

    @OneToMany(mappedBy = "post", cascade = [CascadeType.ALL], orphanRemoval = true)
    val comments: MutableList<Comment> = mutableListOf(),

    @Column(name = "created_at", nullable = false, updatable = false)
    val createdAt: Instant = Instant.now()
)
```

:::tip[Always set `FetchType.LAZY` on `@ManyToOne`]
Eager fetching (the actual default) causes silent N+1 problems.
:::

### Spring Data repositories

Define an interface — Spring generates the implementation:

```kotlin
interface UserRepository : JpaRepository<User, Long> {

    // Derived from method name
    fun findByEmail(email: String): User?
    fun findByActiveTrue(): List<User>
    fun findByNameContainingIgnoreCase(name: String): List<User>

    // Custom JPQL
    @Query("SELECT u FROM User u WHERE u.createdAt > :since AND u.active = true")
    fun findRecentActiveUsers(since: Instant): List<User>

    // Native SQL
    @Query(value = "SELECT * FROM mod10_database.users WHERE email LIKE %:domain", nativeQuery = true)
    fun findByEmailDomain(domain: String): List<User>
}
```

| Method name | Generated SQL |
|---|---|
| `findByEmail(email)` | `WHERE email = ?` |
| `findByActiveTrue()` | `WHERE active = true` |
| `findByNameContainingIgnoreCase(name)` | `WHERE LOWER(name) LIKE LOWER('%' \|\| ? \|\| '%')` |
| `countByActiveTrue()` | `SELECT COUNT(*) ... WHERE active = true` |
| `existsByEmail(email)` | `SELECT EXISTS(... WHERE email = ?)` |

### Specifications for dynamic queries

```kotlin
interface UserRepository : JpaRepository<User, Long>, JpaSpecificationExecutor<User>

object UserSpecs {
    fun hasName(name: String?): Specification<User>? =
        name?.let { Specification { root, _, cb -> cb.like(cb.lower(root.get("name")), "%${it.lowercase()}%") } }

    fun isActive(active: Boolean?): Specification<User>? =
        active?.let { Specification { root, _, cb -> cb.equal(root.get<Boolean>("active"), it) } }
}

fun searchUsers(name: String?, active: Boolean?): List<User> {
    val spec = listOfNotNull(UserSpecs.hasName(name), UserSpecs.isActive(active))
        .reduceOrNull { acc, s -> acc.and(s) }
    return if (spec != null) userRepository.findAll(spec) else userRepository.findAll()
}
```

## Exposed: Kotlin-first SQL

JetBrains' own SQL library. Two flavors: **DSL** (query builder, like Drizzle/Knex) and **DAO** (lightweight ORM, like a simpler Prisma).

```kotlin title="build.gradle.kts"

    implementation("org.jetbrains.exposed:exposed-core:$exposedVersion")

    implementation("org.jetbrains.exposed:exposed-jdbc:$exposedVersion")
    implementation("org.jetbrains.exposed:exposed-java-time:$exposedVersion")
    implementation("org.postgresql:postgresql:42.7.4")
    implementation("com.zaxxer:HikariCP:6.2.1")
}
```

### Table definitions

```kotlin
import org.jetbrains.exposed.sql.*
import org.jetbrains.exposed.sql.javatime.timestamp

object Users : Table("mod10_database.users") {
    val id = long("id").autoIncrement()
    val name = varchar("name", 255)
    val email = varchar("email", 255).uniqueIndex()
    val active = bool("active").default(true)
    val createdAt = timestamp("created_at").defaultExpression(CurrentTimestamp)

    override val primaryKey = PrimaryKey(id)
}

object Posts : Table("mod10_database.posts") {
    val id = long("id").autoIncrement()
    val title = varchar("title", 255)
    val content = text("content")
    val authorId = long("author_id").references(Users.id)
    val createdAt = timestamp("created_at").defaultExpression(CurrentTimestamp)

    override val primaryKey = PrimaryKey(id)
}
```

### DSL approach

```kotlin
fun main() {
    Database.connect(
        url = "jdbc:postgresql://localhost:5432/kotlin_course",
        driver = "org.postgresql.Driver",
        user = "dev",
        password = "dev"
    )

    transaction {
        SchemaUtils.create(Users)   // dev only — use Flyway in production

        // INSERT
        val userId = Users.insertAndGetId {
            it[name] = "Alice"
            it[email] = "alice@example.com"
            it[active] = true
        }

        // SELECT single
        Users.selectAll().where { Users.email eq "alice@example.com" }.singleOrNull()

        // SELECT with conditions
        Users.selectAll()
            .where { Users.active eq true }
            .orderBy(Users.createdAt, SortOrder.DESC)
            .limit(10)
            .map { row -> UserDTO(row[Users.id], row[Users.name], row[Users.email], row[Users.active]) }

        // UPDATE
        Users.update({ Users.id eq userId.value }) { it[name] = "Alice Updated" }

        // DELETE
        Users.deleteWhere { Users.id eq userId.value }

        // JOIN
        (Posts innerJoin Users)
            .select(Posts.title, Posts.content, Users.name)
            .where { Users.active eq true }

        // Aggregation
        Users.selectAll().where { Users.active eq true }.count()
    }
}

data class UserDTO(val id: Long, val name: String, val email: String, val active: Boolean)
```

### DAO approach

```kotlin
import org.jetbrains.exposed.dao.LongEntity
import org.jetbrains.exposed.dao.LongEntityClass
import org.jetbrains.exposed.dao.id.EntityID
import org.jetbrains.exposed.dao.id.LongIdTable

object UsersTable : LongIdTable("mod10_database.users") {
    val name = varchar("name", 255)
    val email = varchar("email", 255).uniqueIndex()
    val active = bool("active").default(true)
    val createdAt = timestamp("created_at").defaultExpression(CurrentTimestamp)
}

class UserEntity(id: EntityID<Long>) : LongEntity(id) {
    companion object : LongEntityClass<UserEntity>(UsersTable)

    var name by UsersTable.name
    var email by UsersTable.email
    var active by UsersTable.active
    val createdAt by UsersTable.createdAt
    val posts by PostEntity referrersOn PostsTable.author
}

// Usage
transaction {
    SchemaUtils.create(UsersTable, PostsTable)

    val alice = UserEntity.new { name = "Alice"; email = "alice@example.com" }
    val user = UserEntity.findById(alice.id)
    val activeUsers = UserEntity.find { UsersTable.active eq true }
    alice.name = "Alice Updated"   // auto-tracked, saved
    alice.delete()
}
```

| Factor | DSL | DAO |
|---|---|---|
| Style | query builder (Drizzle) | ORM entities (Prisma) |
| Control | full SQL control | convention-based |
| Performance | slightly better | small tracking overhead |
| Relationships | manual joins | automatic lazy loading |
| Best for | complex queries, reporting | standard CRUD, prototyping |

### Type-safe queries

```kotlin
import org.jooq.DSLContext
import org.jooq.impl.DSL
import com.example.generated.Tables.USERS
import com.example.generated.Tables.POSTS

fun main() {
    val dsl: DSLContext = DSL.using("jdbc:postgresql://localhost:5432/kotlin_course", "dev", "dev")

    // INSERT
    val userId = dsl.insertInto(USERS)
        .set(USERS.NAME, "Alice")
        .set(USERS.EMAIL, "alice@example.com")
        .set(USERS.ACTIVE, true)
        .returning(USERS.ID)
        .fetchOne()!!
        .id

    // SELECT — fully type-safe
    val user = dsl.selectFrom(USERS).where(USERS.EMAIL.eq("alice@example.com")).fetchOne()

    // JOIN
    dsl.select(POSTS.TITLE, POSTS.CONTENT, USERS.NAME)
        .from(POSTS)
        .join(USERS).on(POSTS.AUTHOR_ID.eq(USERS.ID))
        .where(USERS.ACTIVE.isTrue)
        .orderBy(POSTS.CREATED_AT.desc())
        .fetch()

    // UPDATE / DELETE / UPSERT
    dsl.update(USERS).set(USERS.NAME, "Alice Updated").where(USERS.ID.eq(userId)).execute()
    dsl.deleteFrom(USERS).where(USERS.ID.eq(userId)).execute()

    dsl.insertInto(USERS)
        .set(USERS.NAME, "Bob")
        .set(USERS.EMAIL, "bob@example.com")
        .onConflict(USERS.EMAIL)
        .doUpdate()
        .set(USERS.NAME, DSL.excluded(USERS.NAME))
        .execute()
}
```

With Spring Boot, `spring-boot-starter-jooq` auto-configures `DSLContext` — inject it into services.

## Flyway migrations

Flyway works like Prisma Migrate or golang-migrate: ordered, checksummed SQL files.

Naming: `V{version}__{description}.sql` (two underscores). `V` = versioned (run once), `R` = repeatable (rerun on change).

```sql title="V1__create_users_table.sql"
CREATE TABLE IF NOT EXISTS mod10_database.users (
    id          BIGSERIAL PRIMARY KEY,
    name        VARCHAR(255) NOT NULL,
    email       VARCHAR(255) NOT NULL UNIQUE,
    active      BOOLEAN NOT NULL DEFAULT true,
    created_at  TIMESTAMP NOT NULL DEFAULT now()
);

CREATE INDEX idx_users_email ON mod10_database.users (email);
CREATE INDEX idx_users_active ON mod10_database.users (active);
```

Without Spring Boot:

```kotlin
import org.flywaydb.core.Flyway

fun main() {
    val flyway = Flyway.configure()
        .dataSource("jdbc:postgresql://localhost:5432/kotlin_course", "dev", "dev")
        .schemas("mod10_database")
        .locations("classpath:db/migration")
        .load()

    val result = flyway.migrate()
    println("Applied ${result.migrationsExecuted} migrations")
    // flyway.info() / flyway.validate() / flyway.repair() / flyway.clean()
}
```

| Tip | Explanation |
|---|---|
| Never edit applied migrations | Flyway checksums them; editing breaks validation |
| Use `IF NOT EXISTS` | makes migrations idempotent |
| Version sequentially | `V1`, `V2`... or timestamps: `V20240115120000` |
| Separate DDL and DML | don't mix schema and data changes in one migration |

## Transaction management

### JDBC — manual

```kotlin
fun transferCredits(conn: Connection, fromId: Long, toId: Long, amount: Int) {
    conn.autoCommit = false
    try {
        val debit = conn.prepareStatement(
            "UPDATE accounts SET credits = credits - ? WHERE id = ? AND credits >= ?"
        )
        debit.setInt(1, amount); debit.setLong(2, fromId); debit.setInt(3, amount)
        if (debit.executeUpdate() == 0) throw IllegalStateException("Insufficient credits")

        val credit = conn.prepareStatement("UPDATE accounts SET credits = credits + ? WHERE id = ?")
        credit.setInt(1, amount); credit.setLong(2, toId)
        credit.executeUpdate()

        conn.commit()
    } catch (e: Exception) {
        conn.rollback()
        throw e
    } finally {
        conn.autoCommit = true
    }
}
```

### Spring @Transactional

```kotlin
@Service
class OrderService(
    private val orderRepository: OrderRepository,
    private val inventoryRepository: InventoryRepository,
    private val paymentService: PaymentService
) {
    @Transactional
    fun placeOrder(request: OrderRequest): Order {
        val order = orderRepository.save(Order(userId = request.userId, total = request.total))
        inventoryRepository.decrementStock(request.productId, request.quantity)
        paymentService.charge(request.userId, request.total)
        return order
    }

    @Transactional(readOnly = true)
    fun getOrderHistory(userId: Long): List<Order> = orderRepository.findByUserIdOrderByCreatedAtDesc(userId)

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    fun auditLog(action: String, userId: Long) {
        // own transaction — committed even if outer tx fails
        auditRepository.save(AuditEntry(action = action, userId = userId))
    }
}
```

| Propagation | Behavior |
|---|---|
| `REQUIRED` (default) | join existing tx or create new |
| `REQUIRES_NEW` | always new tx (suspend existing) |
| `NESTED` | savepoint within existing tx |
| `MANDATORY` | must run in existing tx (throw if none) |

### Exposed transactions

```kotlin
// Every Exposed operation must be inside a transaction block
transaction {
    val userId = Users.insertAndGetId { it[name] = "Alice"; it[email] = "alice@example.com" }
    Posts.insert { it[title] = "First Post"; it[content] = "Hello!"; it[authorId] = userId.value }
    // auto-commits if no exception, auto-rollbacks on exception
}

// Nested = savepoint
transaction {
    Users.insert { it[name] = "Bob" }
    try {
        transaction {
            Users.insert { it[name] = "Charlie" }
            throw RuntimeException("Oops")   // inner rolled back, outer continues
        }
    } catch (e: RuntimeException) { println("Inner failed, Bob still inserted") }
}
```

### Common pitfalls

1. **Self-invocation**: calling a `@Transactional` method from the same class bypasses the proxy — no transaction. Fix: inject the service into itself or use a separate service.

2. **Swallowing exceptions**: catching inside a `@Transactional` method and not rethrowing means Spring never sees the failure — the transaction commits. Fix: rethrow.

3. **Long-running transactions**: don't hold a connection for a large file. Batch with chunked transactions instead.

## Kotlin JPA gotchas

| Feature | `data class` | JPA needs |
|---|---|---|
| `equals`/`hashCode` | uses all constructor properties | should use only `id` |
| `val` properties | immutable | Hibernate needs `var` for dirty checking |
| no-arg constructor | not generated by default | required for proxy creation |
| `final` class | Kotlin default | Hibernate needs `open` classes |

```kotlin
// BAD: data class entity
@Entity
data class User(@Id val id: Long = 0, val name: String, val email: String)
// equals/hashCode uses all fields, toString may trigger lazy loading, copy() creates detached entities

// GOOD: regular class
@Entity
@Table(name = "users", schema = "mod10_database")
class User(
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    val id: Long = 0,
    @Column(nullable = false) var name: String,
    @Column(nullable = false, unique = true) var email: String,
    @Column(nullable = false) var active: Boolean = true
) {
    override fun equals(other: Any?): Boolean {
        if (this === other) return true
        if (other !is User) return false
        return id != 0L && id == other.id
    }
    override fun hashCode(): Int = id.hashCode()
    override fun toString(): String = "User(id=$id, name=$name, email=$email)"
}
```

### Lazy loading gotcha

```kotlin
// Outside a transaction:
val post = postRepository.findById(1L).get()
post.author.name   // LazyInitializationException! Session is closed.

// Fix 1: @Transactional on the service method
@Transactional(readOnly = true)
fun getPostWithAuthor(id: Long): Post { ... post.author.name ... }

// Fix 2: JOIN FETCH
@Query("SELECT p FROM Post p JOIN FETCH p.author WHERE p.id = :id")
fun findByIdWithAuthor(id: Long): Post?

// Fix 3: EntityGraph
@EntityGraph(attributePaths = ["author"])
fun findWithAuthorById(id: Long): Post?
```

## When to use what

| Factor | JDBC | Spring Data JPA | Exposed | jOOQ |
|---|---|---|---|---|
| Learning curve | Low | Medium | Low | Medium |
| Type safety | None (strings) | Partial (JPQL) | Full (Kotlin DSL) | Full (generated) |
| SQL control | Full | Limited | Full | Full |
| Boilerplate | High | Low | Low | Low |
| Performance | Best | Good | Good | Good |
| Kotlin-native | No | No | Yes | No |
| Comparable to | `database/sql` | GORM / TypeORM | Drizzle | sqlc |

- **JDBC**: max control/performance, tiny projects.
- **Spring Data JPA**: standard Spring Boot CRUD, complex relationships, auto-generated repositories.
- **Exposed**: Kotlin-first, query builders over ORMs, lighter than JPA, pairs well with Ktor.
- **jOOQ**: you love SQL and want compile-time safety; schema is source of truth.

**You can mix them.** In a Spring Boot app, use JPA for standard CRUD and jOOQ for complex reporting — they share the same `DataSource` and transaction manager.

```kotlin
@Service
class ReportService(
    private val userRepository: UserRepository,  // JPA for simple CRUD
    private val dsl: DSLContext                   // jOOQ for complex queries
) {
    fun getUser(id: Long): User = userRepository.findById(id).orElseThrow()

    fun getUserPostStats(): List<UserStatsDTO> = dsl
        .select(USERS.NAME, DSL.count(POSTS.ID), DSL.max(POSTS.CREATED_AT))
        .from(USERS)
        .leftJoin(POSTS).on(POSTS.AUTHOR_ID.eq(USERS.ID))
        .groupBy(USERS.NAME)
        .fetchInto(UserStatsDTO::class.java)
}
```
