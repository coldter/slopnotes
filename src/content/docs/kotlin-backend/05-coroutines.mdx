Coroutines map to what you know: `async`/`await` in TS, goroutines in Go. Kotlin's standout feature is **structured concurrency** — parent-child lifecycle management built in.

## Mental model

| Concept | TypeScript | Go | Kotlin |
|---|---|---|---|
| Lightweight task | `async function` + event loop | goroutine | coroutine |
| Concurrency model | Single-threaded event loop | M:N green threads | Suspendable computations on thread pools |
| Blocking avoidance | Non-blocking by nature | Goroutines yield at I/O | `suspend` functions yield cooperatively |
| Structured lifecycle | No built-in hierarchy | No built-in (`errgroup` helps) | **Built-in**: parent-child scope |

100,000 coroutines use a few MB — try that with OS threads:

```kotlin
fun main() = runBlocking {
    val jobs = List(100_000) { launch { delay(1000) } }
    jobs.forEach { it.join() }
    println("All done")
}
```

suspend fun fetchUser(): String { delay(1000); return "Alice" }

    val start = System.currentTimeMillis()

- `async` returns `Deferred<T>` (typed `Promise`); `.await()` gets the result.
- `delay()` is non-blocking — suspends the coroutine, frees the thread.

## Structured concurrency

In Go, unsupervised goroutines leak. In TS, floating promises become unhandled rejections. Kotlin's `coroutineScope` waits for all children and propagates failure/cancellation.

```kotlin
suspend fun handleRequest() = coroutineScope {
    val db = async { fetchFromDB() }                 // child of this scope
    val api = async { callExternalAPI() }
    val notification = launch { sendNotification() }
    // scope waits for ALL children; if any fails, ALL siblings cancelled
    db.await() + api.await()
}
```

**Rules:**
1. Every coroutine has a parent scope.
2. Parent doesn't complete until all children complete.
3. Parent cancelled → all children cancelled.
4. Child fails → parent cancelled → all siblings cancelled.

### Scope hierarchy

<Mermaid title="Coroutine scope hierarchy" height={360} code={`
flowchart TB
  R["runBlocking (root scope)"] --> A["launch (Job A)"]
  R --> B["launch (Job B)"]
  A --> A1["async (Job A1)"]
  A --> A2["async (Job A2)"]
  B --> B1["launch (Job B1)"]
  B --> B2["launch (Job B2)"]
`} />

Notice: cancel Job A → A1, A2 cancelled, B unaffected. A1 throws → A2 cancelled, then A cancelled (propagates up).

### coroutineScope vs supervisorScope

`coroutineScope` fails fast — one child's failure cancels siblings. `supervisorScope` isolates — one failure leaves others running.

```kotlin
suspend fun strictScope() = coroutineScope {
    launch { delay(1000); println("Task 1 done") }      // never prints — cancelled
    launch { delay(500); throw RuntimeException("fail") }
}

suspend fun lenientScope() = supervisorScope {
    launch { delay(1000); println("Task 1 done") }      // DOES print
    launch { delay(500); throw RuntimeException("fail") }
}
```

## Builders: launch, async, runBlocking

| Builder | Returns | Use for | Blocks thread? |
|---|---|---|---|
| `launch` | `Job` | Fire-and-forget (side effects) | No |
| `async` | `Deferred<T>` | Concurrent computation returning value | No |
| `runBlocking` | `T` | Bridge from blocking to suspend world | **Yes** |

```kotlin
// launch — fire and forget
fun main() = runBlocking {
    val job: Job = launch { delay(1000); println("Done!") }
    job.join()              // optional — runBlocking waits anyway
    job.cancel()            // request cancellation
    job.cancelAndJoin()     // shorthand
}

// async — get a result
val deferred: Deferred<Int> = async { delay(1000); 42 }
val result: Int = deferred.await()

// Parallel decomposition — total time = max, not sum
suspend fun getUserProfile(): UserProfile = coroutineScope {
    val name = async { fetchName() }      // 300ms
    val orders = async { fetchOrders() }  // 500ms
    val prefs = async { fetchPrefs() }    // 200ms
    UserProfile(name.await(), orders.await(), prefs.await())  // ~500ms total
}
```

:::caution[Never nest runBlocking inside a coroutine]
It blocks the thread and can deadlock. Use `runBlocking` only at edges: `main()`, tests, rare bridges.
:::

## Dispatchers

| Dispatcher | Thread pool | Use for |
|---|---|---|
| `Dispatchers.Default` | Shared pool (CPU cores) | CPU-bound work |
| `Dispatchers.IO` | Elastic pool (64+ threads) | I/O — network, disk, DB |
| `Dispatchers.Unconfined` | No specific thread | Testing, edge cases |
| `Dispatchers.Main` | Main/UI thread | Android/Desktop only |

```kotlin
fun main() = runBlocking {
    launch(Dispatchers.Default) { /* CPU work */ }
    launch(Dispatchers.IO) { /* I/O work */ }
}

// Switch context
suspend fun readFile(path: String): String = withContext(Dispatchers.IO) {
    java.io.File(path).readText()
}

// Limit parallelism — like a Go worker pool / semaphore
val limitedDispatcher = Dispatchers.IO.limitedParallelism(2)
launch(limitedDispatcher) { /* max 2 concurrent */ }
```

## Suspending functions

`suspend` marks a function that can pause and resume without blocking a thread. It returns the actual type (`String`), not a wrapper (`Promise<String>`).

```kotlin
suspend fun processData(): String {
    delay(100)              // suspends — thread freed
    val data = fetchFromNetwork()
    return data.uppercase()
}

// Rules: suspend functions can call suspend functions.
// Regular functions CANNOT call suspend functions.
// COMPILE ERROR: fun regular() { delay(100) }
```

## Channels

Primary way to communicate between coroutines — like Go channels.

```kotlin
val channel = Channel<String>(capacity = 10)   // buffered

launch { channel.send("hello"); channel.close() }
val msg = channel.receive()                     // suspend if empty
for (value in channel) { println(value) }       // iterate until closed
```

| Type | Kotlin | Go equivalent | Behavior |
|---|---|---|---|
| Rendezvous | `Channel<T>()` | `make(chan T)` | Sender suspends until receiver ready |
| Buffered | `Channel<T>(10)` | `make(chan T, 10)` | Suspends when buffer full |
| Unlimited | `Channel<T>(UNLIMITED)` | N/A | Never suspends sender |
| Conflated | `Channel<T>(CONFLATED)` | N/A | Keeps only latest |

### Producer-consumer

```kotlin
fun CoroutineScope.produceNumbers(): ReceiveChannel<Int> = produce {
    for (i in 0 until 5) send(i)
    // auto-closed when block completes
}

fun main() = runBlocking {
    for (value in produceNumbers()) println(value)
}
```

### Select (like Go's select)

```kotlin
val result = select {
    ch1.onReceive { "Ch1: $it" }
    ch2.onReceive { "Ch2: $it" }
    onTimeout(1000) { "Timeout" }
}
```

## Fan-out & fan-in

### Fan-out: one producer, N consumers (worker pool)

<Mermaid title="Fan-out worker pool" height={360} code={`
flowchart LR
  J["jobs channel"] --> W1["Worker 1"]
  J --> W2["Worker 2"]
  J --> W3["Worker 3"]
  W1 --> R["results channel"]
  W2 --> R
  W3 --> R
`} />

```kotlin
fun main() = runBlocking {
    val jobs = Channel<Int>(capacity = 100)
    val results = Channel<String>(capacity = 100)

    // Start 3 workers — each pulls from the same channel
    val workers = (1..3).map { workerId ->
        launch {
            for (job in jobs) {
                delay(100)
                results.send("worker $workerId processed job $job")
            }
        }
    }

    launch {
        for (j in 1..9) jobs.send(j)
        jobs.close()
    }

    launch {
        workers.forEach { it.join() }
        results.close()
    }

    for (result in results) println(result)
}
```

### Fan-in: multiple producers, one consumer

```kotlin
fun CoroutineScope.producer(name: String, delayMs: Long): ReceiveChannel<String> = produce {
    var count = 0
    while (true) { delay(delayMs); send("$name-${count++}") }
}

fun CoroutineScope.fanIn(vararg channels: ReceiveChannel<String>): ReceiveChannel<String> = produce {
    for (channel in channels) {
        launch { for (msg in channel) send(msg) }
    }
}
```

### Pipeline pattern

<Mermaid title="Channel pipeline" height={360} code={`
flowchart LR
  G["generateNumbers"] -->|"Int"| S["square"]
  S -->|"Int"| F["filterEven"]
  F -->|"Int"| O["Consumer (println)"]
`} />

```kotlin
fun CoroutineScope.generateNumbers(count: Int): ReceiveChannel<Int> = produce {
    for (i in 1..count) send(i)
}

fun CoroutineScope.square(input: ReceiveChannel<Int>): ReceiveChannel<Int> = produce {
    for (value in input) send(value * value)
}

fun CoroutineScope.filterEven(input: ReceiveChannel<Int>): ReceiveChannel<Int> = produce {
    for (value in input) if (value % 2 == 0) send(value)
}

fun main() = runBlocking {
    val numbers = generateNumbers(10)
    val squared = square(numbers)
    for (value in filterEven(squared)) println(value)   // 4, 16, 36, 64, 100
}
```

## Exception handling

In `coroutineScope`, any child's exception cancels all siblings and propagates up.

```kotlin
// launch: exception propagates to parent immediately
val job = launch { throw RuntimeException("launch error") }

// async: exception stored, thrown on .await()
val deferred = async { throw RuntimeException("async error") }
try { deferred.await() } catch (e: RuntimeException) { println("Caught: ${e.message}") }
```

:::caution[Always await async results]
Even with `async`, if you don't `.await()`, the exception still propagates to the parent scope.
:::

### CoroutineExceptionHandler

For `launch`-based coroutines on a `SupervisorJob` scope:

```kotlin
val handler = CoroutineExceptionHandler { _, exception ->
    println("Global handler caught: ${exception.message}")
}
val scope = CoroutineScope(SupervisorJob() + handler)

scope.launch { throw RuntimeException("broke") }
scope.launch { delay(1000); println("Still running!") }   // supervised
```

### Error handling comparison

| Pattern | TypeScript | Go | Kotlin |
|---|---|---|---|
| Fail fast | `Promise.all([...])` | `errgroup.WithContext` | `coroutineScope { async {} }` |
| Collect all results | `Promise.allSettled` | manual per-goroutine | `supervisorScope { runCatching {} }` |

## Cancellation & timeouts

```kotlin
val job = launch {
    repeat(1000) { i ->
        println("Working $i")
        delay(200)         // cancellation checked at suspension points
    }
}
delay(1000)
job.cancelAndJoin()
```

Cancellation is cooperative — only at suspension points (`delay`, `yield`, `withContext`). CPU-bound loops check `isActive` manually:

```kotlin
while (isActive) { /* CPU work */ }
```

```kotlin
// Timeouts
val result = withTimeout(1000) { delay(2000); "done" }         // throws TimeoutCancellationException
val result2 = withTimeoutOrNull(1000) { delay(2000); "done" }  // returns null
```

| Pattern | TypeScript | Go | Kotlin |
|---|---|---|---|
| Timeout | `Promise.race([task, timeout])` | `context.WithTimeout` | `withTimeout(ms) {}` |
| Timeout → null | custom wrapper | check `ctx.Err()` | `withTimeoutOrNull(ms) {}` |

### Non-cancellable cleanup

```kotlin
try {
    // work
} finally {
    withContext(NonCancellable) {
        delay(500)   // cleanup that must suspend
    }
}
```

## Shared mutable state

### The problem — race condition

```kotlin
var counter = 0   // BROKEN — not thread-safe
launch(Dispatchers.Default) { repeat(1000) { counter++ } }
```

### Solutions

| Approach | When to use | Go equivalent |
|---|---|---|
| `AtomicInteger` | Simple counters, flags | `atomic.AddInt64` |
| `Mutex` (suspending lock) | Protecting complex state | `sync.Mutex` |
| `Semaphore` | Limiting concurrency | buffered channel as semaphore |
| Channel/Actor | State owned by single coroutine | goroutine + channel |

```kotlin
// AtomicInteger
val counter = AtomicInteger(0)
launch(Dispatchers.Default) { repeat(1000) { counter.incrementAndGet() } }

// Mutex — suspends instead of blocking the thread
val mutex = Mutex()
mutex.withLock { counter++ }

// Semaphore — limit concurrency
val semaphore = Semaphore(permits = 3)
semaphore.withPermit { delay(1000) }

// Actor — message passing, no shared state
sealed class CounterMsg
data object Increment : CounterMsg()
data class GetCount(val response: CompletableDeferred<Int>) : CounterMsg()

fun CoroutineScope.counterActor(): Channel<CounterMsg> {
    val channel = Channel<CounterMsg>()
    launch {
        var counter = 0
        for (msg in channel) {
            when (msg) {
                is Increment -> counter++
                is GetCount -> msg.response.complete(counter)
            }
        }
    }
    return channel
}
```

## Testing coroutines

`runTest` auto-advances virtual time — `delay(5000)` completes instantly.

```kotlin
class MyServiceTest {
    @Test
    fun `test suspending function`() = runTest {
        val result = fetchData()    // delay(5000) inside — runs instantly
        assertEquals("data", result)
    }

    @Test
    fun `test delayed behavior`() = runTest {
        var ticks = 0
        val job = launch { while (true) { delay(1000); ticks++ } }

        assertEquals(0, ticks)
        advanceTimeBy(3000)
        assertEquals(3, ticks)
        job.cancel()
    }

    @Test
    fun `test with injected dispatcher`() = runTest {
        val testDispatcher = StandardTestDispatcher(testScheduler)
        val service = MyService(testDispatcher)
        service.startProcessing()
        advanceUntilIdle()          // run all pending coroutines
        assertEquals(true, service.isComplete)
    }
}
```

## Cheat sheet

| Pattern | TypeScript | Go | Kotlin |
|---|---|---|---|
| Run concurrently | `Promise.all([...])` | `go func(); wg.Wait()` | `coroutineScope { async {} }` |
| First wins | `Promise.race([...])` | `select {}` on channels | `select { onAwait {} }` |
| Worker pool | manual queues | goroutines + buffered channel | `Channel` + N `launch` |
| Timeout | `Promise.race([p, timeout])` | `context.WithTimeout` | `withTimeout(ms) {}` |
| Retry | loop with try/catch | loop with `err != nil` | custom `retry {}` |
| Mutex | N/A (single-threaded) | `sync.Mutex` | `Mutex` (suspending) |
| Rate limit | custom/library | `time.Ticker` + channel | `Semaphore` + `delay` |
| Cancel | `AbortController` | `context.Cancel()` | `job.cancel()` / scope cancel |

### Concurrent map

```kotlin
suspend fun <T, R> Iterable<T>.concurrentMap(transform: suspend (T) -> R): List<R> =
    coroutineScope { map { async { transform(it) } }.awaitAll() }
```

### Retry with exponential backoff

```kotlin
suspend fun <T> retry(
    times: Int = 3, initialDelayMs: Long = 100, maxDelayMs: Long = 5000,
    factor: Double = 2.0, block: suspend () -> T
): T {
    var currentDelay = initialDelayMs
    repeat(times - 1) {
        try { return block() } catch (e: Exception) { println("Retry after ${currentDelay}ms: ${e.message}") }
        delay(currentDelay)
        currentDelay = (currentDelay * factor).toLong().coerceAtMost(maxDelayMs)
    }
    return block()
}
```

### First result wins

```kotlin
suspend fun <T> raceOf(vararg blocks: suspend () -> T): T = coroutineScope {
    select { for (block in blocks) async { block() }.onAwait { it } }
}
```
