Install JDK 21, Gradle, and an IDE, then create your first Kotlin Gradle project. Every tool maps to its npm/go equivalent.

## Install JDK 21

Kotlin compiles to JVM bytecode and runs on the JDK.

| TypeScript | Go | Kotlin |
|---|---|---|
| Node.js runtime | Go runtime (compiled in) | JDK (JVM runtime) |
| `nvm` manages versions | Go manages itself | `sdkman` manages versions |

<Steps>

1. Install SDKMAN:

   ```bash
   curl -s "https://get.sdkman.io" | bash
   source "$HOME/.sdkman/bin/sdkman-init.sh"
   sdk version
   ```

2. Install Eclipse Temurin JDK 21:

   ```bash
   sdk list java
   sdk install java 21.0.5-tem
   java -version    # openjdk version "21.0.5" ...
   javac -version   # javac 21.0.5
   ```

3. Set it as default (like `nvm alias default`):

   ```bash
   sdk use java 21.0.5-tem       # this shell
   sdk default java 21.0.5-tem   # default version
   ```

</Steps>

:::note[Why Temurin?]
Many JDK distributions exist (Oracle, Temurin, Corretto, GraalVM). Temurin is the Eclipse Foundation's free build — the safe default.
:::

SDKMAN sets `JAVA_HOME` for you:

```bash
echo $JAVA_HOME    # /home/youruser/.sdkman/candidates/java/current
which java         # .../bin/java
```

## Install Gradle

| npm (TypeScript) | go (Go) | Gradle (Kotlin) |
|---|---|---|
| `package.json` | `go.mod` | `build.gradle.kts` |
| `package-lock.json` | `go.sum` | `gradle.lockfile` (optional) |
| `node_modules/` | `$GOPATH/pkg/mod/` | `~/.gradle/caches/` |
| `npm install` | `go mod download` | `./gradlew build` |
| `npm run start` | `go run .` | `./gradlew run` |
| `npm test` | `go test ./...` | `./gradlew test` |

```bash
sdk install gradle 8.12
gradle --version
```

:::tip[Always use the wrapper]
Gradle projects ship a wrapper that downloads the exact Gradle version the project needs. You almost never call the global `gradle`.

```bash
./gradlew build    # Linux/macOS
gradlew.bat build  # Windows
```

It's like `.nvmrc` + auto-install combined.
:::

## Your first Kotlin project

```bash
mkdir -p ~/kotlin-hello && cd ~/kotlin-hello

gradle init \
  --type kotlin-application \
  --dsl kotlin \
  --project-name kotlin-hello \
  --package com.example \
  --no-split-project \
  --java-version 21
```

### The entry point

<Tabs syncKey="lang">
  <TabItem label="TypeScript">

```typescript
// src/index.ts
console.log("Hello, TypeScript!");
// Run: npx ts-node src/index.ts
```

  </TabItem>
  <TabItem label="Go">

```go
// main.go
package main

import "fmt"

func main() {
    fmt.Println("Hello, Go!")
}
// Run: go run .
```

  </TabItem>
  <TabItem label="Kotlin">

```kotlin
// src/main/kotlin/com/example/App.kt
package com.example

fun main() {
    println("Hello, Kotlin!")
}
// Run: ./gradlew run
```

  </TabItem>
</Tabs>

Key differences: `main()` is a top-level function (no class wrapper). `println()` is top-level, not `System.out.println()`. Package maps to directory (like Go). Semicolons optional (like Go).

### Build and run

```bash
./gradlew build          # compile + test
./gradlew run            # run the app
./gradlew test           # tests only
./gradlew clean          # remove build artifacts
./gradlew build -x test  # build, skip tests
```

### Minimal single-module project

```kotlin title="settings.gradle.kts"
rootProject.name = "kotlin-hello"
```

```kotlin title="build.gradle.kts"
plugins {
    kotlin("jvm") version "2.1.0"
    application
}

group = "com.example"
version = "1.0-SNAPSHOT"

repositories {
    mavenCentral()
}

dependencies {
    testImplementation(kotlin("test"))
}

tasks.test {
    useJUnitPlatform()
}

application {
    mainClass.set("com.example.MainKt")
}
```

```kotlin title="src/main/kotlin/com/example/Main.kt"
package com.example

fun main() {
    println("Hello from Kotlin!")

    val name = "Kotlin Developer"
    println("Welcome, $name!")

    val message = """
        |This is a multi-line string.
        |The | character marks the margin.
        |Kotlin trims the left margin with trimMargin().
    """.trimMargin()
    println(message)
}
```

:::note[Why `com.example.MainKt`?]
Kotlin compiles a file `Main.kt` with top-level `main()` into a JVM class `MainKt` (the JVM requires code inside classes). That's the name in the Gradle config.
:::

Generate the wrapper if you built by hand:

```bash
gradle wrapper --gradle-version 8.12
./gradlew run
```

## build.gradle.kts explained

```kotlin title="build.gradle.kts"
plugins {
    kotlin("jvm") version "2.1.0"   // compiles .kt files (like typescript + tsconfig)
    application                      // adds `run` task (like "scripts": {"start": ...})
}

group = "com.example"       // like npm org scope: @example/my-app
version = "1.0-SNAPSHOT"    // SNAPSHOT = development

repositories {
    mavenCentral()          // where deps come from (npm has npmjs.com)
}

dependencies {
    implementation("org.jetbrains.kotlinx:kotlinx-serialization-json:1.7.3")
    testImplementation(kotlin("test"))
    testImplementation("org.junit.jupiter:junit-jupiter:5.11.3")
}

tasks.test {
    useJUnitPlatform()
}

application {
    mainClass.set("com.example.MainKt")
}
```

### Dependency scopes

| npm | Go | Gradle | When available |
|---|---|---|---|
| `dependencies` | `require` | `implementation` | Compile + runtime |
| `dependencies` | `require` | `api` | Compile + runtime + exposed to consumers |
| `devDependencies` | test `require` | `testImplementation` | Test only |
| — | — | `runtimeOnly` | Runtime only |
| — | — | `compileOnly` | Compile only (not packaged) |

### Dependency coordinates

```text
org.jetbrains.kotlinx:kotlinx-coroutines-core:1.9.0
│                      │                        │
├── Group ID           ├── Artifact ID          └── Version
    (like npm scope)      (like package name)
```

Find them on [Maven Central](https://search.maven.org/) — the npmjs.com of the JVM world.

### Version catalogs

Centralize versions in `gradle/libs.versions.toml`:

```toml title="gradle/libs.versions.toml"
[versions]
kotlin = "2.1.0"
ktor = "3.0.3"
junit = "5.11.3"

[libraries]
kotlinx-serialization-json = { module = "org.jetbrains.kotlinx:kotlinx-serialization-json", version.ref = "kotlin" }
ktor-server-core = { module = "io.ktor:ktor-server-core", version.ref = "ktor" }
junit-jupiter = { module = "org.junit.jupiter:junit-jupiter", version.ref = "junit" }

[plugins]
kotlin-jvm = { id = "org.jetbrains.kotlin.jvm", version.ref = "kotlin" }
```

```kotlin
dependencies {
    implementation(libs.kotlinx.serialization.json)
    implementation(libs.ktor.server.core)
    testImplementation(libs.junit.jupiter)
}
```

### settings.gradle.kts

Single-module: one line. Multi-module lists modules (like npm workspaces or a Go workspace):

```kotlin
rootProject.name = "my-platform"

include("app")
include("core")
include("api-client")
```

## Gradle commands cheat sheet

| What you want | npm | go | Gradle |
|---|---|---|---|
| Install deps | `npm install` | `go mod download` | `./gradlew build` (auto) |
| Run the app | `npm start` | `go run .` | `./gradlew run` |
| Run tests | `npm test` | `go test ./...` | `./gradlew test` |
| Clean | `rm -rf dist/` | `go clean` | `./gradlew clean` |
| Add a dependency | `npm install lodash` | `go get ...` | edit build.gradle.kts, `./gradlew build` |
| Format code | `prettier --write .` | `gofmt -w .` | `./gradlew ktlintFormat` |
| Lint | `eslint .` | `golangci-lint run` | `./gradlew ktlintCheck` |
| List tasks | `npm run` | — | `./gradlew tasks` |
| Run with args | `npm start -- --port 8080` | `go run . --port 8080` | `./gradlew run --args="--port 8080"` |

```bash
./gradlew tasks                  # list tasks
./gradlew build --info           # verbose
./gradlew build -x test          # skip a task
./gradlew build --refresh-dependencies
./gradlew run --continuous       # rebuild on change (like nodemon)
./gradlew dependencies           # dependency tree (like npm ls)
```

## Docker infrastructure

<Steps>

1. Start all services:

   ```bash
   cd shared-infra
   docker compose up -d
   ```

2. Check status:

   ```bash
   docker compose ps
   ```

3. Verify each service:

   ```bash
   docker exec kotlin-course-postgres pg_isready -U dev
   docker exec kotlin-course-redis redis-cli ping    # PONG
   # Kafka UI at http://localhost:8090
   ```

</Steps>

| Service | Host | Port | Credentials |
|---|---|---|---|
| PostgreSQL | localhost | 5432 | `dev` / `dev` / `kotlin_course` |
| Redis | localhost | 6379 | no auth |
| Kafka | localhost | 29092 | no auth |
| Kafka UI | localhost | 8090 | web UI |

```bash
docker compose stop          # stop, keep data
docker compose down          # remove containers, keep volumes
docker compose down -v       # remove everything including data
docker compose logs -f postgres
docker compose restart redis
```

### Docker for TS/Go devs

| Concept | Node.js / Go | JVM / Kotlin |
|---|---|---|
| Base image | `node:21-alpine` / `golang:1.22` | `eclipse-temurin:21-jre-alpine` |
| Build step | `npm run build` / `go build` | `./gradlew build` |
| Runtime size | ~150MB / ~10MB | ~200MB (JRE) or ~30MB (GraalVM native) |
| Hot reload | `nodemon` / `air` | `./gradlew run --continuous` or Spring DevTools |

```dockerfile title="Dockerfile"
FROM eclipse-temurin:21-jdk-alpine AS build
WORKDIR /app
COPY gradle gradle
COPY gradlew build.gradle.kts settings.gradle.kts ./
RUN ./gradlew dependencies --no-daemon
COPY src src
RUN ./gradlew build -x test --no-daemon

FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY --from=build /app/build/libs/*.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

## Project structure conventions

| TypeScript | Go | Kotlin |
|---|---|---|
| `import { foo } from './utils'` | `import "myapp/internal/utils"` | `import com.example.myapp.utils.foo` |
| File-path based | Module-path based | Package based (maps to directories) |

```kotlin title="src/main/kotlin/com/example/myapp/models/User.kt"
package com.example.myapp.models

data class User(
    val id: Long,
    val name: String,
    val email: String,
)
```

| Source set | Directory | Purpose |
|---|---|---|
| `main` | `src/main/kotlin/` | Application code |

| `test` | `src/test/kotlin/` | Test code |
