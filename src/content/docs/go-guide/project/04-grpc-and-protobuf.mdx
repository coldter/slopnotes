## The big picture

Several Go processes talk to each other. A client speaks the PostgreSQL wire protocol to a gateway; the gateway calls a pooler over gRPC; the pooler runs real SQL against PostgreSQL. Every arrow labelled "gRPC" below is generated from a `.proto` file in `proto/`:

<Mermaid title="Who talks to whom" height={360} code={`
flowchart LR
  Client(["client (PG wire)"]) --> GW["gateway"]
  GW -->|"gRPC"| POOL["pooler"]
  POOL -->|"libpq"| PG[("PostgreSQL")]
  ORCH["orchestrator"] -.->|"consensus / failover"| POOL
  ADMIN["admin"] -.->|"gRPC + REST"| POOL
`} />

The contract — message shapes, method names, error codes — lives in those `.proto` files; the Go under `internal/pb/` is mechanically derived and checked in. Read generated code for *shape*, not logic — one service file alone is ~90 KB. Trace bugs to the hand-written source.

## The proto layout: service vs. data split

RPC messages and service definitions live in separate files on purpose: the messages double as wire format **and** storage format (and feed an internal non-gRPC transport too). A typical service file imports its messages from sibling data files:

| Service file (`*service.proto`) | Data file(s) it imports |
| --- | --- |
| `consensusservice.proto` | `consensusdata.proto`, `poolermanagerdata.proto` |
| `poolermanagerservice.proto` | `poolermanagerdata.proto` |

`proto/consensusservice.proto` defines **no messages of its own** — it imports the data files and references their types directly:

```proto title="proto/consensusservice.proto"
import "consensusdata.proto";
import "poolermanagerdata.proto";

service PoolerConsensus {
  rpc Recruit(consensusdata.RecruitRequest) returns (consensusdata.RecruitResponse);
  rpc Promote(consensusdata.PromoteRequest) returns (consensusdata.PromoteResponse);
  // ...
}
```

:::tip[Why `poolerservice.proto` breaks the convention]
The latency-sensitive query path defines its request/response messages *inline* because it composes shared types from other files — `query.proto` (`query.Target`, `query.QueryResultPayload`, `query.ReservedState`) and `rpc.proto` (`rpc.CallerID`) — so there's no single data file to factor out:

```proto title="proto/poolerservice.proto"
import "clustermetadata.proto";
import "google/protobuf/duration.proto";
import "rpc.proto";
import "query.proto";
```

Not every service follows the split cleanly — `orchservice.proto` also defines messages inline. Check the actual `import` lines before assuming a sibling `*data.proto` is in use.
:::

Every `.proto` declares its package and Go output path:

```proto title="proto/gatewayservice.proto"
package gatewayservice;
option go_package = "github.com/example/platform/internal/pb/gatewayservice";
```

`go_package` is the directory under `internal/pb/` the generator writes into. A proto `import "query.proto"` becomes a normal Go import of `.../internal/pb/query` in the generated code — one proto package per generated Go package:

<FileTree>
- proto/
  - **gatewayservice.proto** service: one `CancelQuery` RPC
  - poolerservice.proto service: query path (inline messages)
  - consensusservice.proto service: imports its data files
  - consensusdata.proto data: `Recruit`/`Promote` messages
  - query.proto shared types (`Target`, `QueryResultPayload`)
  - rpc.proto error model (`Code`, `RPCError`)
- internal/
  - pb/
    - gatewayservice/ generated from `gatewayservice.proto`
    - poolerservice/ generated, ~90 KB of code
    - query/ generated shared types
    - ... one package per `.proto`
</FileTree>

## How the codegen works

`make proto` runs raw `protoc` with three plugins and copies the result into place (no `buf` wrapper):

```bash title="Makefile (the proto recipe)"
protoc \
  --plugin=protoc-gen-go --go_out=. \
  --plugin=protoc-gen-go-grpc --go-grpc_out=. \
  --plugin=protoc-gen-grpc-gateway --grpc-gateway_out=. \
  --grpc-gateway_opt=generate_unbound_methods=true \
  --proto_path=proto $(PROTO_SRCS) && \
mkdir -p internal/pb && \
cp -Rf github.com/example/platform/internal/pb/* internal/pb/ && \
rm -rf github.com/ google.golang.org/
```

Three plugins produce three kinds of output per service:

| Plugin | Reads | Emits | Contains |
| --- | --- | --- | --- |
| `protoc-gen-go` | messages | `*.pb.go` | struct types + getters + reflection |
| `protoc-gen-go-grpc` | services | `*_grpc.pb.go` | client/server interfaces, registration |
| `protoc-gen-grpc-gateway` | `(google.api.http)` annotations | `*.pb.gw.go` | REST-to-gRPC adapter |

Because of `go_package`, the compiler first writes into a scratch `github.com/example/...` tree; the recipe copies that into `internal/pb/` and deletes the scratch dirs. The output is committed and stamped `// Code generated by ... DO NOT EDIT.` Trace bugs to the `.proto` source and regenerate — never hand-edit `internal/pb/`.

## Generated messages (`*.pb.go`)

The simplest service, `GatewayService` (one unary RPC), shows the message shape:

```go title="internal/pb/gatewayservice/gatewayservice.pb.go"
type CancelQueryRequest struct {
	state         protoimpl.MessageState `protogen:"open.v1"`
	ProcessId     uint32 `protobuf:"varint,1,opt,name=process_id,json=processId,proto3" json:"process_id,omitempty"`
	SecretKey     uint32 `protobuf:"varint,2,opt,name=secret_key,json=secretKey,proto3" json:"secret_key,omitempty"`
	Replica       bool   `protobuf:"varint,3,opt,name=replica,proto3" json:"replica,omitempty"`
	unknownFields protoimpl.UnknownFields
	sizeCache     protoimpl.SizeCache
}
```

Anatomy:

- **Opaque header** — `state`, `unknownFields`, `sizeCache` are unexported runtime bookkeeping; never touch them. The `` `protogen:"open.v1"` `` tag marks the modern "opaque API" mode.
- **Exported fields** carry `` `protobuf:"..."` `` tags encoding field number, wire type, and JSON name. The proto field number (`= 1`, `= 2`) is the wire identity and must never be reused — the basis of forward/backward compatibility.
- **Methods** `Reset()`, `String()`, `ProtoReflect()` satisfy the protobuf-v2 `proto.Message` interface.
- **Nil-safe getters** for every field:

```go title="internal/pb/gatewayservice/gatewayservice.pb.go"
func (x *CancelQueryRequest) GetProcessId() uint32 {
	if x != nil {
		return x.ProcessId
	}
	return 0
}
```

:::tip[Idiom: always use `GetX()` on proto messages]
A generated getter returns the zero value when the receiver *or* an intermediate message is nil, so you can chain through optional nested messages safely: `req.GetReservationOptions().GetReasons()` walks two possibly-nil messages without a panic.
:::

An empty message still becomes a real struct (with only the opaque header) — the *fact* of a successful return is the payload.

## Generated service interfaces (`*_grpc.pb.go`)

The `*_grpc.pb.go` file for `GatewayService` is small enough to read end to end. It opens with a **version guard** — a compile-time assertion that the generated file matches the linked gRPC runtime:

```go title="internal/pb/gatewayservice/gatewayservice_grpc.pb.go"
const _ = grpc.SupportPackageIsVersion9 // requires gRPC-Go v1.64.0+
```

**The client side** is an interface, an unexported impl, and a constructor:

```go title="internal/pb/gatewayservice/gatewayservice_grpc.pb.go"
type GatewayServiceClient interface {
	CancelQuery(ctx context.Context, in *CancelQueryRequest, opts ...grpc.CallOption) (*CancelQueryResponse, error)
}

type gatewayServiceClient struct {
	cc grpc.ClientConnInterface
}

func NewGatewayServiceClient(cc grpc.ClientConnInterface) GatewayServiceClient {
	return &gatewayServiceClient{cc}
}
```

Construct a client by handing `NewXClient` a live `*grpc.ClientConn`; the method marshals the request and calls `cc.Invoke` on a generated full-method-name constant (`/gatewayservice.GatewayService/CancelQuery`).

**The server side** is an interface you must implement, plus a mandatory embed:

```go title="internal/pb/gatewayservice/gatewayservice_grpc.pb.go"
type GatewayServiceServer interface {
	CancelQuery(context.Context, *CancelQueryRequest) (*CancelQueryResponse, error)
	mustEmbedUnimplementedGatewayServiceServer()
}

type UnimplementedGatewayServiceServer struct{}

func (UnimplementedGatewayServiceServer) CancelQuery(context.Context, *CancelQueryRequest) (*CancelQueryResponse, error) {
	return nil, status.Errorf(codes.Unimplemented, "method CancelQuery not implemented")
}
func (UnimplementedGatewayServiceServer) mustEmbedUnimplementedGatewayServiceServer() {}
```

The interface has an unexported method `mustEmbedUnimplementedGatewayServiceServer()` — the only way to satisfy it is to embed `UnimplementedGatewayServiceServer` (interface satisfaction by **struct embedding**).

:::caution[Gotcha — embed by value, and embed it for forward compatibility]
Embed `UnimplementedXServer` *by value, not pointer*, to avoid a nil-pointer dereference. The deeper reason: when a new `rpc` is added to the proto, every existing server keeps compiling, because the embedded `Unimplemented` type already provides a method for it. `RegisterXServer` even self-tests this at startup via a generated `testEmbeddedByValue()` probe, so a pointer-embed bug fails at registration instead of at runtime under load.
:::

Finally, the **registration function + service descriptor**:

```go title="internal/pb/gatewayservice/gatewayservice_grpc.pb.go"
func RegisterGatewayServiceServer(s grpc.ServiceRegistrar, srv GatewayServiceServer) {
	// ...
	s.RegisterService(&GatewayService_ServiceDesc, srv)
}

var GatewayService_ServiceDesc = grpc.ServiceDesc{
	ServiceName: "gatewayservice.GatewayService",
	HandlerType: (*GatewayServiceServer)(nil),
	Methods:     []grpc.MethodDesc{{MethodName: "CancelQuery", Handler: _GatewayService_CancelQuery_Handler}},
	Streams:     []grpc.StreamDesc{},
	Metadata:    "gatewayservice.proto",
}
```

The `ServiceDesc` is the routing table mapping wire method names to generated `_Handler` functions.

## Unary vs. streaming RPC shapes

`proto/poolerservice.proto` exercises all three gRPC call shapes:

```proto title="proto/poolerservice.proto"
rpc ExecuteQuery(ExecuteQueryRequest) returns (ExecuteQueryResponse);                          // unary
rpc StreamExecute(StreamExecuteRequest) returns (stream StreamExecuteResponse);                // server-streaming
rpc CopyBidiExecute(stream CopyBidiExecuteRequest) returns (stream CopyBidiExecuteResponse);   // bidi
```

The `stream` keyword changes the generated Go server signature:

| Shape | Server method signature |
| --- | --- |
| Unary | `ExecuteQuery(context.Context, *ExecuteQueryRequest) (*ExecuteQueryResponse, error)` |
| Server-stream | `StreamExecute(*StreamExecuteRequest, grpc.ServerStreamingServer[StreamExecuteResponse]) error` |
| Bidi | `CopyBidiExecute(grpc.BidiStreamingServer[CopyBidiExecuteRequest, CopyBidiExecuteResponse]) error` |

The stream parameter types are **Go generics**: `grpc.ServerStreamingServer[T]` and `grpc.BidiStreamingServer[Req, Resp]` (gRPC-Go v1.64+, hence the `SupportPackageIsVersion9` guard). The generator also emits friendly **type aliases** (note the `=` — aliases, fully interchangeable with the underlying generic instantiation):

```go title="internal/pb/poolerservice/poolerservice_grpc.pb.go"
type PoolerService_StreamExecuteServer   = grpc.ServerStreamingServer[StreamExecuteResponse]
type PoolerService_CopyBidiExecuteServer = grpc.BidiStreamingServer[CopyBidiExecuteRequest, CopyBidiExecuteResponse]
```

Mental model: **unary** = one request, one response (like a function call). **Server-streaming** = one request, the server pushes N responses via `stream.Send(...)`, ending when the handler returns (the framework signals `io.EOF` to the client). **Bidi** = both sides `Send`/`Recv` independently until one closes.

## Registering a server

Gateway, pooler, and orchestrator share one server-construction path in `internal/servenv/grpc_server.go`. `Create()` assembles `grpc.ServerOption`s (TLS creds, message-size limits, keepalive) and adds OpenTelemetry plus interceptors before building the server:

```go title="internal/servenv/grpc_server.go"
opts = append(opts, grpc.KeepaliveParams(ka))
opts = append(opts, grpc.StatsHandler(otelgrpc.NewServerHandler()))  // OTel = StatsHandler, NOT interceptor
interceptorOpts, err := g.interceptors()
// ...
opts = append(opts, interceptorOpts...)
g.Server = grpc.NewServer(opts...)
```

Each service registers itself in a `servenv` `OnRun` hook, gated by `CheckServiceMap` so a process only serves the services it's configured for:

```go title="services/pooler/grpcpoolerservice/service.go"
func RegisterPoolerServices(senv *servenv.ServEnv, grpc *servenv.GrpcServer) {
	poolerserver.RegisterPoolerServices = append(poolerserver.RegisterPoolerServices, func(p *poolerserver.QueryPoolerServer) {
		if grpc.CheckServiceMap("pooler", senv) {
			srv := &poolerService{pooler: p, pubsub: p.PubSubListener()}
			poolerpb.RegisterPoolerServiceServer(grpc.Server, srv)
		}
	})
}
```

And `poolerService` embeds the generated `Unimplemented` type, exactly as predicted:

```go title="services/pooler/grpcpoolerservice/service.go"
type poolerService struct {
	poolerpb.UnimplementedPoolerServiceServer
	pooler *poolerserver.QueryPoolerServer
	pubsub *pubsub.Listener
}
```

:::caution[Gotcha — register before `Serve`]
gRPC panics with `grpc: Server.RegisterService after Server.Serve` if you register after serving starts. The codebase avoids this structurally: `servenv` runs *all* `OnRun` hooks between `Create()` and `Serve()`.
:::

### Interceptors

Interceptors are gRPC's middleware, chained with `grpc-ecosystem/go-grpc-middleware`:

```go title="internal/servenv/grpc_server.go"
return []grpc.ServerOption{
	grpc.UnaryInterceptor(grpcmiddleware.ChainUnaryServer(collector.unaryInterceptors...)),
	grpc.StreamInterceptor(grpcmiddleware.ChainStreamServer(collector.streamInterceptors...)),
}
```

The only built-in interceptor is an optional auth plugin, added as both unary and stream only when auth mode is configured. Two things to internalize: **OpenTelemetry tracing is a `StatsHandler`, not an interceptor** (Stats handlers see lower-level connection/RPC events); and when there are zero interceptors, the builder returns an empty option slice — no chain installed at all.

## Dialing clients

Two client-lifetime strategies — know which one you're looking at.

**(a) Per-connection client (query path).** The gateway holds one generated client per pooler connection:

```go title="services/gateway/poolergateway/grpc_query_service.go"
type grpcQueryService struct {
	conn   *grpc.ClientConn
	client poolerservice.PoolerServiceClient
	// ...
}

func newGRPCQueryService(conn *grpc.ClientConn, /* ... */) queryservice.QueryService {
	return &grpcQueryService{
		conn:   conn,
		client: poolerservice.NewPoolerServiceClient(conn),
		// ...
	}
}
```

**(b) Cached persistent client (consensus/manager path).** `internal/rpcclient` keeps one persistent `*grpc.ClientConn` per pooler address with LRU eviction and reference counting (a pattern Vitess uses too, its `cachedConnDialer`). Every RPC method follows the same shape:

```go title="internal/rpcclient/grpc_client.go"
func (c *Client) Recruit(ctx context.Context, pooler *clustermetadatapb.Pooler, request *consensusdatapb.RecruitRequest) (*consensusdatapb.RecruitResponse, error) {
	conn, closer, err := c.dialPersistent(ctx, pooler)
	if err != nil {
		return nil, err
	}
	defer func() { _ = closer() }()
	return conn.consensusClient.Recruit(ctx, request)
}
```

The cache stores the *generated clients*, not just the conn:

```go title="internal/rpcclient/conn_cache.go"
conn := &cachedConn{
	consensusClient: consensuspb.NewPoolerConsensusClient(grpcConn),
	managerClient:   poolermanagerpb.NewPoolerManagerClient(grpcConn),
	cc:              grpcConn,
	// ...
}
```

The actual `*grpc.ClientConn` is created via `grpccommon.NewClient`, which wraps `grpc.NewClient` and attaches an OTel client `StatsHandler` by default:

```go title="internal/grpccommon/options.go"
allOpts := append([]grpc.DialOption{
	grpc.WithStatsHandler(otelgrpc.NewClientHandler(cfg.otelOptions...)),
}, cfg.dialOptions...)
return grpc.NewClient(target, allOpts...)
```

:::caution[Gotcha — connection lifetime is reference-counted, not per-call]
`dialPersistent` returns a `closer()` that *decrements* a refcount; the conn is reused across calls and only LRU-evicted when its refcount hits zero. Forgetting `defer closer()` leaks a reference and blocks eviction forever — which is why every method in `grpc_client.go` defers it. For streams, the ref is held for the stream's lifetime and released on the first `Recv`/`Send` error via a `sync.Once` wrapper.
:::

## grpc-gateway REST — admin only

Because the codegen runs the grpc-gateway plugin with `generate_unbound_methods=true`, a `.pb.gw.go` is generated for *every* service. But only `proto/adminservice.proto` carries `(google.api.http)` annotations, and `admin` is the only process that mounts a gateway mux. The latency-sensitive client-to-gateway-to-pooler path is pure gRPC (and the gateway speaks raw PG wire to clients, not gRPC). The admin proto annotates each `rpc`:

```proto title="proto/adminservice.proto"
rpc GetCell(GetCellRequest) returns (GetCellResponse) {
  option (google.api.http) = {get: "/api/v1/cells/{name}"};
}
```

And the admin service builds the mux and registers it **in-process**:

```go title="services/admin/init.go"
gwmux := runtime.NewServeMux(
	runtime.WithMarshalerOption(runtime.MIMEWildcard, &runtime.JSONPb{
		MarshalOptions:   protojson.MarshalOptions{EmitUnpopulated: true, UseProtoNames: true},
		UnmarshalOptions: protojson.UnmarshalOptions{DiscardUnknown: true},
	}),
)
if err := adminpb.RegisterAdminServiceHandlerServer(ctx, gwmux, ma.adminServer); err != nil {
	// ...
} else {
	ma.senv.HTTPHandle("/api/", gwmux)
}
```

`RegisterAdminServiceHandlerServer` calls the server methods *directly* — no extra network hop — so REST is just a JSON front door onto the same Go methods the gRPC clients call. The marshaler uses `UseProtoNames: true` (snake_case JSON matching the proto) and `EmitUnpopulated: true` (zero-value fields still appear).

:::caution[Gotcha — not every service has REST]
The `.pb.gw.go` files exist broadly, but only admin registers a mux. Don't assume an arbitrary service exposes HTTP.
:::

## Errors over the wire

The contract is `proto/rpc.proto`. Its `enum Code` deliberately mirrors `grpc/codes` for values 0–16, then adds two custom codes; `message RPCError` carries the message, code, and optional diagnostic:

```proto title="proto/rpc.proto"
enum Code {
  OK = 0;
  CANCELED = 1;
  // ...
  UNAUTHENTICATED = 16;
  CLUSTER_EVENT = 17;   // custom
  READ_ONLY = 18;       // custom
}

message RPCError {
  string message = 1;
  Code code = 2;
  optional query.PgDiagnostic pg_diagnostic = 3;  // full PG error detail
}
```

Because 0–16 match exactly, the conversion is a direct numeric cast — `codes.Code(Code(err))`.

**Outbound: `ToGRPC`.** If the error is (or wraps) a `*PgDiagnostic`, it attaches an `RPCError` carrying the full diagnostic via `status.WithDetails`:

```go title="internal/errx/grpc.go"
func ToGRPC(err error) error {
	if err == nil { return nil }
	var diag *PgDiagnostic
	if errors.As(err, &diag) {
		st := status.New(codes.Code(Code(err)), truncateError(err))
		rpcErr := &rpcpb.RPCError{Message: err.Error(), Code: rpcpb.Code_UNKNOWN, PgDiagnostic: PgDiagnosticToProto(diag)}
		stWithDetails, detailErr := st.WithDetails(rpcErr)
		if detailErr != nil { /* fall back if details too big */ return st.Err() }
		return stWithDetails.Err()
	}
	return status.Errorf(codes.Code(Code(err)), "%v", truncateError(err))
}
```

`truncateError` caps the message length for gRPC's ~8 KiB header budget. Codes 17/18 exceed the standard gRPC range, so they only round-trip through the `RPCError` detail, not the bare status — fine here because both ends are the same system.

**Inbound: `FromGRPC`** reverses it, with three subtle cases:

```go title="internal/errx/grpc.go"
func FromGRPC(err error) error {
	if err == nil { return nil }
	if err == io.EOF { return err }   // (1) pass io.EOF through untouched
	st, ok := status.FromError(err)
	if !ok { return New(rpcpb.Code_UNKNOWN, err.Error()) }

	switch st.Code() {                // (2) rebuild PG cancel/timeout errors
	case codes.DeadlineExceeded:
		return NewStatementTimeout()
	case codes.Canceled:
		return NewQueryCanceled()
	}

	for _, detail := range st.Details() {  // (3) reconstruct PgDiagnostic from details
		if rpcErr, ok := detail.(*rpcpb.RPCError); ok {
			if rpcErr.GetPgDiagnostic() != nil {
				return PgDiagnosticFromProto(rpcErr.GetPgDiagnostic())
			}
			return New(rpcErr.Code, rpcErr.Message)
		}
	}
	return New(rpcpb.Code(st.Code()), st.Message())
}
```

:::caution[Gotcha — PostgreSQL fidelity lives in the status details, not the status code]
A naive client reading only `status.Code()`/`status.Message()` loses SQLSTATE, severity, hint, and position — always round-trip through `errx.FromGRPC`. `WithDetails` can fail silently if the detail exceeds the ~8 KiB budget (ToGRPC logs a warning and falls back to code-only). And **never wrap `io.EOF`**: streaming clients detect a *clean* stream end with `errors.Is(err, io.EOF)`; `FromGRPC` passes it through untouched so normal completion isn't mistaken for a failure.
:::

## The canonical trio: one streamed query, server + client

The proto is one line:

```proto title="proto/poolerservice.proto"
rpc StreamExecute(StreamExecuteRequest) returns (stream StreamExecuteResponse);
```

`StreamExecuteResponse` carries a `query.QueryResultPayload result` and an optional `query.ReservedState reserved_state`. The `result` payload is a `oneof` with three arms — `QueryResult`, `PgDiagnostic`, `PgNotification`.

**Server side** — note the alias signature, `Send` into the stream, and `errx.ToGRPC(err)`:

```go title="services/pooler/grpcpoolerservice/service.go"
func (s *poolerService) StreamExecute(req *poolerpb.StreamExecuteRequest, stream poolerpb.PoolerService_StreamExecuteServer) error {
	if err := s.pooler.StartRequest(req.Target, admissionKind(/* ... */)); err != nil {
		return errx.ToGRPC(err)
	}
	if reasons := req.GetReservationOptions().GetReasons(); reasons != 0 {
		if err := protoutil.ValidateReasons(reasons); err != nil {
			return status.Errorf(codes.InvalidArgument, "invalid reservation reasons: %v", err)  // boundary validation
		}
	}
	// ...
	reservedState, err := executor.StreamExecute(stream.Context(), /* ... */, func(ctx context.Context, result *sqltypes.Result) error {
		resp := &poolerpb.StreamExecuteResponse{Result: rowPayload}
		return stream.Send(resp)
	})
	// ...
	return errx.ToGRPC(err)
}
```

Two error styles coexist on purpose: `status.Errorf(codes.InvalidArgument, ...)` for *trust-boundary validation* (a malformed request from the network), and `errx.ToGRPC(err)` for *domain errors* that may carry a `PgDiagnostic`.

**Client side** — call the generated client, loop on `Recv()` until `io.EOF`, switch on the `oneof`, and wrap every error with `FromGRPC`:

```go title="services/gateway/poolergateway/grpc_query_service.go"
stream, err := g.client.StreamExecute(ctx, req)
if err != nil {
	return nil, errx.Wrapf(errx.FromGRPC(err), "failed to start stream execute")
}
for {
	response, err := stream.Recv()
	if errors.Is(err, io.EOF) {
		return reservedState, nil          // clean end
	}
	if err != nil {
		return reservedState, errx.Wrapf(errx.FromGRPC(err), "stream receive error")
	}
	switch p := response.Result.GetPayload().(type) {
	case *querypb.QueryResultPayload_Result:
		result := sqltypes.ResultFromProto(p.Result)
		if err := callback(ctx, result); err != nil { return reservedState, err }
	case *querypb.QueryResultPayload_Diagnostic:
		diag := errx.PgDiagnosticFromProto(p.Diagnostic)
		// ...
	}
}
```

The `oneof` from the proto becomes a Go interface whose concrete implementations are `QueryResultPayload_Result` / `QueryResultPayload_Diagnostic`; discriminate with a [type switch](/go-guide/language/03-interfaces-composition/). The `ctx` threaded into `client.StreamExecute` carries the deadline/cancellation that `FromGRPC` translates back into PG cancel/timeout errors.

## Checkpoints

<details><summary>Why are <code>RecruitRequest</code>/<code>RecruitResponse</code> defined in <code>consensusdata.proto</code> instead of <code>consensusservice.proto</code>?</summary>
RPC *messages* (data files) are deliberately split from *service* definitions (service files): the messages double as wire/storage format and feed an internal non-gRPC transport, so they're decoupled from the gRPC service. <code>consensusservice.proto</code> imports the data file and references its types directly.</details>

<details><summary>What breaks if a server type embeds <code>UnimplementedXServer</code> by pointer instead of by value, and where is it caught?</summary>
A nil-pointer dereference can occur when an unimplemented method is invoked. The generated comment warns to embed by value, and <code>RegisterXServer</code> runs a <code>testEmbeddedByValue()</code> probe at registration time so the bug surfaces at startup rather than under live traffic.</details>

<details><summary>A PostgreSQL constraint-violation error travels pooler to gateway. How does SQLSTATE survive, and what would lose it?</summary>
<code>errx.ToGRPC</code> detects the <code>*PgDiagnostic</code> via <code>errors.As</code>, packs it into an <code>rpcpb.RPCError</code>, and attaches it to the status with <code>status.WithDetails</code>. <code>errx.FromGRPC</code> reads <code>st.Details()</code>, finds the <code>RPCError</code>, and rebuilds the <code>*PgDiagnostic</code>. A client reading only <code>status.Code()</code>/<code>status.Message()</code> — or a detail too large for the ~8 KiB limit, which triggers the warn-and-fallback path — loses SQLSTATE.</details>

<details><summary>Why must the client stream loop special-case <code>io.EOF</code>, and how does <code>FromGRPC</code> cooperate?</summary>
<code>io.EOF</code> is the normal signal that a server-stream finished cleanly. The client checks <code>errors.Is(err, io.EOF)</code> and returns success. <code>FromGRPC</code> passes <code>io.EOF</code> through untouched; wrapping it would turn clean completion into a spurious error.</details>
