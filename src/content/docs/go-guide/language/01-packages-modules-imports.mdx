## The package clause is not the directory name

Every `.go` file starts with `package <name>`. All files in one directory form one package and must declare the same name. Callers import the *path* but reference the *package name*:

```go title="internal/foo/bar/baz.go"
// directory is "baz"
package baz   // conventional: package name == last path segment

func Hello() string { return "hi" }
```

```go
import "example.com/m/internal/foo/bar/baz"

func main() { _ = baz.Hello() }  // "baz" is the package name, not the path
```

The convention holds across this repo: `internal/parser/keywords.go` is `package parser`, every `cmd/*` binary is `package main`. `main` is the only package that produces an executable (it needs `func main()`).

:::note
Path lives in the import, name lives in the source. When they diverge, call sites get confusing — which is why this repo aliases its generated protobuf imports (see below).
:::

## Exported vs unexported: capitalization is the only rule

No `public`/`private`/`protected`. An identifier is visible outside its package **iff its first letter is uppercase**.

```go
package widget

type Gadget struct {   // exported type
	Name  string        // exported field
	count int           // unexported field — package-private
}

func New() *Gadget { return &Gadget{} } // exported constructor
func reset() {}                          // unexported helper
```

Real example — exported service-name constants:

```go title="internal/constants/service.go"
package constants

const (
	// ServiceGateway is the name of the gateway service.
	ServiceGateway = "gateway"
	// ServicePooler is the name of the pooler service.
	ServicePooler = "pooler"
	// ...
)
```

vs. an unexported lookup table nothing outside the parser should touch:

```go title="internal/parser/keywords.go"
// keywordLookupMap provides fast keyword lookup by name.
var keywordLookupMap map[string]*KeywordInfo
```

`keywordLookupMap` (lowercase `k`) can't be named from any other package; callers go through exported `LookupKeyword`. Pick uppercase only for the API you intend to support.

:::tip[Idiom]
Doc-comment each exported identifier, starting with its name (`// ServiceGateway is ...`). `go vet` and `go doc` rely on this.
:::

## The module: one `go.mod`, one path prefix

One module, one `go.mod` at the root:

```go title="go.mod"
module github.com/example/platform

go 1.25.1
```

Two facts follow:

1. The module path is the import prefix for all internal code: `internal/constants` imports as `github.com/example/platform/internal/constants` (module path + directory).
2. `go 1.25.1` sets the language/toolchain version; constructs newer than the module declares won't build.

`require` blocks list dependencies; transitive ones carry `// indirect`:

```go title="go.mod"
require (
	github.com/davecgh/go-spew v1.1.2-... // indirect
	gopkg.in/yaml.v3 v3.0.1
)
```

`// indirect` is maintained by `go mod tidy` — don't hand-edit. One module means no per-directory `go.mod`; architectural boundaries are enforced by `internal/` + lint rules instead.

## Import grouping: goimports local-prefix

`gofmt` sorts within blank-line-separated groups; `goimports` adds a "local prefix" group, configured in `.golangci.yml`:

```yaml title=".golangci.yml"
formatters:
  enable:
    - gofumpt
    - goimports
  settings:
    goimports:
      local-prefixes:
        - github.com/example
```

Canonical result — stdlib, third-party, then the `github.com/example` local group last (`internal/gateway/manager.go`):

```go title="internal/gateway/manager.go" {1-3,5-7,9-13}
import (
	"context"
	"time"

	"google.golang.org/grpc"
	"google.golang.org/protobuf/types/known/durationpb"
	"google.golang.org/protobuf/types/known/timestamppb"

	"github.com/example/platform/internal/preparedstatement"
	gatewaymanagerpb "github.com/example/platform/internal/pb/gatewaymanager"
	gatewaymanagerdatapb "github.com/example/platform/internal/pb/gatewaymanagerdata"
	"github.com/example/platform/internal/gateway/handler"
	"github.com/example/platform/internal/gateway/handler/queryregistry"
)
```

:::caution[Gotcha]
The prefix is the **org** `github.com/example`, not the full repo `github.com/example/platform`. Get it wrong and CI regroups your imports. goimports guarantees stdlib-first and that local lines group together, but not the local group's position among other third-party groups — run the formatter before committing.
:::

## Aliasing generated protobuf packages

Generated protobuf packages get verbose names; alias them with a `<name>pb` suffix at the import site:

```go
gatewaymanagerpb "github.com/example/platform/internal/pb/gatewaymanager"
```

Call sites read `gatewaymanagerpb.GatewayManagerServer`; the `pb` suffix signals "generated wire type". Same for `querypb`, `topodatapb`, etc. Alias the *import*, never the generated source (it's regenerated by `make proto`).

## `internal/`: compiler-enforced visibility

A package whose import path contains `internal/` is importable **only by code rooted at `internal/`'s parent** — a compile error otherwise, not suppressible with `//nolint`:

```text
example.com/m/foo/internal/secret   // importable by foo/... and foo/internal/...
example.com/m/bar/baz.go            // CANNOT import foo/internal/secret -> build fails
```

Real `internal/` directories in this tree:

<FileTree>
- internal/
  - config/
    - **internal/** subpkgs: registry, sync, value
  - asthelpergen/
    - internal/
  - servenv/
    - internal/ subpkg: mux
  - pooler/
    - internal/
</FileTree>

A package importing its *own* internal subpackage:

```go title="internal/config/registry.go" {4}
import (
	"github.com/spf13/viper"

	"github.com/example/platform/internal/config/internal/sync"
)
```

Only code under `internal/config/...` may import `.../config/internal/sync`; `internal/pooler` attempting it fails with `use of internal package ... not allowed`.

:::caution[Gotcha]
This `sync` package *shadows* stdlib `sync` within `registry.go` — the field `dynamic *sync.Viper` is the internal type, not `sync.Mutex`. Read the import block before assuming what a short package name resolves to.
:::

## depguard: architecture the language cannot express

`internal/` encodes only parent/child visibility. The wider dependency direction is enforced at lint time in `.golangci.yml`:

| Directory | Rule |
|---|---|
| `./cmd/...` | can depend on anything |
| `./internal/<service>/...` | cannot depend on `cmd/` or other services |
| `./internal/...` (shared) | cannot depend on `cmd/` or services |
| `./internal/tools/...` | cannot depend on any repo code outside `tools/` |

Key rules:

- **`parser-isolation`** — `internal/parser/**` may import only itself + stdlib, so the parser lifts out as a standalone library:
  ```yaml title=".golangci.yml"
  parser-isolation:
    list-mode: lax
    files: ["**/internal/parser/**"]
    deny:
      - pkg: "github.com/example/platform/internal"
        desc: "parser can only depend on itself ..."
    allow:
      - $gostd
      - github.com/example/platform/internal/parser
  ```
- **`tools-isolation`** — denies `github.com/example/platform` outside `internal/tools`.
- **Per-service isolation** (`pooler-isolation`, `orch-isolation`, …) — importable only by own package + its `cmd`.
- **`use_modern_packages`** — denies `math/rand$`, forcing `math/rand/v2`.

:::caution[Gotcha]
depguard is lint-time only and `list-mode: lax` (deny-list): an unmentioned new import is allowed by default. It complements, not replaces, `internal/`. Also: `import "math/rand"` compiles but fails lint, and so does `os.Exit` outside `main`/`TestMain` (`forbidigo`). "If it compiles, it passes" is wrong here.
:::

## Package-level `var`/`const` and `init()`

Package-level blocks initialize before any `init()`. `const` + `iota` builds an enum:

```go
type Color int
const (
	Red   Color = iota // 0
	Green              // 1
	Blue               // 2
)
```

Real use in `internal/parser/keywords.go`:

```go title="internal/parser/keywords.go"
type KeywordCategory int
const (
	UnreservedKeyword KeywordCategory = iota // 0
	ColNameKeyword                            // 1
	TypeFuncNameKeyword                       // 2
	ReservedKeyword                           // 3
)
```

`init()` runs once per package after vars, before `main`. Multiple `init()`s (even across files) are allowed. The keyword map:

```go title="internal/parser/keywords.go"
func init() {
	keywordLookupMap = make(map[string]*KeywordInfo, len(Keywords))
	for i := range Keywords {
		keywordLookupMap[Keywords[i].Name] = &Keywords[i]
	}
}
```

`init()` turns the `Keywords` slice into an O(1) map. `internal/config/config.go` similarly inverts maps in a second example.

:::caution[Gotcha]
Ordering guarantee: package vars first (dependency order), then `init()` in file-name sort order within a package, then `main`. Cross-package order is by import edges only. And inside `init()` use `panic()`, never `os.Exit` (the `forbidigo` rule says so) — `os.Exit` skips defers and is only allowed in `main`/`TestMain` with `//nolint:forbidigo`.
:::

## The blank-import plugin pattern

`import _ "path"` imports a package solely for side effects — its `init()` runs, no identifiers become available. The repo uses it to register pluggable backends. The chain:

```go title="cmd/pooler/plugin_topo.go"
package main

import (
	_ "github.com/example/platform/internal/plugins/topo"
)
```

```go title="internal/plugins/topo/plugins.go"
// Package topo provides a central place to import all topology plugins.
package topo

import (
	_ "github.com/example/platform/internal/topo/etcdtopo"
	_ "github.com/example/platform/internal/topo/memorytopo"
)
```

```go title="internal/topo/etcdtopo/store.go"
func init() {
	servenv.OnParse(registerEtcdTopoFlags)
	topo.RegisterFactory(topo.DefaultTopoImplementation, Factory{})
}
```

`main` never names `etcdtopo` or `RegisterFactory`, yet by the time `main` runs the etcd factory is registered. Dropping a backend is a one-line edit to the blank-import list.

:::caution[Gotcha]
Blank imports look like dead code and your editor's "remove unused imports" will silently delete them, disabling a feature (a topo backend never registers, then fails at runtime with "unknown implementation"). The leading `_` is load-bearing.
:::

## Build constraints

Two mechanisms select which files compile:

1. **`//go:build` lines** before the `package` clause, followed by a blank line. Three flavors appear:
   ```go
   //go:build !windows
   ```
   `internal/servenv/servenv_unix.go` compiles only on non-Windows.
   ```go
   //go:build ruleguard
   ```
   `internal/tools/ruleguard/rules.go` compiles only when the `ruleguard` tag is set (`.golangci.yml` sets it via `run.build-tags: [ruleguard]`) — pure lint-time definitions, invisible to `go build`.
   ```go
   //go:build integration
   ```
   `test/endtoend/topo_test.go` runs only under the `integration` tag.
2. **GOOS/GOARCH filename suffixes** need no `//go:build` line: `internal/config/internal/sync/sync_darwin_test.go` compiles only on macOS, `sync_linux_test.go` only on Linux.

:::caution[Gotcha]
A `//go:build` line must be followed by a blank line before the `package` clause (in `servenv_unix.go`: build line, blank, license, blank, `package servenv`). Glue them and the constraint is silently treated as an ordinary comment.
:::

## External test packages (`package foo_test`)

A `_test.go` file may declare `package foo_test` — a separate package in the same directory that sees only `foo`'s **exported** API. Use it to test as a real consumer and to break import cycles:

```go title="internal/config/internal/sync/sync_darwin_test.go"
package sync_test
```

`package foo` and `package foo_test` are the only two names allowed in one directory; anything else is a compile error ("found packages foo and bar").

## The monorepo layout

| Directory | Contents | Package | May depend on |
|---|---|---|---|
| `cmd/*` | binaries, CLIs (cobra) | `package main` | anything |
| `internal/<service>/*` | per-service logic | named | shared code, tools, pb |
| `internal/*` (shared) | parser, errx, pgprotocol, … | named | tools, pb |
| `internal/tools/*` | codebase-agnostic utilities | named | only `$gostd` + other tools |
| `internal/pb/*` | generated protobuf | named (aliased `<name>pb`) | — |

This table tells you what a file is *allowed* to import before you read a line.

## Checkpoints

1. A file at `internal/foo/bar.go` declares `package foo`. What import path do others use, and what identifier do they type?
   <details><summary>Answer</summary>Import `github.com/example/platform/internal/foo` (module path + directory), reference identifiers via package name <code>foo</code> (e.g. <code>foo.Thing</code>). Path and name are independent; here they match the last segment.</details>

2. Why can't `internal/pooler` import `internal/config/internal/sync`, and what failure is it?
   <details><summary>Answer</summary><code>internal/</code> packages are importable only by code rooted at <code>internal/</code>'s parent — here <code>internal/config/...</code>. A <em>compile error</em> ("use of internal package ... not allowed"), compiler-enforced, not suppressible with <code>//nolint</code>.</details>

3. You delete `_ "github.com/example/platform/internal/plugins/topo"` from `cmd/pooler/plugin_topo.go`. It still compiles. What breaks?
   <details><summary>Answer</summary>The blank import existed only for side effects: its <code>init()</code> chain calls <code>topo.RegisterFactory</code>. Without it no topo backend registers, and the service fails at runtime ("unknown implementation").</details>

4. `import "math/rand"` compiles. Why does CI reject it?
   <details><summary>Answer</summary>The <code>use_modern_packages</code> depguard rule denies <code>math/rand$</code>, requiring <code>math/rand/v2</code>. depguard runs at lint time, so it compiles but fails the lint gate.</details>
