## `io.Reader` / `io.Writer` / `io.Closer`: the universal stream interfaces

One-method interfaces that are the backbone of all I/O. `net.Conn`, `*bytes.Buffer`, `*os.File`, `http.ResponseWriter`, `*strings.Reader` all satisfy them implicitly:

```go
type Reader interface { Read(p []byte) (n int, err error) }
type Writer interface { Write(p []byte) (n int, err error) }
type Closer interface { Close() error }
```

The contract that trips up newcomers: `Read` can return `n > 0` **and** `err == io.EOF` in the same call. `io.EOF` is a **sentinel**, not a failure — the normal signal that the stream ended:

```go title="copyAll: treat io.EOF as 'done', not as an error"
func copyAll(dst io.Writer, src io.Reader) error {
	buf := make([]byte, 4096)
	for {
		n, err := src.Read(buf)
		if n > 0 {
			if _, werr := dst.Write(buf[:n]); werr != nil {
				return werr
			}
		}
		if err == io.EOF {
			return nil // normal termination, NOT an error
		}
		if err != nil {
			return err
		}
	}
}
```

Interfaces combine by embedding: `io.ReadWriteCloser` = `Reader` + `Writer` + `Closer`. "Accept interfaces, return structs" means functions take the *narrowest* interface they need. An event parser accepts any `io.Reader` — file, pipe, or `*bytes.Buffer` in a test:

```go title="test/endtoend/shardsetup/events.go"
func ParseEvents(t *testing.T, r io.Reader) []map[string]any {
	t.Helper()
	var events []map[string]any
	scanner := bufio.NewScanner(r)
	for scanner.Scan() {
		line := scanner.Text()
		var m map[string]any
		if err := json.Unmarshal([]byte(line), &m); err != nil {
			continue // not JSON, skip
		}
		if m["msg"] == "platform.event" {
			events = append(events, m)
		}
	}
	return events
}
```

`io.EOF` is a normal terminator elsewhere too: the PG wire client returns it to signal the *end of a COPY stream* (`return nil, io.EOF` on `CopyDone`).

:::caution[Gotcha]
Never log `io.EOF` as an error. Callers distinguish it with `err == io.EOF` or `errors.Is(err, io.EOF)`. In tests, prefer `bytes.NewReader([]byte)` / `strings.NewReader(string)` over a temp file — they allocate nothing beyond a tiny header.
:::

## `bufio`: amortizing syscalls on the hot path

Every raw `conn.Read`/`conn.Write` is a syscall. `bufio.Reader`/`bufio.Writer` batch many small operations into a few large syscalls:

```go title="Batch many small writes into one syscall on Flush"
bw := bufio.NewWriter(conn)
bw.WriteString("Q")            // buffered, no syscall
bw.Write(queryBytes)           // buffered, no syscall
if err := bw.Flush(); err != nil { // ONE syscall flushes everything
	return err
}
```

:::caution[Gotcha]
A `bufio.Writer` does nothing until you call `Flush()`. Forgetting `Flush` is the classic "my write disappeared" bug.
:::

`bufio.NewScanner` is the line-oriented reader: `scanner.Scan()` returns false at EOF; `scanner.Text()` is the current line without the trailing newline. A busy gateway recycles its buffered reader/writer through a `sync.Pool`, using `Reset` to rebind without reallocating:

```go title="internal/pgprotocol/server/conn.go"
// check out, rebind to this connection
c.bufferedReader = listener.readersPool.Get().(*bufio.Reader)
c.bufferedReader.Reset(netConn)
```

```go title="internal/pgprotocol/server/conn.go"
// on teardown: detach, then return to pool
if c.bufferedReader != nil {
	c.bufferedReader.Reset(nil)
	c.listener.readersPool.Put(c.bufferedReader)
	c.bufferedReader = nil
}
```

:::caution[Gotcha]
When pooling buffered readers/writers you **must** call `Reset(newConn)` before use and `Reset(nil)` before returning to the pool — otherwise the pooled buffer keeps a live reference to the now-closed connection (a leak, and a correctness bug if it still holds the previous connection's bytes).
:::

## `encoding/json`: struct tags, streaming, pitfalls

`json.Marshal(v)` → `[]byte`; `json.Unmarshal(data, &v)` fills a value. Field mapping is driven by **struct tags**. Three rules:

1. **Only exported (capitalized) fields are marshaled/unmarshaled.** A lowercase field's tag is dead.
2. **With no tag, the exported field *name* is the key verbatim** — `HostName` → `"HostName"`, not `"host_name"`.
3. **`omitempty` drops zero values** (`0`, `""`, `nil`, `false`, empty slice/map). `json:"-"` excludes entirely.

```go title="JSON struct tags"
type Person struct {
	Name    string `json:"name"`
	Age     int    `json:"age,omitempty"` // omit when zero (0)
	private string `json:"secret"`        // IGNORED: unexported, tag is dead
}
```

`json.NewEncoder(w).Encode(v)` writes JSON *directly* to any `io.Writer` with no intermediate `[]byte`. A `/version` HTTP handler does exactly this (anonymous struct, `omitempty`, RFC 3339 time):

```go title="internal/servenv/pages.go" {16-18,20-21}
func versionHandler(w http.ResponseWriter, _ *http.Request) {
	snap := readBuildSnapshot()
	payload := struct {
		Revision   string `json:"revision,omitempty"`
		Modified   bool   `json:"modified"`
		CommitTime string `json:"commit_time,omitempty"`
		GoVersion  string `json:"go_version,omitempty"`
		MainPath   string `json:"main_path,omitempty"`
	}{
		Revision:  snap.revision,
		Modified:  snap.modified,
		GoVersion: snap.goVersion,
		MainPath:  snap.mainPath,
	}
	if !snap.commitTime.IsZero() {
		payload.CommitTime = snap.commitTime.UTC().Format(time.RFC3339)
	}
	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(payload)
}
```

`http.ResponseWriter` is an `io.Writer`, so JSON streams straight to the socket. `Modified bool` has no `omitempty`, so it always appears — `false` is meaningful here. An untagged struct (a `Lock` type) pretty-prints with `json.MarshalIndent` and emits `"Action"`, `"HostName"`, … — the exported names verbatim. When the shape is unknown, unmarshal into `map[string]any` (JSON numbers decode to `float64`, objects to `map[string]any`, arrays to `[]any`). Generated proto messages are *not* serialized with `encoding/json` here — they use `protojson`.

## `gopkg.in/yaml.v3`: typed config + validate-after-unmarshal

The API mirrors `encoding/json` but uses separate **`yaml:"..."` tags**:

```go title="YAML uses its own tag namespace"
type Config struct {
	Port    int  `yaml:"port"`
	Verbose bool `yaml:"verbose"`
}
var c Config
_ = yaml.Unmarshal(data, &c)
```

A telemetry sampler config is the cleanest end-to-end example — typed struct (with a nested `map[string]CategoryConfig`), `yaml.Unmarshal`, then **post-unmarshal validation**:

```go title="internal/telemetry/sampler.go" {12-17}
type SamplingConfig struct {
	Categories map[string]CategoryConfig `yaml:"categories"`
	GRPC       GRPCSpanConfig            `yaml:"grpc"`
	HTTP       HTTPSpanConfig            `yaml:"http"`
	Spans      SpanConfig                `yaml:"spans"`
}

func loadSamplingConfig(path string) (*SamplingConfig, error) {
	data, err := os.ReadFile(path)
	if err != nil {
		return nil, fmt.Errorf("failed to read sampling config file: %w", err)
	}
	var config SamplingConfig
	if err := yaml.Unmarshal(data, &config); err != nil {
		return nil, fmt.Errorf("failed to parse sampling config YAML: %w", err)
	}
	if len(config.Categories) == 0 {
		return nil, errors.New("sampling config must define at least one category")
	}
	if _, ok := config.Categories["default"]; !ok {
		return nil, errors.New("sampling config must define a 'default' category")
	}
	...
	return &config, nil
}
```

This is the **validate-after-unmarshal idiom**: unmarshalers fill structural data but can't enforce business rules ("a `default` category must exist") — you check those *after* a successful `Unmarshal` and return wrapped errors. The same loader uses `maps.Copy` to merge six maps into one before validating.

:::caution[Gotcha]
`yaml:"..."` and `json:"..."` are two independent tag mechanisms. A struct round-tripping through both needs *both* tag sets: `` `json:"port" yaml:"port"` ``. A `json:"port"` tag alone has zero effect on `yaml.Unmarshal` — yaml.v3 falls back to a lowercased field name, which may or may not match your file.
:::

## `time`: Duration, Ticker, Timer, and the `time.After` trap

`time.Duration` is an `int64` count of nanoseconds with typed unit constants — build durations by multiplying by a unit, never bare integers:

```go title="Durations are typed and add like numbers"
d := 15 * time.Second
timeout := 500 * time.Millisecond
total := d + 2*time.Minute
```

Defining timeouts as `Duration` constants in one place makes tuning a single-file change:

```go title="internal/timeouts/rpc.go"
const RemoteOperationTimeout = 15 * time.Second
const DefaultHealthStreamStalenessTimeout = 90 * time.Second
const PollResponseWait = 500 * time.Millisecond
```

For repeated work that must stop cleanly on shutdown, the canonical pattern is a `Ticker` plus `defer ticker.Stop()` inside a `for { select { ... } }`:

```go title="internal/gateway/cancel.go"
func (cm *CancelManager) refreshPrefixCachePeriodically(ctx context.Context) {
	ticker := time.NewTicker(prefixCacheRefreshInterval)
	defer ticker.Stop()

	for {
		select {
		case <-ctx.Done():
			return
		case <-ticker.C:
			cm.rebuildPrefixCache(ctx)
		}
	}
}
```

A `Ticker` you never `Stop()` keeps firing forever and leaks its underlying timer goroutine — always pair `NewTicker` with `defer ticker.Stop()`. For a single deferred callback, `time.AfterFunc(d, fn)` runs `fn` **once, on its own goroutine**, after `d`; a failover buffer uses it as a safety timer and cancels it (`sb.maxDurationTimer.Stop()`) when the failover ends early:

```go title="internal/gateway/buffer/shard_buffer.go"
sb.maxDurationTimer = time.AfterFunc(sb.buf.config.MaxFailoverDuration.Get(), func() {
	sb.logger.Warn("max failover duration exceeded, stopping buffering")
	sb.stopBuffering("max duration exceeded", gen)
})
```

:::caution[Gotcha]
`AfterFunc`'s callback runs on a *separate* goroutine, so it must be goroutine-safe with respect to everything it touches. This code captures a `gen` (generation counter) so a *stale* callback that fires after a new failover started is ignored. And `time.After(d)` in a `select` allocates a new `Timer` per call — before Go 1.23 an unfired one wasn't GC'd until it fired, so a loop selecting on `time.After` on the non-firing branch leaked one timer per iteration. Reserve `time.After` for one-shot timeouts (typically in tests); for repeated waits hoist a single `time.NewTicker`.
:::

For machine- and human-readable timestamps, RFC 3339 is the default: `time.Now().UTC().Format(time.RFC3339)`. Go's time-format layout is the reference date `Mon Jan 2 15:04:05 MST 2006`, not `%Y-%m-%d` — use the predefined constants (`time.RFC3339`, `time.Kitchen`, …) when one fits.

## The `slices` and `cmp` packages (Go 1.21+)

`slices` replaces hand-rolled loops for common slice operations; `cmp` supplies `cmp.Compare` and the `cmp.Ordered` constraint:

```go title="Common slices operations"
xs := []int{3, 1, 2}
slices.Sort(xs)              // [1 2 3]
ok := slices.Contains(xs, 2) // true
ys := slices.Clone(xs)       // independent copy
eq := slices.Equal(xs, ys)   // true
```

`slices.Contains` pairs with a variadic parameter — checking whether an error's SQLSTATE matches any of several codes:

```go title="internal/errx/code.go"
func IsErrorCode(err error, codes ...string) bool {
	if err == nil {
		return false
	}
	var diag *PgDiagnostic
	if errors.As(err, &diag) {
		return slices.Contains(codes, diag.Code)
	}
	return false
}
```

For ordering by a derived key, `slices.SortFunc` takes a **comparator returning an `int`** (negative/zero/positive), built with `cmp.Compare`:

```go title="internal/orchestrator/recovery/analysis/shard_analysis.go"
func compareLeaderTimeline(a, b *PoolerAnalysis) int {
	return cmp.Compare(
		commonconsensus.LeaderTerm(a.ConsensusStatus),
		commonconsensus.LeaderTerm(b.ConsensusStatus),
	)
}

// at the call site:
slices.SortFunc(staleLeaders, compareLeaderTimeline)
```

:::caution[Gotcha]
`slices.SortFunc` wants an **`int` comparator**; the older `sort.Slice` wanted a **`bool` less-than**. Always go through `cmp.Compare(a, b)` — returning a `bool`, or only ever `1`/`0` (never negative), silently breaks ordering.
:::

## The `maps` package — and why some of it gets banned

```go title="Merge one map into another"
m := map[string]int{"a": 1, "b": 2}
dst := map[string]int{}
maps.Copy(dst, m) // merge m into dst
```

The telemetry loader merges six span-mapping maps into one before validation via repeated `maps.Copy`. But there's a sharper lesson:

:::caution[Gotcha — map order is non-deterministic on purpose]
Go *randomizes map iteration order on every run* to stop code depending on it. In a distributed-consensus system that's a **correctness** problem, not cosmetic: two replicas iterating a map of voters in different orders can diverge, and tests become irreproducible. A custom golangci-lint *ruleguard* rule **bans** stdlib `maps.Keys/Values/All` inside the consensus package, and a sibling bans raw `for k := range someMap` there. The blessed replacement is `sortedmaps`, which sorts keys before iterating:

```go title="internal/ruleguard/rules.go"
func requireSortedMapsOverStdlibMaps(m dsl.Matcher) {
	m.Import("maps")
	m.Match(
		`maps.Keys($x)`,
		`maps.Values($x)`,
		`maps.All($x)`,
	).Where(
		m.File().PkgPath.Matches(`internal/consensus`)).
		Report("maps.Keys/Values/All iterate in non-deterministic order; use sortedmaps.Keys/Values/All instead")
}
```

```go title="internal/sortedmaps/sortedmaps.go"
func Keys[K cmp.Ordered, V any](m map[K]V) []K {
	keys := make([]K, 0, len(m))
	for k := range m {
		keys = append(keys, k)
	}
	slices.Sort(keys)
	return keys
}
```

In Go 1.23+ stdlib `maps.Keys(m)` returns an **iterator** (`iter.Seq`), not a slice — wrap with `slices.Sorted(maps.Keys(m))` or `slices.Collect(maps.Keys(m))`; `sortedmaps.Keys` sidesteps this by returning a sorted `[]K` directly. General rule: **never assume map order** — sort keys first (`slices.Sort`) or use a `sortedmaps`-style helper when you serialize, log deterministically, or compare map iteration.
:::

## `sort` vs `slices`

| Old (`sort`) | New (`slices` + `cmp`) |
|---|---|
| `sort.Ints(s)` / `sort.Strings(s)` | `slices.Sort(s)` |
| `sort.Slice(s, func(i,j int) bool {...})` | `slices.SortFunc(s, func(a,b T) int {...})` |
| `sort.SliceStable(...)` | `slices.SortStableFunc(...)` |
| `sort.SearchInts(...)` | `slices.BinarySearch(...)` |

In new code, default to `slices.Sort`/`slices.SortFunc`; reach for `sort` only when implementing `sort.Interface` for an API that demands it.

## The functional-options pattern

No keyword arguments or default parameters — the idiom is **functional options**: a constructor takes required args plus `opts ...Option`, where `Option` is a function that mutates the config:

```go title="The functional-options shape"
type Option func(*config)

func WithTimeout(d time.Duration) Option {
	return func(c *config) { c.timeout = d }
}

func New(required string, opts ...Option) *Thing {
	c := config{timeout: time.Second} // defaults
	for _, opt := range opts {
		opt(&c)
	}
	return &Thing{cfg: c}
}

// Call: New("x"), or New("x", WithTimeout(5*time.Second))
```

Used for two distinct purposes that look identical at the call site — production tuning and test seams:

A retry helper defines `type Option func(*retryConfig)` and applies options in a loop inside `New`. `WithInitialDelay` tweaks *production behavior*:

```go title="internal/retry/retry.go"
type Option func(*retryConfig)

func WithInitialDelay() Option {
	return func(c *retryConfig) { c.InitialDelay = true }
}

func New(baseDelay, maxDelay time.Duration, opts ...Option) *Retry {
	cfg := retryConfig{
		BaseDelay: baseDelay,
		MaxDelay:  maxDelay,
		backoff:   newExponentialFullJitterBackoff(baseDelay, maxDelay),
	}
	for _, opt := range opts {
		opt(&cfg)
	}
	return &Retry{cfg: cfg, timer: realTimer{}}
}
```

  </TabItem>
  <TabItem label="Test seam">

The same pattern injects a fake clock for deterministic tests. The default is `time.Now`; tests pass a fixed clock instead of sleeping on the wall clock:

```go title="internal/gateway/buffer/buffer.go"
type Option func(*Buffer)

// WithNowFunc overrides the clock used by the buffer. Intended for tests
// that need deterministic time control. Production callers should not set
// this; it defaults to time.Now.
func WithNowFunc(now func() time.Time) Option {
	return func(b *Buffer) { b.now = now }
}

func New(ctx context.Context, config *Config, logger *slog.Logger, opts ...Option) *Buffer {
	b := &Buffer{
		logger: logger.With("component", "buffer"),
		now:    time.Now, // default
		...
	}
	for _, opt := range opts {
		opt(b)
	}
	...
}
```

  </TabItem>
</Tabs>

:::tip[Idiom]
Functional options are cleaner than exporting a settable field because the default is enforced at construction and callers cannot forget to set it. A test passes `WithNowFunc(func() time.Time { return fixed })`; production callers omit it and get `time.Now`.
:::

## Range-over-func iterators (Go 1.23+)

You can `range` over a *function* of a specific shape. An iterator takes a `yield` callback and calls it per element; if `yield` returns `false`, iteration must stop (that's how `break` propagates):

```go title="A minimal single-value iterator"
// Single value:      func(yield func(V) bool)
// Key/value (Seq2):  func(yield func(K, V) bool)
func countTo(n int) func(yield func(int) bool) {
	return func(yield func(int) bool) {
		for i := 0; i < n; i++ {
			if !yield(i) {
				return // consumer did `break`/`return`
			}
		}
	}
}

for i := range countTo(3) { fmt.Println(i) } // 0 1 2
```

The crown-jewel example: a retry helper exposes `Attempts` as an iterator that yields `(attempt, err)` pairs forever — or until the consumer stops, or the context is cancelled:

```go title="internal/retry/retry.go"
func (r *Retry) Attempts(ctx context.Context) func(yield func(int, error) bool) {
	return func(yield func(int, error) bool) {
		for {
			err := r.startAttempt(ctx)
			if !yield(r.attempt, err) {
				return
			}
		}
	}
}
```

The payoff: retry logic reads like an ordinary loop:

```go title="Retrying reads like a plain for-range loop"
r := retry.New(100*time.Millisecond, 30*time.Second)
for attempt, err := range r.Attempts(ctx) {
	if err != nil {
		return fmt.Errorf("failed after %d attempts: %w", attempt, err)
	}
	result, err := makeAPICall()
	if err == nil {
		return result // Success!
	}
	// loop backs off, then yields the next attempt
}
```

`startAttempt` does the backoff wait inside a `select` on a timer vs `ctx.Done()`, tying the iterator's pacing to context cancellation. When the loop body executes `break`/`return`, `yield` returns `false` and the iterator returns. The key/value form uses `iter.Seq2[K, V]` — `sortedmaps.All` returns one so callers get sorted, deterministic ranging: `for k, v := range sortedmaps.All(myMap) { ... }`:

```go title="internal/sortedmaps/sortedmaps.go"
func All[K cmp.Ordered, V any](m map[K]V) iter.Seq2[K, V] {
	return func(yield func(K, V) bool) {
		for _, k := range Keys(m) {
			if !yield(k, m[k]) {
				return
			}
		}
	}
}
```

:::caution[Gotcha]
The `if !yield(...) { return }` early-return is **mandatory**, not optional. If your iterator keeps calling `yield` after it returns `false`, you break `break`/`return`/`defer` semantics in the consumer's loop and the runtime panics with "range function continued iteration after function did a non-local jump".
:::

## Structured logging with `log/slog`

`slog` is the standard structured logger (since 1.21), used pervasively as a **dependency-injected `*slog.Logger`** passed into constructors and stored as a struct field — never a package-global:

```go title="Constructing an slog logger"
logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
	Level: slog.LevelInfo,
}))
logger.Info("server started", "port", 8080, "tls", true)
```

The variadic `Info(msg, key, val, ...)` form boxes every argument into `[]any` (heap allocation). The low-allocation path builds a `[]slog.Attr` with **typed constructors** and calls `LogAttrs`. A query-log function on the latency-sensitive path uses typed attrs, conditional appends, an `Enabled` guard, and `LogAttrs`:

```go title="internal/gateway/handler/querylog.go" {3-4}
if !isWarn {
	...
	if !logger.Enabled(ctx, slog.LevelDebug) {
		return // skip building attrs when DEBUG is filtered out
	}
}

attrs := []slog.Attr{
	slog.String("db.namespace", entry.Database),
	slog.String("db.operation.name", entry.OperationName),
	slog.Float64("duration.total", entry.TotalDuration.Seconds()),
	slog.Int64("rows_returned", entry.RowCount),
	// ... more
}
if entry.PlanType != "" {
	attrs = append(attrs, slog.String("db.plan.type", entry.PlanType))
}
if len(entry.TablesUsed) > 0 {
	attrs = append(attrs, slog.Any("db.tables_used", entry.TablesUsed))
}
if entry.Error != nil {
	attrs = append(attrs,
		slog.String("error", entry.Error.Error()),
		slog.String("sqlstate", entry.SQLSTATE),
		slog.String("error.source", entry.ErrorSource),
	)
}
logger.LogAttrs(ctx, level, "query completed", attrs...)
```

Three idioms in one function: **typed attr constructors** (`slog.String`, `slog.Int64`, `slog.Float64`, `slog.Bool`, `slog.Any`) avoid the `[]any` boxing; **conditional appends** keep the line lean; and the **`logger.Enabled(ctx, level)` guard** returns *before* building the attrs slice when the level is filtered out, so you don't pay construction cost for a dropped line. `logger.With(...)` returns a **new** `*slog.Logger` with attributes permanently bound — it does *not* mutate the receiver, so you must store the returned logger (e.g. `logger.With("component", "buffer")` in a struct field) for the bound attribute to appear on later lines. Passing `ctx` to `LogAttrs`/`InfoContext` is also what lets a slog-to-OpenTelemetry bridge inject `trace_id`/`span_id` automatically. For hot paths prefer `LogAttrs(ctx, level, msg, attrs...)` with typed `slog.Attr`; for cold paths `logger.Info(msg, "k", v)` is fine. Choose the handler with `slog.NewTextHandler` (human) or `slog.NewJSONHandler` (machine), and set the minimum level via `slog.HandlerOptions{Level: ...}`.

## Checkpoints

1. A loop reads from an `io.Reader` and gets `(n=20, err=io.EOF)` on one call. Is that an error? What should the loop do with the 20 bytes?
   <details><summary>Answer</summary>Not an error — `io.EOF` is the normal end-of-stream sentinel. The 20 bytes are valid data: process `buf[:20]` first, then treat `io.EOF` as the loop's exit condition (`return nil`). `Read` may return `n > 0` with `io.EOF` in the same call.</details>

2. Why provide a `sortedmaps` helper instead of just using stdlib `maps.Keys`? Name both a correctness reason and an API reason.
   <details><summary>Answer</summary>Correctness: Go randomizes map iteration order every run, which can make consensus replicas diverge and tests irreproducible — `sortedmaps` sorts keys first, and a ruleguard lint bans stdlib `maps.Keys/Values/All` in the consensus package. API: in Go 1.23+ stdlib `maps.Keys` returns an *iterator* (`iter.Seq`), not a slice, whereas `sortedmaps.Keys` returns a sorted `[]K` directly.</details>

3. What is the difference between the comparator `slices.SortFunc` expects and the one `sort.Slice` expects, and how do you build the former safely?
   <details><summary>Answer</summary>`slices.SortFunc` wants `func(a, b T) int` returning negative/zero/positive; `sort.Slice` wanted `func(i, j int) bool` (less-than). Build the `int` comparator with `cmp.Compare(a, b)`. Returning a `bool` (or only ever `1`/`0`, never negative) silently breaks ordering.</details>

4. You write `logger.With("component", "buffer")` on its own line and the attribute never appears in later logs. Why?
   <details><summary>Answer</summary>`With` returns a *new* `*slog.Logger`; it does not mutate the receiver. You discarded the return value. You must assign it (e.g. store it in a struct field) and log through the *returned* logger.</details>
