No exceptions. A fallible function returns an `error` as its last result; the caller checks it. The engineering lives in how you classify, wrap, and inspect errors across an RPC boundary — that's the `errx` package in this repo.

## `error` is just an interface

```go
type error interface {
    Error() string
}
```

Any type with `Error() string` *is* an `error`:

```go
type parseError struct {
    line int
    msg  string
}

func (e *parseError) Error() string {
    return fmt.Sprintf("line %d: %s", e.line, e.msg)
}

func parse(s string) error {
    return &parseError{line: 3, msg: "unexpected token"}
}
```

The PostgreSQL diagnostic type works the same way — a struct carrying all 14 PG error fields, made an `error` by one method:

```go title="internal/errx/pgdiagnostic.go"
func (d *PgDiagnostic) Error() string {
    if d == nil {
        return "ERROR: unknown error"
    }
    return d.Severity + ": " + d.Message
}
```

:::caution[Gotcha — the nil-receiver guard is not paranoia]
A pointer-receiver method can be called on a `nil` pointer — it runs with `d == nil` and only crashes if it *dereferences* a field. `Error()` checks `if d == nil` first, so a `(*PgDiagnostic)(nil)` boxed into `error` still produces a sensible string instead of panicking. This is the typed-nil-interface trap; see [Interfaces](/go-guide/language/03-interfaces-composition/).
:::

Other error types here: `*fundamental` (basic coded error), `*wrapping` (context-adding wrapper), and `TopoError` (a value-type error) — each a struct with `Error() string`.

## Creating errors: `Wrap`/`Wrapf`, not `fmt.Errorf`, for propagation

Stdlib constructors:

```go
err1 := errors.New("connection refused")          // static message
err2 := fmt.Errorf("connect to %s failed", addr)   // formatted message
```

The repo's leaf errors also carry a **canonical code** and a **stack trace** captured at the call site:

```go title="internal/errx/errx.go"
func New(code rpcpb.Code, message string) error {
    return &fundamental{
        msg:   message,
        code:  code,
        stack: callers(),   // captures the stack at the call site
    }
}
```

Propagation rule: wrap with `Wrap`/`Wrapf`, never `fmt.Errorf`, so the stack and code survive every layer. Reserve `fmt.Errorf` for purely local validation strings that never propagate. (The package also keeps a legacy `Cause()`/`RootCause()` API descended from `pkg/errors`.)

## Wrapping and unwrapping: `%w` and `Unwrap() error`

`%w` in `fmt.Errorf` links the chain so `errors.Is`/`errors.As` can traverse it; `%v` severs it:

```go
func loadConfig(path string) error {
    f, err := os.Open(path)
    if err != nil {
        return fmt.Errorf("load config %q: %w", path, err)  // %w, not %v
    }
    defer f.Close()
    return nil
}
```

`*wrapping` implements both the stdlib contract and the older `pkg/errors` one:

```go title="internal/errx/errx.go"
func (w *wrapping) Error() string { return w.msg + ": " + w.cause.Error() }
func (w *wrapping) Cause() error  { return w.cause }

// Unwrap implements Go's standard error-unwrapping interface,
// so errors.Is and errors.As work with wrapped errors.
func (w *wrapping) Unwrap() error { return w.cause }
```

- **`Unwrap() error`** — the stdlib contract; `errors.Is`/`As` use it. Reach for this almost always.
- **`Cause() error`** — the older `causer` interface; `RootCause` walks to the bottom.

:::caution[Gotcha — `errx.Unwrap` is NOT `errors.Unwrap`]
The package exports its own `Unwrap(err) (wasWrapped bool, unwrapped error)` that peels only a `*wrapping`. The stdlib `errors.Unwrap` returns a single `error`. When you mean standard chain traversal, use `errors.Is`/`errors.As`, not `errx.Unwrap`.
:::

`Wrap` short-circuits on `nil`, so callers can wrap unconditionally:

```go title="internal/errx/errx.go"
func Wrap(err error, message string) error {
    if err == nil {
        return nil   // wrapping nil yields nil
    }
    return &wrapping{cause: err, msg: message, stack: callers()}
}
```

## `errors.Is` vs `errors.As`

Both walk the `Unwrap()` chain. They differ in what they match on:

- `errors.Is(err, target)` — "is this error, or anything it wraps, **equal to** `target` (or does a link claim a match via a custom `Is`)?" → use for **sentinels**.
- `errors.As(err, &target)` — "is there a link whose **concrete type** matches? If so, assign it into `target`." → use for **typed** errors you read fields off.

```go
if errors.Is(err, io.EOF) { /* end of stream */ }

var perr *parseError
if errors.As(err, &perr) {
    fmt.Println("failed at line", perr.line)  // perr now points at the matching link
}
```

:::caution[Gotcha — `errors.As` takes a pointer to the target]
The second argument is a *pointer to* the variable to fill (here `&perr`, a `**parseError`). Passing the value itself is an error.
:::

The repo uses `errors.As(err, &diag)` pervasively to pull a `*PgDiagnostic` out of a `Wrapf`-layered chain (a plain type assertion would fail — the outermost error is `*wrapping`). Combined with sentinel checks:

```go title="internal/errx/errx.go"
var diag *PgDiagnostic
if errors.As(err, &diag) {
    // Class 08: Connection Exception (all codes in this class).
    if diag.IsClass("08") {
        return true
    }
    switch diag.Code {
    case "57P01", "57P02", "57P03":   // admin/crash shutdown, cannot_connect_now
        return true
    }
    // Don't return false here — fall through to check for I/O errors.
}

if errors.Is(err, io.EOF) ||
    errors.Is(err, io.ErrUnexpectedEOF) ||
    errors.Is(err, net.ErrClosed) {
    return true
}
```

One wrapped chain can hold *both* a `*PgDiagnostic` (SQLSTATE level) and an underlying `io.EOF` (transport level) — so don't return early after the SQLSTATE checks.

## Sentinel errors vs typed errors

| | Sentinel | Typed error |
|---|---|---|
| Shape | package-level `var` from `errors.New` | struct carrying structured data |
| Match with | `errors.Is` (identity) | `errors.As` (or custom `Is`) |
| Carries | just a message | fields you read |

Sentinels from the pool:

```go title="internal/pooler/internal/pools/connpool/pool.go"
var (
    ErrTimeout    = errors.New("connection pool timed out")
    ErrCtxTimeout = errors.New("connection pool context already expired")
    ErrPoolClosed = errors.New("connection pool is closed")
)
```

```go
if errors.Is(err, ErrManagerClosed) || errors.Is(err, connpool.ErrPoolClosed) {
    // pool/manager is shutting down — handle gracefully
}
```

`TopoError` is the instructive typed error — a **value type** with a **custom `Is`** that compares only `.Code`:

```go title="internal/topo/errors.go"
type TopoError struct {
    Code    ErrorCode
    Message string
}

func (e TopoError) Is(target error) bool {
    if targetTopo, ok := target.(*TopoError); ok {
        return e.Code == targetTopo.Code
    }
    return false
}
```

```go title="internal/gateway/discovery.go"
if errors.Is(watchData.Err, &topoclient.TopoError{Code: topoclient.NoNode}) {
    // a topo node was deleted — handle the deletion event
}
```

Without the custom `Is`, `errors.Is` falls back to `==`, comparing the whole struct including `Message` (which embeds the node path) — almost never true. The custom `Is` is what makes "match any NoNode error" work.

## The `if err != nil` discipline — classify on code, not message

Canonical shape — check, decorate, return:

```go title="internal/gateway/poolergateway/grpc_query_service.go"
res, err := g.client.ExecuteQuery(ctx, req)
if err != nil {
    return nil, nil, errx.Wrapf(errx.FromGRPC(err), "execute query")
}
```

Inner-to-outer: `FromGRPC` reconstructs an error (preserving code + `PgDiagnostic`) from the gRPC status; `Wrapf` adds local context and a fresh stack frame. This two-step repeats across the gateway.

Callers branch on a **canonical code** enum, not strings:

```go title="internal/errx/errx.go"
func Code(err error) rpcpb.Code {
    if err == nil {
        return rpcpb.Code_OK
    }
    if err, ok := err.(ErrorWithCode); ok {   // does this error carry a code?
        return err.ErrorCode()
    }
    cause := Cause(err)
    if cause != err && cause != nil {
        return Code(cause)                     // recurse into the wrapped cause
    }
    switch err {
    case context.Canceled:
        return rpcpb.Code_CANCELED
    case context.DeadlineExceeded:
        return rpcpb.Code_DEADLINE_EXCEEDED
    }
    return rpcpb.Code_UNKNOWN
}
```

`err.(ErrorWithCode)` is a type assertion to an interface that embeds `error`:

```go title="internal/errx/state.go"
type ErrorWithCode interface {
    error
    ErrorCode() rpcpb.Code
}
```

For PostgreSQL errors, classify on **SQLSTATE** via `errors.As`:

```go title="internal/errx/code.go"
func IsErrorCode(err error, codes ...string) bool {
    if err == nil {
        return false
    }
    var diag *PgDiagnostic
    if errors.As(err, &diag) {
        return slices.Contains(codes, diag.Code)
    }
    return false
}
```

Operational teeth — the gateway buffers-and-retries during a planned failover purely from the code:

```go title="internal/gateway/poolergateway/pooler_gateway.go"
func classifyError(err error, target *query.Target) errorAction {
    if target.PoolerType != clustermetadatapb.PoolerType_PRIMARY {
        return actionFail
    }
    if errx.IsErrorCode(err, errx.PXF01.ID, errx.PgSSReadOnlyTransaction) {
        return actionBuffer
    }
    return actionFail
}
```

:::caution[Gotcha — never branch on the message text]
`PXF01.ID` is `"PXF01"`, `PgSSReadOnlyTransaction` is `"25006"` — stable identifiers. String-matching `err.Error()` silently breaks when a message is reworded, translated, or wrapped. Classify on the code.
:::

### PX codes are synthetic SQLSTATEs

`PXError` is a template producing a `*PgDiagnostic` whose SQLSTATE `Code` holds a project-specific 5-char ID like `PXF01`/`PXD01` — not real PostgreSQL codes; they occupy the SQLSTATE slot so clients can spot system conditions. A helper distinguishes them by prefix for metric attribution:

```go title="internal/errx/error_helpers.go"
var diag *PgDiagnostic
if errors.As(err, &diag) {
    if strings.HasPrefix(diag.Code, "PX") {
        return "internal"   // PX-prefixed → our bug/condition, not the backend's
    }
    return "backend"        // real PostgreSQL SQLSTATE
}
```

## Decorating errors with `defer` + named returns

To observe/alter the final error after all return paths — record a metric, set span status — use a deferred closure over a **named return**:

```go
func doWork() (retErr error) {                 // named return
    defer func() {
        if retErr != nil {
            log.Printf("doWork failed: %v", retErr)
        }
    }()
    // ... any number of `return someErr` paths ...
    return nil
}
```

:::caution[Gotcha — only works with a named return]
A deferred closure sees the named return's final value because it runs after `return` assigns it. `defer logIfErr(err)` would capture `err` at defer-registration time (usually `nil`), not at return time.
:::

**Variant A — closure over the named return** (backup metrics):

```go title="internal/pooler/internal/manager/rpc_backup.go"
func (pm *PoolerManager) backupLocked(ctx context.Context /* ... */) (retBackupID string, retErr error) {
    metrics := pm.backup.Metrics()
    metrics.IncBackupAttempts(ctx)
    defer func() {
        if retErr == nil {
            metrics.IncBackupSuccesses(ctx)
        } else {
            metrics.IncBackupFailures(ctx)
        }
    }()
    // ... many `return "", err` paths; each is observed by the defer ...
}
```

**Variant B — pass `*error` into a helper** (shared decoration logic):

```go title="internal/gateway/scatterconn/scatter_conn.go"
defer sc.endAction(ctx, span, start, conn.Database(), tableGroup, shard, &retErr)
```

```go title="internal/gateway/scatterconn/scatter_conn.go"
func (sc *ScatterConn) endAction(ctx context.Context, span trace.Span, start time.Time,
    dbNamespace, tableGroup, shard string, err *error) {
    duration := time.Since(start).Seconds()
    if *err != nil {                              // dereference to read the final value
        sqlstate := errx.ExtractSQLSTATE(*err)
        span.RecordError(*err)
        span.SetStatus(codes.Error, (*err).Error())
        // ... record error metric labelled with sqlstate ...
        return
    }
    // ... record success metric ...
}
```

Variant A when the logic is short and local; Variant B when one helper is shared across functions. `errors.Join(errs...)` collapses a slice into one error whose chain matches any constituent — returns `nil` if all are `nil`.

## `panic`/`recover` — and when *not* to use them

`panic` unwinds the stack running defers; `recover` (inside a deferred func) stops the unwind. Use them for truly unrecoverable situations and programmer bugs — **not** ordinary failures, which return `error`:

```go
func mustParse(s string) int {
    n, err := strconv.Atoi(s)
    if err != nil {
        panic("mustParse: " + err.Error())  // only when the input is guaranteed valid
    }
    return n
}
```

The repo models "this should never happen" as a normal error, not a panic — the `PXD01` template:

```go title="internal/errx/code.go"
PXD01 = &PXError{
    ID: "PXD01", Severity: "ERROR",
    Format:      "[BUG] %s",
    Description: "This error should not happen and is a bug. Please file an issue on GitHub...",
}
```

```go title="internal/pooler/internal/poolerserver/pooler.go"
return errx.PXD01.New("target tablegroup %q does not match pooler tablegroup %q",
    target.TableGroup, s.tableGroup)
```

The one genuine `recover()` is at a **goroutine/connection boundary**, so one panicking client can't take down the server:

```go title="internal/pgprotocol/server/listener.go"
func (l *Listener) handleConnection(conn *Conn) {
    // Catch panics and ensure cleanup happens in all cases.
    defer func() {
        if x := recover(); x != nil {
            conn.logger.Error("panic in connection handler",
                "panic", x, "remote_addr", conn.RemoteAddr())
        }
        l.UnregisterConn(conn.ConnectionID())
        if conn.handler != nil {
            conn.handler.ConnectionClosed(conn)   // cleanup still runs
        }
        if err := conn.Close(); err != nil {
            conn.logger.Error("error closing connection", "error", err)
        }
    }()
    // ... serve the connection ...
}
```

:::caution[Gotcha — `recover` only catches panics in *its own goroutine*]
A panic in a spawned goroutine crashes the whole process unless *that* goroutine has its own deferred `recover` — which is why recovering at `main()` would be useless here. Don't sprinkle `recover()` through normal code to "handle errors"; it hides bugs and breaks the `if err != nil` contract. Recover only at a goroutine boundary to contain blast radius, and log it as the bug it is.
:::

## Errors across the RPC wire: codes survive, identities are special-cased

Across gRPC, object identity is lost — the **code** is what must survive. `ToGRPC` attaches the `PgDiagnostic` as a status detail and stamps the canonical code; `FromGRPC` reconstructs it:

<Mermaid title="An error crossing the gRPC boundary" code={`
flowchart LR
  subgraph Server["Server side"]
    E["errx error + PgDiagnostic"] --> TG["ToGRPC"]
    TG --> ST["gRPC status (code + RPCError detail)"]
  end
  ST -->|"the wire"| FG["FromGRPC"]
  subgraph Client["Client side"]
    FG --> R["reconstructed errx error (code + SQLSTATE preserved)"]
  end
`} />

```go title="internal/errx/grpc.go"
func FromGRPC(err error) error {
    if err == nil {
        return nil
    }
    if err == io.EOF {
        // Do not wrap io.EOF — we compare against it for finished streams.
        return err
    }
    st, ok := status.FromError(err)
    if !ok {
        return New(rpcpb.Code_UNKNOWN, err.Error())
    }
    switch st.Code() {
    case codes.DeadlineExceeded:
        return NewStatementTimeout()   // gRPC deadline → PG query_canceled diagnostic
    case codes.Canceled:
        return NewQueryCanceled()
    }
    for _, detail := range st.Details() {
        if rpcErr, ok := detail.(*rpcpb.RPCError); ok {
            if rpcErr.GetPgDiagnostic() != nil {
                return PgDiagnosticFromProto(rpcErr.GetPgDiagnostic())  // full SQLSTATE preserved
            }
            return New(rpcErr.Code, rpcErr.Message)
        }
    }
    return New(rpcpb.Code(st.Code()), st.Message())
}
```

:::caution[Gotcha — `io.EOF` must never be wrapped]
Stream-finished detection compares against `io.EOF` by identity. `FromGRPC` special-cases it and returns it untouched; wrapping it would silently break stream termination. The human-readable *message* may be reworded across the boundary; the *code/SQLSTATE* is the contract.
:::

### The typed-nil-interface trap

A `nil` typed pointer boxed into an interface is **not** a nil interface:

```go
func badIdea() error {
    var d *PgDiagnostic   // d == nil
    return d              // returns a non-nil error interface wrapping a nil pointer!
}

err := badIdea()
if err != nil {          // TRUE — the interface has a type (*PgDiagnostic) even though the value is nil
    fmt.Println(err.Error())  // would panic if Error() dereferenced d without the nil guard
}
```

That's why `PgDiagnostic.Error()` defends with `if d == nil`. Safe rule: return the untyped `nil` literal, or keep the variable typed as `error`. See [Pointers, values & memory](/go-guide/language/04-pointers-values-memory/) for why the interface header carries a type word.

## Checkpoints

<details><summary>Why use <code>errors.As(err, &diag)</code> instead of a type assertion <code>err.(*PgDiagnostic)</code> to get a PostgreSQL diagnostic?</summary>
By the time the error reaches the inspecting code it has usually been wrapped by <code>Wrapf</code>, so the outermost concrete type is <code>*wrapping</code>, not <code>*PgDiagnostic</code>. A type assertion checks only the top of the chain and would fail; <code>errors.As</code> walks the <code>Unwrap()</code> chain and assigns the first <code>*PgDiagnostic</code> into <code>&diag</code>.</details>

<details><summary>What breaks if you wrap an <code>io.EOF</code> returned from a gRPC stream?</summary>
Stream-finished detection relies on <code>err == io.EOF</code> identity (and <code>errors.Is(err, io.EOF)</code>). <code>FromGRPC</code> deliberately returns <code>io.EOF</code> unwrapped. Wrapping it changes the value so the finished-stream check no longer recognizes it, silently breaking stream termination.</details>

<details><summary>Why must the deferred metric-recording closure in <code>backupLocked</code> use a <em>named</em> return <code>retErr</code>?</summary>
A deferred closure observes the named return's value *after* the <code>return</code> statement assigns it. With a bare <code>error</code> return and the defer capturing a local <code>err</code>, it would see the value at defer-registration time (typically nil), not the final error. The <code>*error</code>-pointer variant (a helper taking <code>&retErr</code>) achieves the same post-return visibility.</details>

<details><summary>Why is <code>PXD01.New(...)</code> returned instead of <code>panic</code> for a "this should never happen" invariant?</summary>
Unexpected conditions are recoverable failures that propagate as ordinary errors carrying a <code>[BUG]</code> code, so one bad request fails cleanly with a diagnostic clients/metrics can classify (<code>PX</code>-prefixed → <code>"internal"</code>) instead of crashing the process. <code>panic</code>/<code>recover</code> is reserved for the goroutine boundary in <code>handleConnection</code>.</details>

2. Read `internal/topo/errors.go`. Explain why `TopoError` uses a **value** receiver on `Is` and is stored as a value, yet callers pass `&topoclient.TopoError{Code: ...}` (a pointer) as the `errors.Is` target. Trace how `Is` handles the pointer target via its type assertion.

3. Find every package-level sentinel declared with `errors.New` under `internal/pooler/internal/pools` and, for each, find the matching `errors.Is` consumer. Argue why a sentinel (not a typed error) was right for these conditions.
