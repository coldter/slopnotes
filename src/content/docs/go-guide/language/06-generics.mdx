Go's generics are deliberately narrow: no specialization, no method-level type parameters, no variance — a constraint can only express a *type set*.

## Type parameters on functions, and inference

Declare type parameters in square brackets after the name. `T any` means "no constraint":

```go title="Teaching example — not from the repo"
func First[T any](s []T) (T, bool) {
	if len(s) == 0 {
		var zero T // can't write `return nil` or `return 0` — T is unknown
		return zero, false
	}
	return s[0], true
}

// Caller writes no type arguments; T is inferred from the slice's element type.
x, ok := First([]int{1, 2, 3}) // T = int
```

Key idiom: inside a generic function you can't spell `T`'s "empty" value literally. `var zero T` gives the zero value for whatever `T` is — `nil` for pointers/maps/slices, `0` for numbers, `false` for bool, all-fields-zero for a struct.

### Real usage: a connection-pool retry helper

The query path wraps every backend operation in a generic helper so retry-on-connection-error is written once:

```go title="internal/pooler/internal/pools/regular/regular_conn.go" {6-7,9-11}
// retryOnConnectionError executes op with automatic retry on connection error.
func retryOnConnectionError[T any](c *Conn, ctx context.Context, op func() (T, error)) (T, error) {
	for attempt := 1; attempt <= constants.MaxConnPoolRetryAttempts; attempt++ {
		val, err := execOnce(c, ctx, op)
		switch {
		case err == nil:
			return val, nil
		case !errx.IsConnectionError(err):
			var zero T
			return zero, err
		case attempt == constants.MaxConnPoolRetryAttempts:
			c.conn.Close()
			var zero T
			return zero, err
		}
		// ... backoff + reconnect ...
	}
	panic("unreachable")
}
```

Companions `execWithContextCancel[T any]` / `execOnce[T any]` have the same shape: take `op func() (T, error)`, run it, `select` on cancellation vs completion. Every error path returns `var zero T, err`.

Why generics and not `interface{}`? Without them the helper returns `(interface{}, error)` and every caller type-asserts — a boxing allocation plus a runtime cast that can panic. With `[T any]` the return is the exact type, checked at compile time.

Inference flows from the types of the *value arguments*. At the call sites the caller writes no type arguments — `T` is deduced from `op`'s return type:

```go title="Call sites in the same file"
// T = []*sqltypes.Result
return execWithContextCancel(c, ctx, func() ([]*sqltypes.Result, error) {
	return c.conn.Query(ctx, sql)
})

// T = bool
return execWithContextCancel(c, ctx, func() (bool, error) {
	return c.conn.BindAndExecute(ctx, /* ... */)
})

// T = struct{}  — the op has no meaningful return value
_, err := execWithContextCancel(c, ctx, func() (struct{}, error) {
	return struct{}{}, c.conn.QueryStreaming(ctx, sql, callback)
})
```

The `struct{}` cases are an idiom: "fire and check the error" with no payload → use the zero-byte struct and discard with `_,`. Note: inference needs `T` in a value argument; if `T` appeared *only* in the return type, you'd have to instantiate explicitly.

:::caution[Gotcha]
`var zero T` is not optional. Returning `nil` would not compile when `T = bool` (no nil). `var zero T; return zero, err` is the only uniform empty value across all instantiations.
:::

## Type parameters on types

A type can carry its own type parameters, in scope on every field and method:

```go title="Teaching example"
type Box[T any] struct {
	value T
}

func (b *Box[T]) Get() T  { return b.value }   // method reuses the receiver's T
func (b *Box[T]) Set(v T) { b.value = v }
```

The receiver is `(b *Box[T])`, not `(b *Box)` — the method reuses the bound `T`, it does **not** re-declare it. Methods cannot introduce their *own* type parameters (see the rule below).

### Real usage: a two-parameter store

```go title="internal/orchestrator/store/store.go" {1,11}
type ProtoStore[K comparable, V proto.Message] struct {
	mu    sync.Mutex
	items map[K]V
}

func (s *ProtoStore[K, V]) Get(key K) (V, bool) {
	s.mu.Lock()
	defer s.mu.Unlock()

	v, ok := s.items[key]
	if !ok {
		var zero V
		return zero, false
	}
	cloned := proto.Clone(v).(V) // legal because V is constrained to proto.Message
	return cloned, true
}
```

Two constraints carry weight:

- `K comparable` — `K` is a **map key** (`items map[K]V`); map keys need `==`, and `comparable` promises exactly that. `any` wouldn't compile.
- `V proto.Message` — lets the body call `proto.Clone(v)`; `.(V)` asserts the result back (always succeeds for values from this store).

Every method (`Get`/`Set`/`Range`/`DoUpdate`/`Delete`/`Len`/`Clear`) is `func (s *ProtoStore[K, V]) ...`. A custom struct over `sync.Map` was chosen deliberately: the recovery engine is write-heavy, defeating `sync.Map`'s read-optimized design.

:::caution[Gotcha — the boxing comparison trick]
`DoUpdate` asks "did the callback return the zero value?" but can't write `newValue == zero` (`V` is a non-comparable interface constraint). It boxes both to `any` and compares interface headers:

```go
var zero V
if newValue := fn(v); any(newValue) != any(zero) {
	s.items[key] = newValue
}
```

This works *here* because `V` is always a pointer type — don't copy it blindly to value types.
:::

## The constraint taxonomy

| Constraint | Permits | Reach for it when |
|---|---|---|
| `any` | anything; only assignment/`var zero T` | no operations on `T` needed |
| `comparable` | `==`, `!=`, map keys | `T` is a map key or compared |
| `cmp.Ordered` | `<`, `<=`, `>`, `>=` (superset of comparable) | sorting/ordering (`slices.Sort`) |
| `A \| B` union (or `~A`) | any listed type (or underlying-type match) | narrowing a cast (e.g. config plumbing) |

### `comparable` — map keys and equality

`internal/gateway/handler/gateway_managed_variable.go` models `SET`/`SET LOCAL`/`SAVEPOINT` for one session variable:

```go title="internal/gateway/handler/gateway_managed_variable.go"
type GatewayManagedVariable[T comparable] struct {
	defaultValue T
	currentValue T
	isSet        bool
	localValue   T
	isLocalSet   bool
	snapshots    []gmvSnapshot[T]
}
```

`comparable` excludes slices, maps, funcs — and any struct containing one. So `GatewayManagedVariable[[]byte]` is a compile error, not a runtime one.

### `cmp.Ordered` — ordering (stdlib `cmp`, Go 1.21+)

`sortedmaps` exists so map iteration is deterministic (Go randomizes `range` over maps). `Keys` needs `<`, hence `cmp.Ordered`:

```go title="internal/tools/sortedmaps/sortedmaps.go"
func Keys[K cmp.Ordered, V any](m map[K]V) []K {
	keys := make([]K, 0, len(m))
	for k := range m {
		keys = append(keys, k)
	}
	slices.Sort(keys) // needs <, hence cmp.Ordered, not just comparable
	return keys
}
```

`ByStr` handles keys that are comparable but not orderable — it sorts by the `fmt.Sprintf("%v", key)` string form with `slices.SortFunc`:

```go title="internal/tools/sortedmaps/sortedmaps.go"
// ByStr ... Use this when K is comparable but not cmp.Ordered ...
func ByStr[K comparable, V any](m map[K]V) iter.Seq2[K, V] {
	keys := make([]K, 0, len(m))
	for k := range m {
		keys = append(keys, k)
	}
	slices.SortFunc(keys, func(a, b K) int {
		return strings.Compare(fmt.Sprintf("%v", a), fmt.Sprintf("%v", b))
	})
	// ... yield in that order ...
}
```

:::caution[Gotcha — `comparable` ≠ `cmp.Ordered`]
`comparable` guarantees only `==`/`!=`, not `<`. `a < b` on a `comparable` type parameter won't compile. Widen to `cmp.Ordered` or sort with `slices.SortFunc` — that distinction is the entire reason `ByStr` exists.
:::

### Union / type-set constraints (`|`)

An interface listing concrete types separated by `|`; the parameter may be any one of them:

```go title="Teaching example"
type SignedSmall interface {
	int8 | int16 | int32 | int64
}
func Abs[T SignedSmall](x T) T { if x < 0 { return -x }; return x }
```

The repo's only unions are inline exact-type unions in config plumbing, casting viper's wide getters to narrow numeric types:

```go title="internal/config/get_func.go"
func getCastedInt[T int8 | int16]() func(v *viper.Viper) func(key string) T {
	return func(v *viper.Viper) func(key string) T {
		return func(key string) T {
			return T(v.GetInt(key)) // legal: every member of the set is convertible from int
		}
	}
}

func getCastedUint[T uint8 | uint16]() func(v *viper.Viper) func(key string) T { /* ... */ }
func getComplex[T complex64 | complex128](bitSize int) func(v *viper.Viper) func(key string) T { /* ... */ }
```

Exact types only: `getCastedInt[T int8 | int16]` accepts `int8`/`int16`, **not** `type myByte int8` — for "any type whose underlying type is `int8`" you'd write `~int8`. This repo uses no `~` and doesn't import `x/exp/constraints`; the one stdlib constraints package it uses is `cmp`.

:::caution[Gotcha — constraint-only interfaces]
An interface embedding `comparable` or containing a `|` union can be used **only as a constraint**, never as an ordinary variable type. You cannot declare `var x SignedSmall`.
:::

## Custom interfaces as constraints — interfaces wear two hats

An interface is both a runtime value type *and* a compile-time constraint (a type set). The connection pool uses one interface for both jobs. First as an ordinary method-set interface:

```go title="internal/pooler/internal/pools/connpool/interfaces.go"
type Connection interface {
	Settings() *connstate.Settings
	IsClosed() bool
	Close() error
	ApplySettings(ctx context.Context, desired *connstate.Settings) error
	ResetAllSettings(ctx context.Context) error
}
```

Then as a generic constraint:

```go title="internal/pooler/internal/pools/connpool/pool.go"
type Connector[C Connection] func(ctx context.Context, poolCtx context.Context) (C, error)

type Pool[C Connection] struct {
	clean  connStack[C]
	states [stackMask + 1]connStack[C] // array of generic-typed stacks
	wait   waitlist[C]
	// ...
}
```

Why constrain `C` instead of using `Connection` directly? `Pool[*regularConn]` stores/hands back `*regularConn` with **no interface boxing and no assertions** — monomorphized at compile time — while the constraint still guarantees `c.Close()`, `c.Settings()`, etc. Interface-level guarantees with concrete-type performance on a latency-sensitive path.

### A constraint mixing `comparable` with methods

```go title="internal/cache/theine/store.go"
type cachekey interface {
	comparable
	Hash() uint64
	Hash2() (uint64, uint64)
}

type cacheval interface {
	CachedSize(alloc bool) int64
}

type Store[K cachekey, V cacheval] struct {
	// ...
	shards []*Shard[K, V]
}
```

`cachekey` embeds `comparable` because `K` is a map key inside each shard (`hashmap map[K]*Entry[K, V]`) *and* requires the hash methods for sharding/bloom-filter logic. Drop the embedded `comparable` and the `map[K]...` field stops compiling; drop the methods and the sharding code stops compiling. Read `comparable` inside a custom constraint as "map key **and** these methods".

## Explicit instantiation — when inference cannot help

Generic **functions** usually infer; generic **types** never can — there's nothing to infer from when you name a type:

```go title="Teaching example"
// Generic type — explicit args are mandatory:
b := Box[int]{value: 7}

// Generic function — args usually inferred, but you may write them:
x, _ := First[string](nil) // explicit because nil gives no element type to infer
```

### Real usage: `Options[T]` literals

Config call sites instantiate the generic `Options[T]` explicitly, then let `Configure[T]` infer `T` from that argument:

```go title="internal/gateway/buffer/config.go"
Enabled: config.Configure(reg, "buffer-enabled", config.Options[bool]{
	Default: false, FlagName: "buffer-enabled", EnvVars: []string{"PLATFORM_BUFFER_ENABLED"},
}),
Window: config.Configure(reg, "buffer-window", config.Options[time.Duration]{
	Default: 10 * time.Second, /* ... */
}),
Size: config.Configure(reg, "buffer-size", config.Options[int]{ Default: 1000, /* ... */ }),
```

`Options[bool]{...}` must be written explicitly (a generic type literal), but `Configure(reg, key, opts)` needs no `[bool]` — its signature `Configure[T any](reg *Registry, key string, opts Options[T]) Value[T]` infers `T` from the `Options[T]` argument. The other explicit flavor lives in `GetFuncForType[T]`, which switches on `reflect.Kind` and instantiates the numeric helpers by hand (`getCastedInt[int8]()`, …) because a `reflect` switch gives no value to infer from.

:::caution[Gotcha]
Every place that names a generic *type* needs explicit arguments: `Options[bool]{}`, `list.List[waiter[C]]`, `deque.Deque[*Entry[K, V]]`. Only generic *functions* lean on inference, and only when the type parameter appears in a value argument.
:::

### Generic interfaces and the satisfaction-assertion idiom

```go title="internal/config/value.go"
type Value[T any] interface {
	value.Registerable // embedded non-generic interface
	Get() T
	Set(v T)
	Default() T
}
```

```go title="internal/config/value.go"
var (
	_ Value[int] = (*value.Static[int])(nil)
	_ Value[int] = (*value.Dynamic[int])(nil)
)
```

`var _ Iface = (*Impl)(nil)` is a compile-time assertion that `*Impl` satisfies `Iface`, at zero runtime cost; with generics you instantiate both sides at a concrete type. If `value.Static[int]` ever stopped implementing `Value[int]`, the build fails at this line.

### Nested instantiation

A generic type can be parameterized by another generic type — the waitlist stacks two deep:

```go title="internal/pooler/internal/pools/connpool/waitlist.go"
type waitlist[C Connection] struct {
	nodes sync.Pool
	mu    sync.Mutex
	list  list.List[waiter[C]] // List instantiated at element type waiter[C]
}
```

```go title="internal/pooler/internal/pools/connpool/waitlist.go"
elem := wl.nodes.Get().(*list.Element[waiter[C]])
```

`C` flows from the enclosing `waitlist`'s own type parameter into `List` and `Element`. `[C]` is just a name threaded through.

## Third-party generic types

The cache's per-shard recency queue is a `github.com/gammazero/deque`:

```go title="internal/cache/theine/store.go"
import "github.com/gammazero/deque"

type Shard[K cachekey, V any] struct {
	// ...
	deque *deque.Deque[*Entry[K, V]] // element type is the generic *Entry[K,V]
}

// inside NewShard:
deque: &deque.Deque[*Entry[K, V]]{},
```

When `Store` is instantiated as `Store[StringKey, *someval]`, the deque's element type becomes `*Entry[StringKey, *someval]`; `PushFront`/`PopBack` are fully type-checked — no cast, no `interface{}` boxing. That type safety is the payoff of a generic library over a `container/list`-style `interface{}` container.

### A first-party generic container

The repo keeps a generics fork of `container/list`:

```go title="internal/tools/list/list.go"
// Package list is the standard library's 'container/list', but using Generics
// for performance.

type Element[T any] struct {
	next, prev *Element[T]
	list       *List[T]
	Value      T
}

type List[T any] struct {
	root Element[T]
	len  atomic.Int64
}

func New[T any]() *List[T] { return new(List[T]).Init() }
func (l *List[T]) Front() *Element[T] { /* ... */ }
```

Stdlib `container/list` stores `interface{}` in `Element.Value`; this fork stores `T` — for the connection pool's waitlist that means no boxing of `waiter[C]` per borrow, on the latency-sensitive query path.

## The rule that bites everyone: methods can't have their own type parameters

**Go forbids** a type parameter on an individual method. A method may *reuse* the receiver's type parameters but may not introduce new ones:

```go title="Teaching example — does NOT compile in Go"
func (b *Box[T]) Map[U any](f func(T) U) U { // error: methods cannot have type parameters
	return f(b.value)
}
```

The workaround everywhere in this repo is a **top-level generic function** instead of a method — the receiver-like object becomes the first argument:

- `sortedmaps.Keys[K cmp.Ordered, V any](m map[K]V)` — a free function, not a method on a map wrapper.
- `prototest.RequireElementsMatch[T proto.Message](t *testing.T, expected, actual []T, ...)` — a free generic test helper.
- The connpool retry helpers `retryOnConnectionError[T any]` / `execWithContextCancel[T any]` take the `*Conn` as an ordinary first argument so each call can pick its own `T`.

```go title="internal/tools/prototest/prototest.go"
func RequireElementsMatch[T proto.Message](t *testing.T, expected, actual []T, msgAndArgs ...any) {
	t.Helper()
	if len(expected) != len(actual) { /* ... */ }
	// ... order-insensitive proto.Equal comparison ...
}
```

:::caution[Gotcha]
If you find yourself wanting `obj.DoSomething[U](...)`, stop — Go won't allow it. Rewrite as `DoSomething[U](obj, ...)`. This is *the* most surprising generics rule for newcomers from other typed languages.
:::

## Generics vs interfaces vs codegen

| Use | Reach for it when | What you get |
|---|---|---|
| **Generics** | a type-safe container or one algorithm over many element types, no runtime polymorphism | no `interface{}` boxing, no casts; monomorphized at compile time. `Pool[C]`, `ProtoStore[K, V]`, `retryOnConnectionError[T]` |
| **Interfaces** | you need *runtime* polymorphism — heterogeneous values dispatched through one method set | dynamic dispatch. `Connection` plays this role as a value type (and as a constraint) |
| **Codegen** | the transformation can't be expressed as "same code over different types" at all | generated code per concrete type: whole-AST clone/rewrite, generated protobuf messages |

Walking every concrete AST node type to clone/rewrite it can't be a generic — no single type parameter captures "for each field of each of these many unrelated structs, recurse appropriately." So a helper tool generates clone/rewrite by reflecting over the AST node set, and `protoc` generates message types. See [Parser, Lexer, AST & Codegen](/go-guide/project/06-parser-lexer-ast-codegen/).

:::note[Each instantiation is a distinct type — no variance]
`Pool[*regularConn]` and `Pool[*otherConn]` are unrelated types: no assignment between them, no `[]Pool[*regularConn]` where `[]Pool[Connection]` is wanted. Go generics have no covariance. If you need to treat differently-instantiated values uniformly at runtime, use an interface, not a generic.
:::

## Checkpoints

1. Inside `retryOnConnectionError[T any]`, why can't the error paths `return nil, err`, and what do they write instead?
   <details><summary>Answer</summary>Because `T` is unknown at definition time and not every `T` has a `nil` (e.g. `T = bool`). Every error path declares `var zero T` and returns `zero, err` — the correct empty value for whatever `T` is at the instantiation site.</details>

2. `sortedmaps.Keys` is `cmp.Ordered` but `ByStr` only `comparable`. What does the stronger constraint buy, and how does `ByStr` cope without it?
   <details><summary>Answer</summary><code>cmp.Ordered</code> adds <code>&lt;</code>/<code>&lt;=</code>/<code>&gt;</code>/<code>&gt;=</code>, which <code>slices.Sort</code> needs. <code>comparable</code> only promises <code>==</code>/<code>!=</code>, so <code>ByStr</code> uses <code>slices.SortFunc</code> comparing <code>fmt.Sprintf("%v", key)</code> string forms.</details>

3. Why is `var _ Value[int] = (*value.Static[int])(nil)` written in `config/value.go`, and what does it cost at runtime?
   <details><summary>Answer</summary>It's a compile-time assertion that <code>*value.Static[int]</code> satisfies the generic interface <code>Value[int]</code>. Assigned to the blank identifier, it costs nothing at runtime; if the implementation ever stopped satisfying the interface, the build would fail at this line.</details>

4. You want `func (s *ProtoStore[K, V]) Decode[U any](key K) U`. Will it compile? What's the idiomatic fix?
   <details><summary>Answer</summary>No — Go forbids methods declaring their own type parameters. The fix is a top-level generic function taking the store as its first argument: <code>func Decode[K comparable, V proto.Message, U any](s *ProtoStore[K, V], key K) U</code>, mirroring <code>prototest.RequireElementsMatch</code> and the connpool retry helpers.</details>
