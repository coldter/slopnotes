No classes, no inheritance, no `implements`/`extends`. Two tools instead: **interfaces** (a method set a value satisfies) and **embedding** (placing one type inside another to reuse its methods).

## Implicit satisfaction: no `implements`

A type satisfies an interface the moment its method set covers the interface's methods — nothing is written down:

```go
type Stringer interface {
	String() string
}

type Point struct{ X, Y int }

func (p Point) String() string { return fmt.Sprintf("(%d,%d)", p.X, p.Y) }

func describe(s Stringer) { fmt.Println(s.String()) }

func main() { describe(Point{1, 2}) } // works; compiler matches method sets
```

Interfaces are defined by the **consumer**, not the producer — implementers may live in packages that never import the interface. The textbook case is `QueryService`, whose doc comment is the only place implementers are named:

```go title="internal/queryservice/queryservice.go"
// QueryService is the interface for executing queries on a pooler.
//
// This interface is implemented by the grpcQueryService (the gRPC client to the
// pooler), by the in-process executor, and by the PoolerGateway router.
type QueryService interface {
	ExecuteQuery(
		ctx context.Context,
		target *query.Target,
		sql string,
		options *query.ExecuteOptions,
	) (*sqltypes.Result, *query.ReservedState, error)

	StreamExecute( /* ... */ )
	// ... more methods
}
```

Three structurally unrelated types satisfy it without saying so. That lets the system swap a real gRPC backend for an in-process executor or a test mock at the boundary, with zero caller changes.

:::tip[Idiom]
Document implementers in the interface comment, and add a compile-time assertion `var _ QueryService = (*grpcQueryService)(nil)` to force a build error if a type drifts out of conformance. A typo in a method name silently *un-implements* the interface otherwise.
:::

## Small vs. large interfaces

Go favors **small** interfaces (`io.Reader` is just `Read`) — easy to satisfy, mock, and compose. But deliberately **large** capability interfaces exist too. `internal/rpcclient/client.go` shows both:

Small — a pure behavioral interface:

```go title="internal/rpcclient/client.go"
type ManagerHealthStream interface {
	Recv() (*poolermanagerdatapb.ManagerHealthStreamResponse, error)
	Send(*poolermanagerdatapb.ManagerHealthStreamClientMessage) error
}
```

Large — a capability interface aggregating an entire RPC surface (~20 methods) so one object means "talk to a pooler node":

```go title="internal/rpcclient/client.go"
// PoolerClient defines the unified interface for communicating with a pooler node.
type PoolerClient interface {
	Recruit(ctx context.Context, pooler *clustermetadatapb.Pooler, request *consensusdatapb.RecruitRequest) (*consensusdatapb.RecruitResponse, error)
	Promote(ctx context.Context, pooler *clustermetadatapb.Pooler, request *consensusdatapb.PromoteRequest) (*consensusdatapb.PromoteResponse, error)
	// ... ~20 methods
}
```

Reach for a small interface when many unrelated types implement it and callers need one behavior; for a large one when abstracting a whole subsystem behind one swappable seam. The cost of large: every implementer (incl. mocks) must supply all methods — hence generated mocks.

## Interface embedding (interface-in-interface)

An interface can embed another; the outer one is the **set union**. The AST builds a three-level chain in `internal/parser/ast/nodes.go`:

```go
type Reader interface{ Read(p []byte) (int, error) }
type Closer interface{ Close() error }

// ReadCloser = Read + Close. A type satisfies it iff it has both methods.
type ReadCloser interface {
	Reader
	Closer
}
```

```go title="internal/parser/ast/nodes.go"
type Node interface {
	NodeTag() NodeTag
	Location() int
	SetLocation(location int)
	String() string
	SqlString() string
}
```

```go title="internal/parser/ast/nodes.go"
type Stmt interface {
	Node
	StatementType() string
}

type Expression interface {
	Node
	ExpressionType() string
}

type Value interface {
	Expression // which embeds Node
	IsValue() bool
}
```

A `Value` requires all of `Node`'s five methods plus `ExpressionType()` plus `IsValue()` — "a value is a kind of expression is a kind of node" expressed as method-set containment. A `*Integer` satisfies `Value` and can be assigned to `Value`, `Expression`, or `Node` interchangeably.

Not confined to the parser — the gateway grows its capability interface by embedding `QueryService`:

```go title="internal/gateway/poolergateway/pooler_gateway.go"
type Gateway interface {
	// the query service that this Gateway wraps around
	queryservice.QueryService

	// QueryServiceByID returns a QueryService
	QueryServiceByID(ctx context.Context, id *clustermetadatapb.ID, target *query.Target) (queryservice.QueryService, error)
}
```

A `Gateway` *is* a `QueryService` and can also resolve by ID. If `QueryService` gains a method, `Gateway` automatically requires it too. (Don't confuse the `Gateway` interface with the `PoolerGateway` struct implementing it — the struct uses plain named fields, not embedding.)

## Struct embedding and method promotion

Embed a type as an **anonymous field** (type name, no field name) and the outer struct *promotes* the embedded fields/methods:

```go
type Base struct{ ID int }
func (b *Base) Describe() string { return fmt.Sprintf("id=%d", b.ID) }

type User struct {
	Base // anonymous field — embedding
	Name string
}

func main() {
	u := &User{Base: Base{ID: 7}, Name: "ada"}
	fmt.Println(u.ID)         // promoted field: actually u.Base.ID
	fmt.Println(u.Describe()) // promoted method: actually u.Base.Describe()
}
```

Every AST node embeds `BaseNode` to inherit the boilerplate:

```go title="internal/parser/ast/nodes.go"
type BaseNode struct {
	Tag NodeTag
	Loc int
}

func (n *BaseNode) NodeTag() NodeTag         { return n.Tag }
func (n *BaseNode) Location() int            { return n.Loc }
func (n *BaseNode) String() string           { return fmt.Sprintf("%s@%d", n.Tag, n.Loc) }
func (n *BaseNode) SetLocation(location int) { n.Loc = location }
```

```go title="internal/parser/ast/nodes.go"
type Integer struct {
	BaseNode
	IVal int
}

func NewInteger(value int) *Integer {
	return &Integer{
		BaseNode: BaseNode{Tag: T_Integer},
		IVal:     value,
	}
}

func (i *Integer) String() string    { return fmt.Sprintf("Integer(%d)@%d", i.IVal, i.Location()) }
func (i *Integer) SqlString() string { return strconv.Itoa(i.IVal) }
```

`*Integer` has `NodeTag`/`Location`/`SetLocation` promoted from `*BaseNode` plus its own `String`/`SqlString`, so its method set covers all of `Node` (and with `ExpressionType()`/`IsValue()` elsewhere, `Value` too). Embedding supplied the shared 80%; the override supplied the unique 20%.

### The override / shadowing rule

An outer method with the same name *shadows* the promoted one for calls through the outer type:

```go
i := NewInteger(42)
i.SqlString()          // "42"  — Integer.SqlString wins
i.BaseNode.SqlString() // panics — you explicitly selected the base version
```

`BaseNode.SqlString()` deliberately **panics** (fail loud) — there's no sensible default SQL for an arbitrary node:

```go title="internal/parser/ast/nodes.go"
func (n *BaseNode) SqlString() string {
	if n.Tag == T_Invalid {
		return "<INVALID>"
	}
	panic(fmt.Sprintf("SqlString() not implemented for node type %s (tag: %d). "+
		"Please implement SqlString() method for this node type to enable SQL deparsing.",
		n.Tag, int(n.Tag)))
}
```

### Embedding is **not** inheritance

Promotion is *forwarding*, not virtual dispatch. If `BaseNode.Render()` calls `n.NodeTag()`, it calls **`BaseNode`'s** `NodeTag` — `n` is a `*BaseNode`, resolved against `*BaseNode`'s method set, not the embedder's dynamic type. No `super` back-reference. When you need that polymorphism, pass the *interface* and let dispatch pick the method — the deparser calls `someNode.SqlString()` through `Node` and lands on `Integer.SqlString`.

:::caution[Gotcha]
Pointer vs. value receivers decide which type satisfies the interface. Every AST method is pointer-receiver, so only `*Integer` satisfies `Node`/`Value`. Embedding `BaseNode` by value inside `Integer` still promotes `*BaseNode`'s pointer methods because the embedding struct is addressable when you hold a `*Integer`. Rule of thumb: hold AST nodes as pointers.
:::

## Embedding an interface in a struct (the `Unimplemented*Server` idiom)

Embed an *interface* as an anonymous field and the struct promotes its methods — and satisfies that interface even defining none itself. This powers gRPC server forward-compatibility: for every service, protoc generates an `Unimplemented<Service>Server` whose methods all return "unimplemented", and every server struct embeds it:

```go title="internal/orchestrator/grpcserver/server.go"
type OrchServer struct {
	orchpb.UnimplementedOrchServiceServer
	engine      *recovery.Engine
	coordinator *consensus.Coordinator
	logger      *slog.Logger
}
```

When a new RPC is added to the proto and regenerated, the interface grows a method — but the embedded `Unimplemented` type already provides it (returning "unimplemented" at runtime), so the struct keeps satisfying the interface and the build stays green. Override only the RPCs you handle. Same struct in every service.

:::caution[Gotcha]
Embedding a *real* interface field can accidentally promote methods you didn't mean to forward. To wrap/decorate rather than expose, use a **named** field (`rw io.ReadWriteCloser`) and forward only intended methods.
:::

## Accept interfaces, return structs

Guideline: functions **accept** interfaces (any implementation) but **return** concrete types (full API, no premature narrowing). The repo follows it with one deliberate twist — `newGRPCQueryService` returns the *interface* because the concrete type is unexported:

```go title="internal/gateway/poolergateway/grpc_query_service.go"
type grpcQueryService struct { // lowercase — package-private
	conn   *grpc.ClientConn
	client poolerservice.PoolerServiceClient
	// ...
}

func newGRPCQueryService(
	conn *grpc.ClientConn,
	poolerID topoclient.ComponentID,
	logger *slog.Logger,
) queryservice.QueryService { // returns the INTERFACE
	return &grpcQueryService{ /* ... */ }
}
```

Returning the interface here is intentional narrowing: nobody outside the package can name the concrete type, so the gRPC backend is genuinely swappable. Contrast AST constructors returning concrete structs (`NewInteger(value int) *Integer`) — callers read `i.IVal` directly — and factories that pick a concrete type dynamically and return the common interface:

```go title="internal/parser/ast/nodes.go"
func NewQualifiedName(schema, name string) Node { // returns interface; builds a *RangeVar
	return &RangeVar{ /* ... */ }
}
```

Rule: **return the most specific type your caller can usefully depend on.** A factory hiding its backend returns an interface; a constructor for a concrete value returns the struct. When in doubt, return the struct — loosening later is easy, tightening is breaking.

## Type assertions

An interface hides its dynamic type; a **type assertion** recovers it. Two forms:

```go
var n Node = NewInteger(5)

i := n.(*Integer)     // single-value: panics if n is not actually a *Integer
i, ok := n.(*Integer) // comma-ok: ok is false (and i is zero) on mismatch — no panic
```

You can also assert to an *interface* (a runtime conformance check). The AST helpers use comma-ok on `any`:

```go title="internal/parser/ast/nodes.go"
func IsNode(v any) bool {
	_, ok := v.(Node) // does v satisfy the Node interface at runtime?
	return ok
}

func CastNode(v any) Node {
	if node, ok := v.(Node); ok {
		return node
	}
	return nil // not a node → nil interface, no panic
}
```

```go title="internal/parser/ast/nodes.go"
func IntVal(node Node) int {
	if i, ok := node.(*Integer); ok {
		return i.IVal
	}
	return 0
}
```

`NodeTagOf`, `LocationOf`, `BoolVal`/`FloatVal` follow the same comma-ok shape. Use the single-value form only when a mismatch is a programmer bug, not a data condition.

## Type switches

A multi-way comma-ok assertion — dispatch over a closed family of node types:

```go
func area(s Shape) float64 {
	switch v := s.(type) { // v is bound to the concrete type in each case
	case *Circle:
		return 3.14159 * v.R * v.R // v is *Circle here
	case *Rect:
		return v.W * v.H // v is *Rect here
	default:
		return 0 // v keeps the interface type (Shape) here
	}
}
```

`GetExpressionArgs` dispatches over a dozen expression node types:

```go title="internal/parser/ast/expressions.go"
func GetExpressionArgs(expr Node) *NodeList {
	switch e := expr.(type) {
	case *FuncExpr:
		return e.Args
	case *OpExpr:
		return e.Args
	case *BoolExpr:
		return e.Args
	case *CaseExpr:
		return e.Args
	case *CaseWhen:
		return NewNodeList(e.Expr, e.Result)
	// ... *CoalesceExpr, *ArrayExpr, *ScalarArrayOpExpr,
	//     *RowExpr, *Aggref, *WindowFunc, *SubLink ...
	default:
		return nil
	}
}
```

In a **grouped** case the bound variable keeps the **interface** type (the cases disagree on the concrete type):

```go title="internal/parser/ast/nodes.go"
switch n := node.(type) {
case *NodeList:
	for _, item := range n.Items { // n is *NodeList — concrete, single case
		if item != nil {
			WalkNodes(item, walker)
		}
	}
case *Integer, *Float, *Boolean, *String, *BitString, *Null:
	// n is still Node here (grouped case) — these are all leaves, no traversal
	return
default:
	// other node types: not yet traversed
}
```

The normalizer uses a type switch to skip subtrees and finishes with a single-value assertion back to `Stmt` — justified because `Rewrite` is *known* to return a `Stmt` there (a documented invariant, not a runtime branch):

```go title="internal/parser/ast/normalizer.go"
switch n := node.(type) {
case *VariableSetStmt, *VariableShowStmt, *DefElem:
	return false // grouped: don't normalize these subtrees
case *FuncCall:
	if isPlannerLiteralFunc(n.Funcname) { // single case: n is *FuncCall
		return false
	}
}
// ...
}, nil).(Stmt) // assert Rewrite's Node result back to Stmt
```

:::note
The AST has two dispatch styles: type switch (Go's dynamic type) and tag-based (`node.NodeTag()` switches on an integer — cheaper, no concrete-type imports). The generated `ast_clone.go`/`ast_rewrite.go` contain huge machine-generated type switches — regenerated, not hand-written.
:::

## The empty interface and `any`

`interface{}` has no methods, so every type satisfies it — Go's dynamic-typing escape hatch. Since Go 1.18, `any` is an alias; write `any`. `NewValue` sits at the Go-literal ↔ AST boundary, so it takes `any` and type-switches:

```go title="internal/parser/ast/nodes.go"
func NewValue(val any) Node {
	switch v := val.(type) {
	case string:
		return NewString(v)
	case int:
		return NewInteger(v)
	case int32:
		return NewInteger(int(v))
	case int64:
		return NewInteger(int(v))
	case float32:
		return NewFloat(fmt.Sprintf("%g", v))
	case float64:
		return NewFloat(fmt.Sprintf("%g", v))
	case bool:
		return NewBoolean(v)
	case nil: // matches an untyped nil val
		return NewNull()
	default:
		return NewString(fmt.Sprintf("%v", v)) // unknown: stringify it
	}
}
```

:::caution[Gotcha]
`any` discards compile-time safety — the `default` here *silently stringifies* unknown types. Reserve `any` for genuine boundaries (parsing Go literals, JSON, reflection); prefer generics when the type is known at the call site.
:::

## The typed-nil gotcha

An interface value is a `(type, value)` pair and is `== nil` **only when both halves are nil**. Storing a nil concrete pointer into an interface sets the type half, so the interface is **not** `== nil`:

```go
type E struct{}
func (*E) Error() string { return "boom" }

func bad() error {
	var p *E = nil
	return p // returns a non-nil error wrapping a nil *E !!
}

func main() {
	err := bad()
	fmt.Println(err == nil) // FALSE
}
```

Production code guards explicitly — nil-check before returning, and return the literal `nil` (a truly nil interface):

```go title="internal/pooler/internal/poolerserver/pooler.go"
func (s *QueryPoolerServer) InternalQueryService() executor.InternalQueryService {
	// Explicit nil check required: returning a nil *Executor directly would produce a
	// non-nil interface value wrapping a nil pointer, causing callers' == nil checks to
	// pass but method calls on the interface to panic.
	if s.executor == nil {
		return nil
	}
	return s.executor
}
```

A regression test reproduces the bug deliberately:

```go title="internal/topoclient/wrapperconn_test.go"
func (f *typedNilMockFactory) newConn() (Conn, error) {
	var conn *mockConn // concrete type → typed nil
	if f.shouldFail {
		return conn, errx.Errorf(rpcpb.Code_UNAVAILABLE, "factory error")
	}
	// ...
}
```

and the code under test checks the *error* first, never trusting the conn:

```go title="internal/topoclient/wrapperconn.go"
// Check error first - if err != nil, conn is unusable (may be typed nil).
if err != nil {
	if c.closed {
		return false
	}
	return true
}
```

:::caution[Gotcha — the one to memorize]
Never return a concrete nil pointer where the signature is an interface. Nil-check and `return nil`, check the accompanying error first, or return the concrete pointer type and let the caller decide when to box it. The compiler won't catch this.
:::

## Checkpoints

1. `*Foo` has `Bar()` and `Baz()`; interface `Doer` requires only `Bar()`. Does `*Foo` satisfy `Doer`, and where is that written down?
   <details><summary>Answer</summary>Yes — implicit and structural; extra methods are fine. Written down <em>nowhere</em> in code; at most a comment or <code>var _ Doer = (*Foo)(nil)</code>. No <code>implements</code> keyword.</details>

2. `BaseNode.SqlString()` panics; `Integer` overrides it. What happens on `someInteger.BaseNode.SqlString()` directly, and why doesn't the override save you?
   <details><summary>Answer</summary>It panics. <code>.BaseNode.SqlString()</code> explicitly selects the embedded base method, bypassing the override. Promotion is forwarding, not virtual dispatch — no back-reference from <code>BaseNode</code> to <code>Integer</code>. Calls through <code>someInteger.SqlString()</code> or the <code>Node</code> interface resolve to the override.</details>

3. `func provide() error { var e *myErr = nil; return e }`. Is `provide() == nil` true? What's the fix?
   <details><summary>Answer</summary>False — the returned <code>error</code> has dynamic type <code>*myErr</code> and nil value, so it's not <code>== nil</code>. Fix: nil-check first and <code>return nil</code>, or return <code>*myErr</code> and box only when non-nil — the pattern in <code>InternalQueryService</code>.</details>

4. In a type switch, when does the bound variable have the concrete type vs. the interface type?
   <details><summary>Answer</summary>Single-type case (<code>case *FuncExpr:</code>) → concrete type, fields accessible. Grouped case (<code>case *Integer, *Float:</code>) and <code>default</code> → the original interface type.</details>
