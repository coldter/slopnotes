Methods can only be declared in the same package as their type.

## Type definition vs alias

| | Definition `type T U` | Alias `type T = U` |
|---|---|---|
| Creates | a brand-new type (same underlying layout, distinct identity) | nothing — a second spelling for `U` |
| Conversion | needs explicit `T(x)` to cross | assignable both ways, no conversion |
| Methods | you can attach your own | **cannot** attach (you don't own `U`) |

```go
type Celsius float64      // definition: NEW type over float64
func (c Celsius) String() string { return fmt.Sprintf("%.1f°C", float64(c)) }

var t Celsius = 36.6
var f float64 = 36.6
// t = f                  // COMPILE ERROR
t = Celsius(f)            // ok: explicit conversion

type Temp = float64       // alias: Temp and float64 are the SAME type
var x Temp = 1.5
var y float64 = x         // ok, no conversion
// func (t Temp) Foo() {} // COMPILE ERROR: cannot define methods on float64 here
```

### Definition over a builtin

The AST defines PostgreSQL's object identifier as a distinct type:

```go title="internal/parser/ast/expressions.go"
type Oid uint32
```

Payoff: type safety. A bare `uint32` is anything; an `Oid` is unambiguously a PG type OID. Use named constants (`ast.TEXTOID`) — never hardcode `uint32 = 25` for TEXT. The required `Oid(x)` conversion is the documentation. Same file: `type AttrNumber int16`, `type Index uint32`, `type Datum uintptr`.

### Alias to re-export a third-party type

```go title="internal/tools/pgutil/lsn.go"
// LSN is a PostgreSQL Log Sequence Number.
type LSN = pglogrepl.LSN
```

`pgutil.LSN` *is* `pglogrepl.LSN` — values flow both ways with no conversion; `ParseLSN` just forwards. To add an `LSN` method you'd have to switch to a definition and pay the conversion.

### Alias as a migration shim

```go title="internal/parser/tokens.go"
// TokenType represents the type of a lexical token.
// This is now just an alias for int to maintain compatibility during transition.
// New code should use the generated parser constants directly.
type TokenType = int
```

Because `TokenType` *is* `int`, existing `int` call sites keep compiling during the migration to generated constants. A definition would have broken them all at once.

## Structs and keyed literals

Always use the **keyed** literal; avoid positional:

```go
type Point struct {
	X, Y int
}

p := Point{X: 1, Y: 2}   // keyed: explicit, order-independent, future-proof
q := Point{3, 4}         // positional: breaks/silently shifts when fields are added
```

Real constructor setting every field by name:

```go title="internal/parser/ast/expressions.go"
func NewVar(varno int, varattno AttrNumber, vartype Oid) *Var {
	return &Var{
		BaseExpr: BaseExpr{BaseNode: BaseNode{Tag: T_Var}},
		Varno:    varno,
		Varattno: varattno,
		Vartype:  vartype,
	}
}
```

Unset fields (`Vartypmod`, `Varcollid`, …) take their zero value — not an error. Keyed literals let you set only what matters. `go vet`'s `composites` check flags positional literals for imported structs.

## Field tags

A backtick-quoted **tag** is reflection-read metadata; `encoding/json`, `yaml.v3`, and the protobuf runtime read it. Convention: `` `key:"value,opt1,opt2"` ``.

```go
type Server struct {
	Host string `yaml:"host"`
	Port int    `yaml:"port,omitempty"`
}
```

### YAML config tags

Smallest real example — the cluster config:

```go title="cmd/platformctl/command/cluster/config.go"
type ClusterConfig struct {
	Provisioner       string         `yaml:"provisioner"`
	ProvisionerConfig map[string]any `yaml:"provisioner-config,omitempty"`
}
```

```go title="cmd/platformctl/command/cluster/config.go"
var config ClusterConfig
if err := yaml.Unmarshal(data, &config); err != nil { /* ... */ }
if config.Provisioner == "" {
	return nil, "", fmt.Errorf("provisioner not specified in config file %s", configFile)
}
```

The `yaml:"provisioner"` tag maps YAML key `provisioner` onto Go field `Provisioner` (exported Go name is capitalized; wire name is lowercase).

Bigger example — renames, `omitempty`, pointer fields for optional sub-config:

```go title="internal/provisioner/local/config.go"
type BackupConfig struct {
	Type  string       `yaml:"type"` // "local", "s3", "azure", etc.
	Local *LocalBackup `yaml:"local,omitempty"`
	S3    *S3Backup    `yaml:"s3,omitempty"`
}

type S3Backup struct {
	Bucket            string `yaml:"bucket"`
	Region            string `yaml:"region"`
	Endpoint          string `yaml:"endpoint,omitempty"`
	KeyPrefix         string `yaml:"key-prefix,omitempty"`
	UseEnvCredentials bool   `yaml:"use-env-credentials,omitempty"`
}
```

`KeyPrefix` serializes as `key-prefix` (Go CamelCase → YAML kebab-case). Optional sub-configs are **pointers** (`*LocalBackup`): `nil` distinguishes "absent" from "present but empty".

:::caution[Gotcha]
`omitempty` affects only *marshaling*. An absent YAML key leaves the Go field at zero value — nothing errors. That's why the loader validates required fields by hand (`if config.Provisioner == ""`). Tags are not a validation schema.
:::

### Generated protobuf tags — dual tags, opaque fields

```go title="internal/pb/serviceinfo/serviceinfoservice.pb.go"
type BuildInfo struct {
	state         protoimpl.MessageState `protogen:"open.v1"`
	Revision      string                 `protobuf:"bytes,1,opt,name=revision,proto3" json:"revision,omitempty"`
	Modified      bool                   `protobuf:"varint,2,opt,name=modified,proto3" json:"modified,omitempty"`
	CommitTime    *timestamppb.Timestamp `protobuf:"bytes,3,opt,name=commit_time,json=commitTime,proto3" json:"commit_time,omitempty"`
	GoVersion     string                 `protobuf:"bytes,4,opt,name=go_version,json=goVersion,proto3" json:"go_version,omitempty"`
	unknownFields protoimpl.UnknownFields
	sizeCache     protoimpl.SizeCache
}
```

One tag holds multiple `key:"..."` groups: `protobuf:` carries wire type + field number + proto name (field numbers are the wire identity); `json:` carries the JSON name. Message-typed fields are pointers so absence is `nil`. Treat generated `pb` structs as opaque — use generated getters, never hand-edit (`// Code generated`, regenerated by `make proto`).

## Methods and receivers

A method is a function with a **receiver** before the name; the receiver type must be a named type in the same package (any named type — struct, slice, or integer):

```go
func (c Celsius) String() string { return fmt.Sprintf("%.1f°C", float64(c)) }
```

Value-receiver method on a named slice type:

```go title="internal/sqltypes/sqltypes.go"
// Value represents a nullable column value.
// nil means NULL, []byte{} means empty string.
type Value []byte

// IsNull returns true if the value is NULL.
func (v Value) IsNull() bool {
	return v == nil
}
```

`Value` is `type Value []byte` — a definition, so it owns its method set. Value receivers are fine here: copying a slice copies only the 3-word header, not the bytes.

## Value vs pointer receivers

Use a **pointer receiver `(*T)`** when any of these hold:

1. the method **mutates** the receiver;
2. the struct is **large** (copying is wasteful);
3. the struct contains a `sync.Mutex` or other must-not-copy field;
4. for **consistency** — if any method needs a pointer, make them all pointers.

Use a **value receiver `(T)`** when the type is small, read-only, and naturally immutable (like `Value []byte`).

### The decisive pointer case: `Consolidator`

```go title="internal/preparedstatement/consolidator.go"
type Consolidator struct {
	mu sync.Mutex // protects the fields below

	stmts      map[string]*PreparedStatementInfo
	incoming   map[uint32]map[string]*PreparedStatementInfo
	usageCount map[*PreparedStatementInfo]int
	lastUsedID int
}
```

```go title="internal/preparedstatement/consolidator.go"
func (psc *Consolidator) AddPreparedStatement(connId uint32, name, queryStr string, paramTypes []uint32) (*PreparedStatementInfo, error) {
	psc.mu.Lock()
	defer psc.mu.Unlock()
	// ...
}
```

Two clauses fire at once: the method mutates state, and `sync.Mutex` must never be copied (a value receiver copies the lock per call, defeating exclusion — `go vet`'s `copylocks` flags this). Pointer receiver is mandatory. Never pass such a struct by value, range over a slice of them by value, or store them in a map by value.

## Method sets and interface satisfaction

- Method set of value `T`: only **value-receiver** methods.
- Method set of pointer `*T`: **both** value- and pointer-receiver methods.

So if a type has any pointer-receiver method an interface requires, **only `*T` satisfies it**:

```go
type Stringer interface{ String() string }

type Counter struct{ n int }
func (c *Counter) String() string { return strconv.Itoa(c.n) }  // POINTER receiver

var _ Stringer = &Counter{}   // ok
// var _ Stringer = Counter{} // COMPILE ERROR: value lacks String()
```

### `*fundamental` implements `error` only via pointer

```go title="internal/errx/errx.go"
// fundamental is an error that has a message and a stack, but no caller.
type fundamental struct {
	msg  string
	code rpcpb.Code
	*stack
}

func (f *fundamental) Error() string { return f.msg }
```

`Error()`/`Format()` are pointer receivers, so only `*fundamental` satisfies `error` — constructors return `&fundamental{...}`:

```go title="internal/errx/errx.go"
func New(code rpcpb.Code, message string) error {
	return &fundamental{
		msg:   message,
		code:  code,
		stack: callers(),
	}
}
```

Same for `PgDiagnostic`; extract with a pointer target:

```go title="internal/gateway/auth/pooler_credential_provider.go"
var diag *errx.PgDiagnostic
if errors.As(err, &diag) {
	switch diag.Code { /* ... */ }
}
```

`errors.As` walks the chain for something assignable to `*PgDiagnostic` (a `**PgDiagnostic` target).

## Zero values and useful-zero-value design

Every type has a zero value: `0`, `""`, `false`, `nil` (pointers/slices/maps/channels/interfaces/funcs), recursively-zeroed structs. Design so the zero value is **useful** and skip the constructor.

### `sync.Mutex` is usable at zero

`var mu sync.Mutex` is ready to `Lock()` — no init. That's why `Consolidator.mu` needs no setup; only its maps do.

### `Value(nil)` means SQL NULL

```go title="internal/sqltypes/sqltypes.go"
func (v Value) IsNull() bool {
	return v == nil
}
```

The zero of `Value` (`nil`, since underlying is `[]byte`) is given domain meaning: **SQL NULL**. `[]byte{}` is the empty string — a distinct state. `IsNull` checks `v == nil`, so empty-but-non-nil is not null.

:::caution[Gotcha]
Don't normalize `[]byte{}` ↔ `nil`. `Value([]byte{})` (empty string) and `Value(nil)` (NULL) are intentionally different; "cleaning up" empty slices to nil turns empty strings into NULLs — a SQL correctness bug.
:::

### A nil pointer receiver can be a valid no-op

```go title="internal/sqltypes/sqltypes.go"
func (r *Result) ToProto() *query.QueryResult {
	if r == nil {
		return nil
	}
	// ...
}
```

Calling a pointer-receiver method on a nil pointer is **legal** — it only panics on field dereference. The `if r == nil` guard lets callers write `result.ToProto()` without a nil check. The panic happens on *field access*, not on the call.

## The `NewXxx` constructor convention

No language constructors — the idiom is `New`/`NewType` returning `*T`. Write one **only when the zero value is not enough**.

### Mandatory: `NewConsolidator`

```go title="internal/preparedstatement/consolidator.go"
func NewConsolidator() *Consolidator {
	return &Consolidator{
		stmts:      make(map[string]*PreparedStatementInfo),
		incoming:   make(map[uint32]map[string]*PreparedStatementInfo),
		usageCount: make(map[*PreparedStatementInfo]int),
		lastUsedID: 0,
	}
}
```

A nil map **panics on write** (read/range are fine). `Consolidator` has three written maps, so a bare `Consolidator{}` panics on first `AddPreparedStatement` with "assignment to entry in nil map" — at runtime, far from the declaration. Litmus test: if the zero value panics or misbehaves, a constructor is mandatory.

### Used though no maps/mutex: the AST `NewXxx` family

```go title="internal/parser/ast/expressions.go"
func NewVar(varno int, varattno AttrNumber, vartype Oid) *Var {
	return &Var{
		BaseExpr: BaseExpr{BaseNode: BaseNode{Tag: T_Var}},
		Varno:    varno,
		Varattno: varattno,
		Vartype:  vartype,
	}
}
```

`Var` has no maps/mutex, but the embedded `Tag` **must** be `T_Var` — the zero `T_Invalid` would be wrong. A constructor is justified whenever there's a non-zero invariant to establish, not only memory to allocate. (They return `*Var` because AST nodes travel by pointer with pointer-receiver methods.)

:::tip[Idiom]
Zero value fully usable (like `Value` or `sync.Mutex`) → write no constructor. Map/channel to `make`, default to set, or invariant to enforce (a tag) → write `NewXxx` returning a pointer.
:::

## Embedding (teaser)

No inheritance — **embedding**: a field with no name (just a type) promotes the embedded type's exported fields/methods onto the outer struct. Composition that looks like inheritance at the call site.

The AST nodes form a two-level chain:

```go title="internal/parser/ast/nodes.go"
type BaseNode struct {
	Tag NodeTag // Node type tag
	Loc int     // Source location in bytes
}

func (n *BaseNode) NodeTag() NodeTag { return n.Tag }
func (n *BaseNode) Location() int    { return n.Loc }
```

```go title="internal/parser/ast/expressions.go"
// BaseExpr provides common expression functionality.
type BaseExpr struct {
	BaseNode
}

func (e *BaseExpr) IsExpr() bool { return true }
```

A concrete node embeds the middle layer (`type Var struct { BaseExpr; Varno int; ... }`). Through two levels of promotion, `*Var` can call `Location()` — even though `Var` declares none — because it's promoted up from `*BaseNode` through `BaseExpr`. That's why `Var.String()` can write `v.Location()`. Error types use pointer embedding (`fundamental` embeds `*stack`).

Full treatment of promotion, shadowing, and interface satisfaction: [Interfaces & Composition](/go-guide/language/03-interfaces-composition/).

## Checkpoints

1. `type Status = int` vs `type Status int` — which lets you define `func (s Status) String() string`, and which requires `Status(x)` to assign from a plain `int`?
   <details><summary>Answer</summary>Only the definition <code>type Status int</code> lets you attach methods and requires <code>Status(x)</code>. The alias is the same type as <code>int</code> — no methods, no conversion. See <code>type Oid uint32</code> (definition) vs <code>type TokenType = int</code> (alias).</details>

2. `Consolidator` has all pointer receivers + a mandatory `NewConsolidator`; `Value` has value receivers and no constructor. Give the one structural fact forcing each.
   <details><summary>Answer</summary><code>Consolidator</code> contains a <code>sync.Mutex</code> (never copy → pointer receivers) and three written maps (nil-map write panics → <code>make()</code> them in <code>NewConsolidator</code>). <code>Value []byte</code> has neither: small, read-only, meaningful zero (<code>nil</code>) → value receivers, no constructor.</details>

3. Why does `errx.New` return `&fundamental{...}` not `fundamental{...}`?
   <details><summary>Answer</summary><code>Error()</code>/<code>Format</code> are pointer-receiver methods, so only <code>*fundamental</code> has them in its method set and only the pointer satisfies <code>error</code>. Returning a value would fail to compile.</details>

4. `func (r *Result) ToProto() ... { if r == nil { return nil }; ... }` — why doesn't calling this on nil `*Result` panic, but removing the guard would?
   <details><summary>Answer</summary>Calling a pointer-receiver method on nil is legal; <code>r</code> is just nil inside. Panic happens only on field dereference. The guard returns before touching <code>r.Rows</code>/<code>r.Fields</code>; without it the first field access panics.</details>
