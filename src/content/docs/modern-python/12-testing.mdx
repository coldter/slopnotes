Python testing in 2026 is one tool wearing many hats: **pytest** is your runner, assertion library, fixture/DI system, and plugin host at once. No separate matcher library, no `expect().toBe()` chain, no `if got != want { t.Errorf(...) }` — you write `assert x == y` and pytest rewrites it so the failure shows exactly what `x` and `y` were. Around that core: `pytest-asyncio` (async tests), `pytest-mock` (mocking), **Hypothesis** (property testing), **Testcontainers** (real Postgres/Redis in tests). The stdlib `unittest` is legacy — ignore it for new work.

## The ecosystem at a glance

| Concept | TypeScript | Go | Python |
|---------|-----------|-----|--------|
| Test runner | Jest / Vitest | `go test` | **pytest** |
| Assertions | `expect(x).toBe(y)` | `if x != y { t.Errorf() }` | plain `assert x == y` |
| Setup/teardown | `beforeEach` / `afterEach` | `TestMain`, `t.Cleanup` | **fixtures** (`@pytest.fixture`) |
| Table tests | `test.each([...])` | `[]struct{}` + `t.Run` | `@pytest.mark.parametrize` |
| Mocking | `jest.mock()` / `vi.fn()` | hand-rolled / testify | `unittest.mock` / `pytest-mock` |
| Async tests | native `async () => {}` | goroutines + sync | `pytest-asyncio` |
| Property testing | fast-check | rapid / gopter | **Hypothesis** |
| Integration (Docker) | testcontainers-node | testcontainers-go | **testcontainers** |
| Coverage | `--coverage` | `go test -cover` | `pytest-cov` / `coverage` |
| HTTP-level tests | supertest | `httptest` | `httpx.AsyncClient` + `ASGITransport` |

## pytest fundamentals

### Test discovery

pytest finds tests by **convention** (like Go's `_test.go` / `TestXxx`): files matching `test_*.py` or `*_test.py`, functions prefixed `test_`, methods prefixed `test_` inside `Test*` classes without `__init__`. No registration, no decorator to be "a test."

```python title="tests/test_calculator.py"
from app.calc import add, divide
import pytest


def test_adds_two_numbers():
    assert add(2, 3) == 5


def test_divide_by_zero_raises():
    with pytest.raises(ZeroDivisionError):
        divide(1, 0)
```

### Plain assert, rich introspection

No matcher library — pytest **rewrites the assertion's bytecode** at import time so a failure shows the operands:

```python
def test_introspection():
    actual = {"name": "alice", "roles": ["user"]}
    expected = {"name": "alice", "roles": ["user", "admin"]}
    assert actual == expected
```

```text
E       AssertionError: assert {'name': 'alice', 'roles': ['user']} == {'name': 'alice', 'roles': ['user', 'admin']}
E         Common items:
E         {'name': 'alice'}
E         Differing items:
E         {'roles': ['user']} != {'roles': ['user', 'admin']}
```

The Jest matcher vocabulary collapses into plain Python operators:

| Jest / Vitest | testify (Go) | pytest |
|---------------|-------------|--------|
| `expect(x).toBe(y)` | `assert.Equal(t, y, x)` | `assert x == y` |
| `expect(arr).toContain(v)` | `assert.Contains(t, arr, v)` | `assert v in arr` |
| `expect(x).toBeNull()` | `assert.Nil(t, x)` | `assert x is None` |
| `expect(fn).toThrow()` | — | `with pytest.raises(E):` |
| `expect(x).toBeCloseTo(y)` | `assert.InDelta(...)` | `assert x == pytest.approx(y)` |

`pytest.raises` doubles as an inspector — `match=` is a **regex searched** against `str(exception)`:

```python
def test_validation_message():
    with pytest.raises(ValueError, match="must be positive") as exc_info:
        set_quantity(-1)
    assert exc_info.value.args[0].startswith("quantity")
```

### Selecting tests: -k, markers, node IDs

```bash
uv run pytest tests/test_tasks.py            # one file
uv run pytest tests/test_tasks.py::test_create  # one test (node ID)
uv run pytest -k "create and not slow"       # keyword expression over names
uv run pytest -m integration                 # only @pytest.mark.integration tests
uv run pytest -m "not integration"           # everything except them
```

`-k` matches substrings of test names/paths with `and`/`or`/`not` (≈ `go test -run` / Vitest `-t`). **Markers** are labels via `@pytest.mark.<name>`, declared in `pyproject.toml` — `--strict-markers` makes a typo'd marker an error, not a silent no-op. Built-ins: `@pytest.mark.skip`, `@pytest.mark.skipif(condition, reason=...)`, `@pytest.mark.xfail`.

### conftest.py: shared fixtures & config

`conftest.py` is auto-discovered by every test in that directory and below — no import needed. Fixtures compose by directory tree:

<FileTree>
- tests/

  - unit/
    - test_service.py
  - integration/
    - conftest.py extra fixtures only integration tests see
    - test_api.py

A fixture in the top `conftest.py` is visible everywhere; one in `integration/conftest.py` only under `integration/`.

## Fixtures: dependency injection for tests

Fixtures are pytest's headline feature. Instead of imperative setup hooks mutating shared state, a fixture is a **function that produces a value**, and a test **requests it by naming it as a parameter** — constructor injection for tests. Fixtures depend on fixtures, so pytest builds a dependency graph and runs each only as needed.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">

```ts
describe("UserService", () => {
  let db: Database;
  beforeEach(async () => { db = await connectDb(); });
  afterEach(async () => { await db.close(); });

  test("creates user", async () => {
    const svc = new UserService(db);
    expect(await svc.create("alice")).toBeDefined();
  });
});
```

  </TabItem>
  <TabItem label="Go">

```go
func TestMain(m *testing.M) {
    db = connectDb()           // shared package var
    code := m.Run()
    db.Close()
    os.Exit(code)
}

func TestCreateUser(t *testing.T) {
    svc := NewUserService(db)
    // ...
}
```

  </TabItem>
  <TabItem label="Python">

```python
import pytest


@pytest.fixture
def db():
    conn = connect_db()
    yield conn          # everything before yield is setup
    conn.close()        # everything after is teardown


def test_creates_user(db):           # "db" param -> inject the fixture
    svc = UserService(db)
    assert svc.create("alice") is not None
```

  </TabItem>
</Tabs>

**The parameter list is your `beforeEach`** — a test that needs a DB asks for `db`; one that doesn't never pays for it.

### Yield fixtures: setup and teardown in one place

A `yield` fixture splits into setup (before) and teardown (after); teardown runs even if the test fails — pytest's answer to `t.Cleanup` / `afterEach`, co-located so you read the lifecycle top to bottom:

```python
@pytest.fixture
def temp_table(db):
    db.execute("CREATE TABLE t (id INT)")
    yield "t"
    db.execute("DROP TABLE t")     # always runs, even on test failure
```

### Scopes: function, module, session

Default is `function` (recreated per test). Widen the scope to share an expensive resource — you control reuse per fixture, not per describe block:

| Scope | Created once per | Use for |
|-------|------------------|---------|
| `function` (default) | each test function | cheap, mutable, per-test state |
| `class` | each test class | shared within a `Test*` class |
| `module` | each test file | a file's worth of tests share it |
| `package` | each package/dir | dir-wide setup |
| `session` | the whole `pytest` run | a Docker container, a connection pool |

```python
@pytest.fixture(scope="session")
def postgres_container():
    with PostgresContainer("postgres:17") as pg:
        yield pg              # one container for the entire test run


@pytest.fixture(scope="function")
def db_session(postgres_container):
    # fresh, rolled-back session per test, built on the shared container
    ...
```

A narrow fixture can depend on a wide one; never the reverse. Typical pattern: **session**-scoped container + **function**-scoped transaction that rolls back, so tests stay isolated without restarting Postgres.

### tmp_path, monkeypatch, capsys: the built-in fixtures

Request them without defining them:

```python
def test_writes_config(tmp_path):
    # tmp_path is a unique pathlib.Path per test, auto-cleaned (= t.TempDir())
    cfg = tmp_path / "config.toml"
    cfg.write_text("debug = true")
    assert load_config(cfg).debug is True


def test_reads_env(monkeypatch):
    # monkeypatch undoes itself after the test — no leaked global state
    monkeypatch.setenv("API_KEY", "test-key")
    monkeypatch.setattr("app.clock.now", lambda: FIXED_TIME)
    assert get_api_key() == "test-key"


def test_prints_banner(capsys):
    print_banner()
    captured = capsys.readouterr()
    assert "Welcome" in captured.out
```

`monkeypatch` safely patches env vars, attributes, and dict items, reverting at test end.

### autouse: the implicit beforeEach

An `autouse=True` fixture runs for every test in scope **without being requested** — the literal `beforeEach`. Use sparingly (implicit setup is harder to trace), perfect for resetting global state:

```python
@pytest.fixture(autouse=True)
def reset_cache():
    cache.clear()
    yield
    cache.clear()
```

## Parametrization: table-driven tests

`@pytest.mark.parametrize` is the direct analog of Go's `[]struct{}` table tests and Jest's `test.each` — one body, many rows, **each row reported as a separate test**:

<Tabs syncKey="lang">
  <TabItem label="TypeScript">

```ts
test.each([
  [1, 1, 2],
  [2, 3, 5],
  [0, 0, 0],
  [-1, 1, 0],
])("add(%i, %i) === %i", (a, b, expected) => {
  expect(add(a, b)).toBe(expected);
});
```

  </TabItem>
  <TabItem label="Go">

```go
func TestAdd(t *testing.T) {
    cases := []struct {
        name          string
        a, b, want    int
    }{
        {"ones", 1, 1, 2},
        {"mixed", 2, 3, 5},
        {"zeros", 0, 0, 0},
        {"negative", -1, 1, 0},
    }
    for _, tc := range cases {
        t.Run(tc.name, func(t *testing.T) {
            if got := Add(tc.a, tc.b); got != tc.want {
                t.Errorf("Add(%d,%d)=%d want %d", tc.a, tc.b, got, tc.want)
            }
        })
    }
}
```

  </TabItem>
  <TabItem label="Python">

```python
import pytest


@pytest.mark.parametrize(
    ("a", "b", "expected"),
    [
        (1, 1, 2),
        (2, 3, 5),
        (0, 0, 0),
        (-1, 1, 0),
    ],
)
def test_add(a, b, expected):
    assert add(a, b) == expected
```

  </TabItem>
</Tabs>

That generates `test_add[1-1-2]`, `test_add[2-3-5]`, … — readable IDs via `pytest.param(..., id="...")` (≈ Go's `tc.name`). Stack multiple `parametrize` decorators for the **cross product** (a 3×4 grid = 12 tests) — something Go table tests make you nest loops for. You can also parametrize a **fixture** (`@pytest.fixture(params=[...])`), rerunning every dependent test once per param — "run the whole suite against sqlite and Postgres."

```python
@pytest.mark.parametrize(
    ("raw", "expected"),
    [
        pytest.param("Hello World", "hello-world", id="simple"),
        pytest.param("  spaced  out  ", "spaced-out", id="extra-spaces"),
        pytest.param("Café!", "cafe", id="strips-accents-and-punct"),
        pytest.param("already-a-slug", "already-a-slug", id="idempotent"),
    ],
)
def test_slugify(raw, expected):
    assert slugify(raw) == expected


@pytest.mark.parametrize("role", ["user", "admin", "guest"])
@pytest.mark.parametrize("method", ["GET", "POST", "PUT", "DELETE"])
def test_authz_matrix(role, method):
    ...   # runs 3 * 4 = 12 times
```

## Async testing with pytest-asyncio

With `asyncio_mode = "auto"`, **every** `async def test_*` is collected and awaited — no decorator. (In `strict` mode, tag each with `@pytest.mark.asyncio`.) Async fixtures work the same — `async def` plus `yield`:

```python
import pytest_asyncio


@pytest_asyncio.fixture
async def db_pool():
    pool = await asyncpg.create_pool(DSN)
    yield pool
    await pool.close()
```

### Testing a FastAPI app with httpx AsyncClient

The supertest/httptest equivalent: drive the app **in-process**, no socket, no `uvicorn`. Point an `httpx.AsyncClient` at an `ASGITransport` wrapping your app:

```python title="tests/test_api.py"
import httpx
from httpx import ASGITransport
from app.main import app


async def test_create_and_get_task():
    transport = ASGITransport(app=app)
    async with httpx.AsyncClient(
        transport=transport, base_url="http://test"
    ) as client:
        resp = await client.post("/tasks", json={"title": "write tests"})
        assert resp.status_code == 201
        task_id = resp.json()["id"]

        resp = await client.get(f"/tasks/{task_id}")
        assert resp.status_code == 200
        assert resp.json()["title"] == "write tests"
```

:::tip[ASGITransport vs TestClient]
FastAPI also ships a synchronous `TestClient` (Starlette's, built on httpx) for quick sync tests. Once your endpoints, DB calls, and tests are all async, `AsyncClient` + `ASGITransport` keeps everything on one event loop and lets you `await` your real async dependencies — no thread-bridging surprises. Ties into [module 07](/modern-python/07-fastapi/).
:::

Wrap the client in a fixture so every test gets one cheaply:

```python title="tests/conftest.py"
import pytest_asyncio
import httpx
from httpx import ASGITransport
from app.main import app


@pytest_asyncio.fixture
async def client():
    transport = ASGITransport(app=app)
    async with httpx.AsyncClient(
        transport=transport, base_url="http://test"
    ) as c:
        yield c
```

```python
async def test_list_is_empty(client):     # request the fixture
    resp = await client.get("/tasks")
    assert resp.json() == []
```

## Mocking: do less of it than you think

Python mocking lives in stdlib `unittest.mock`, but you'll almost always reach it through **pytest-mock**, whose `mocker` fixture auto-undoes every patch at test end:

<Tabs syncKey="lang">
  <TabItem label="TypeScript">

```ts
import { vi } from "vitest";

test("sends email on signup", () => {
  const send = vi.fn().mockResolvedValue(true);
  const svc = new SignupService({ sendEmail: send });
  svc.signup("alice@test.com");
  expect(send).toHaveBeenCalledWith("alice@test.com");
});
```

  </TabItem>
  <TabItem label="Go">

```go
// Hand-rolled fake satisfying the interface.
type fakeMailer struct{ sent []string }

func (f *fakeMailer) Send(to string) error {
    f.sent = append(f.sent, to)
    return nil
}

func TestSignup(t *testing.T) {
    m := &fakeMailer{}
    svc := NewSignupService(m)
    svc.Signup("alice@test.com")
    assert.Equal(t, []string{"alice@test.com"}, m.sent)
}
```

  </TabItem>
  <TabItem label="Python">

```python
def test_sends_email_on_signup(mocker):
    send = mocker.patch("app.signup.send_email", return_value=True)
    signup("alice@test.com")
    send.assert_called_once_with("alice@test.com")
```

  </TabItem>
</Tabs>

**Patch where the name is looked up, not where it's defined.** If `app/signup.py` does `from app.mail import send_email`, patch `"app.signup.send_email"` — the name in the module that *uses* it. This trips up everyone once.

### AsyncMock and patching async deps

`mocker.patch` auto-detects async targets and returns an `AsyncMock`; `autospec=True` makes the mock match the real signature, so a wrong-argument call fails the test (≈ Go's compile-time interface check):

```python
async def test_service_uses_repo(mocker):
    fake_repo = mocker.patch("app.service.repo", autospec=True)
    fake_repo.get = mocker.AsyncMock(return_value=Task(id=1, title="x"))

    result = await service.get_task(1)

    assert result.title == "x"
    fake_repo.get.assert_awaited_once_with(1)
```

### When NOT to mock

Mocking means your test verifies your *assumptions* about the real thing, not the real thing — mock a Postgres client and your test passes even if your SQL is malformed. **Mock what you don't own and can't run; spin up what you do.**

| Mock it | Use the real thing (Testcontainers) |
|---------|-------------------------------------|
| Third-party HTTP APIs (Stripe, SendGrid) | Your own Postgres / Redis / Kafka |
| Slow/flaky external services | Anything where the integration *is* the logic |
| Clock, randomness, UUIDs | ORM queries, migrations, transactions |
| Code paths you can't trigger otherwise | Cache hit/miss behavior |

## Property-based testing with Hypothesis

Example tests check the inputs you thought of; **property tests** check the ones you didn't. Describe the shape of valid inputs with a **strategy**, declare a property that must hold, and Hypothesis throws hundreds of generated cases at it — `fast-check` for Python, and arguably the most mature property library in any ecosystem.

<Tabs syncKey="lang">
  <TabItem label="TypeScript">

```ts
import fc from "fast-check";

test("reverse of reverse is identity", () => {
  fc.assert(
    fc.property(fc.array(fc.integer()), (xs) => {
      expect([...xs].reverse().reverse()).toEqual(xs);
    }),
  );
});
```

  </TabItem>
  <TabItem label="Python">

```python
from hypothesis import given, strategies as st


@given(st.lists(st.integers()))
def test_reverse_of_reverse_is_identity(xs):
    assert list(reversed(list(reversed(xs)))) == xs
```

  </TabItem>
</Tabs>

`@given` feeds generated values as arguments; `st` is the generator vocabulary — `st.integers()`, `st.text()`, `st.lists(...)`, `st.builds(MyModel, ...)`, `st.from_type(...)`. The headline feature is **shrinking**: on failure, Hypothesis simplifies the input and re-runs until it finds the *minimal* failing case — usually the bug stated plainly.

A real property worth writing — a round-trip:

```python
from hypothesis import given, strategies as st
from app.models import Task


@given(
    st.builds(
        Task,
        id=st.integers(min_value=1),
        title=st.text(min_size=1, max_size=200),
        done=st.booleans(),
    )
)
def test_task_json_roundtrip(task: Task):
    # Pydantic: dump to JSON, parse back -> must be equal
    restored = Task.model_validate_json(task.model_dump_json())
    assert restored == task
```

Two more tools: **`assume(predicate)`** discards an input that fails a precondition (without failing), and **stateful testing** (`RuleBasedStateMachine`) generates whole *sequences* of operations and checks invariants after each:

```python
from hypothesis import given, assume, strategies as st

@given(st.integers(), st.integers())
def test_division(a, b):
    assume(b != 0)          # skip b == 0 rather than dividing by zero
    assert (a // b) * b + (a % b) == a
```

```python
from hypothesis.stateful import RuleBasedStateMachine, rule, invariant

class CacheMachine(RuleBasedStateMachine):
    def __init__(self):
        super().__init__()
        self.cache = LRUCache(capacity=3)
        self.model: dict[str, int] = {}

    @rule(k=st.text(max_size=2), v=st.integers())
    def put(self, k, v):
        self.cache.put(k, v)
        self.model[k] = v

    @invariant()
    def never_exceeds_capacity(self):
        assert len(self.cache) <= 3
```

:::caution[Property tests are slower — budget for it]
Each property runs many examples (100 by default) and shrinking adds more on failure. Keep them in your normal suite, but don't put network or DB calls inside a `@given` body — that's hundreds of round-trips. Property-test pure logic (parsers, serializers, domain invariants); integration-test the wiring separately.
:::

## Testcontainers: real dependencies, disposable

Testcontainers spins up a real service in a Docker container scoped to your test run — no `docker compose up` ceremony, no readiness polling; the library waits and hands you connection details. The `with` block *is* the lifecycle:

```python
import pytest
from testcontainers.postgres import PostgresContainer


@pytest.fixture(scope="session")
def postgres_url():
    with PostgresContainer("postgres:17") as pg:
        # the container is up and ready here; tears down on block exit
        yield pg.get_connection_url()   # postgresql+psycopg2://test:test@.../test


@pytest.mark.integration
def test_real_query(postgres_url):
    # convert to the asyncpg DSN your app uses, run a real query...
    ...
```

A `session`-scoped container starts **once** for the whole run; pair it with a `function`-scoped transaction-rollback fixture so each test sees a clean DB without restarting Postgres. Redis, Kafka, and generic containers follow the same pattern (`RedisContainer`, `KafkaContainer`). This is the payoff of modules 09/10 — you test against the actual engines those modules target.

:::caution[Honest take: Testcontainers needs Docker, and it's not free]
Containers add seconds to your suite and require a Docker daemon (locally and in CI). The discipline that keeps it sane: **mark them** (`@pytest.mark.integration`) and **scope the container to the session**. Inner loop: `uv run pytest -m "not integration"` (pure Python, sub-second). Full suite (`uv run pytest`) runs the integration layer before merge and in CI — real-database confidence without paying on every save.
:::

## Coverage

`pytest-cov` wraps `coverage.py` and plugs `--cov` into pytest:

```bash
uv run pytest --cov=app --cov-report=term-missing   # uncovered line numbers per file
uv run pytest --cov=app --cov-report=html            # htmlcov/index.html
```

Enforce a floor so coverage can't silently rot — `term-missing` is the actionable part (`go test -cover` + `go tool cover -html` / Jest `--coverage` equivalents). Coverage is a floor, not a target: 85% means 15% has *zero* tests — act on untested *logic*, don't grind a vanity metric.

```toml title="pyproject.toml"
[tool.coverage.report]
fail_under = 85
show_missing = true

[tool.coverage.run]
branch = true                  # measure branch coverage, not just lines
omit = ["*/migrations/*", "*/__main__.py"]
```

```bash
uv run pytest --cov=app        # exits non-zero if below fail_under
```

## Test layout, speed, and the pyramid

Separate fast unit tests from Docker-backed integration tests by directory, mirroring the marker split:

<FileTree>
- pyproject.toml pytest + coverage + markers config
- src/
  - app/
    - main.py
    - service.py
    - repository.py
- tests/
  - conftest.py shared fixtures
  - unit/ fast, no I/O — pure logic
    - test_service.py
  - integration/ Testcontainers, real Postgres
    - conftest.py db/container fixtures
    - test_repository.py
    - test_api.py
</FileTree>

| Layer | What | Speed | How many |
|-------|------|-------|----------|
| Unit | service/domain logic, mocked or pure | µs–ms | most |
| Integration | repo + real DB (Testcontainers), API via `AsyncClient` | 10s–100s ms | some |
| Property | invariants of pure functions (Hypothesis) | ms each, many cases | targeted |
| E2E | full stack over real HTTP | seconds | a handful |

Push assertions down to the cheap unit layer; reserve container-backed integration tests for the seams where the integration *is* the logic (SQL, serialization, transactions). Run `uv run pytest -m "not integration"` constantly while coding; run the full suite before you merge.

### Fixtures vs factories

Fixtures answer "what's set up." For test *data*, use a **factory function** with defaults (the Kotlin/Go test-data builder) so each test overrides only what it cares about:

```python
def make_task(**overrides) -> Task:
    return Task(**{"id": 1, "title": "test task", "done": False, **overrides})


def test_completed_filter():
    tasks = [make_task(id=1, done=True), make_task(id=2, done=False)]
    assert [t.id for t in completed(tasks)] == [1]
```

For larger projects, **factory-boy** generates model instances with sequences, sub-factories, and faker-backed fields (the fishery analog) — reach for it once hand-rolled `make_*` helpers start duplicating logic.

## Summary

| Concept | TypeScript | Go | Python |
|---------|-----------|-----|--------|
| Runner | Jest / Vitest | `go test` | `pytest` |

| Setup/teardown | `beforeEach` / `afterEach` | `TestMain` / `t.Cleanup` | fixtures + `yield` |
| Table tests | `test.each` | `[]struct{}` + `t.Run` | `@pytest.mark.parametrize` |

| Async tests | native | goroutines | `pytest-asyncio` |
| HTTP tests | supertest | `httptest` | `AsyncClient` + `ASGITransport` |
| Property testing | fast-check | rapid | Hypothesis (`@given`) |
| Docker deps | testcontainers-node | testcontainers-go | testcontainers |
| Coverage | `--coverage` | `go test -cover` | `pytest-cov` / `coverage` |
