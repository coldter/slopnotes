Auther is a single Next.js app acting as an OAuth2/OIDC identity provider. Each chapter in Part 1 maps to a directory in the tree below.

## Technology stack

| Layer | Technology | Purpose |
|-------|-----------|---------|
| Framework | Next.js 16 (App Router) | SSR, API routes, server actions |
| Auth engine | better-auth | Auth core, sessions, the OIDC provider |
| Database | SQLite via Turso / libSQL | Serverless, edge-compatible; libSQL speaks HTTP |
| ORM | Drizzle ORM | Type-safe schema and queries |
| Token signing | jose (RS256) | Asymmetric JWT sign/verify — clients verify offline |
| Policy engine | wasmoon (Lua-in-WASM) | ABAC policies and pipeline scripts in a hard sandbox |
| Queue | Upstash QStash | Async webhook delivery with retries — workers are API routes |
| Cache | Upstash Redis | Webhook idempotency, rate limiting |
| Email | Resend + React Email | Verification, password reset |
| UI | Radix UI + Tailwind CSS 4 | Admin dashboard |
| Validation | Zod | API inputs, authorization models |
| Editor | CodeMirror 6 | Lua script editing |
| Visualization | React Flow (`@xyflow/react`) | Pipeline DAG editor |
| Charts | Recharts | Dashboard metrics |

Two rows are load-bearing:

- **RS256 via `jose`.** Clients fetch the public key once from JWKS, cache it, and verify every token offline — Auther is never on the request hot path. Swap to HS256 and every verification becomes a call back to the server.
- **Lua-in-WASM via `wasmoon`.** User-authored policies run sandboxed with no host access, and they change at runtime — no rebuild, no restart.

:::tip[Two choices, two superpowers]
Asymmetric signing buys **stateless verification**; WASM-sandboxed Lua buys **runtime-editable logic**. Almost every Part 1 design decision traces back to one of them.
:::

## Project structure

Three concerns dominate: auth config (`lib/auth.ts`), the authorization engine (`lib/auth/`), and the schemas that back them (`db/`).

<FileTree>
- src/
  - app/
    - admin/ admin dashboard (users, clients, groups, keys…)
    - api/
      - auth/
        - [...betterAuth]/ better-auth catch-all route handler
        - api-key/exchange/ API key → JWT exchange endpoint
        - check-permission/ runtime ABAC permission-check endpoint
        - verify-invite/ invite-token verification endpoint
      - internal/
        - rotate-jwks/ JWKS rotation cron endpoint
        - queues/ QStash webhook delivery workers
        - cleanup-traces/ pipeline trace cleanup
      - webhooks/payload/ inbound webhook receiver
    - sign-in/ authentication UI
    - reset-password/ password-reset UI
  - components/
    - admin/ admin dashboard, pipelines, access control
    - auth/ authentication form components
    - ui/ shared UI (code editor, forms)
  - db/
    - auth-schema.ts **better-auth core tables (user, session, account, apikey, jwks, oauth)**
    - app-schema.ts application tables (access control, webhooks, client metadata, groups)
    - rebac-schema.ts **ReBAC tables (access_tuples, authorization_models)**
    - abac-schema.ts ABAC tables (audit logs, policy versions)
    - pipeline-schema.ts pipeline tables (scripts, execution plans, graphs, traces, spans)
    - platform-access-schema.ts registration contexts, invites, permission requests/rules, templates
    - metrics-schema.ts metrics storage table
  - lib/
    - auth/ **the authorization engine (permission service, models, policy engine, guards)**
    - auth.ts **better-auth server configuration**
    - auth-client.ts better-auth React client
    - session.ts server-side session helpers (`getSession`, `requireAuth`, `requireAdmin`)
    - repositories/ data-access layer (15+ repository classes)
    - services/ business logic (API-key resolver, metrics, registration, templates)
    - pipelines/ pipeline integration (definitions, hooks, execution)
    - webhooks/ webhook delivery (signatures, queue, service)
    - email/ email sending (Resend) and templates (React Email)
    - middleware/ origin validation
    - utils/ helpers (CORS, OAuth, URL handling, wildcards)
  - schemas/ Zod validation schemas (ReBAC models, clients, users, groups)
  - proxy.ts Next.js edge middleware (route protection)
  - env.ts environment-variable validation (Zod-based)
- scripts/ CLI utilities (seed admin, seed clients, test auth flow)
- drizzle/ database migrations
- docs/ architecture and implementation documents
</FileTree>

:::note[How to read Part 1]
[Authentication](/auther/server/authentication/) lives in `lib/auth.ts` and `app/api/auth/`; [ReBAC](/auther/server/rebac/) and [ABAC](/auther/server/abac-groups/) in `lib/auth/` and the `*-schema.ts` files; [pipelines and webhooks](/auther/server/pipelines-webhooks/) in `lib/pipelines/` and `lib/webhooks/`.
:::
