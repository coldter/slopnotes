When you adopt a centralized identity provider, you stop owning authentication. The
IdP runs sign-up, sign-in, password hashes, 2FA, session tokens, and key rotation;
your app gets a signed JWT and trusts it. **Auther** is that identity provider —
built so you can run it yourself instead of renting Auth0, Keycloak, or Ory.

Auther is a standalone OAuth2 / OIDC server (a Next.js 16 app on `better-auth`) that
serves *many* client applications at once. What sets it apart from a plain login
service is the authorization half: a hybrid **ReBAC + ABAC** permission engine
inspired by Google Zanzibar. Permissions are computed from relationship tuples and
embedded directly in the JWT, so the common-case check is zero-latency; only
context-dependent decisions fall back to a live call.

This course has two parts. **Part 1** explains what Auther *is* — every subsystem,
how it makes decisions, and how the six kinds of client connect to it. **Part 2** is
the hard part nobody warns you about: landing a centralized IdP into an app that
already owns its `users` table and a web of foreign keys, without a multi-week
rewrite.

## Who this is for

- You build and operate backends, and you're evaluating or adopting a centralized IdP.
- You're comfortable with OAuth2/OIDC, JWTs, and HTTP, and you want the internals —
  not a quickstart.
- You need to integrate auth into a *real* codebase with existing data, not a
  greenfield toy.
